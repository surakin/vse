# The module map of the dependency gate (Phase 12 Day 141; ARCHITECTURE.md section 1 is the source for the layers).
#
#   scan <dir>                        a directory whose sources and CMakeLists.txt files are checked
#   exclude <substring>               a path containing it is neither scanned nor mapped (fixtures, vendored code)
#   include-dir <dir>                 an include directory, tried after the including file's own directory, in this order
#   system-include <regex>            a quoted include that is not ours (a system or generated-code header) and need not resolve
#   module <path> <name> <layer>      a file, or a directory when the path ends in '/', belongs to the module; the longest path wins
#   allow <from> <to>                 a same-layer edge a module's row permits (an edge to a lower layer needs no entry)
#   same-layer-ok <layer>             every module of the layer may use every other (the programs); cycles are still checked
#   forbid <from> <to>                an edge that is wrong whatever the layers say (a backend using another backend, the
#                                     renderer using a backend directly)
#   platform-dir <dir/> <owner/>,...  files under <dir/> are per-platform code: only files under an owner directory (or the
#                                     directory itself) may include them
#   layer <module> <layer>            the layer of a module that has no files of its own (a CMake aggregate)
#   target <cmake-target> <module>    the module a CMake library or executable belongs to (flavor suffixes _asan/_tsan are
#                                     stripped before the lookup); every add_library/add_executable under a scan directory needs one
#   syslib <prefix> <module>          a system library (a CMake imported target) that only this module's targets may link
#
# A violation that is known and scheduled goes in allowlist.txt, not here.
