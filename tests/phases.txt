# The phase that owns each test (Phase 6, docs/superpowers/specs/2026-11-05-test-scoping-design.md).
#
# `<pattern>  <phase>`: a source path relative to the repo root (`*` inside one segment; a trailing `/` is a whole
# directory), or `test:<glob>` for a test that is not a Catch2 test case. Phases: 0 foundation, 1 Linux platform,
# 2 jobs, 3 docs tooling, 4 RHI, 5 renderer, 6 test scoping, 7 debugging facilities, 8 RHI reset, 9 file handling, 10 standard types and containers, 11 settings system, 12 module layering, 13 Windows port, 14 font and text, 15 UI system, 16 standard-library wrappers, 17 ECS, 18 spatial partitioning, 19 storage, 20 networking, 22 asset pipeline and resource system, 21 macOS port (a side phase, run on the Mac beside the main line: `SIDE_PHASES`, Phase 21 Day 283). The rule is the phase that owns the behavior, not the directory.

# Adding a Catch2 test file: add a line here, or the build stops naming the file. Adding another kind of test: add a
# `test:` line and call engine_label_tests() after add_test. Labels are `phase0` ... `phase20`, `phase21` (the macOS port) and `phase22`.
# `flavors <phase> plain,asan,tsan` lines (below) list the sanitizer flavors each phase has tests in; a new phase needs one.
