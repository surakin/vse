# Phase 7 / Day 112 — Reset Loops, Golden Equality & Sanitizers

**Phase:** [Phase 7 — RHI Reset](../phase-07-rhi-reset.md)
**Depends on:** Days 108-111.

The phase's acceptance tests: the definition of done, stated as tests, plus planted regressions to prove they catch breakage.

## Tasks

- [x] **Reset loop:** a test that applies a `DeviceReset` 100 times (null backend, in every flavor) and 100 times on Vulkan (GPU label; 20 in ASan/TSan flavors if 100 is too slow, recorded) with a scene of objects, lights and materials; after each iteration `ResourceCounts` equals the first iteration's, device memory is equal, the registry holds the same owners, `RendererStats` shows no failures; after the loop resident memory and open fds are within the tolerance measured in Day 103.
- [x] **Golden equality:** render the `renderer_demo` offscreen scene, reset, render again: the two images are pixel-identical on the same adapter (zero tolerance, same GPU and driver), and both match the existing blessed golden within its existing tolerance. A cross-adapter variant (iGPU vs dGPU) compares with the golden tolerance only and skips on a single-adapter machine.
- [x] **Reset during a frame sequence:** 50 frames with a changing camera, a reset requested at frames 7, 8 (a newer request replacing it), 20 (swapchain class) and 31 (device class); the scene state (object transforms, light list, material parameters) is identical before and after by value, and frame indexes continue.
- [x] **Every cost class under load:** one test per class asserting what *did not* happen (a `Dynamic` change creates no device object; a `Swapchain` change keeps the device epoch), using device statistics, not timing.
- [x] **Concurrency:** a scheduler-backed renderer resetting while worker jobs are queued (TSan flavor); the reset joins the workers' recording before touching the device; a job submitted during the reset waits.
- [x] **Planted regressions** (restored afterwards), recording which are caught: skip one owner's `Release` (leak count fails); keep a stale handle in a material (stale-handle abort or the equality test fails); skip the dirty flag of `FrameData` (golden equality fails); skip the registry's tier order (a test of order fails); skip the `Quiesce` before destruction (validation or TSan catches it); make rollback a no-op (the rollback test fails); make recovery ignore the retry limit (the limit test fails). Uncaught ones go to `KNOWN-ISSUES.md` with the test gap.
- [x] Add each new test file to `tests/phases.txt` (phase 7) and verify `scripts/test-phase.sh --affected` selects them from a change to `engine/renderer/material.cpp` and to `engine/rhi/device_host.cpp`.
- [x] **Documentation:** the guide's "Testing a reset" paragraph (how to write a test that survives a reset, how to use the counts); `docs/guide/building-and-testing.md` lists the new GPU tests and the multi-adapter skip; `ctest -L docs`.
- [x] Run the scoped tests and the asan and tsan flavors; quote the lines.
- [x] **End-of-day review (CLAUDE.md):** `/code-review high` on the day's diff (mostly tests and any fixes they forced); record it.
- [x] Update `STATUS.md` and `KNOWN-ISSUES.md`; commit.

**Done:** the loop, golden, mid-sequence and concurrency tests pass in the plain, ASan and TSan flavors, the seven planted regressions are caught or filed, and nothing leaked across 100 resets on either backend.

## Result

New: `tests/renderer/reset_rig.h` (the deferred demo frame on a replaceable device, every owner registered), `tests/renderer/reset_soak_test.cpp` (100 resets on the null backend with the counts, registry size and statistics unchanged; a 50-frame sequence with resets at frames 7, 8, 31 and a swapchain-class change at 20, material parameters byte-identical and the frame numbering continuing; each cost class leaves alone what it should, by object counts and device serial; a reset with the job scheduler running; a material following an owner rebuilt on its own), `tests/rhi/vulkan_reset_golden_test.cpp` (on the real device: the picture before and after a reset is byte-identical and both match the blessed `renderer_demo.ppm` golden within its tolerance; 100 resets, 20 under the sanitizers, counts and device memory equal after each, +520 KiB resident and 0 descriptors over 95 resets). `DeviceHost::LeakedObjects()` counts objects still alive when a device is destroyed after the observers released; both loops assert it is 0. `DemoFrame` gained `FrameSetup::host/create_info/initial_settings/window/recovery` and `GetRenderer()`. Guide: `building-and-testing.md` "Testing a reset".
Planted regressions (restored afterwards): skip one owner's `Release` (`FrameResources`) caught by the soak loop through `LeakedObjects`; a stale raw handle in a material caught; skipping the owner-handle refresh (the dirty logic) caught by the "follows an owner rebuilt on its own" test (not by the reset tests: `Recreate` refreshes the same handles itself); wrong registry tier order caught; rollback made a no-op caught by two tests; recovery ignoring the retry limit caught. **Not caught:** removing the `Quiesce` calls in `DeviceHost` (all of them): the device's own destructor and `DeviceDeleter` wait for idle anyway, so the mutation changes nothing a test can see (an equivalent mutant of the host-level call; filed). The plan's "skip FrameData's dirty flag" has no counterpart: `FrameResources` rewrites everything every frame.
Deviations (filed in `KNOWN-ISSUES.md`): no test resets with worker jobs queued (the contract is that `ApplySettings` is called on the owning thread between frames and never from a job); the cross-adapter golden variant needs two GPUs; the 50-frame test compares the object and light counts and one material's parameter bytes, not every transform and light by value; `scripts/test-phase.sh --affected` always includes the new tests because phase 7 is the current phase.
Scoped runs: plain `ran 1022 of 2713 tests (phases: all; flavors: plain; display: included; crash tests: excluded)`, all pass; asan `ran 749 of 2713 ... flavors: asan`; tsan `ran 470 of 2713 ... flavors: tsan`; docs 4/4.
