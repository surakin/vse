# Phase 26 / Day 432 — Compressed Audio I: Vendoring libogg and libvorbis

**Phase:** [Phase 26 — Audio](../phase-26-audio.md)
**Depends on:** Day 414 spike 5; Days 416, 417.

Bring in the Vorbis decoder as a vendored library (the user's decision, 2026-11-17), behind a facade, with the hostile-input rules around it. A deliberate, individually justified exception to the third-party line, in the same category as FreeType, SQLite and LuaJIT; `PLAN.md` assumption #30.

## Tasks

- [ ] Vendor libogg and libvorbis as source under `third_party/libogg/` and `third_party/libvorbis/` at the versions Day 414 pinned (SHA-256 and licence in `VENDORED.md`, the BSD licence texts kept); only the decoder files (`vorbisfile`, `vorbisenc` and the encoder are not built); portable C, built by our CMake on all three platform paths; our warning flags do not apply to them (they sit after `third_party/` like the others); `BUILD.md` lists them.
- [ ] `audio/vorbis.h` and `audio/vorbis.cpp`: the facade and the only file that includes the libraries' headers (a gate enforces it, as for sentry and FreeType: `module_deps_check`, `std_usage_check` and the vendored-include check get entries with reasons). The facade owns the Ogg sync and stream state and the Vorbis decode state through `UniquePtr`-style owners with deleters; nothing of libvorbis crosses the header.
- [ ] `VorbisDecoder::Open(bytes)`: parses the three headers through the libraries and reports every failure as a status value (never an abort or exit); returns channels, rate, nominal bitrate, tags (strings, never trusted) and, when the stream says so, the length in frames; refuses what the engine does not take (more than 8 channels, a rate outside 8,000 to 384,000, a setup larger than a fixed byte budget, a stream that is not Vorbis, a chained or multiplexed stream beyond the first logical stream, which is skipped).
- [ ] `Decode(f32* out, frames)`: pulls pages from the byte source or from an `io::File` reader, feeds them to the libraries and converts the planar `float**` output to the engine's interleaved layout and channel order (Vorbis order for 3 to 8 channels mapped to the engine's layouts by name); the output of a decode call is a block of at most N frames; no allocation after `Open` except what the libraries make themselves; it runs on a job, never on the audio thread.
- [ ] Hostile input around a library that is not ours: input size and page count limits checked before feeding, a per-call step budget so a stream that never produces audio cannot hang a job, a cap on the total decoded frames against the header's claim, an allocation budget (a counting hook through the libraries' allocator macros, `_ogg_malloc` and friends, where they allow it, otherwise the setup limit above); a mutation fuzz (fixed seed, a time limit) over the fixtures: bit flips, truncation at every length and page-level shuffles, under asan and ubsan, no crash, no hang, no unbounded memory.
- [ ] Fixtures: small committed test streams (a sine, noise, a stereo mix, a short- and long-block mix, a coupled-channel stream, a 5.1 stream) with a README giving the source recipe and licence, made as Day 414 spike 5 decided.
- [ ] Tests: the fixtures open and report channels, rate, tags and length; every refusal path (bad magic, setup too large, too many channels, truncated header, not Vorbis) has a test; the fuzz passes; the facade header includes no library header.
- [ ] **Runs (CLAUDE.md "Tests run by phase"):** `scripts/test-phase.sh --affected` plain; then the asan and tsan flavors (this phase is concurrency, lifetime and memory code on nearly every day); quote each run's final `ran X of Y tests (phases ...)` line in this file and never say "all tests pass" for a reduced run. `ctest -L docs` when a public header or a guide changed. Build clean (warnings are errors) with both compilers and unity on and off; `-DENGINE_BUILD_SHARED=ON` and `-DENGINE_LIBRARY_WITH_IMPORTER=OFF` still build.
- [ ] **Three machines (CLAUDE.md):** built and tested on the machine the day is done on (Linux); shared code (CMake, the gates, tests, headers) is checked on the Windows PC and the Mac no later than Days 440-441, and `KNOWN-ISSUES.md` lists what waits for those runs.
- [ ] **Documentation (CLAUDE.md "Public API is documented before a day is done"), when a public header changed:** `///` comments with the contract labels and `docgen lint` at zero; `cmake --build build --target docs` output committed; `docs/guide/audio.md` updated or created; tagged samples compile and run.
- [ ] **Module rules (CLAUDE.md):** a new module, target or edge updates `ARCHITECTURE.md`, `tools/module_deps_check/modules.txt`, `tests/module_map.txt` and `BUILD.md` in the same commit; every new test file has its line in `tests/phases.txt` (phase 26); only wrapped types, no `std`, no raw platform macros; the audio thread never allocates, locks or does I/O.
- [ ] **Day review (CLAUDE.md, required):** `/code-review high` over the day's diff after the scoped tests; verify, fix (with a regression test shown to fail without the fix) or decline each finding with a reason; record the count and outcome under "Post-implementation code review" below and in `STATUS.md`.
- [ ] `STATUS.md` and `KNOWN-ISSUES.md` updated in the same commit; commit and push.

**Done:** libogg and libvorbis are vendored and built on every platform path, the facade opens the fixtures and refuses malformed input by status, and the fuzz run is clean under asan and ubsan.
