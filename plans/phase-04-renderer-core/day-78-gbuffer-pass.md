# Phase 4 / Day 78 — The G-buffer Geometry Pass

**Phase:** [Phase 4 — Renderer Core](../phase-04-renderer-core.md)
**Depends on:** Day 77.

The first real renderer pass: draw every visible object into the G-buffer with its material, depth-tested.

## Tasks

- [ ] Create the G-buffer targets as graph transients from the formats fixed in the spec, sized to the swapchain, validated with `FormatSupport` at renderer creation (a missing format is a logged failure naming the format, not a crash).
- [ ] Slang geometry shaders: a base `gbuffer.slang` (vertex: object matrix from the object buffer by instance index, world normal; fragment: sample albedo/normal map/material params and pack into the MRTs) with permutations for normal map and alpha test; octahedral normal packing in a shared Slang module with CPU reference functions and a round-trip test.
- [ ] Vertex colors (needed by Phase 7's colored 3D text, and generally useful for tinted/baked geometry): meshes may carry an optional per-vertex color. `MeshData` gains an optional RGBA8 color array (absent means none, `StandardVertex` and every existing mesh and test stay unchanged); `GpuMesh` uploads it as a second vertex stream at a fixed location after the four standard attributes, and `ColorVertexLayout()` describes it (the pipeline cache already keys on the vertex layout). `gbuffer.slang` gets a `VERTEX_COLOR` permutation that multiplies the material albedo by the interpolated color. Colors are authored in sRGB and converted to linear in the shader (decide and document the convention in the spec; add the round-trip to the shader/CPU reference tests). A mesh with colors drawn through a material without the permutation, or the reverse, is a named error at draw-list build time, not a silent mismatch. Test: a two-colored triangle strip reads back per-vertex gradients analytically, and a mesh without colors renders exactly as before.
- [ ] Triangle strips (and the other topologies) end to end. Today `rhi::PrimitiveTopology::TriangleStrip` exists in `GraphicsPipelineDesc` and maps to Vulkan, but nothing renders with it: no test draws a strip, the RHI has no primitive restart (so one indexed draw cannot hold several strips), and the renderer has no notion of topology. Add: (a) `GraphicsPipelineDesc::primitive_restart` (Vulkan `primitiveRestartEnable`; the restart index is the all-ones value of the index type; validated: only for indexed draws, and only strip topologies unless the device reports list-restart support), documented in the RHI header, with null-device validation; (b) an RHI GPU test with validation and sync validation that draws a quad as a 4-vertex strip, as an indexed strip, and two strips in one indexed draw split by a restart index, reading pixels back (a strip with the wrong winding alternation or a missing restart shows up as a wrong or missing triangle); (c) `MeshData`/`GpuMesh` carry a `PrimitiveTopology` (default `TriangleList`; line and point topologies allowed), the material template's pipeline state takes it from the mesh, and the pipeline cache key includes it, so a strip mesh and a list mesh with the same material get separate pipelines; (d) CPU helpers `StripToList` and `ListToStrip` (degenerate-triangle joins or restart indices, chosen by a flag) with tests that the triangle sets match, and a strip builder for the procedural meshes where it saves vertices (grid, cylinder side); (e) the culling and draw-sort paths handle strips (bounds come from vertices, not triangle counts), pinned by a test.
- [ ] The pass: cull the scene (Day 73), sort by the Day 74 key, bind pipeline/material groups only on change and issue instanced draws for runs of the same mesh and material; per-draw cost is a handful of RHI calls and no object creation.
- [ ] Depth keeps the Phase 3 convention (no reverse-Z): stored `DepthAttachment`, read in the lighting pass as `DepthRead`; near/far derived from the scene bounds by a camera helper.
- [ ] Offscreen GPU tests (golden + analytic): in a known scene (a plane, a sphere, a cube behind it) read back the G-buffer layers - albedo equals the material albedo, decoded normals match the geometry within tolerance, the nearer object wins in depth; a shuffled draw order gives identical results; culled objects do not appear.
- [ ] A debug view (`ShowGBuffer(layer)`) for the demo: albedo, normals, material, linear depth.
- [ ] **Documentation (CLAUDE.md "Public API is documented before a day is done"):** The pass, the G-buffer layout and the geometry shader contract are documented in the guide and spec. `docgen lint` stays at zero findings, `cmake --build build --target docs` output is committed, `ctest -L docs` passes.
- [ ] **End-of-day review (CLAUDE.md):** run `/code-review high` on the day's diff, fix/decline each finding with a reason, record it under a "Post-implementation code review" section here, and mention it in `STATUS.md`.
- [ ] Update `STATUS.md`; commit (code, tests, regenerated `docs/reference/` and the guide pages together).

**Done:** A scene of many materials renders into a G-buffer whose layers are verified analytically and by golden image, with correct depth ordering independent of draw order.
