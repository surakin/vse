# Phase 20 / Day 268 — Linux Socket Backend, the Socket Interface & the Access Gate

**Phase:** [Phase 20 — Networking](../phase-20-networking.md)
**Depends on:** Days 266-267; Phase 9 (the `BACKEND.md` pattern and `file_access_check`).

The one place that calls `socket`, `bind`, `connect`, `send` and the like on Linux, behind an interface a Windows backend can implement, and the gate that keeps it so.

## Tasks

- [ ] **`net::Socket`** (move-only handle): `OpenTcp`, `OpenUdp`, `Bind`, `Listen`, `Accept`, `Connect` (non-blocking, completes later), `Send`, `Receive`, `SendTo`, `ReceiveFrom`, `Shutdown`, `Close`, `LocalEndpoint`, `PeerEndpoint`, option setters (`ReuseAddress`, `NoDelay`, `KeepAlive`, `ReceiveBuffer`, `SendBuffer`, `DualStack`, `Broadcast` off by default); **every socket is non-blocking and close-on-exec from creation** (`SOCK_NONBLOCK | SOCK_CLOEXEC`); partial reads and writes are normal results; `EINTR` retried inside the backend; `SIGPIPE` never raised (`MSG_NOSIGNAL`).
- [ ] **Linux backend** in `engine/net/linux/` and the shared POSIX parts in `engine/net/posix/` (the macOS backend will reuse them); errno mapped through the Day 267 table.
- [ ] **`engine/net/BACKEND.md`** (what a new platform implements: every `Socket` operation, error mapping, readiness, resolver, and the platform's quirks), kept in step by a ctest `net_backend_lists` as `io_backend_lists` does.
- [ ] **Gate `net_access_check`** (`tools/net_access_check`, ctest `net_access_check`): fails on `socket(`, `bind(`, `connect(`, `listen(`, `accept(`, `send(`, `recv(`, `sendto(`, `recvfrom(`, `getsockopt(`, `setsockopt(`, `getaddrinfo(`, `epoll_*`, `WSA*` and `<sys/socket.h>`, `<netinet/*>`, `<arpa/inet.h>`, `<winsock2.h>` outside `engine/net/{linux,posix,windows,macos}/`; allow list with a reason per entry and a stale entry fails; `platform_neutral_check` and `std_usage_check` allow lists updated.
- [ ] **Tests** (`tests/net/socket_test.cpp`, label `network`): loopback TCP connect/accept/echo through a polling loop (no reactor yet); UDP echo; `Bind` to port 0 reports the chosen port; `AddressInUse`; `Refused` on a closed port; partial write of a buffer larger than the socket buffer; `Shutdown` then read returns closed; a socket closed twice or used after close is `Invalid`, never a crash; the skip path when sockets are unavailable prints its reason.
- [ ] **Runs (CLAUDE.md "Tests run by phase"):** `scripts/test-phase.sh --affected` plain; then the asan and tsan flavors (sockets, readiness and connection state are concurrency and lifetime code); quote each run's final `ran X of Y tests (phases ...)` line in this file and never say "all tests pass" for a reduced run. Real-socket tests are labelled `network` and use loopback with ephemeral ports only. `ctest -L docs` when a public header or a guide changed. Build clean (warnings are errors) with Clang and GCC, unity on and off. New code uses the engine's wrappers and types, never `std` (`std_usage_check`).
- [ ] **Two machines (CLAUDE.md "Windows is a supported platform"):** shared code is portable and checked on the Windows PC no later than Day 281 (Day 278 for the socket backend itself); until then the day is "open until the other machine runs it" in `KNOWN-ISSUES.md`.
- [ ] **Documentation (CLAUDE.md "Public API is documented before a day is done"):** public headers carry `///` comments with the contract labels (`docs/DOC-CONVENTIONS.md`); `docgen lint` stays at zero; `cmake --build build --target docs` output committed; new modules are added to `docs/reference/modules.txt`; the guide page `docs/guide/net.md` is updated or created and its tagged samples compile and run.
- [ ] **Module rules (CLAUDE.md "Module dependencies follow ARCHITECTURE.md"):** a new module or edge updates `ARCHITECTURE.md`, `tools/module_deps_check/modules.txt` and the CMake targets (with `_asan`/`_tsan` flavors) in the same commit; no upward edge, no cycle; every new test file has its line in `tests/phases.txt` (phase 20).
- [ ] **Day review (CLAUDE.md, required):** `/code-review high` over the day's diff after the scoped tests; verify, fix (with a regression test that fails without the fix) or decline each finding with a reason; record the count and outcome under "Post-implementation code review" below and in `STATUS.md`.
- [ ] `STATUS.md` and `KNOWN-ISSUES.md` updated in the same commit; commit and push.

**Done:** a non-blocking socket interface works on Linux loopback for TCP and UDP, every error is a portable value, and the gate stops a raw socket call anywhere else.
