## Post-implementation code review

The uncapped end-of-phase review (Days 266-281, about 15,600 lines of `engine/net`) was done by two read-only reviewers (transports; sockets, reactor and addresses) instead of `/code-review` in one context, because the diff does not fit in one. **19 findings** (12 and 7), the reviewers' other areas (codec, frames, rate limiter, simulated network, addresses, epoll and select pollers) gave none.

Fixed: `Reactor::Shutdown` returned without joining the thread after a poller failure (destroying a joinable thread terminates); a lost empty UDP packet halved the congestion window; `close_repeats = 0` made a closing UDP connection last forever; the UDP per-address cap compared exact addresses while the TCP one groups an IPv6 /64; `net.timeout_ms` below the fixed keep-alive or ping interval killed healthy idle connections (the keep-alive and ping are now at most a quarter of the time-out; regression test in `net_settings_test.cpp`); the `handshake_limits` doc promised bans; `reactor.h` and `Reactor::Close` comments were stale or overclaimed; `net_probe ping --count=0` read out of bounds; `net_demo`'s header listed an option that does not exist. Regression tests only for the time-out clamp; the others have no practical injection point or are one-line guards.

Filed in `KNOWN-ISSUES.md`, not fixed (protocol or contract changes, or no way to reproduce here): the UDP wire-id misrouting when both ends listen and connect, the receiver ending a connection when a lost message lets later ones run too far ahead, unreliable partial messages filling the reassembly slots, TCP receive memory outside the budget, `SendFrame` between the queue size and the frame limit, `net_probe echo` ignoring a full queue, `SetLinger` with a positive time, a dropped waiter on a failed re-arm inside `Begin`, and two platform error-code differences.
