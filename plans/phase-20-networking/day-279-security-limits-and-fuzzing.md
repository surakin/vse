# Phase 20 / Day 279 — Security Basics: Budgets, Rate Limits & Fuzzing

**Phase:** [Phase 20 — Networking](../phase-20-networking.md)
**Depends on:** Days 274-277.

Nothing is trusted before the handshake completes; every length is bounded before allocation; hostile input is fuzzed.

## Tasks

- [x] **Budgets:** a per-connection memory budget (receive buffers, reassembly, reorder buffer, send queues) and a global one, enforced by the transports with `LimitExceeded` closes and counted in statistics; no allocation sized by a peer-supplied number without checking it against the budget first (an audit pass over Days 271-277 with a checklist in this file).
- [x] **Rate limits:** handshakes per second per endpoint and in total, accepts per second, new connections per endpoint; a token bucket with a documented clock; excess is dropped silently (UDP) or refused (TCP); a ban list with expiry for repeat offenders, bounded in size.
- [x] **Fuzzing:** deterministic fuzz tests (a seeded generator and mutation of valid packets and frames) through the UDP packet parser, the handshake, the fragment reassembler, the TCP frame reader, `NetReader` with random schemas, and the address parser, 1 million cases each, plain and asan, no crash, no allocation above the limits, no state before the handshake; a libFuzzer-style entry point is **not** added (no new dependency), the corpus is generated.
- [x] **Threat notes** `docs/guide/net.md` section "What the network layer does not protect against": spoofing on an untrusted path, eavesdropping and tampering (until Day 280's outcome), amplification, state exhaustion; what is mitigated and how.
- [x] **Tests** (`tests/net/security_test.cpp`): half-open floods, handshake floods, fragment bombs, slow-loris on TCP, reorder-gap attack, ack-bitfield lies (acking packets never sent), sequence-number games; each ends within its budget and the server stays responsive to a good client.
- [x] **Runs (CLAUDE.md "Tests run by phase"):** `scripts/test-phase.sh --affected` plain; then the asan and tsan flavors (sockets, readiness and connection state are concurrency and lifetime code); quote each run's final `ran X of Y tests (phases ...)` line in this file and never say "all tests pass" for a reduced run. Real-socket tests are labelled `network` and use loopback with ephemeral ports only. `ctest -L docs` when a public header or a guide changed. Build clean (warnings are errors) with Clang and GCC, unity on and off. New code uses the engine's wrappers and types, never `std` (`std_usage_check`).
- [x] **Two machines (CLAUDE.md "Windows is a supported platform"):** shared code is portable and checked on the Windows PC no later than Day 281 (Day 278 for the socket backend itself); until then the day is "open until the other machine runs it" in `KNOWN-ISSUES.md`.
- [x] **Documentation (CLAUDE.md "Public API is documented before a day is done"):** public headers carry `///` comments with the contract labels (`docs/DOC-CONVENTIONS.md`); `docgen lint` stays at zero; `cmake --build build --target docs` output committed; new modules are added to `docs/reference/modules.txt`; the guide page `docs/guide/net.md` is updated or created and its tagged samples compile and run.

**Done:** hostile peers and malformed packets cannot exhaust memory or state, the limits are measured, and the parsers survive the fuzz.

## Outcome (2026-11-12, Linux machine)

- **Rate limits:** `net::RateLimiter` (`net/rate_limit.h`): token bucket per address (IPv6 /64 as one) and global, strikes and a ban list, in a fixed table of 8-entry buckets that never grows. UDP: handshake requests over the limit are dropped silently (`handshake_limits`, `DefaultHandshakeLimits()`); **no bans on UDP** (review finding: a forged source would lock a real address out). TCP: accepts limited per address and in total, `max_connections_per_address`, a stream that fails its handshake is a strike (three in a minute ban for five minutes).
- **Budgets:** global receive budget in UDP (`max_total_receive_buffer_bytes`, ends the connection that would pass it, `budget_closes`), global send budget in TCP (`max_total_send_queue_bytes`, `Send` returns `LimitExceeded`), a Hello-sized frame limit before the TCP handshake, Pong replies bounded by the send queue limit. `net::TcpStream` allocates its read and scratch buffers on first use and its send ring at 4 KiB, doubling to its capacity (`SendQueueAllocatedBytes()`): the Day 271 entry in `KNOWN-ISSUES.md` is removed (`net.connection_budget_bytes` is the settings name on Day 281).
- **Allocation audit checklist (Days 271-277):** `FrameReader` payload grows with arrived bytes, never with the declared length [ok]; UDP reassembly: `total` and `count` checked against the fragment size, the message limit, `max_reassemblies` and both budgets before `Resize` [ok]; UDP reorder buffer: per-connection and global budget before `Push` [ok]; `NetReader::ReadBytes/ReadString`: length against the caller's maximum and the bits left before allocation [ok]; TCP Data frame: channel, kind and size against the negotiated limits before the copy [ok]; Hello: channels and size are clamped to ours [ok]; UDP handshake tables: capped, fail closed (Day 274) [ok]; `TcpStream` queue: capped by `send_queue_bytes`, grown only for a frame that fits [ok].
- **Fuzzing** (`tests/net/fuzz_test.cpp`): 1,000,000 cases each for the address and endpoint parsers (round trip) and the packet header readers with the sequence windows (lying acknowledgements), 100,000 each for the frame reader (cut anywhere), 250,000 for `NetReader`, 100,000 datagrams and 20,000 streams against live UDP and TCP servers; plain and asan, about 2 s plain.
- **Tests:** `rate_limit_test.cpp` (6), `security_test.cpp` (9: handshake flood, spoofed sources, forged bad cookies, global receive budget, lying acks, sequence games, slow-loris, accept flood, send budget), a regression test for the ping flood exists from Day 277; `tcp_test.cpp` (idle stream memory). Fix to an existing test: the spoofed-flood test of Day 274 turns the limits off (it tests state, not rates).
- **Runs:** plain `ran 2830 of 7520 tests (phases: all; flavors: plain; display: included; crash tests: excluded)` (all passed), asan `ran 2251 of 7520 tests (phases: all; flavors: asan; display: included; crash tests: excluded)` (all passed), tsan `ran 1927 of 7520 tests (phases: all; flavors: tsan; display: included; crash tests: excluded)` (only the known scene test failed). Clean on Clang unity and non-unity, GCC, release; docs 7 of 7.
- **Not done:** the real-socket variants of the attacks (loopback has one address; the simulated network gives addresses); the mixed-connection tsan test of Day 277 is still open.
