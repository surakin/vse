# Phase 11 / Day 138 — Command Line, the Demos and the Other Consumers

**Phase:** [Phase 11 — Settings System](../phase-11-settings-system.md)
**Depends on:** Days 134-137.

The user-visible end: the demos finally get the options that were held back (`KNOWN-ISSUES.md`, "Needed: an engine settings system"), and the engine's scattered environment variables and the log configuration become settings. Files touched: `game/renderer_demo`, `game/rhi_demo`, `game/*_bench`, `engine/foundation/log`, `engine/foundation/main.cpp`, `engine/rhi`, `engine/jobs`, `engine/foundation/debug`.

## Tasks

- [x] A shared `demo::SettingsMain` helper in `game/common` that builds a `Settings` for a demo (application name, registered settings, command line), handles `--settings FILE`, `--save-settings [FILE]`, `--set key=value`, `--list-settings` (every setting: key, type, default, current value, where it came from, description) and prints `--help` **generated from the registry and the flag aliases**; unknown options are errors with a suggestion.
- [x] `renderer_demo` and `rhi_demo` use it: their existing flags (`--gpu`, `--no-vsync`, `--validation`, `--backend`, `--frames`, `--script`, ...) become flag aliases of settings where they are settings and stay plain launch options where they are not (the Day 130 inventory decides each); behavior of every existing invocation is unchanged (the demo ctests pass unmodified); the F-keys of `renderer_demo` go through `Settings::Set`, so a saved file reproduces a session (`--save-settings out.cfg`, then `--settings out.cfg`).
- [x] The engine's own environment variables registered as settings with `env` aliases and read through the environment layer where an application has a `Settings`, with the old direct `getenv` kept only where no `Settings` can exist yet (before `main` has built one; each such place listed in the spec): `ENGINE_RHI_GPU`, `ENGINE_RHI_VALIDATION*`, `ENGINE_RHI_CACHE_DIR`, `ENGINE_WINDOW_BACKEND`, `ENGINE_JOB_THREADS`, `ENGINE_CRASH_HANDLER`. `DeviceCreateInfo` is filled from the settings by one function.
- [x] Logging: channel verbosity and enabled state are settings (`log.<channel>.verbosity`, `log.<channel>.enabled`), applied through a listener; `log::LoadConfig` is reimplemented on the settings system (same file lines still work through a documented migration) or removed with its test ported; the Phase 7 log tests pass.
- [x] `KNOWN-ISSUES.md`: the "Needed: an engine settings system" entry is removed; entries for what this phase leaves (remote config, a UI binding layer, secrets) are filed.
- [x] Tests (phase 11 and the demo ctests): `--list-settings` golden output; `--help` golden output; `--set` of every type through the demo's argument parser; a saved file reproduces a scripted session; the old flags still work; the environment variables still work and now show their provenance; log channel verbosity from a settings file.
- [x] **Documentation:** the demo READMEs (options tables generated or checked against the registry by a ctest `demo_help_current`); the guide gets "Settings in an application" (the standard `main`); reference regenerated; `docgen lint` zero; `ctest -L docs`.
- [x] Run `scripts/test-phase.sh --affected` and the asan and tsan flavors; both demos 1000 frames with `--validation` on Wayland and X11; quote the lines.
- [x] **End-of-day review (CLAUDE.md):** `/code-review high`.
- [x] Update `STATUS.md`; commit.

**Done:** both demos read, list, set and save settings, the old invocations behave exactly as before, the engine's environment variables and log configuration are settings with visible provenance, and the held-back item is gone from `KNOWN-ISSUES.md`.


## Result

- New: `game/common/settings_main.h/.cpp` (`demo::DemoSettings`: `Begin`, `SetLegacy`, `FillDeviceCreateInfo`, `ReadEffective`, `Finish`), `settings/engine_settings.h/.cpp` (`RegisterEngineSettings`, `RegisterLogSettings`, `AttachLogSettings`), `settings/report.h/.cpp` (`FormatSettingsListing`, `FormatSettingsHelp`, `SaveSettingsTo`), env/flag aliases and descriptions on the rendering settings, `LogChannel::First/Next`, `SettingDesc::max_text` earlier; both demos call `Begin`/`Finish`; `renderer_demo` starts from the shared settings and its F keys and `--script` go through `Settings::Apply` with `ApplySharedChange`; both demos fill the device description from the settings in one function. Tests: 9 demo CLI checks per demo (`--list-settings` and `--help` against goldens, every type through `--set`, the environment and its provenance, the old flags, a legacy flag yielding to `--set`, a bad key with a suggestion, a bad value, `--save-settings` then `--settings`), `readme_current` per demo (the README block must equal the generated help), and `tests/settings/engine_settings_test.cpp`.
- Deviations: the old flags (`--no-vsync`, `--validation`) stay the demos' own and are translated into settings (they cannot be flag aliases of an enum); `--backend` and `--gpu` are now aliases of `platform.window_backend` and `renderer.adapter`; only settings something reads are declared (`platform.window_backend`, `rhi.pipeline_cache`, `rhi.pipeline_cache_dir` and the 14 rendering settings): `ENGINE_JOB_THREADS`, `ENGINE_CRASH_HANDLER` and `ENGINE_RHI_VALIDATION_BEST_PRACTICES` stay environment variables read before any settings exist (listed for Day 139's configuration check); `log::LoadConfig` is unchanged and the `log.<channel>.*` settings are a second way (KNOWN-ISSUES).
- Runs: plain `ran 1303 of 3389 tests (phases: all; flavors: plain; display: included; crash tests: excluded)` (only the known X11 test fails); asan `ran 948 of 3389`; tsan `ran 665 of 3389`; both demos 1000 frames `--validation` on Wayland and X11 exit 0; docs lint 4009/4009.

## Post-implementation code review

`/code-review high`: 10 findings. Fixed (with tests): a secret's value showed in the `--set` origin of the listing; settings were declared that nothing read (removed; the three that remain are wired); a convenience flag overrode an explicit `--set` (now it only applies to a default); a refused `Apply` logged the previous result (now says why and stops); a long row was cut and glued to the next (no fixed buffer); `--save-settings=FILE` was world-readable, wrote secrets and overwrote a file it could not read (mode 0600, secrets left out, a read error stops it); log channel handling (a name too long is skipped, the key table only grows so older registries stay valid, attach applies only what a layer set). Declined: the `jobs.threads` range note (the setting is gone).
