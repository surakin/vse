## Outcome

The spec `docs/superpowers/specs/2026-11-16-c-api-scenes-design.md` holds the nine decisions and the numbers of the five spikes (`tests/scene/scene_spikes_test.cpp`, `[spike]`): a renderer on a window's device (3.9 ms per frame; findings: the frame object must move from `game/renderer_demo` into the engine, and the renderer needs a before-present hook for read-backs), two devices (a second device adds about 7 ms of content upload once), live textures (0.22 ms CPU per 720p upload, one per frame), labels (+0.14 ms per name tag, +1.4 ms for a hundred), goldens (two devices: 0 of 65,536 values differ; the cross-GPU figure was not measurable, no software rasteriser installed). `CURRENT_PHASE` is 24; the phase file lists each decision with its day; Days 359 and 367 were edited. No public header changed, so no docs regeneration beyond the link in `docs/README.md` (`ctest -L docs` passes).

Runs (`--affected`): plain `ran 3377 of 8927 tests (phases: all; flavors: plain; display: included; crash tests: excluded)`, asan `ran 2689 of 8927`, tsan `ran 2349 of 8927` (the GPU spikes leave tsan out on Linux). The plain run had one failure, `X11Window releases keys and modifiers on a real focus loss but not during WM grabs`, which passes alone (the X11 focus family flakes under load, `KNOWN-ISSUES.md`). Builds clean with GCC, non-unity and shared. The three-machine check of the spike file is open (it skips without an X11 window on Windows and macOS).
