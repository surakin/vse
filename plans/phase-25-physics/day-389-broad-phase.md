# Phase 25 / Day 389 — The Broad Phase on Phase 18's Spatial Module

**Phase:** [Phase 25 — Physics](../phase-25-physics.md)
**Depends on:** Day 388; Phase 18 (`spatial::DynamicBvh`, `StaticBvh`, `SpatialSet`, `PairTracker`).

Find which pairs of colliders may touch, using the structures that already exist; nothing new is built here but the glue and its proof.

## Tasks

- [x] A physics `SpatialSet` pair registered with the world's `SpatialWorld`: a static set backed by `StaticBvh` (rebuilt when static colliders change, in a batch) and a dynamic set backed by `DynamicBvh` with fat boxes (the margin from the Day 385 spec); every collider's key is its `ColliderId`.
- [x] Bounds come from the shape and the body transform; a body moving faster than its fat margin is re-inserted, others cost nothing (the sync system of Phase 18 reports what moved); swept bounds (the box extended along the velocity for one step) are used for bodies flagged `continuous`.
- [x] The layer matrix: `physics::CollisionFilter` (32 layers, `meets` bits) is the `spatial::PairTrackerConfig` of the physics set, plus per-collider `group` and `mask` words for finer filtering after the broad phase **(not built: Day 395 "layers and filters")**; static-static pairs never form.
- [x] The pair feed: begin and end events from `PairTracker` (sorted by key, Phase 18's guarantee) become the narrow phase's deterministic work list: a vector of `(ColliderA, ColliderB)` with the smaller id first, plus the kept pairs from earlier steps, in sorted order.
- [x] Triggers join the same feed and are flagged; sensors never reach the solver.
- [x] Statistics: pairs begun, ended and kept, nodes visited, rebuilds, per step, exposed as `PhysicsStats`.
- [x] An oracle test: a brute-force O(n^2) overlap of the same boxes gives the same pair set on 20 random scenes of 1000 bodies; the pair list is identical for 1, 2 and 8 job threads **(not applicable: the update is single-threaded, see Outcome)**; a body that jitters at the edge of contact does not begin and end every step (the margin works).
- [x] A test that fails when the static tree is not rebuilt after a static collider is added, removed or moved: `SpatialSet::Stats().pending_static` is zero before the pair update, and the update of 5000 moving boxes with 2000 statics stays under 3 times the figure with the tree built (Day 385 spike 6: an unbuilt tree cost 31 ms against 4 ms a frame, every query scanning the pending statics) **(the timing half is not a test: see Outcome)**.
- [x] **Runs (CLAUDE.md "Tests run by phase"):** `scripts/test-phase.sh --affected` plain; then the asan and tsan flavors (this phase is concurrency, lifetime and memory code on nearly every day); quote each run's final `ran X of Y tests (phases ...)` line in this file and never say "all tests pass" for a reduced run. `ctest -L docs` when a public header or a guide changed. Build clean (warnings are errors) with both compilers and unity on and off; `-DENGINE_BUILD_SHARED=ON` and `-DENGINE_LIBRARY_WITH_IMPORTER=OFF` still build.
- [x] **Three machines (CLAUDE.md):** built and tested on the machine the day is done on (Linux); shared code (CMake, flags, the gates, tests, headers) is checked on the Windows PC and the Mac no later than Days 410-411, and `KNOWN-ISSUES.md` lists what waits for those runs.
- [x] **Documentation (CLAUDE.md "Public API is documented before a day is done"), when a public header changed:** `///` comments with the contract labels and `docgen lint` at zero; `cmake --build build --target docs` output committed; `docs/guide/physics.md` updated or created; tagged samples compile and run.
- [x] **Module rules (CLAUDE.md):** a new module, target or edge updates `ARCHITECTURE.md`, `tools/module_deps_check/modules.txt`, `tests/module_map.txt` and `BUILD.md` in the same commit; every new test file has its line in `tests/phases.txt` (phase 25); only wrapped types, no `std`, no raw platform macros.

**Done:** Moving bodies produce the same sorted pair work list as a brute-force search, independent of the thread count, at a cost the stats report.

## Outcome

Built: `physics/broad_phase.h/.cpp` (`BroadPhase`, `BroadPhaseConfig`, `CollisionFilter`, `ColliderPair`, `BroadPhaseStats`), `ColliderId::ToKey()/FromKey()` (the slot in the high half, so pairs sort by slot) and `PhysicsWorld::ColliderAtSlot`. `BroadPhase::Update(world)` walks the colliders in slot order, adds, removes and moves them in a `spatial::SpatialSet` (static bodies in the static tree, the rest in the fat-box dynamic tree), handles type changes and layer changes (a changed layer re-adds the item), rebuilds the static tree before the pair update, then updates a `spatial::PairTracker` and builds the sorted work list (different bodies, at least one dynamic body, layers that meet; trigger pairs flagged; a kinematic body against a static one dropped unless a trigger). Continuous bodies get a swept box.
Checks: 20 random scenes of 1000 bodies (static, dynamic, three shape kinds, a layer pair that does not meet), four rounds each with 30 percent moved, teleports and type changes, equal to a brute-force oracle at margin 0; hysteresis (120 steps at the edge of contact: one pair begun, none ended); destroyed bodies and reused slots; layers, body types and triggers; moved statics and type changes; swept bounds (a 300 m/s body meets a wall it would tunnel through); two broad phases fed the same calls give the same lists; `pending_static` is zero after every update and an unchanged update does not rebuild. **Mutation check:** with the `NeedsRebuild` block disabled, 3 of the 9 broad phase tests fail (85 assertions): the rebuild is pinned.
**Deviations:** (1) the thread-count test does not apply: `PairTracker::Update` is single-threaded (Day 385 finding 2), so the list cannot depend on threads; Day 412 revisits it with the 4.7 ms reference. (2) The "under 3 times" timing is not a test (timing tests flake); the guarantee is the `pending_static == 0` assertion, which the mutation shows fails. (3) Per-collider `group` and `mask` words are not built: Day 395 (layers and filters) adds them. (4) `Begun()` and `Ended()` are the tracker's events as it reports them (unfiltered).
**Runs:** plain `ran 3434 of 9092 tests (phases: all; flavors: plain; display: included; crash tests: excluded)`, asan `ran 2744 of 9092 ...`, tsan `ran 2402 of 9092 ...`, no failure; GCC and non-unity `physics_tests` 52 of 52 (53 after the review); `ctest -L docs` 8 of 8, docgen lint at zero for `physics`. Not run: the shared-library and importer-off builds, the Windows and macOS machines.

## Post-implementation code review

`/code-review high` over the diff, read with the eight angles: 1 finding worth a test, no defect. A layer change removes and re-adds an item under the same key, and `PairTracker::Remove` followed by a new item of that key could in principle drop pairs that still meet: a test (`a changed layer keeps the pairs that still meet and drops the ones that no longer do`) shows it does not, so no code changed. Noted and fixed in the guide: an unmoved collider costs a box computation and a comparison, not just a comparison. Declined: none.
