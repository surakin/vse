# Phase 5 / Day 71 — Shader Reflection & the Mint Tool

**Phase:** [Phase 5 — Renderer Core](../phase-05-renderer-core.md)
**Depends on:** Day 70.

Make shaders describe themselves so materials and bind group layouts are generated from them, not written twice. This is the first piece of the Phase 28 mint, scoped to shaders.

## Tasks

- [x] Add `tools/shader_mint/` (a C++ tool using the foundation): consumes the SPIR-V and the `-reflection-json` that CMake's `slangc` invocation writes (CMake already owns the pinned arguments and version; the tool does not spawn the compiler), parses the JSON with nlohmann/json (vendored under `third_party/nlohmann_json/`, tool-only, `PLAN.md` assumption #19; decided 2026-11-05 instead of a hand-written reader), writes the SPIR-V words as `*.spv.inc` and a compact reflection blob as `*.refl.inc`. `spv_embed` is folded into it.
- [x] Define `renderer::ShaderReflection` (`engine/renderer/shader_reflection.h`): entry/stage, bindings (set, binding, `rhi::BindingType`, array size, stages, name), uniform block layouts (member names, offsets, sizes, types), push-constant range, vertex inputs (location, `VertexFormat`, name), compute local size. Plain data.
- [x] Round-trip tests: reflect each existing shader and compare with hand-written expectations (the lit shader's block: 176 bytes and member offsets; its three bindings; the cube vertex layout); a C++ struct whose size disagrees with the reflected block fails a generated size check.
- [x] Builders `MakeBindGroupLayoutDesc(const ShaderReflection&, set)` and vertex attribute builders, tested on the null and real devices; merging a vertex+fragment pair into one layout (stage masks OR-ed, conflicting types reported with names).
- [x] Reflection output is committed like the `.spv.inc` files, `shaders_check` verifies it is current, and the whole path still builds without `slangc` installed.
- [x] Failure tests: a reflection blob with a bad version, truncated data or an unknown type is rejected with a message and never read out of bounds (random-truncation test, run under ASan).
- [x] **Documentation (CLAUDE.md "Public API is documented before a day is done"):** `ShaderReflection`, the builders and the mint tool are documented in headers and in the shaders guide (what is generated, what is committed, how to regenerate). `docgen lint` stays at zero findings, `cmake --build build --target docs` output is committed, `ctest -L docs` passes.
- [x] **End-of-day review (CLAUDE.md):** run `/code-review high` on the day's diff, fix/decline each finding with a reason, record it under a "Post-implementation code review" section here, and mention it in `STATUS.md`.
- [x] Update `STATUS.md`; commit (code, tests, regenerated `docs/reference/` and the guide pages together).

**Done:** Every engine shader has committed reflection data, layouts and vertex inputs are built from it, and malformed blobs are rejected safely.

## Result

- **`tools/shader_mint/`** replaces `spv_embed` (deleted): `slangc ... -o x.spv -reflection-json x.json`, `spirv-val`, then `shader_mint --spv --reflection ...` writes the committed `<name>.spv.inc` and `<name>.refl.inc` (the SPIR-V words are unchanged; only the banner line differs). The JSON is read with vendored nlohmann/json v3.12.0 (`third_party/nlohmann_json/`, tool-only), not a hand-written reader: decided with the user on 2026-11-05 and recorded as `PLAN.md` assumption #19 and in `CLAUDE.md` before use. Plan deviations: the tool does not spawn `slangc` (CMake does), and the tool and its tests use `std::string`/`std::vector` because the library requires them (the engine runtime libraries still do not; recorded in #19).
- **`renderer::ShaderReflection`** (`engine/renderer/shader_reflection.{h,cpp}`): plain fixed-capacity data (stage, entry, local size, bindings with set/binding/`BindingType`/array count/stages/block, uniform and push-constant block layouts with member names/offsets/sizes/types, vertex inputs); `ValidateShaderReflection`, `SerializeShaderReflection`/`ParseShaderReflection` (versioned little-endian blob, strict: identifier-only names, canonical flags, counts and enums range-checked, no trailing bytes), `FindBlock`, `CheckBlockSize`.
- **Builders:** `BuildBindGroupLayout` (one or more shaders, stage masks OR-ed, conflicts reported with both variable names, sorted by binding), `BuildBindGroupLayoutFor` (one shader), `BuildVertexLayout` (packed interleaved binding). Tested against hand-written expectations (lit: 176-byte block, offsets 0/64/128/144/160, three bindings; cube: stride 32, offsets 0/12/24), on the null device and on a real device with validation and sync validation.
- **Generated size checks:** each `.refl.inc` also carries `k<Name><Block>Size` and `k<Name><Block><Member>Offset`; `LitUniforms` and the cube `Mat4` block in `game/common/cube_scene.cpp` now `static_assert` against them instead of typed numbers.
- **Safety nets in the tool:** `CrossCheckSpirv` compares the reflected (set, binding) pairs, compute local size and vertex input locations (Input variables only, both directions) with the compiled SPIR-V; layout facts missing from the JSON are errors, not zeros; generated constant-name collisions are errors; both output files are written to temporaries and renamed together.
- **Failure tests:** every prefix of every committed blob is rejected (exact-size heap copies, run under ASan), 5200 deterministic random corruptions are either rejected or re-serialize to the same bytes, plus bad magic, bad version, unknown stage, unknown binding type, trailing bytes, null input; `tests/shader_mint` tests the JSON conversion's rejections (unsupported types, missing fields, long names, duplicate bindings, bad group size).
- **Builds without `slangc`:** configuring with `-DSLANGC=SLANGC-NOTFOUND` builds and passes all reflection, interface and tool tests from the committed files; `shaders_check` verifies both `.inc` files when `slangc` is present.
- **Docs:** headers carry `///` comments (renderer module 79/79), `docs/guide/rhi-shaders.md` has a "Reflection" section with a tagged sample (docs samples now link `renderer`), `docs/guide/renderer.md`, `shaders/README.md`, `docs/reference/` regenerated; docs 1770/1770.
- Full suite 1339/1339 except the Xwayland `X11Window::Create opens a mapped window on the real X server` (Day 69 environment problem).

## Post-implementation code review

`/code-review high` returned 10 findings.

Fixed: (1) `CrossCheckSpirv` counted every `Location` (outputs included): now Input-storage-class variables only, compared in both directions; test with an output-only location. (2) Missing or mistyped `offset`/`size`/block size/`space`/`index` silently became 0: now errors, with tests. (3) Generated constant names could collide (a member called `size`; `a_b` vs `aB`): the tool rejects duplicates, and `ValidateShaderReflection` rejects duplicate block or member names. (4) The guide still listed `tools/spv_embed/` and `PLAN.md` named it: guide fixed, `PLAN.md` notes the fold into `shader_mint`. (5) `vertex_inputs` documented as declaration order but sorted by location: doc fixed. (6) `Appendf` truncated at 512 bytes: sizes the output (checked with 700-character arguments). (7) The two outputs were not written atomically as a pair: both temporaries are written before either rename. (8) A stale `error` string leaked into a later message: cleared on entry, with a test. (9) `threadGroupSize` truncated above 32 bits: range-checked, with a test.

Declined, with reason: (10) The tool uses `std::string`, `std::vector` and `<algorithm>` although the project avoids the STL: the JSON library is built on them and the tool is offline-only; `PLAN.md` #19 and `CLAUDE.md` now say exactly that, and the engine runtime libraries are unaffected. Also found by the day's own tests, not the review: the parser accepted non-canonical blobs (a flag byte other than 0/1, names with embedded NULs); fixed by strict parsing and identifier-only names, and the lsan suppressions were shared with the renderer GPU test.
