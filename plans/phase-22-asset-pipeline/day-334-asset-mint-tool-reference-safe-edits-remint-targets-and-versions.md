# Phase 22 / Day 334 — The `asset_mint` Tool II: Reference-Safe Edits, Remint, Target Packs & Version Enforcement

**Phase:** [Phase 22 — Asset Pipeline & Resource System](../phase-22-asset-pipeline.md)
**Depends on:** Day 333 (the tool's project file, `mint`, `pack`, `verify`, `list`, `check`, the manifest).

The commands that change a project without breaking a reference, the upgrade path, retargeting for another platform and the checks that no old blob slips through. (Split from Day 333 on 2026-11-14, the user's decision.)

## Tasks

- [ ] **Level column images (moved from Day 327, 2026-11-14):** decide spike 5's question for levels (the design spec says it is answered on this day's planning step, not on Day 327): whether components that are trivially copyable plain data (the registered fields cover the whole object, no padding) are stored as one memory image per component type with a layout fingerprint (name, id, version, size, alignment, field kinds) checked at load, and whether the ECS can adopt a column into an archetype chunk without per-entity work; measure against Day 327's loader (`LoadLevelBlob`, which decodes every record through the registry and fills the world through `storage::WorldStorage::Load`) on a 100,000-entity level before building it. If the numbers do not justify it, record that in the spec and drop it.
- [ ] **Commands (part II):** `asset_mint copy` and `reid` (a new id for a duplicated source; `reid` fixes the duplicate-id failure of Day 333), `refs <asset>` (what references it and what it references), `rename` and `move` (change the alias, never the id; nothing else to update), `delete` (**refused while anything references the asset**, listing the referrers; `--with-dependents` lists what would have to go first and still does nothing without the user removing the references), `remint` (rewrite old-version blobs to the current version: the upgrade chains of every type live in this tool, implemented from Day 318 on; the result must be byte-identical to a fresh mint of the same source where the source is available, and is verified so) and `unmint` (blob back to source text for levels and materials).
- [ ] **Breaking a reference is impossible through the tool (part II):** tests: rename and move leave every dependent's blob bytes unchanged (ids only); delete of a referenced asset exits non-zero with the referrers named and changes nothing; `reid` fixes two sources that share an id.
- [ ] **`pack --target <platform>` retargets the blobs (the user, 2026-11-13: packaging must be able to change the minted files when the target platform requires it).** Minting produces blobs for the development target (the host platform and its graphics API); packing may rewrite them for another. A `TargetTransform` registry lives in `tools/asset_mint` only (never linked into a game), one optional function per resource type: `(blob, target, context) -> blob`. Rules: the result is a current-version blob of the same type and **the same id**; the dependency section may not change (a transform cannot add or drop a reference; checked per blob); the output is deterministic; the content hash is recomputed and the whole closure is verified again after every transform, then the pak is written. A transform may ask the context for the **source** and re-mint with target options instead of converting the blob (needed where converting would compress twice, such as BC7 to ASTC: the texture transform re-mints from the source). The incremental manifest keys on the target, so a second target does not redo the first. Targets in this phase: the host platforms; the built-in transform is the **texture relayout** (the minter records the row pitch and slice alignment of the target API, Day 323, which differ between Vulkan, Direct3D 12 and Metal); every other type passes through unchanged. Phase 28 (ASTC, mobile mesh and texture variants) and Phase 29 (console formats) add transforms through the same registry. `verify --target` checks a pak against its target. Tests: a pass-through target leaves the bytes identical; a transform that changes a dependency is refused; two packs for one target are byte-identical; a pak for one target is refused by the runtime for another (Day 316).
- [ ] **Version enforcement:** `verify --require-current` fails (non-zero exit, names every old blob and the fix) when any blob or pak is not the current version of its type; `pack` refuses non-current or unverifiable blobs; the manifest records every type's format version so a bump rebuilds all blobs of that type on the next `mint`; ctest `asset_mint_old_versions_fixture` runs `verify --require-current` over a fixture directory with one blob of every older version of every type (it must fail naming all of them), then `remint` (it must succeed), then `verify --require-current` (it must pass) and compares with a fresh mint.
- [ ] **Runs (CLAUDE.md "Tests run by phase"):** `scripts/test-phase.sh --affected` plain; then the asan and tsan flavors when the day touched concurrency, lifetime or memory code; quote each run's final `ran X of Y tests (phases ...)` line in this file and never say "all tests pass" for a reduced run. `ctest -L docs` when a public header or a guide changed. Build clean (warnings are errors) with Clang and GCC, unity on and off. New code uses the engine's wrappers and types, never `std` (`std_usage_check`); file access only through `io::` (`file_access_check`); settings only through `settings::Registry` (`config_access_check`).
- [ ] **Three machines (CLAUDE.md "Three machines"):** shared code is portable and checked on the Windows PC and the Mac no later than Day 340; until then the day is "open until the other machines run it" in `KNOWN-ISSUES.md`.
- [ ] **Documentation (CLAUDE.md "Public API is documented before a day is done"):** public headers carry `///` comments with the contract labels (`docs/DOC-CONVENTIONS.md`); `docgen lint` stays at zero; `cmake --build build --target docs` output committed; new modules are added to `docs/reference/modules.txt`; the guide page `docs/guide/assets.md` is updated and its tagged samples compile and run.
- [ ] **Module rules (CLAUDE.md "Module dependencies follow ARCHITECTURE.md"):** a new module or edge updates `ARCHITECTURE.md`, `tools/module_deps_check/modules.txt` and the CMake targets (with `_asan`/`_tsan` flavors) in the same commit; no upward edge, no cycle; every new test file has its line in `tests/phases.txt` (phase 22).
- [ ] **Day review (CLAUDE.md, required):** `/code-review high` over the day's diff after the scoped tests; verify, fix (with a regression test that fails without the fix) or decline each finding with a reason; record the count and outcome under "Post-implementation code review" below and in `STATUS.md`.
- [ ] `STATUS.md` and `KNOWN-ISSUES.md` updated in the same commit; commit and push.

**Done:** assets can be renamed, moved, copied and deleted through the tool without a dangling reference, old blobs are upgraded and verified against a fresh mint, `pack --target` retargets a pak through the transform registry, and `verify --require-current` names every old blob.
