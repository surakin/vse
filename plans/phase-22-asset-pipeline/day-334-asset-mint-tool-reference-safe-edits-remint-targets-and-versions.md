# Phase 22 / Day 334 — The `asset_mint` Tool II: Reference-Safe Edits, Remint, Target Packs & Version Enforcement

**Phase:** [Phase 22 — Asset Pipeline & Resource System](../phase-22-asset-pipeline.md)
**Depends on:** Day 333 (the tool's project file, `mint`, `pack`, `verify`, `list`, `check`, the manifest).

The commands that change a project without breaking a reference, the upgrade path, retargeting for another platform and the checks that no old blob slips through. (Split from Day 333 on 2026-11-14, the user's decision.)

## Tasks

- [x] **Level column images (moved from Day 327, 2026-11-14):** decide spike 5's question for levels (the design spec says it is answered on this day's planning step, not on Day 327): whether components that are trivially copyable plain data (the registered fields cover the whole object, no padding) are stored as one memory image per component type with a layout fingerprint (name, id, version, size, alignment, field kinds) checked at load, and whether the ECS can adopt a column into an archetype chunk without per-entity work; measure against Day 327's loader (`LoadLevelBlob`, which decodes every record through the registry and fills the world through `storage::WorldStorage::Load`) on a 100,000-entity level before building it. If the numbers do not justify it, record that in the spec and drop it.
- [x] **Commands (part II):** `asset_mint copy` and `reid` (a new id for a duplicated source; `reid` fixes the duplicate-id failure of Day 333), `refs <asset>` (what references it and what it references), `rename` and `move` (change the alias, never the id; nothing else to update), `delete` (**refused while anything references the asset**, listing the referrers; `--with-dependents` lists what would have to go first and still does nothing without the user removing the references), `remint` (rewrite old-version blobs to the current version: the upgrade chains of every type live in this tool, implemented from Day 318 on; the result must be byte-identical to a fresh mint of the same source where the source is available, and is verified so) and `unmint` (blob back to source text for levels and materials).
- [x] **Breaking a reference is impossible through the tool (part II):** tests: rename and move leave every dependent's blob bytes unchanged (ids only); delete of a referenced asset exits non-zero with the referrers named and changes nothing; `reid` fixes two sources that share an id.
- [x] **`pack --target <platform>` retargets the blobs (the user, 2026-11-13: packaging must be able to change the minted files when the target platform requires it).** Minting produces blobs for the development target (the host platform and its graphics API); packing may rewrite them for another. A `TargetTransform` registry lives in `tools/asset_mint` only (never linked into a game), one optional function per resource type: `(blob, target, context) -> blob`. Rules: the result is a current-version blob of the same type and **the same id**; the dependency section may not change (a transform cannot add or drop a reference; checked per blob); the output is deterministic; the content hash is recomputed and the whole closure is verified again after every transform, then the pak is written. A transform may ask the context for the **source** and re-mint with target options instead of converting the blob (needed where converting would compress twice, such as BC7 to ASTC: the texture transform re-mints from the source). The incremental manifest keys on the target, so a second target does not redo the first. Targets in this phase: the host platforms; the built-in transform is the **texture relayout** (the minter records the row pitch and slice alignment of the target API, Day 323, which differ between Vulkan, Direct3D 12 and Metal); every other type passes through unchanged. Phase 31 (ASTC, mobile mesh and texture variants) and Phase 32 (console formats) add transforms through the same registry. `verify --target` checks a pak against its target. Tests: a pass-through target leaves the bytes identical; a transform that changes a dependency is refused; two packs for one target are byte-identical; a pak for one target is refused by the runtime for another (Day 316).
- [x] **Version enforcement:** `verify --require-current` fails (non-zero exit, names every old blob and the fix) when any blob or pak is not the current version of its type; `pack` refuses non-current or unverifiable blobs; the manifest records every type's format version so a bump rebuilds all blobs of that type on the next `mint`; ctest `asset_mint_old_versions_fixture` runs `verify --require-current` over a fixture directory with one blob of every older version of every type (it must fail naming all of them), then `remint` (it must succeed), then `verify --require-current` (it must pass) and compares with a fresh mint.

## Outcome

`tools/asset_mint/project.{h,cpp}` gained `Refs`, `Rename`, `Move`, `Delete`, `Copy`, `Reid`, `Unmint`, `Pack` and `Verify` with options and the free functions `PackDirectory(PackRequest)`, `VerifyDirectory` and `RemintDirectory`; `target_transform.{h,cpp}` (the `TargetTransforms` registry: the texture relayout through `RetargetTextureBlob`, every other type retagged through the new `asset::SetBlobTarget`; `TransformBlob` checks the same type, id, target and references, a valid hash and two equal runs); `upgrade.{h,cpp}` (`UpgradeChains`, `UpgradeBlob`: one function per type and version); `FormatMaterialBlob` in `material_source.*`. The commands: `refs`, `rename`, `move`, `delete [--with-dependents]`, `copy`, `reid [--update-references]`, `unmint [--out]`, `remint PROJECT|DIRECTORY`, `pack --target N` and `verify --target N --require-current`. Tests: `tests/asset/mint_edit_test.cpp` (rename and move leave every dependent's blob bytes unchanged and rewrite the references, including a material's relative texture path and a texture's image file; delete refuses a referenced asset and changes nothing; reid fixes a shared id and refuses to orphan a reference; copy; unmint of a material and a level gives text that mints the same bytes; pack for another target, two packs byte-identical, the pak refused for another target, a transform that adds a reference, ignores the target or is not deterministic refused; and `asset_mint_old_versions_fixture`: an old-version blob is named by `verify --require-current`, `remint` upgrades it to what a fresh mint gives, and verify then passes) and the script tests `asset_mint_edit` and `asset_mint_target`. Spike 5 (level column images) is decided: not built; the figures and reasons are in the spec ("Level column images").

Two findings of this day: (1) the Day 333 `pack` and its tests were vacuous: a pak packed from a project output was empty (the backend's stored table names file locations, the project's table names resource paths), and nothing counted the entries; `PackDirectory` now reads such a folder through its `resources.table`, and the tests check the entry count. (2) The level text minter is super-linear in the number of entities (see `KNOWN-ISSUES.md`).

Deviations (also in `KNOWN-ISSUES.md`): no built-in type has an older version yet (all are at version 1), so there is no real old-version blob and no built-in upgrade step; the old-version fixture uses a synthetic type with its own registries (the mechanism is tested, the chains of the real types are written when a type's version is raised); `rename` and `move` rewrite references by path in the other sources (blobs hold ids, but sources name paths), so a dependent's source file changes with them.

Runs: see `STATUS.md`.

## Post-implementation code review

`/code-review high` over the day's tree: 10 findings, 9 fixed, 1 handled differently. Handled differently: the formatting churn in `material_source.cpp` came from files that were not clang-format clean at the previous commit; they are a formatting-only commit of their own (`a59868bd`, listed in `.git-blame-ignore-revs`) before this one. The day's own tests did not catch the empty pak of Day 333, the review of that day did not either: the pak tests now count the entries of a pak.
