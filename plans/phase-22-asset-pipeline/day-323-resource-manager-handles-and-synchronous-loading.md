# Phase 22 / Day 323 — The Resource Manager: Handles, Cache, Dependencies & Synchronous Loading

**Phase:** [Phase 22 — Asset Pipeline & Resource System](../phase-22-asset-pipeline.md)
**Depends on:** Days 314-322; Phase 8 (`Recreatable`, `DeviceResources`).

The runtime face of the system: ask for a resource by id, get a handle, never know which backend served it.

## Tasks

- [ ] **`asset::ResourceManager`:** owns the mount table and a cache; `Load<T>(id) -> Handle<T>` synchronous; `Get(handle)`; reference counts (a handle copy adds one); a resource is freed when its count reaches zero and it is not pinned; a generation in every handle so a stale handle reads as invalid, never as another resource.
- [ ] **Per-type loaders registered with the manager** (`RegisterLoader<T>`): mesh (builds a `renderer::GpuMesh`), texture (a `GpuTexture` made with a loader that re-reads through the manager, so a device reset recreates it: the `Recreatable` rule of CLAUDE.md), material (creates the `MaterialId`, binds textures by owner), level (spawns entities through the world; `MeshRenderer` gets a `SharedPtr<MeshAsset>` from the manager).
- [ ] **Dependency graph, atomic closure (the principle: a dependency can never be broken):** the manager follows only the blob's declared dependency section; loading a resource loads its whole closure first and publishes the handle only when every dependency is loaded **and of the declared type and version** (`DependencyTypeMismatch` otherwise: this catches a loose file shadowing a pak entry with the wrong type); a failure returns `MissingDependency` naming the chain (`level -> material -> texture`) and leaves nothing half-loaded and no handle published; a cycle is `DependencyCycle` (the mint already refuses it; the manager checks anyway, since a hostile pak is possible); unloading a dependent releases its dependencies; tests: remove one dependency from the backend at every depth of a chain, swap one for a wrong-typed blob, a cycle in a hostile pak, a diamond (shared dependency loaded once), and concurrent loads of two roots sharing a dependency (asan, tsan).
- [ ] **Errors, no silent fallback:** a missing or invalid resource returns the `Status` and no handle (strict is the default). Per-type *fallbacks* (a checker texture, a magenta material, a unit cube) exist only behind the development setting `assets.allow_fallbacks` (default off); each use is logged, counted in `Stats::fallbacks_used`, and the demo and every test that loads minted data assert the count is zero. A fallback never stands in for a dependency inside a closure: a closure with a missing member fails as a whole.
- [ ] **`Stats`:** loads, cache hits, bytes resident, per-backend reads, fallbacks used, `load_conversions` (anything the loader had to convert or copy beyond the one read into the aligned buffer and the bulk upload; must be zero for minted data), `rejected_old_version`, bytes read per millisecond of load time.
- [ ] **Load-path rules:** no allocation per element (one aligned buffer per blob, taken from a pool and recycled), no text parsing, no hash verification unless `assets.verify_on_load` is set (default off; development convenience), no per-field decoding of bulk sections, no mip generation or format conversion; an old-version or mismatched blob is refused at once with the fix named, never converted; mounts are checked for announced versions at mount time (a pak or server serving old versions is refused when mounted).
- [ ] **Settings** `assets.*` (`mounts`, `strict`, `cache_bytes`) through `settings::Registry`; `RegisterAssetSettings`, `ManagerConfigFromSettings`.
- [ ] **`ResourceInUse(id, &dependents)` and the memory backend's change records (added 2026-11-13):** the manager answers whether a loaded resource depends on an id (naming the dependents) so `HostMemoryBackend::Remove` and `Replace` can refuse with `InUse` (Day 315); a `Watch` record from the memory backend reloads the resource and its dependents atomically (the closure rule), and a replace that fails to load (wrong type, a broken dependency) leaves the old version loaded and reports the error.
- [ ] **Tests:** `Stats::load_conversions` is zero after loading every type; an old-version blob is refused with `UnsupportedVersion` and counted; load every type from a memory backend and from a pak of the same blobs with identical results (the "never know which backend" test); override by a loose mount; a device reset (`tests/renderer/reset_rig.h`) leaves the textures and meshes intact and the counts equal (the Phase 8 pattern); reference counting and generations under a stale handle; a dependency cycle; fallbacks; a level that loads its meshes and renders the same pixels as the hand-built scene (a golden image through the scene bridge).
- [ ] **Runs (CLAUDE.md "Tests run by phase"):** `scripts/test-phase.sh --affected` plain; then the asan and tsan flavors when the day touched concurrency, lifetime or memory code; quote each run's final `ran X of Y tests (phases ...)` line in this file and never say "all tests pass" for a reduced run. `ctest -L docs` when a public header or a guide changed. Build clean (warnings are errors) with Clang and GCC, unity on and off. New code uses the engine's wrappers and types, never `std` (`std_usage_check`); file access only through `io::` (`file_access_check`); settings only through `settings::Registry` (`config_access_check`).
- [ ] **Three machines (CLAUDE.md "Three machines"):** shared code is portable and checked on the Windows PC and the Mac no later than Day 330; until then the day is "open until the other machines run it" in `KNOWN-ISSUES.md`.
- [ ] **Documentation (CLAUDE.md "Public API is documented before a day is done"):** public headers carry `///` comments with the contract labels (`docs/DOC-CONVENTIONS.md`); `docgen lint` stays at zero; `cmake --build build --target docs` output committed; new modules are added to `docs/reference/modules.txt`; the guide page `docs/guide/assets.md` is updated and its tagged samples compile and run.
- [ ] **Module rules (CLAUDE.md "Module dependencies follow ARCHITECTURE.md"):** a new module or edge updates `ARCHITECTURE.md`, `tools/module_deps_check/modules.txt` and the CMake targets (with `_asan`/`_tsan` flavors) in the same commit; no upward edge, no cycle; every new test file has its line in `tests/phases.txt` (phase 22).
- [ ] **Day review (CLAUDE.md, required):** `/code-review high` over the day's diff after the scoped tests; verify, fix (with a regression test that fails without the fix) or decline each finding with a reason; record the count and outcome under "Post-implementation code review" below and in `STATUS.md`.
- [ ] `STATUS.md` and `KNOWN-ISSUES.md` updated in the same commit; commit and push.

**Done:** all four types load through the manager from any backend with identical results, a device reset recreates them, missing resources fall back visibly, and a level renders like its hand-built twin.
