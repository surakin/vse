## Outcome

`engine/asset/resource_protocol.{h,cpp}` (protocol v1: `Hello`, `HelloAck`, `Stat`, `Table`, `List`, `Read`, their replies and `Error`, encoded with `net::NetWriter`, one encoding per message, every length bounded before it is allocated), `engine/asset/resource_server.{h,cpp}` (`ResourceServer` over any `ResourceBackend` and any `net::Transport`; read-only; limits from `assets.net.max_read_bytes`, `assets.net.max_inflight`, `assets.net.page_entries`), `tools/resource_server` (`--root DIR | --pak FILE`, `--listen ADDR:PORT`, `--seconds N`) and `tests/asset/resource_server_test.cpp` (13 cases: stat and ranged reads with the short last range and the past-the-end error, a client that takes less, table pages and generations, list pages, `Busy`, protocol breaks, 200 clients at once, a fuzz of 300 clients sending random and mutated messages, the generation as a hash, versions, pages that fit a small transport, settings and the codec round trip). The table generation is a hash of the entries, so it survives a restart and ignores new bytes under the same names; the backend's `Watch` is asked only when a client asks for the table. `asset` links `net` now. The protocol is written in `docs/guide/assets.md` and the spec.

Runs: see `STATUS.md`.

## Post-implementation code review

`/code-review high` over the day's tree: 11 findings. Fixed (with regression tests that fail without the fix where practical): `Watch` ran on every `Update` (a directory walk per call; now only when a client asks for the table); the table generation was a per-process counter that could match another table after a restart (now a hash of the entries), and a `Replaced` record bumped it though the table was the same (it is ignored); a table or list page could be too large for a small transport and fail forever (the page size is derived from the message size, tested with a 4 KiB transport); a full client queue closed the connection (the answer is replaced by `Busy`, the connection ends only if that fails too); `Hello` versions were not checked (`Unsupported`, then the connection ends); `ListOk` had no generation (it has one); `--seconds 0` or an unparsable value made the server exit at once (now a usage error); the settings were documented in the wrong header; a borrowed `ByteSpan` member of the message struct (the gate caught it: the payload is an argument now); and the per-read zero fill. Declined: a reader cache per connection for `Read` (each read opens the backend's reader: a file open for the filesystem and pak backends; the cost is per request and the bound is the request rate the transport allows), and the copy of the matching entries of a list (the table is in memory; the copy is of views).
