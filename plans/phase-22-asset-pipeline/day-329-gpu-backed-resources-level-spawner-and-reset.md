# Phase 22 / Day 329 — GPU-Backed Resources, the Level Spawner & Surviving a Device Reset

**Phase:** [Phase 22 — Asset Pipeline & Resource System](../phase-22-asset-pipeline.md)
**Depends on:** Day 328; Phase 4 (`renderer::MaterialSystem`), Phase 8 (`Recreatable`, `DeviceResources`), Phase 17 (`scene`), Day 322 (GPU skinning).

The resources that live on the GPU, loaded through the manager of Day 328 so that a device reset rebuilds them from the manager's own bytes, and the spawner that turns a level into entities that draw. Split from Day 328 on 2026-11-14 (the user's decision).

## Outcome

Built as planned, under the rule the user gave on 2026-11-14 (classes that need the same data share a `SharedPtr` to a small class that holds it; never a raw pointer into another class's storage), which changed the first design:

- **`SharedBytes`** (`foundation/containers/shared_bytes.h`): immutable bytes with a shared owner. `asset::BlobBuffer` is one: the pooled buffer a blob was read into, holding a share of its pool and of the `ResidentBytes` counter. The manager's slot, the loaded object and the GPU objects uploaded from it each hold a share; the last holder returns the buffer. `Stats().bytes_resident` counts a buffer until then.
- **`renderer::MeshGeometry`** names a mesh's sections by offset into a `SharedBytes` (no pointers); `GpuMesh::CreateFromGeometry` uploads from it and keeps it as the recreate source, so a mesh survives a reset after the manager has unloaded the resource. **`GpuTexture::CreateFromSharedLevels`** does the same for the texels (`TextureLevelSpan`: offset and size, checked against the region and against what the device reads). `MeshData` keeps owning its bytes; it gained no borrowing mode.
- **GPU loaders** (`gpu_loaders.*`): `GpuMeshAsset`, `GpuTextureAsset`, `GpuMaterialAsset` over `SharedPtr<GpuMesh>`, `SharedPtr<GpuTexture>`, `SharedPtr<GpuMaterial>` (the material, its textures and its samplers); the CPU loaders are replaced for those types. Fallbacks (`RegisterGpuFallbacks`): a unit cube, a magenta and black checker, a magenta material, behind `assets.allow_fallbacks`.
- **Spawner** (`scene/level_spawner.*`, the new edge `scene -> asset`): `SpawnLevel` loads the level and its closure, spawns the included levels first (each once), adds the world transform, gives each `mesh_reference` a `MeshRenderer` sharing the manager's mesh (`MeshAsset::shared`, a `SharedPtr<GpuMesh>`) and the material's slot (the level holds a share of the material); `DestroyLevel`. **`animation::ManagerResolver`** answers the animation system from the loaded resources.
- Verified on a null device (the loaders, the reset with every kind of object and a skinned mesh, fallbacks, a pak against a memory backend, shared bytes outliving the manager's resource) and on Vulkan (a spawned level renders pixel-identical to a hand-built scene of the same loaded meshes and materials, and the frame is not empty).
- Not done, filed in `KNOWN-ISSUES.md`: per-material render-state overrides are recorded and not applied; a loaded mesh's barrier is recorded by the caller; the reset test is not run through a real `DeviceHost`; the older raw-pointer sharing found by the audit (list in `KNOWN-ISSUES.md`) is to be removed by a refactor day.

Runs: see `STATUS.md` (plain, asan and tsan scoped runs, no failures); Clang and GCC (non-unity) clean; tidy no findings; docs 7 of 7; the gates pass.


## Post-implementation code review

`/code-review high`: 9 findings, 8 fixed (a regression test for each, checked to fail without the fix for the diamond include, the texture size and the material slot), 1 declined.

- Fixed: a spawned entity's material slot went stale when the manager reloaded the material (the level now holds a share of the material); `CreateFromSharedLevels` accepted a level that holds fewer bytes than the device reads (checked against the rows and the pitch); two sort-id counters gave one id to different meshes (one counter); a refused registration left the buffers and the share of the bytes allocated (rolled back); a level included by two levels was spawned twice and failed on its keys (spawned once); a moved-from mesh kept its share of the bytes, and `MakeRecreatable` on a mesh with geometry would be ignored (cleared, asserted); a buffer kept by a GPU object was not counted as resident (a shared counter counts it until the last holder lets go); `LoadGpuTexture` grew a vector without checking memory (`TryReserve`); an inverted check on the fallback cube and an ignored name result (fixed).
- Declined: the mesh's `RecordPrepare` and `MarkReady` are left to the caller, as for every mesh, so a spawned renderer is not drawn until the caller prepares the meshes (filed in `KNOWN-ISSUES.md`; a readiness API is renderer work for its own day).
