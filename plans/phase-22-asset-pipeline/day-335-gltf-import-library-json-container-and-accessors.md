# Phase 22 / Day 335 — glTF Import I: The Importer Library, a Bounded JSON Reader, the Container & Accessors

**Phase:** [Phase 22 — Asset Pipeline & Resource System](../phase-22-asset-pipeline.md)
**Depends on:** Days 315 (`HostMemoryBackend`), 319 (mesh), 333 (the `asset_mint` project); PLAN.md assumptions #4, #17 and #19 as amended 2026-11-14.

Added 2026-11-14 (the user): glTF 2.0 assets (`.gltf` and `.glb`) import into the engine's own formats, **in memory, from a library an application may link** (amended the same day: the first plan made the importer an offline tool that no program could link). The use that decides the design is the host (the user's Matrix client, whose 3D rooms fetch `.glb` files at run time): bytes in, minted blobs out, added to a `HostMemoryBackend` that the rest of the engine reads like any other backend. The offline `asset_mint import-gltf` of Day 338 is a thin command over the same library. This day builds the library's foundation (module, JSON reader, container, accessors, limits); Day 336 imports meshes; Day 337 skeletons and animation; Day 338 images, textures, materials, the in-memory entry and the command.

## Decisions (planner's defaults; the user confirms or overrides)

- **A new module, `engine/asset_import`** (library `asset_import`, header `asset_import/gltf_import.h`), above `asset` and `renderer` (the material templates) in `ARCHITECTURE.md`, with **nothing in the engine depending on it**: the runtime libraries (`asset`, `renderer`, `scene`, ...) never include it, a program links it only if it imports at run time. `module_deps_check` and the Day 339 gate enforce the direction.
- **The importer works on bytes and returns bytes.** `ImportGltf(ByteSpan file, const GltfSource& source, const ImportOptions&, ImportResult*)`: `source` is an interface that reads what the glTF names by URI (`GltfSource::Read(uri, Vector<byte>*)`; the tool's implementation reads files through `io::` inside the glTF's directory, a host's reads from wherever it fetched the file, a `.glb` needs none). The result holds each imported resource (id, type, blob bytes, a suggested resource path), the import manifest **as data** (kind, glTF index and name, id; the tool writes it next to the file, a host keeps it or not) and the report (counts, every dropped feature and warning with its glTF object). `ImportIntoBackend(HostMemoryBackend&, const ImportResult&)` adds every blob under its suggested path; the dependencies are in the blobs, so the closure loads atomically (Day 328).
- **ids:** from the manifest passed in (a re-import keeps them), else drawn from an `IdSource` (the random source by default; tests pass a seeded one so imports are byte-identical).
- **No exceptions, no abort on a hostile file** (the input may come from the network): every failure is a `Status` naming the glTF object; limits (`ImportLimits`: file bytes, JSON depth, node, mesh, accessor, buffer view and image counts, decoded pixels, total output bytes) are settings (`assets.import.*`, Day 339) with the defaults of the struct, checked before anything is allocated.
- **JSON: our own bounded reader, not nlohmann/json** (a change from the first plan). nlohmann needs exceptions or aborts on a wrong type, the input is hostile and untrusted, and `std::string`/`std::vector` are not allowed outside a wrapper module. `engine/asset_import/json.{h,cpp}` is a strict RFC 8259 reader (UTF-8 validated, depth and size bounded, duplicate keys refused, numbers exact through `ParseDoubleExact`) that builds a compact arena-backed tree with typed accessors that return a `Status`, never abort. `nlohmann/json` stays in `tools/shader_mint` only, and PLAN.md #19's list does not grow.
- **Work runs on the job system** (assumption #15): `ImportGltfAsync` (Day 338) returns a ticket like `TableTicket` (progress, cancel); the block compression of textures already fans out over the workers.
- **The `.gltf`/`.glb` file is the source of truth for the offline tool** (a mesh of a million vertices would be a half-gigabyte text file): `asset_mint mint` regenerates every blob from it deterministically through this library, and the project's source kind `.gltf` keeps an import manifest `NAME.gltf.import` next to the file (the one place the "source carries its id" rule of 2026-11-13 does not hold: a third-party format has no id field). An in-memory host has no sidecar: it passes the manifest it kept.

## Tasks

- [ ] **The module:** `engine/asset_import/` with its CMake target (and `_asan`/`_tsan` flavors), `docs/reference/modules.txt` line, `ARCHITECTURE.md` row, `tools/module_deps_check/modules.txt` and `tests/module_map.txt` entries; the public header with the API above (declared, the parts that later days fill return `Unsupported` until then).
- [ ] **The bounded JSON reader (`json.{h,cpp}`):** objects, arrays, strings (escapes, `\u` surrogate pairs, UTF-8 validated), numbers (finite doubles only, exact), `true`/`false`/`null`; nesting depth and total node count bounded by the limits; duplicate keys, trailing commas, comments, a BOM and trailing bytes refused; typed accessors (`FindMember`, `AsInt`, `AsArray`, ...) return a `Status` that names the path (`meshes[2].primitives[0].attributes`); tests: the RFC 8259 conformance cases we write, 2,000 mutated and truncated documents under asan with no crash and bounded memory, a deep-nesting bomb, a 100 MB-string refusal.
- [ ] **The container (`gltf_container.{h,cpp}`):** `.gltf` (JSON, external `.bin` files through `GltfSource`, `data:` base64 URIs) and `.glb` (12-byte header, JSON chunk, optional BIN chunk, chunk lengths and padding checked); `asset` version 2.0 only; an external URI must be relative and free of `..`, absolute paths and schemes other than `data:` (the `GltfSource` gets the cleaned relative name; the tool's source resolves it inside the glTF's directory through `io::Path`); `extensionsRequired` checked against the supported list (the rest refused naming the extension).
- [ ] **Accessors:** every component type (`BYTE`..`FLOAT`), `normalized`, `byteStride`, `sparse` accessors, and checked arithmetic on every offset and count so a hostile file cannot read outside its buffer; the accessor's declared `min`/`max` are ignored (bounds are recomputed).
- [ ] **Hostile and malformed files (the container and accessors):** a table of files generated by the test, not downloaded: truncated GLB, chunk length past the end, an accessor whose count overflows, a buffer view past its buffer, a sparse accessor with an index past the count, a `..` URI, an absolute URI, a URI scheme, deep JSON nesting, a base64 bomb; each refused with the glTF object named and no crash under asan.
- [ ] **Tests:** hand-authored fixtures written by `tests/asset/gltf_writer.h` (a minimal glTF/GLB writer for tests, extended by Days 336-338): container round trips (`.glb` with and without BIN, `.gltf` with an external `.bin` through a test `GltfSource`, a `data:` URI), every accessor type, `normalized`, `byteStride`, sparse accessors; the manifest and the id source (a seeded `IdSource` gives the same ids twice).
- [ ] **Runs (CLAUDE.md "Tests run by phase"):** `scripts/test-phase.sh --affected` plain; then the asan and tsan flavors (the importer parses hostile files); quote each run's final `ran X of Y tests (phases ...)` line in this file and never say "all tests pass" for a reduced run. `ctest -L docs` when a public header or a guide changed. Build clean (warnings are errors) with Clang and GCC, unity on and off. Importer code that is not behind the JSON or image-decoder wrappers uses the engine's types, never `std` (`std_usage_check`); file access only through `io::` (`file_access_check`).
- [ ] **Three machines (CLAUDE.md "Three machines"):** shared code is portable and checked on the Windows PC and the Mac no later than Day 341; until then the day is "open until the other machines run it" in `KNOWN-ISSUES.md`.
- [ ] **Documentation (CLAUDE.md "Public API is documented before a day is done"):** public headers carry `///` comments with the contract labels; `docgen lint` stays at zero; `cmake --build build --target docs` output committed; the guide page `docs/guide/assets.md` gets the "Importing glTF" section (this phase's three days add to it) and its tagged samples compile and run.
- [ ] **Module rules (CLAUDE.md "Module dependencies follow ARCHITECTURE.md"):** the importer lives in `engine/asset_import/`, a leaf module nothing else in the engine depends on (the Day 339 gate checks it); a new target or edge updates `ARCHITECTURE.md` and `tools/module_deps_check/modules.txt` in the same commit; every new test file has its line in `tests/phases.txt` (phase 22).
- [ ] **Day review (CLAUDE.md, required):** `/code-review high` over the day's diff after the scoped tests; verify, fix (with a regression test that fails without the fix) or decline each finding with a reason; record the count and outcome under "Post-implementation code review" below and in `STATUS.md`.
- [ ] `STATUS.md` and `KNOWN-ISSUES.md` updated in the same commit; commit and push.

**Done:** the `asset_import` module builds, its JSON reader and glTF container reader refuse every hostile file in the table naming the object, the accessors read every component type without leaving their buffers, and the API of the whole importer is declared in one documented header.
