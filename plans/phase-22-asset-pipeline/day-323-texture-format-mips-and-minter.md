# Phase 22 / Day 323 — The Texture Format, Mip Generation & the Texture Minter

**Phase:** [Phase 22 — Asset Pipeline & Resource System](../phase-22-asset-pipeline.md)
**Depends on:** Days 314-318; Phase 5 (`renderer::TextureImage`).

Textures without compression yet: formats, mips, color space, and the minter around them.

## Tasks

- [x] **Texture blob v1:** dimension (2D, cube, array), width, height, depth/layers, `rhi::Format`, color space (sRGB or linear), the mip chain tightly packed per level, bounds on sizes and mip counts enforced by the loader. **Every mip level is stored** (there is no "generate at load" flag: mip generation, sRGB handling and premultiplication all happen in the minter), and each level starts at an aligned offset in the layout the upload wants (row pitch and slice alignment of the target API recorded by the minter from the RHI's rules, so the loader copies nothing; **because that layout depends on the target API, the texture minter also exposes `Retarget` and `MintForTarget` for `pack --target`, Day 332**).
- [x] **Trusted, zero-copy renderer entry (Day 313 Spike 5):** `GpuTexture` and `TextureImage` take an owned `Vector<u8>`; add an entry that uploads from a span of the blob's mip sections (the staging copy into device memory is the only copy); the existing path stays for runtime images; a reset test as for meshes.
- [x] **Source form `.tex.src`:** text parameters (`source`, `format`, `srgb`, `mips`, `filter`, `alpha`) naming a raw image file in a trivial custom container (`.raw`: a small header plus RGBA8 rows) that the tool's test generator and the Phase 30 importer produce; no PNG (the user's answer).

## Outcome

Built as planned, with these deviations:

- **Blob layout:** header (16), a subresource table (17: offset, size, row pitch) and one data section (18) rather than one section per level (the container allows 64 user sections; a cube with a full chain needs more). Each subresource sits at the target's subresource alignment inside the data section and its rows at the target's row pitch; `TextureLayoutForTarget` defines target 0 (development, Vulkan: rows 4, subresources 16), 1 (Direct3D 12: 256 and 512) and 2 (Metal: 16 and 16). `RetargetTextureBlob` re-lays a blob out and equals minting for the target (tested byte for byte); `MintTexture(..., target)` is the `MintForTarget` of the plan.
- **Loader:** `TextureView::Open` and `Level(layer, mip)` give spans for `Device::UploadTexture` unchanged. The `TextureImage`-compatible copying overload is not written (the zero-copy entry is `renderer::GpuTexture::CreateFromLevels`, which borrows the blob's bytes and uploads each level with its pitch; a reset uploads again from the same bytes). A cube is created as a 6-layer array.
- **Mips:** `asset/texture_mips.h`: integer-only box and 6-tap Kaiser (`-5 24 109 109 24 -5`) filters, a fixed sRGB table, alpha `straight` (weighted), `premultiply` or `ignore`, half floats as exact 2^-24 integers (`straight` refused for them). Golden hashes of a gradient, a checker and two noise images are in the test.
- **Source:** `.tex.src` (`id`, `kind`, `source` per layer, `format`, `srgb`, `mips`, `filter`, `alpha`), the `RAW1` raw container (24-byte header with an id field) and `asset_mint mint-texture`. The `id` line is required and its error names `asset_mint adopt`; `adopt` itself is Day 332.
- **Formats:** R8, RG8, RGBA8 (UNORM and sRGB), R16F, RGBA16F.
