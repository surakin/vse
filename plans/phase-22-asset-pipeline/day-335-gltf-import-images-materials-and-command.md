# Phase 22 / Day 335 — glTF Import III: Images, Textures, Materials & the `import-gltf` Command

**Phase:** [Phase 22 — Asset Pipeline & Resource System](../phase-22-asset-pipeline.md)
**Depends on:** Days 323-327 (texture, material and level formats and minters), 332 (the tool), 333 and 334; PLAN.md assumptions #4, #17 and #19 as amended 2026-11-14.

The last piece: pixels and materials, then the command that ties the three days together.

## Decision for the user to confirm (their answer on 2026-11-14: vendor the decoders, tool only)

- **Vendored decoders, linked into `asset_mint` only.** zlib and libpng are vendored here, **earlier than** Phase 27 Day 350, which then only enables PNG in FreeType and reuses these sources (it no longer vendors them: Day 350 is amended in this commit). A baseline JPEG decoder is chosen by a half-day spike at the start of this day among a small single-file decoder (stb_image's JPEG path, public domain) and libjpeg-turbo, by size, license, security history and determinism (same pixels on every machine: integer IDCT only); the loser is recorded in the spec. All are pinned by version and SHA-256 under `third_party/` with `VENDORED.md`, portable C, never linked into the engine, a game, the renderer or an engine test target; the decoder boundary is a gate (`module_deps_check` and `std_usage_check` entries).

## Tasks

- [ ] **Decoder spike and vendoring:** the JPEG choice above; zlib and libpng pinned and built from source for the tool (Windows, Linux, macOS); decode limits set before decoding (dimensions, bytes, chunk counts: `png_set_user_limits` and the JPEG equivalent), so a hostile image fails with a named error and bounded memory; a fuzz-style test feeds 2,000 mutated PNG and JPEG files and truncations under asan with no crash and no unbounded allocation.
- [ ] **Images:** glTF `images` (a URI inside the glTF directory, a `data:` URI or a `bufferView` with `mimeType`) decode to RGBA8 (16-bit PNGs reduce to 8 with a counted warning; palette, grayscale and alpha forms expand; progressive JPEG refused if the spike's decoder lacks it, named in the message); the decoded pixels go to the Day 323 texture minter through its in-memory entry, not through a `.raw` file; the CMYK JPEG and interlaced-PNG cases are tested.
- [ ] **Textures:** each glTF `texture` (image plus sampler) becomes a texture resource; the color space is decided by use (sRGB for base color and emissive, linear for the rest) and a texture used both ways is imported twice with the manifest recording both ids; sampler wrap and filter map to the sampler description of the material's texture binding; BC format by use (BC7 color, BC5 normals, BC4 single channel, per the Day 323-325 quality settings); a texture used as a normal map is checked to be 3-channel unit vectors within tolerance (counted warning).
- [ ] **Materials:** the metallic-roughness model maps to one engine template (the standard G-buffer template) with parameters `base_color`, `metallic`, `roughness`, `emissive`, `alpha_cutoff`, textures `base_color`, `metallic_roughness` (the glTF packing, G roughness and B metallic, read as the template's expected packing or repacked by the importer into the engine's: decided here against the template), `normal` (with scale), `occlusion`, `emissive`; `alphaMode` OPAQUE, MASK and BLEND select the permutation and render state; `doubleSided` sets culling; extensions: `KHR_texture_transform` (baked into the texture binding's transform when the template supports one, else refused naming the material) and `KHR_materials_emissive_strength` are supported, `KHR_materials_unlit`, `KHR_draco_mesh_compression`, `EXT_meshopt_compression`, `KHR_mesh_quantization` and any other `extensionsRequired` entry are refused with the extension named (`KHR_mesh_quantization` is listed in `KNOWN-ISSUES.md` as the first one to add); a material with no template match fails the import, never silently approximates.
- [ ] **Scenes:** with `--emit-level`, the default scene's node tree becomes a level source (Day 327 text form: one entity per node with a transform, a mesh and a skeleton-instance reference where present); without it only the resources are produced.
- [ ] **`asset_mint import-gltf FILE [options]` and mint integration:** registers the file with the project (`assets.project` rule for `.gltf` and `.glb`), writes or updates the import manifest, and `asset_mint mint` regenerates every blob from the glTF and the manifest in dependency order (images, textures, materials, skeletons, meshes, clips, level); the incremental cache keys on the glTF's bytes, the manifest and the tool version; the import report (counts of each kind, every dropped feature and warning with its glTF object) is printed and written next to the manifest; exit code non-zero for a refusal, zero with warnings.
- [ ] **Dependencies stay unbreakable:** the manifest is the id map, so a re-export of the glTF (objects reordered, renamed in the source) keeps ids by kind and index or name, an object removed from the glTF fails `mint` naming the dependents until `asset_mint unmint` is used (the Day 332 rule applies unchanged); two glTF files cannot claim one id.
- [ ] **End-to-end test:** a fixture glTF written by the test writer (textured, skinned and animated, two materials) imports, mints, packs into a pak and loads through `PakBackend` with the Day 328 manager (the demo of Day 336 later shows it on screen): blobs verify, the closure is complete and typed, rendering a frame of the imported model with `renderer_demo`-style headless code matches a golden image within tolerance on the Linux machine; the same project minted twice with 1 and 8 workers is byte-identical.
- [ ] **Fixtures:** only files we author (the writer plus a few files committed under `tests/asset/data/gltf/`, each a few KiB, license-free); no Khronos sample asset is committed (licenses vary); a documented manual run of the Khronos sample models is recorded in this file as a smoke check (not a test) when the user supplies them.
- [ ] **Runs (CLAUDE.md "Tests run by phase"):** `scripts/test-phase.sh --affected` plain; then the asan and tsan flavors (the importer parses hostile files); quote each run's final `ran X of Y tests (phases ...)` line in this file and never say "all tests pass" for a reduced run. `ctest -L docs` when a public header or a guide changed. Build clean (warnings are errors) with Clang and GCC, unity on and off. Importer code that is not behind the JSON or image-decoder wrappers uses the engine's types, never `std` (`std_usage_check`); file access only through `io::` (`file_access_check`).
- [ ] **Three machines (CLAUDE.md "Three machines"):** shared code is portable and checked on the Windows PC and the Mac no later than Day 338; until then the day is "open until the other machines run it" in `KNOWN-ISSUES.md`.
- [ ] **Documentation (CLAUDE.md "Public API is documented before a day is done"):** public headers carry `///` comments with the contract labels; `docgen lint` stays at zero; `cmake --build build --target docs` output committed; the guide page `docs/guide/assets.md` gets the "Importing glTF" section (this phase's three days add to it) and its tagged samples compile and run.
- [ ] **Module rules (CLAUDE.md "Module dependencies follow ARCHITECTURE.md"):** the importer lives in `tools/asset_mint/gltf/` and is never linked into the engine or a game (the Day 336 gate checks it); a new target or edge updates `ARCHITECTURE.md` and `tools/module_deps_check/modules.txt` in the same commit; every new test file has its line in `tests/phases.txt` (phase 22).
- [ ] **Day review (CLAUDE.md, required):** `/code-review high` over the day's diff after the scoped tests; verify, fix (with a regression test that fails without the fix) or decline each finding with a reason; record the count and outcome under "Post-implementation code review" below and in `STATUS.md`.
- [ ] `STATUS.md` and `KNOWN-ISSUES.md` updated in the same commit; commit and push.

**Done:** `asset_mint import-gltf` turns a glTF with meshes, a skin, animations, textures and materials into engine blobs with stable ids, refuses what it cannot represent naming it, and the result renders and animates in the engine.
