# Phase 22 / Day 332 — The Network Backend: Cache, Retry & Offline Mode

**Phase:** [Phase 22 — Asset Pipeline & Resource System](../phase-22-asset-pipeline.md)
**Depends on:** Day 331; Phase 20 (`net::TcpTransport`, `Clock`).

The client half: a `ResourceBackend` whose resources live on a server, with a content-hash cache on disk.

## Tasks

- [x] **`NetworkBackend`** implementing `ResourceBackend`: connects through a `net::Transport` it is given (so tests use the simulated stream and the loopback), `Stat`/`List`/ranged `Open` over the protocol, **`ReadTableAsync` natively over the paged `Table` request (no thread parked on the connection; pages handed out as they arrive; the generation number makes a refresh fetch only a changed table, and an offline backend serves the cached table with `Offline` marked)**, one request in flight per reader and many per connection, timeouts from settings.
- [x] **The disk cache:** files named by content hash in `assets.cache_dir` (written through `io::`, atomically replaced), an index of id to hash, a size limit with least-recently-used eviction, verification of a cached blob's hash when it is fetched and when the cache is opened (not on every read: the cache is local and the hash is stored with the index), so a corrupt entry is dropped and refetched without taxing the load path; verification of a cached blob's hash before use (a corrupt cache entry is dropped and refetched), and whole-blob prefetch for small resources while large ones are read by range.
- [x] **Retry and back-off:** a failed or timed-out request retries with bounded exponential back-off and jitter (the jitter from a seeded generator in tests); after `assets.net.max_retries` the backend reports `Offline`.
- [x] **Offline mode:** while offline, `Stat` and reads are served from the cache when the cache holds the id and its hash matches the last known one; misses return `Offline`; the backend reconnects in the background and reports `Online` through its state; the resource manager treats `Offline` like `NotFound` for fallbacks but does not cache the failure.
- [x] **Mount integration:** the network backend mounts like any other (`/` over a pak for development with a remote content server); the conformance suite runs on it.
- [x] **Tests:** the conformance suite over a sim stream; cache hit, miss, eviction and corruption; a server that disappears mid-read and returns (loss, latency and disconnect injected through the sim network); offline serving from the cache; a content change on the server seen by `Watch`; real loopback sockets with the `resource_server` library class (label `network`); asan and tsan for the background reconnect.
- [x] **Runs (CLAUDE.md "Tests run by phase"):** `scripts/test-phase.sh --affected` plain; then the asan and tsan flavors when the day touched concurrency, lifetime or memory code; quote each run's final `ran X of Y tests (phases ...)` line in this file and never say "all tests pass" for a reduced run. `ctest -L docs` when a public header or a guide changed. Build clean (warnings are errors) with Clang and GCC, unity on and off. New code uses the engine's wrappers and types, never `std` (`std_usage_check`); file access only through `io::` (`file_access_check`); settings only through `settings::Registry` (`config_access_check`).
- [x] **Three machines (CLAUDE.md "Three machines"):** shared code is portable and checked on the Windows PC and the Mac no later than Day 341; until then the day is "open until the other machines run it" in `KNOWN-ISSUES.md`.
- [x] **Documentation (CLAUDE.md "Public API is documented before a day is done"):** public headers carry `///` comments with the contract labels (`docs/DOC-CONVENTIONS.md`); `docgen lint` stays at zero; `cmake --build build --target docs` output committed; new modules are added to `docs/reference/modules.txt`; the guide page `docs/guide/assets.md` is updated and its tagged samples compile and run.
- [x] **Module rules (CLAUDE.md "Module dependencies follow ARCHITECTURE.md"):** a new module or edge updates `ARCHITECTURE.md`, `tools/module_deps_check/modules.txt` and the CMake targets (with `_asan`/`_tsan` flavors) in the same commit; no upward edge, no cycle; every new test file has its line in `tests/phases.txt` (phase 22).

**Done:** the network backend passes the conformance suite, caches by content hash, retries with back-off, serves from the cache offline, and recovers when the server returns.

## Post-implementation code review

`/code-review high` over the day's tree: 10 findings. Fixed: `SetOffline` left a greeted connection up, so the state could never return to `Online` (it now closes the connection, and the reconnect brings the state back); a table ticket was completed while the backend's mutex was held, which deadlocks when the completion function takes a lock that a caller of `ReadTableAsync` holds (a mount table does) and inverts the lock order (tickets are now completed by `Drain`, outside the mutex; a test completes one with a callback that calls back in); `Watch` stored the new epoch and dropped the held table before the re-read after a reset had succeeded (the epoch is taken and the table replaced only when it succeeded, so a failed re-read is asked again); a timed-out request counted twice in `failures_` (the connection drop does not count; the test of the retry count passes with and without the fix because the next `HelloAck` clears the count, so it is a cleanup, not a visible bug); the asynchronous table read merged pages of two generations, treated `unchanged` without a held table as an empty table, read a slot after freeing it (`timed_out` is taken before the slot is removed) and ignored `Publish` failures (it now ends the read with an error that says to read again, and every step reports its failure); the blocking table read reported a change between pages as `Offline` (it starts over up to three times, then `Other`); `FetchBlob` reported a resource replaced between its requests as `Corrupt` (`Open` looks again twice); a second `B` line for one hash in the cache index double-counted the file (it is ignored; tested); the change log shifted every element per change once full and the epoch was a counter from zero, so a restarted server could answer a client's old epoch as a continuation (the log drops its oldest half at once, and the epoch starts from the monotonic clock of the run). Declined: the cache rewrites its whole index on every `Put` and scans its names linearly (the cache holds blobs of at most `assets.net.prefetch_bytes` and the index is a few dozen bytes a line; filed in `KNOWN-ISSUES.md` with the figures to take when a project has tens of thousands of resources).
