      - modules [`engine/asset`: ids, the blob container, backends, the resource manager, the per-type loaders (mesh, texture, material, level); `tools/asset_mint`: the minters, the packer and the verifier; `tools/resource_server`; nothing in `engine/asset` includes a tool header, and no game binary links a minter (a gate, Day 328)];

      - the blob container [magic, type id, format version, flags, payload size, content hash, then typed sections with their own sizes; every size checked against the file before allocation; little-endian; 16-byte aligned sections];
      - versioning [the user's rule of 2026-11-13: the runtime loads the current version only and refuses older ones; each type's `Upgrade(from, bytes) -> bytes` chain lives in `tools/asset_mint` and `asset_mint remint` rewrites old blobs offline; enforcement points: mint writes current only, pack refuses non-current blobs, a version bump re-mints that type, `verify --require-current` in ctest, paks and servers announce versions and the manager refuses an old mount at mount time; tested with a golden blob of every older version];
      - load path [the user's rule of 2026-11-13: loading performance is paramount and load-time conversions are discouraged: sections aligned for direct GPU upload, GPU-native layouts and formats, mips pre-generated, references pre-resolved, no text parsing, no decompression, no re-validation of minted data on the load path (bounds checks only), hash verification at mount, fetch and `verify` rather than per load; a `load_conversions` counter that must stay zero];
      - backends [`ResourceBackend`: `Stat`, `Open` a ranged reader, `List`, `Watch` (polling); filesystem, pak and network; a mount table with priorities so a loose file overrides a pak entry in development];
      - pak format [one index (sorted by `ResourceId`, binary-searched) after the data, a footer with the index offset and a hash, entries aligned, no compression in version 1];
      - source formats [custom only: `.mesh.src` (text), `.tex.src` (text parameters naming a raw `.rgba` or `.pgm`-like file), `.mat.src` (text), `.level.src` (text); no PNG and no glTF reader (the user, 2026-11-12); Phase 30 writes the same blob formats];
      - texture compression [an own deterministic encoder for BC1, BC4, BC5 and a limited BC7; ASTC is Phase 28; the decoder (needed for tests and for the CPU fallback) is ours too (PLAN.md assumption #4)];
      - determinism [minting is a pure function of the inputs and the tool version: no time stamps, no absolute paths, no hash-table order, no thread-count dependence; tested by minting twice and with 1 and 8 workers];
      - the resource manager [a handle is a `ResourceId` plus a generation; `Load<T>` synchronous, `LoadAsync<T>` on jobs (decode on workers, GPU upload on the owner thread), reference counts, a dependency graph, `Recreatable` owners keep their loader so a device reset reloads from the backend];
      - the network backend [read-only, over `net::TcpTransport`; a server tool serves a directory or a pak; requests: stat, list, read range; responses bounded by settings; an on-disk cache keyed by content hash; retry with back-off and an offline mode that serves the cache; no authentication and no encryption (trusted networks only, the user's deferral of 2026-11-12)];
      - levels [the binary level format is the storage module's component records (`ComponentRegistry`) plus a resource-reference table; the text form is a line-oriented file where each entity lists components and fields by name; the text form is the only optional text format of this phase, with materials' source form];
      - settings [`assets.*` through `settings::Registry`: mounts, cache directory and size, streaming budget, worker count, network timeouts].

## Outcome

Spec: `docs/superpowers/specs/2026-11-13-asset-pipeline-design.md`. Spikes: SHA-256 at 375 MB/s; pak hash table built at open 0.42 ms and 5 ns a lookup (binary search 79 ns); a pre-faulted buffer reads 256 MiB in 17.5 ms against 75 ms for a fresh one and a copy costs 104 to 176 ms (so no copy, a buffer pool, and trusted zero-copy renderer entries); BC7 mode 6 alone gives +8 to +10 dB over BC1 on smooth content (partitioned modes not built). Later days amended: 315 (buffer pool), 316 (hash table at open), 317 and 318 (trusted renderer entries), 319 (`BC4_UNorm`), 320 (mode 6 only). `CURRENT_PHASE` is 22; `SIDE_PHASES` lost its line for 21 (`test_phase_labels` demands it). The skeleton (`engine/asset`, `tests/asset`, the guide page `docs/guide/assets.md`, reference page `docs/reference/asset.md`) builds in plain, asan and tsan.

Run: `scripts/test-phase.sh --affected` (plain): `ran 2848 of 7565 tests (phases: all; flavors: plain; display: included; crash tests: excluded) in 76 s`, run on everything because `tests/phases.txt` and `CMakeLists.txt` had lines edited. Two failures, both in a shell with no display and neither near this day's code (`KNOWN-ISSUES.md`): the XDND test and the real-device reset test. `ctest -L docs` 7 of 7 after `cmake --build build --target docs`. No sanitizer reruns of the whole suite: the day touched no concurrency or memory code (the new tests ran in asan and tsan as part of the run's discovery, not as a selection).
