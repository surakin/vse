# Phase 22 / Day 328 — The Resource Manager: Handles, Cache, Dependencies & Synchronous Loading of CPU Resources

**Phase:** [Phase 22 — Asset Pipeline & Resource System](../phase-22-asset-pipeline.md)
**Depends on:** Days 314-327.

The runtime face of the system: ask for a resource by id, get a handle, never know which backend served it. This day builds the manager and every loader that needs no GPU; Day 329 adds the GPU-backed loaders, the level spawner and the reset test on top of the same registration seam (split from one day on 2026-11-14, the user's decision).

## Tasks

- [x] **`asset::ResourceManager`:** owns the mount table (Day 315) and a cache; `Load<T>(id) -> Handle<T>` synchronous; `Get(handle)`; reference counts (a handle copy adds one); a resource is freed when its count reaches zero and it is not pinned; a generation in every handle so a stale handle reads as invalid, never as another resource. Reads go through the load buffer pool into one aligned buffer per blob, which the manager keeps while the loaded object views it.
- [x] **The loader seam (`RegisterLoader`):** a loader turns a blob (its validated `BlobReader`, the buffer, and the handles of its already loaded dependencies) into an object of its type, and says what it needs resident; a type has one loader, and a later registration replaces the earlier one (Day 329 replaces the CPU mesh, texture and material loaders with GPU-backed ones without touching the manager). CPU loaders registered here: `SKEL` (the buffer stays owned by the manager; `asset::SkeletonView` is a span of it), `ANIM` (`ClipView`), `LEVL` (`LevelData` with its resource and reference lists; the spawner is Day 329), and the descriptions of `MESH` (`MeshView`), `TEXR` (`TextureView`) and `MATL` (`MaterialAssetData`).
- [x] **Skeletal closure rules (added 2026-11-13):** a skinned mesh is published only when its skeleton is loaded and its recorded skeleton hash and joint count match, and a clip only when its skeleton hash matches the loaded skeleton (`DependencyTypeMismatch` naming both); unloading a skeleton while a mesh or a clip uses it is `InUse`; tests for each refusal.
- [x] **Dependency graph, atomic closure (the principle: a dependency can never be broken):** the manager follows only the blob's declared dependency section; loading a resource loads its whole closure first and publishes the handle only when every dependency is loaded **and of the declared type and version** (`DependencyTypeMismatch` otherwise: this catches a loose file shadowing a pak entry with the wrong type); a failure returns `MissingDependency` naming the chain (`level -> material -> texture`) and leaves nothing half-loaded and no handle published; a cycle is `DependencyCycle` (the mint already refuses it; the manager checks anyway, since a hostile pak is possible); unloading a dependent releases its dependencies; tests: remove one dependency from the backend at every depth of a chain, swap one for a wrong-typed blob, a cycle in a hostile pak, a diamond (shared dependency loaded once), and concurrent loads of two roots sharing a dependency (asan, tsan).
- [x] **Errors, no silent fallback:** a missing or invalid resource returns the `Status` and no handle (strict is the default). The *mechanism* of per-type fallbacks is here (`RegisterFallback`, behind the development setting `assets.allow_fallbacks`, default off; each use is logged and counted in `Stats::fallbacks_used`); the fallbacks themselves for GPU types (a checker texture, a magenta material, a unit cube) are Day 329. A fallback never stands in for a dependency inside a closure: a closure with a missing member fails as a whole. Tests use a test type.
- [x] **`Stats`:** loads, cache hits, bytes resident, per-backend reads, fallbacks used, `load_conversions` (anything the loader had to convert or copy beyond the one read into the aligned buffer; must be zero for minted data), `rejected_old_version`, bytes read per millisecond of load time.
- [x] **Load-path rules:** no allocation per element (one aligned buffer per blob, taken from a pool and recycled), no text parsing, no hash verification unless `assets.verify_on_load` is set (default off; development convenience), no per-field decoding of bulk sections, no mip generation or format conversion; an old-version or mismatched blob is refused at once with the fix named, never converted; mounts are checked for announced versions at mount time (a pak or server serving old versions is refused when mounted).
- [x] **Settings** `assets.*` (`mounts`, `cache_bytes`, `allow_fallbacks`, `verify_on_load`; no `strict`: it is the only behavior) through `settings::Registry`; `RegisterAssetSettings`, `ManagerConfigFromSettings`.
- [x] **`ResourceInUse(id, &dependents)` and the memory backend's change records (added 2026-11-13):** the manager answers whether a loaded resource depends on an id (naming the dependents) so `HostMemoryBackend::Remove` and `Replace` can refuse with `InUse` (Day 315); a `Watch` record from the memory backend reloads the resource and its dependents atomically (the closure rule), and a replace that fails to load (wrong type, a broken dependency) leaves the old version loaded and reports the error.
- [x] **Tests:** `Stats::load_conversions` is zero after loading every CPU type; an old-version blob is refused with `UnsupportedVersion` and counted; load every CPU type from a memory backend and from a pak of the same blobs with identical results (the "never know which backend" test); override by a loose mount; reference counting and generations under a stale handle; a dependency cycle; fallbacks with a test type; the skeletal refusals; a level loaded as `LevelData` lists the resources the manager must hold.
- [x] **Runs (CLAUDE.md "Tests run by phase"):** `scripts/test-phase.sh --affected` plain; then the asan and tsan flavors when the day touched concurrency, lifetime or memory code; quote each run's final `ran X of Y tests (phases ...)` line in this file and never say "all tests pass" for a reduced run. `ctest -L docs` when a public header or a guide changed. Build clean (warnings are errors) with Clang and GCC, unity on and off. New code uses the engine's wrappers and types, never `std` (`std_usage_check`); file access only through `io::` (`file_access_check`); settings only through `settings::Registry` (`config_access_check`).
- [x] **Three machines (CLAUDE.md "Three machines"):** shared code is portable and checked on the Windows PC and the Mac no later than Day 341; until then the day is "open until the other machines run it" in `KNOWN-ISSUES.md`.
- [x] **Documentation (CLAUDE.md "Public API is documented before a day is done"):** public headers carry `///` comments with the contract labels (`docs/DOC-CONVENTIONS.md`); `docgen lint` stays at zero; `cmake --build build --target docs` output committed; new modules are added to `docs/reference/modules.txt`; the guide page `docs/guide/assets.md` is updated and its tagged samples compile and run.

## Outcome

Built as planned, with these decisions:

- **`asset::ResourceManager`** (`resource_manager.*`): mounts (`Mount`, `MountOwned`, `MountPath` for a directory or a pak, `MountFromSettings`), `Load<T>`/`LoadPath<T>`, owning reference-counted handles with a generation, `Unload` (`InUse`, or forced with the dependents), `Pin`/`Unpin`, `ResourceInUse` and `InUseQuery()` for `HostMemoryBackend`, `PollChanges` (reload with the dependents, atomically; the closure rules are checked again; a replacement that fails leaves the old version loaded), `RegisterFallback`, `Stats()`.
- **The closure** follows only the declared dependencies; each is loaded first and held with one reference by its dependent; a loaded dependency is checked against the declared type and version too; a failure releases everything and names the chain.
- **The loader seam:** `RegisterLoader<T>(fn)` with `ResourceTraits<T>::kType` (the resource type) and `kKind` (a code of the C++ type, so a CPU view and a GPU object made from one resource type do not mix, and the key is a constant, safe across the Phase 23 module split). The loaders are given the bytes (kept by the manager while the object lives), the opened blob and the objects of the declared dependencies.
- **CPU loaders** (`cpu_loaders.*`): skeletons, clips, meshes and textures as views over the manager's buffer (nothing is copied), materials as their description, levels as `LevelSummary` (new `ReadLevelSummary`: header and dependency list only). A clip and a skinned mesh are published only against the skeleton they were made for (`DependencyTypeMismatch`).
- **Settings:** `assets.cache_bytes`, `assets.allow_fallbacks`, `assets.verify_on_load`, `assets.mounts` (`RegisterManagerSettings`, `ManagerConfigFromSettings`, `MountSpecsFromSettings`). There is no `assets.strict`: strict is the only behavior; the one relaxation is `allow_fallbacks`.
- **Fallbacks:** the mechanism is here; the GPU ones are Day 329.
- A load holds one lock (loads are serialized, handle operations wait for a load in progress): Day 330 replaces that with asynchronous loading. `assets.buffer_pool_bytes` is what really bounds residency, because a loaded resource keeps its buffer.

Runs: plain `ran 3099 of 8312 tests (phases: all; flavors: plain; display: included; crash tests: excluded)`, asan `ran 2514 of 8312`, tsan `ran 2187 of 8312`; Clang and GCC (non-unity) clean; tidy no findings; docs 7 of 7; the gates pass.


## Post-implementation code review

`/code-review high`: 10 findings, 7 fixed (the cycle, budget and timing ones with regression tests that fail without the fix), 3 declined.

- Fixed: `assets.mounts` read into a buffer that `TextSetting::Get` leaves unwritten when the text is too long (a text setting is at most 511 bytes, so it cannot happen, but the length is now checked); a reload was held to the cache budget with the old copy counted (`ReadBlobLocked` takes the bytes the reload gives back); a reload could make a cycle with a loaded dependent (the new dependencies are checked against everything that already depends on the resource); `read_nanos` counted each nested load once per level of the closure (only reads and loader calls are timed now); a type with no loader returned `NotFound`, which made it eligible for a fallback (now `TypeMismatch`, documented and tested); `ReadLevelSummary` ignored short header reads, the record count and the containers section (checked); the object key was the address of a function-local static (now a constant per C++ type, `ResourceTraits<T>::kKind`); dead code and per-byte copies removed.
- Declined: handle operations take the manager's one lock, which a load holds across its read (loads are serialized by design on this day; Day 330's asynchronous loading is where reads leave the lock; filed in `KNOWN-ISSUES.md`); `assets.buffer_pool_bytes` bounds residency even when `assets.cache_bytes` is 0 (a resident resource keeps its buffer in the pool by design; documented on `Load`, filed); the `STATUS.md`/day file/`KNOWN-ISSUES.md` finding was about the working tree before this step and is done by this commit.
