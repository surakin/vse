# Phase 22 / Day 328 — The Resource Manager: Handles, Cache, Dependencies & Synchronous Loading of CPU Resources

**Phase:** [Phase 22 — Asset Pipeline & Resource System](../phase-22-asset-pipeline.md)
**Depends on:** Days 314-327.

The runtime face of the system: ask for a resource by id, get a handle, never know which backend served it. This day builds the manager and every loader that needs no GPU; Day 329 adds the GPU-backed loaders, the level spawner and the reset test on top of the same registration seam (split from one day on 2026-11-14, the user's decision).

## Tasks

- [ ] **`asset::ResourceManager`:** owns the mount table (Day 315) and a cache; `Load<T>(id) -> Handle<T>` synchronous; `Get(handle)`; reference counts (a handle copy adds one); a resource is freed when its count reaches zero and it is not pinned; a generation in every handle so a stale handle reads as invalid, never as another resource. Reads go through the load buffer pool into one aligned buffer per blob, which the manager keeps while the loaded object views it.
- [ ] **The loader seam (`RegisterLoader`):** a loader turns a blob (its validated `BlobReader`, the buffer, and the handles of its already loaded dependencies) into an object of its type, and says what it needs resident; a type has one loader, and a later registration replaces the earlier one (Day 329 replaces the CPU mesh, texture and material loaders with GPU-backed ones without touching the manager). CPU loaders registered here: `SKEL` (the buffer stays owned by the manager; `asset::SkeletonView` is a span of it), `ANIM` (`ClipView`), `LEVL` (`LevelData` with its resource and reference lists; the spawner is Day 329), and the descriptions of `MESH` (`MeshView`), `TEXR` (`TextureView`) and `MATL` (`MaterialAssetData`).
- [ ] **Skeletal closure rules (added 2026-11-13):** a skinned mesh is published only when its skeleton is loaded and its recorded skeleton hash and joint count match, and a clip only when its skeleton hash matches the loaded skeleton (`DependencyTypeMismatch` naming both); unloading a skeleton while a mesh or a clip uses it is `InUse`; tests for each refusal.
- [ ] **Dependency graph, atomic closure (the principle: a dependency can never be broken):** the manager follows only the blob's declared dependency section; loading a resource loads its whole closure first and publishes the handle only when every dependency is loaded **and of the declared type and version** (`DependencyTypeMismatch` otherwise: this catches a loose file shadowing a pak entry with the wrong type); a failure returns `MissingDependency` naming the chain (`level -> material -> texture`) and leaves nothing half-loaded and no handle published; a cycle is `DependencyCycle` (the mint already refuses it; the manager checks anyway, since a hostile pak is possible); unloading a dependent releases its dependencies; tests: remove one dependency from the backend at every depth of a chain, swap one for a wrong-typed blob, a cycle in a hostile pak, a diamond (shared dependency loaded once), and concurrent loads of two roots sharing a dependency (asan, tsan).
- [ ] **Errors, no silent fallback:** a missing or invalid resource returns the `Status` and no handle (strict is the default). The *mechanism* of per-type fallbacks is here (`RegisterFallback`, behind the development setting `assets.allow_fallbacks`, default off; each use is logged and counted in `Stats::fallbacks_used`); the fallbacks themselves for GPU types (a checker texture, a magenta material, a unit cube) are Day 329. A fallback never stands in for a dependency inside a closure: a closure with a missing member fails as a whole. Tests use a test type.
- [ ] **`Stats`:** loads, cache hits, bytes resident, per-backend reads, fallbacks used, `load_conversions` (anything the loader had to convert or copy beyond the one read into the aligned buffer; must be zero for minted data), `rejected_old_version`, bytes read per millisecond of load time.
- [ ] **Load-path rules:** no allocation per element (one aligned buffer per blob, taken from a pool and recycled), no text parsing, no hash verification unless `assets.verify_on_load` is set (default off; development convenience), no per-field decoding of bulk sections, no mip generation or format conversion; an old-version or mismatched blob is refused at once with the fix named, never converted; mounts are checked for announced versions at mount time (a pak or server serving old versions is refused when mounted).
- [ ] **Settings** `assets.*` (`mounts`, `strict`, `cache_bytes`, `allow_fallbacks`, `verify_on_load`) through `settings::Registry`; `RegisterAssetSettings`, `ManagerConfigFromSettings`.
- [ ] **`ResourceInUse(id, &dependents)` and the memory backend's change records (added 2026-11-13):** the manager answers whether a loaded resource depends on an id (naming the dependents) so `HostMemoryBackend::Remove` and `Replace` can refuse with `InUse` (Day 315); a `Watch` record from the memory backend reloads the resource and its dependents atomically (the closure rule), and a replace that fails to load (wrong type, a broken dependency) leaves the old version loaded and reports the error.
- [ ] **Tests:** `Stats::load_conversions` is zero after loading every CPU type; an old-version blob is refused with `UnsupportedVersion` and counted; load every CPU type from a memory backend and from a pak of the same blobs with identical results (the "never know which backend" test); override by a loose mount; reference counting and generations under a stale handle; a dependency cycle; fallbacks with a test type; the skeletal refusals; a level loaded as `LevelData` lists the resources the manager must hold.
- [ ] **Runs (CLAUDE.md "Tests run by phase"):** `scripts/test-phase.sh --affected` plain; then the asan and tsan flavors when the day touched concurrency, lifetime or memory code; quote each run's final `ran X of Y tests (phases ...)` line in this file and never say "all tests pass" for a reduced run. `ctest -L docs` when a public header or a guide changed. Build clean (warnings are errors) with Clang and GCC, unity on and off. New code uses the engine's wrappers and types, never `std` (`std_usage_check`); file access only through `io::` (`file_access_check`); settings only through `settings::Registry` (`config_access_check`).
- [ ] **Three machines (CLAUDE.md "Three machines"):** shared code is portable and checked on the Windows PC and the Mac no later than Day 339; until then the day is "open until the other machines run it" in `KNOWN-ISSUES.md`.
- [ ] **Documentation (CLAUDE.md "Public API is documented before a day is done"):** public headers carry `///` comments with the contract labels (`docs/DOC-CONVENTIONS.md`); `docgen lint` stays at zero; `cmake --build build --target docs` output committed; new modules are added to `docs/reference/modules.txt`; the guide page `docs/guide/assets.md` is updated and its tagged samples compile and run.
