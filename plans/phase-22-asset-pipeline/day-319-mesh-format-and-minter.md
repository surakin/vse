# Phase 22 / Day 319 — The Mesh Format, Its Source Form & the Mesh Minter

**Phase:** [Phase 22 — Asset Pipeline & Resource System](../phase-22-asset-pipeline.md)
**Depends on:** Days 314-318 (blob container, the packed vertex formats of Day 317, the skeleton of Day 318); Phase 5 (`renderer::MeshData`, `VertexLayoutData`).

The mesh, end to end: source text to blob to `MeshData`. Amended 2026-11-13 (the user asked for skeletons and animation to be considered first): the mesh blob carries packed attributes (Day 317 formats) and an optional skin stream that refers to a skeleton by id (Day 318), so a skinned mesh is a first-class mesh and Phase 33's skeletal import has a format to write into.

## Tasks

- [x] **Mesh blob v1 (laid out for the GPU: the vertex and index sections are the exact bytes the RHI buffers hold, aligned for upload, no conversion at load):** sections for the vertex layout (the attribute list `MeshData::Set` takes), vertex bytes, index bytes (16 or 32 bit), topology, bounds, LODs (a list of index ranges with a screen-size threshold), material slots (a name and a range of indices per slot); every count bounded by a limit in the loader.
- [x] **Packed attributes (Day 317 formats):** the mesh layout the minter writes by default is binding 0: position `Float3`, a tangent frame (normal and tangent packed as `SNorm8x4` each, the bitangent sign in the tangent's w), texture coordinates `UNorm16x2` with a per-mesh scale and offset in the header for coordinates outside [0,1] (or `Float16x2` when the range needs it; the minter picks per mesh, deterministically, by the measured error against the source values and records the measured error in the header); an option keeps full `Float3`/`Float4` attributes (`quality full`) for meshes that need them; the shaders read the packed formats as `float4` inputs, so nothing is converted at load. Quantized positions (a per-mesh decode transform) are out of scope for v1 and filed in `KNOWN-ISSUES.md` on this day. The built-in `StandardVertex` shapes keep their layout (the equality test below compares decoded values within the declared error, not bytes).
- [x] **Skin stream (optional):** binding 1, per vertex joint indices `UInt8x4` (location 5) and weights `UNorm8x4` (location 6), at most four influences; the minter keeps the four largest weights of the source (ties by joint index), renormalizes in `f64`, rounds to bytes with the largest-remainder rule so the four weights sum to **exactly 255** (the shader needs no renormalization), and sorts each vertex's influences by descending weight then joint index (deterministic); a vertex with no influence is an error naming the line; joint indices must be below the skeleton's joint count (checked against the skeleton source or blob given to the minter, at most 256).
- [x] **Skeleton reference:** a skinned mesh declares the skeleton as a standard dependency with role `skin-skeleton` and records the skeleton hash (Day 318) and the joint count in a skin header section; `BlobReader` and the manager (Day 328) load the skeleton first and refuse a mesh whose recorded hash or joint count differs from the loaded skeleton's (`DependencyTypeMismatch`), so a skinned mesh can never be drawn with another skeleton's palette; the mesh source gains `skeleton <hex id>` and `skin <vertex> <joint> <weight> ...` records.
- [x] **Bounds of a skinned mesh:** the blob stores the bind-pose bounds and, per skin, the bind-pose bounds of each joint's influence set (a small table, 256 boxes at most) so the renderer can bound a posed mesh from the pose when a clip's bounds are not available; the extra section is skipped by loaders that do not skin.
- [x] **Morph targets (blend shapes) are out of scope for v1:** the section tag `MORP` is reserved and refused as unknown by this version; the decision is recorded in `KNOWN-ISSUES.md` so Phase 33 files its missing support rather than discovering it.
- [ ] **Trusted, zero-copy renderer entry (Day 313 Spike 5: `MeshData::Set` validates and copies; a copy costs 6x to 10x the read):** add to the renderer a way to build a `GpuMesh` from a span of a minted blob's vertex and index sections without `MeshData::Set`'s copy and validation (a `TrustedMeshView` the loader fills after the blob's own validation; with one or two vertex streams); the existing `MeshData` path stays for runtime-built meshes; a device-reset test shows the owner keeps the blob buffer (or reloads from the backend) and recreates the GPU mesh from it. **(deferred to Day 328, see Outcome)**
- [x] **Source form `.mesh.src`:** a line-oriented text file (`attribute`, `v`, `i`, `lod`, `slot` records) defined in the guide with an example; a parser with line-numbered errors; no OBJ or glTF reader (the user's answer).
- [x] **`MeshMinter`:** source to blob; computes bounds; reorders indices for the post-transform cache and vertices for fetch locality by a deterministic algorithm (ties broken by index), quantizes or packs attributes into the layout the shaders read (so nothing is converted at load), and validates fully (everything `MeshData::Set` checks, plus bounds and LOD ranges) so the runtime need not; validates through `MeshData::Set`'s own rules so what is minted loads.
- [x] **Loader `LoadMeshBlob(bytes) -> MeshAssetData`** (CPU side: `MeshData` plus LODs and slots) through `BlobReader` (current version only): bounds-checked, then spans into the buffer, no copy of the vertex or index data into an intermediate `MeshData` (the trusted entry Day 313's spike chose; the renderer change, if any, is part of this day); the GPU object is made by the manager on Day 328.
- [x] **The source carries its id (2026-11-13, no sidecar):** the mesh source has an `id` field in its header (a first line `id <hex>` in a text form), written only by `asset_mint adopt` (Day 333); the parser reads and round-trips it, a missing id is the error that names `adopt`, and the minter writes the id into the blob header (Day 314); a test per format.
- [x] **Tests:** the skin cases: weights sum to 255 in every vertex of a minted skinned mesh (property test over random sources), the four-largest rule and its tie-break, a joint index past the skeleton's count refused with the line number, a mesh minted against skeleton A refused when loaded with skeleton B, the packed-attribute error recorded in the header equals the error a test measures independently; plus a table of source files (valid, and each error with its line number); the minted blob of a cube and of a sphere loads to the same `MeshData` the `Make...Mesh` functions build (bounds, counts, bytes); LOD and slot ranges are checked against the index count; a v0 golden blob (a deliberately older layout kept as a fixture) is refused by the loader, and `asset_mint remint`'s mesh upgrade (implemented in the tool this day) rewrites it to bytes identical to a fresh mint of the same source; hostile blobs (counts that overflow, ranges past the end) refused; minting twice is byte-identical.
- [x] **Runs (CLAUDE.md "Tests run by phase"):** `scripts/test-phase.sh --affected` plain; then the asan and tsan flavors when the day touched concurrency, lifetime or memory code; quote each run's final `ran X of Y tests (phases ...)` line in this file and never say "all tests pass" for a reduced run. `ctest -L docs` when a public header or a guide changed. - [x] **Documentation (CLAUDE.md "Public API is documented before a day is done"):** public headers carry `///` comments with the contract labels (`docs/DOC-CONVENTIONS.md`); `docgen lint` stays at zero; `cmake --build build --target docs` output committed; new modules are added to `docs/reference/modules.txt`; the guide page `docs/guide/assets.md` is updated and its tagged samples compile and run.

## Outcome
