# Phase 22 / Day 321 — The Animation Runtime: Sampling, Blending & Skinning Matrices

**Phase:** [Phase 22 — Asset Pipeline & Resource System](../phase-22-asset-pipeline.md)
**Depends on:** Days 314-320; Phase 17 (ECS), Phase 2 (jobs), `engine/foundation` math.

The CPU side that turns a clip and a time into joint matrices for the renderer. It must not need the asset module (that module sits above the renderer); it works on plain views, so the module is placed below it.

## Tasks

- [ ] **Module placement (decide and record first):** the new module `engine/animation` at layer 12 beside the renderer: depends on `foundation`, `jobs` and `ecs`, includes nothing from `asset`, `rhi` or `renderer`; `asset` depends on it (the loaders of Days 318 and 320 fill `animation::SkeletonView` and `animation::ClipView`, which are defined in `animation` with the blob layouts they read; the minters write those layouts). `ARCHITECTURE.md`, `tools/module_deps_check/modules.txt`, `docs/reference/modules.txt`, the CMake targets with `_asan`/`_tsan` flavors and the `tests/module_map.txt` line are written in the same commit; `module_deps_check` must pass with no allowlist entry. If a cycle shows (the layouts living in `animation` while the minters live in `asset`), stop and re-plan here rather than adding an edge.
- [ ] **Sampler:** `animation::SampleClip(ClipView, f32 time, SamplerState*, LocalPose* out)`: finds the key segment by binary search on first use and by a cached cursor on forward playback (`SamplerState` holds one cursor per track, so a steady playback is O(1) per track), decodes quantized keys on the fly (nothing is decoded into a table), interpolates rotation by normalized lerp between the neighboring keys (nlerp, the cost/quality choice recorded with its error against slerp), translation and scale linearly; looping and clamping modes; the output is a structure-of-arrays local pose.
- [ ] **Pose operations:** `Blend(a, b, weight)`, `BlendMasked(a, b, weight, joint mask)`, `AddAdditive(base, additive_clip_pose, weight)` (an additive clip stores the difference from the bind pose by its flag), `Mirror` is out of scope; weights normalized by the caller; every operation works in place on caller-provided pose storage (no allocation per call; the pose is a fixed 256-joint structure).
- [ ] **Model-space and palette:** `ModelFromLocal(SkeletonView, LocalPose, ModelPose*)` walks the parent-first joint table once, `SkinningMatrices(SkeletonView, ModelPose, Span<Mat3x4> out)` multiplies by the inverse bind matrices into the 48-byte palette layout the GPU takes (the same bytes as the skeleton section, row-major 3x4); a golden test compares the result with a test-local straightforward 4x4 reference on a 20-joint skeleton within 1e-5.
- [ ] **ECS components and the system:** `AnimationPlayer` (clip `ResourceRef`, time, speed, playing, looping, blend weight), `SkeletonInstance` (skeleton `ResourceRef`, palette storage owned by a chunk-friendly pool) registered with `ecs::ComponentRegistry` and `storage` (stable ids, versions, fields, so levels save them), and an `AnimationSystem` that advances time and samples every player in parallel through the job system (one job per batch of entities, deterministic regardless of worker count: each entity's result depends only on its own components); events crossed in a frame are published as `AnimationEvent` records in time order.
- [ ] **Root motion:** a clip flagged root-motion exposes the root joint's delta translation and rotation over the frame; the system writes it into `RootMotionDelta` and the sampled pose has the root held at its first-frame value; the game applies the delta (no physics yet).
- [ ] **Tests:** exact key and mid-key samples against the reference sampler; nlerp versus slerp error recorded for a 170-degree segment; cursor playback equals binary-search playback for forward, looping and a seek; blend weights 0 and 1 reproduce the inputs bit for bit; masked blend leaves unmasked joints untouched; additive clip at weight 1 applied to the bind pose reproduces the clip pose; skinning palette golden; the system produces the same palettes at 1 and 8 workers byte for byte; events fire once per crossing, including across a loop; a clip bound to the wrong skeleton is refused by the system with a log line, not a crash; tsan clean for the parallel system.
- [ ] **Benchmark (hidden `[.][animation-bench]`):** samples per second for a 40-joint clip, and entities per second through `AnimationSystem` at 1 and 8 workers for 10,000 characters, recorded for Day 337 (a stated target: 10,000 40-joint characters in 4 ms on 8 workers; the user confirms the figure on Day 337).
- [ ] **Runs (CLAUDE.md "Tests run by phase"):** `scripts/test-phase.sh --affected` plain; then the asan and tsan flavors when the day touched concurrency, lifetime or memory code; quote each run's final `ran X of Y tests (phases ...)` line in this file and never say "all tests pass" for a reduced run. `ctest -L docs` when a public header or a guide changed. Build clean (warnings are errors) with Clang and GCC, unity on and off. New code uses the engine's wrappers and types, never `std` (`std_usage_check`); file access only through `io::` (`file_access_check`); settings only through `settings::Registry` (`config_access_check`).
- [ ] **Three machines (CLAUDE.md "Three machines"):** shared code is portable and checked on the Windows PC and the Mac no later than Day 338; until then the day is "open until the other machines run it" in `KNOWN-ISSUES.md`.
- [ ] **Documentation (CLAUDE.md "Public API is documented before a day is done"):** public headers carry `///` comments with the contract labels (`docs/DOC-CONVENTIONS.md`); `docgen lint` stays at zero; `cmake --build build --target docs` output committed; new modules are added to `docs/reference/modules.txt`; the guide page `docs/guide/assets.md` is updated and its tagged samples compile and run.
- [ ] **Module rules (CLAUDE.md "Module dependencies follow ARCHITECTURE.md"):** a new module or edge updates `ARCHITECTURE.md`, `tools/module_deps_check/modules.txt` and the CMake targets (with `_asan`/`_tsan` flavors) in the same commit; no upward edge, no cycle; every new test file has its line in `tests/phases.txt` (phase 22).
- [ ] **Day review (CLAUDE.md, required):** `/code-review high` over the day's diff after the scoped tests; verify, fix (with a regression test that fails without the fix) or decline each finding with a reason; record the count and outcome under "Post-implementation code review" below and in `STATUS.md`.
- [ ] `STATUS.md` and `KNOWN-ISSUES.md` updated in the same commit; commit and push.

**Done:** a clip and a time produce joint matrices that match a reference implementation, blending and additive poses behave as specified, the parallel system is deterministic at any worker count, and the module obeys the layering rules.
