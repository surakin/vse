# Phase 22 / Day 321 — The Animation Runtime: Sampling, Blending & Skinning Matrices

**Phase:** [Phase 22 — Asset Pipeline & Resource System](../phase-22-asset-pipeline.md)
**Depends on:** Days 314-320; Phase 17 (ECS), Phase 2 (jobs), `engine/foundation` math.

The CPU side that turns a clip and a time into joint matrices for the renderer. It must not need the asset module (that module sits above the renderer); it works on plain views, so the module is placed below it.

## Tasks

- [x] **Module placement (decide and record first):** the new module `engine/animation` at layer 12 beside the renderer: depends on `foundation`, `jobs` and `ecs`, includes nothing from `asset`, `rhi` or `renderer`; `asset` depends on it (the loaders of Days 318 and 320 fill `animation::SkeletonView` and `animation::ClipView`, which are defined in `animation` with the blob layouts they read; the minters write those layouts). `ARCHITECTURE.md`, `tools/module_deps_check/modules.txt`, `docs/reference/modules.txt`, the CMake targets with `_asan`/`_tsan` flavors and the `tests/module_map.txt` line are written in the same commit; `module_deps_check` must pass with no allowlist entry. If a cycle shows (the layouts living in `animation` while the minters live in `asset`), stop and re-plan here rather than adding an edge.
- [x] **Sampler:** `animation::SampleClip(ClipView, f32 time, SamplerState*, LocalPose* out)`: finds the key segment by binary search on first use and by a cached cursor on forward playback (`SamplerState` holds one cursor per track, so a steady playback is O(1) per track), decodes quantized keys on the fly (nothing is decoded into a table), interpolates rotation by normalized lerp between the neighboring keys (nlerp, the cost/quality choice recorded with its error against slerp), translation and scale linearly; looping and clamping modes; the output is a structure-of-arrays local pose.
- [x] **Pose operations:** `Blend(a, b, weight)`, `BlendMasked(a, b, weight, joint mask)`, `AddAdditive(base, additive_clip_pose, weight)` (an additive clip stores the difference from the bind pose by its flag), `Mirror` is out of scope; weights normalized by the caller; every operation works in place on caller-provided pose storage (no allocation per call; the pose is a fixed 256-joint structure).
- [x] **Model-space and palette:** `ModelFromLocal(SkeletonView, LocalPose, ModelPose*)` walks the parent-first joint table once, `SkinningMatrices(SkeletonView, ModelPose, Span<Mat3x4> out)` multiplies by the inverse bind matrices into the 48-byte palette layout the GPU takes (the same bytes as the skeleton section, row-major 3x4); a golden test compares the result with a test-local straightforward 4x4 reference on a 20-joint skeleton within 1e-5.
- [x] **ECS components and the system:** `AnimationPlayer` (clip `ResourceRef`, time, speed, playing, looping, blend weight), `SkeletonInstance` (skeleton `ResourceRef`, palette storage owned by a chunk-friendly pool) registered with `ecs::ComponentRegistry` and `storage` (stable ids, versions, fields, so levels save them), and an `AnimationSystem` that advances time and samples every player in parallel through the job system (one job per batch of entities, deterministic regardless of worker count: each entity's result depends only on its own components); events crossed in a frame are published as `AnimationEvent` records in time order.
- [x] **Root motion:** a clip flagged root-motion exposes the root joint's delta translation and rotation over the frame; the system writes it into `RootMotionDelta` and the sampled pose has the root held at its first-frame value; the game applies the delta (no physics yet).
- [x] **Tests:** exact key and mid-key samples against the reference sampler; nlerp versus slerp error recorded for a 170-degree segment; cursor playback equals binary-search playback for forward, looping and a seek; blend weights 0 and 1 reproduce the inputs bit for bit; masked blend leaves unmasked joints untouched; additive clip at weight 1 applied to the bind pose reproduces the clip pose; skinning palette golden; the system produces the same palettes at 1 and 8 workers byte for byte; events fire once per crossing, including across a loop; a clip bound to the wrong skeleton is refused by the system with a log line, not a crash; tsan clean for the parallel system.
- [x] **Benchmark (hidden `[.][animation-bench]`):** samples per second for a 40-joint clip, and entities per second through `AnimationSystem` at 1 and 8 workers for 10,000 characters, recorded for Day 337 (a stated target: 10,000 40-joint characters in 4 ms on 8 workers; the user confirms the figure on Day 337).
- [x] **Runs (CLAUDE.md "Tests run by phase"):** `scripts/test-phase.sh --affected` plain; then the asan and tsan flavors when the day touched concurrency, lifetime or memory code; quote each run's final `ran X of Y tests (phases ...)` line in this file and never say "all tests pass" for a reduced run. `ctest -L docs` when a public header or a guide changed. ## Outcome

Built, with these deviations. **Module placement re-planned:** the skeleton and clip views were built in `asset` (Days 318 and 320), so `engine/animation` sits at layer 13 beside `asset` and reads them (the one same-layer edge `animation -> asset`, `allow animation asset` in `tools/module_deps_check/modules.txt`; no cycle: `asset` does not include `animation`); `ARCHITECTURE.md`, `docs/reference/modules.txt`, `tests/module_map.txt`, `tests/phases.txt`, the CMake targets with `_asan`/`_tsan` flavors and `docs/guide/animation.md` are in the same commit. `ClipView::Sample` gained a cursor argument (O(1) forward playback). The components hold resource ids as raw `u64` (the typed `ResourceRef` arrives with the manager, Day 328); `AnimationSystem` is a class with `Update(world, scheduler, dt)` over `Query::ForEachChunkParallel`, not a `Schedule` system, and resolves ids through an `AnimationResolver` interface; the palette is a `Vector<Mat3x4>` in `SkeletonInstance` (allocated on first update, not a pool); events go to an `AnimationEvents` resource in entity order; the system refuses additive clips; the time-advance and events API is `AdvanceTime` / `CollectEvents`. The nlerp-vs-slerp error over 170 degrees is 6.75 degrees at worst (recorded in the guide).

**Benchmark (Debug build, unoptimized, so only an upper bound; the target of 4 ms on 8 workers is for Day 337 in Release):** 437,000 clip samples per second (40 joints, 3 tracks); 10,000 characters of 20 joints: 160 ms per update at 1 worker, 23.8 ms at 8 workers.

Runs: plain `ran 861 of 8026 tests (phases: 3 4 5 6 12 22; flavors: plain; display: excluded; crash tests: excluded)`; asan `ran 727 of 8026 tests (phases: 3 4 5 6 12 22; flavors: asan; display: excluded; crash tests: excluded)`; tsan `ran 452 of 8026 tests (phases: 3 4 5 6 12 22; flavors: tsan; display: excluded; crash tests: excluded)` with the 2 known RHI SegFaults only (`KNOWN-ISSUES.md`); the 15 animation cases pass in all three, including the 1-versus-8-worker palette equality. Clang and GCC, unity on and off; `ctest -L docs` 7 of 7, 114 samples, docs lint zero; the gates pass.

## Post-implementation code review

`/code-review high`: 7 findings. Fixed (4, each with a test): events replayed after an entity lost its `SkeletonInstance`; a saved weight above 1 aborted in `Blend` (now clamped); an infinite step gave a NaN time (now limited); an additive clip was played as a pose (now refused). Recorded, not changed (3): root rotation composes at most 64 whole loop passes; raw `u64` ids instead of `ResourceRef` (Day 328); about 32 KB of poses on the worker stack per entity update (throughput is Day 337's figure).
