# Phase 22 / Day 322 — GPU Skinning in the Renderer

**Phase:** [Phase 22 — Asset Pipeline & Resource System](../phase-22-asset-pipeline.md)
**Depends on:** Days 317 (vertex formats), 319 (mesh with skin stream), 321 (palette layout); Phase 5, Phase 8 (device reset), Phase 13 (DX12), Phase 21 (Metal).

Skinning in the vertex shader from a per-frame joint palette: the cheapest design that keeps meshes immutable and works identically on all backends. Compute pre-skinning (for many instances sharing a pose, or for ray tracing) is a later optimization, filed in `KNOWN-ISSUES.md`.

## Tasks

- [ ] **Skinned vertex layout:** `renderer::SkinnedVertexLayout()` = the standard attributes in binding 0 (from Day 319: whatever packed layout the mesh blob declares) plus the skin stream in binding 1: joint indices `UInt8x4` (location 5), weights `UNorm8x4` (location 6); `GpuMesh` accepts two streams (a mesh without the skin stream is a rigid mesh, unchanged); the existing `MeshData` path and the trusted entry of Day 319 both carry the second stream.
- [ ] **The joint palette:** a per-frame-slot structured buffer of 48-byte matrices (the layout of Days 318 and 321), written by the render-scene sync before the frame records; budget setting `renderer.joint_palette_bytes` (default 16 MiB: about 340,000 joints); each skinned instance gets an offset into the palette; an instance whose palette does not fit is **not drawn** and counted in `FrameStats::skinned_dropped` with one log line per frame (never a crash, never a stale pose); the palette buffer is a `DeviceResources` member with `Release`/`Recreate` (CPU-side source: the instance poses are rewritten every frame).
- [ ] **Shader:** a `SKINNED` option on the geometry-pass vertex shader (the permutation system of Phase 5: `gbuffer.vert.slang` with `// permutation-options` extended), skinning position, normal and tangent with the weighted matrix sum (the 3x4 form; normals and tangents use the matrix's 3x3 part, valid for the uniform-scale case documented; non-uniform scale in a pose is out of scope and noted), the committed SPIR-V, DXIL and Metal library outputs regenerated (Windows PC for the DXIL, the Mac's interim metallib route until the user's next Mac, `KNOWN-ISSUES.md` records what waits); every pass that draws geometry (the G-buffer pass and, where the renderer has them, the depth and shadow passes) selects the skinned permutation for skinned instances.
- [ ] **Render scene:** `RenderScene` gets `AddSkinned(mesh, material, transform, palette span)` (or the existing entry with a skin parameter: decided by what the code review of `render_scene.h` shows first); culling uses the clip's bounds box (Day 320) or the mesh's bind-pose bounds inflated by a per-instance `skin_bounds_scale` the game can set; `scene::RenderSync` mirrors `SkeletonInstance` palettes of ECS entities into the palette buffer, with the same change detection the transform sync uses (an unchanged palette is not rewritten).
- [ ] **Materials:** a material works skinned when its geometry shader has the `SKINNED` permutation; the material system reports a mismatch (a non-skinnable material on a skinned mesh) when the pipeline is built, naming both, and the mesh falls back to the error material (never an unskinned draw of a skinned mesh).
- [ ] **Tests:** a 3-joint test mesh (a tube bent by a 90-degree joint rotation) rendered skinned and read back, compared to the CPU reference skinning of `animation` within a pixel tolerance, on Vulkan on Linux; the same test on DX12 and Metal on their machines; weights summing to exactly 255 in every vertex of a minted mesh asserted by the minter test (Day 319) so the shader needs no renormalization; a palette-budget test drops exactly the instances that do not fit and counts them; a reset test through `tests/renderer/reset_rig.h` (the palette buffer and the skinned mesh survive and the image is unchanged); validation layers silent; 1,000 skinned instances share one mesh and one pipeline (a draw-count assertion).
- [ ] **Benchmark (hidden `[.][render-bench]`):** 1,000 and 10,000 skinned instances of a 5,000-vertex, 40-joint mesh, CPU record time and GPU time where the backend reports it, for Day 337.
- [ ] **Three machines:** DX12 and Metal paths written here, checked on the Windows PC and the Mac no later than Day 338; waiting entries in `KNOWN-ISSUES.md`.
