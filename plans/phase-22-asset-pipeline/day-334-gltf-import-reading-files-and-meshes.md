# Phase 22 / Day 334 — glTF Import I: Reading Files & Importing Meshes

**Phase:** [Phase 22 — Asset Pipeline & Resource System](../phase-22-asset-pipeline.md)
**Depends on:** Days 319 (mesh), 318 (skeleton), 332 (the `asset_mint` project and `adopt`); PLAN.md assumptions #4 and #19 as amended 2026-11-14.

Added 2026-11-14 (the user): glTF 2.0 assets (`.gltf` and `.glb`) import into the engine's own formats. The importer is an offline `asset_mint` command; the engine never reads glTF, so the load path is unchanged (blobs only). This day reads the container and imports geometry; Day 335 imports skeletons and animation; Day 336 imports images, textures and materials and finishes the command.

## Decisions (planner's defaults; the user confirms or overrides)

- **The `.gltf`/`.glb` file stays the source of truth** (a mesh of a million vertices would be a half-gigabyte text file); `asset_mint mint` regenerates every blob from it deterministically. The ids cannot live in a file we do not own, so the importer keeps a text **import manifest** `NAME.gltf.import` next to the file (options, then one line per imported object: kind, glTF index and name, `ResourceId`). This is the one place the "source carries its id, no sidecar" rule (2026-11-13) does not hold: a third-party format has no id field. Re-import reuses an id when the kind and the glTF index (or name) match, so a re-exported file keeps every reference; an object that vanished from the file is reported and its id is never reused.
- **JSON parsing uses nlohmann/json** (already vendored for `shader_mint`; PLAN.md #19 now lists `asset_mint`'s importer). Only the files under `tools/asset_mint/gltf/` that read JSON include it (allow-listed in `std_usage_check` with the reason, as `shader_mint` is); everything after the JSON is turned into engine types.

## Tasks

- [ ] **Container (`tools/asset_mint/gltf/`):** `.gltf` (JSON, external `.bin` files and `data:` base64 URIs) and `.glb` (12-byte header, JSON chunk, optional BIN chunk, chunk lengths and padding checked); `asset` version 2.0 only; every limit bounded (file bytes, node, mesh, accessor, buffer view and image counts, JSON depth); an external URI must stay inside the glTF file's directory (no absolute path, no `..` escape, no scheme but `data:`), resolved through `io::Path`.
- [ ] **Accessors:** every component type (`BYTE`..`FLOAT`), `normalized`, `byteStride`, `sparse` accessors, and checked arithmetic on every offset and count so a hostile file cannot read outside its buffer; the accessor's declared `min`/`max` are ignored (bounds are recomputed).
- [ ] **Meshes:** each glTF mesh becomes one engine mesh resource; each primitive becomes a material slot (named after the material, or `primitive<N>`) with its own vertex range appended to the mesh's vertex pool and its index range; modes `TRIANGLES`, `TRIANGLE_STRIP` and `TRIANGLE_FAN` are converted to a list, other modes are refused with the mesh and primitive named; indices are widened or narrowed as the mesh rule requires.
- [ ] **Missing attributes, deterministically:** no normals: area-weighted smooth normals (flat when `--flat-normals`); no tangents: per-triangle UV-derivative tangents accumulated per vertex and orthonormalized, bitangent sign from the UV handedness (documented, deterministic, **not** MikkTSpace; filed in `KNOWN-ISSUES.md`); no UVs: zeros with a counted warning; vertex colors and `TEXCOORD_1` and up are dropped with a counted warning.
- [ ] **Engine conventions:** the importer converts glTF's right-handed, Y-up, metre units to the engine's convention (decided on this day from `renderer::Camera` and the winding the Make...Mesh functions use; a flip also reverses the winding), with `--scale` for another unit; node transforms are not baked into meshes except through `--bake-nodes` (default: one mesh resource per glTF mesh in its own space, the scene structure is Day 336's `level` output).
- [ ] **Morph targets** (`targets`, `weights`): refused with the primitive named, unless `--drop-morph-targets` imports the base shape (counted warning); the mesh format has no morph section (Day 319).
- [ ] **Skin attributes:** `JOINTS_0` and `WEIGHTS_0` map to the mesh skin stream (the four-largest rule of Day 319); `JOINTS_1` and up (more than four influences) keep the four largest with a counted warning; the skeleton reference is filled by Day 335.
- [ ] **Mesh minting path:** the importer builds `MeshBuildInput` and calls `BuildMeshBlob` (Day 319): what is imported is exactly what `.mesh.src` would mint; a `--emit-src` option writes the equivalent `.mesh.src` for small meshes (tests and inspection), refusing meshes over 10,000 vertices.
- [ ] **Hostile and malformed files:** a table of files (generated by the test, not downloaded): truncated GLB, chunk length past the end, an accessor whose count overflows, a buffer view past its buffer, a sparse accessor with an index past the count, indices past the vertex count, a primitive with no `POSITION`, NaN positions, a `..` URI, deep JSON nesting; each refused with the glTF object named and no crash under asan.
- [ ] **Tests:** hand-authored fixtures written by `tests/asset/gltf_writer.h` (a minimal glTF/GLB writer for tests): a triangle, a cube with normals and UVs (one glTF primitive with three slots), a mesh with sparse accessors, strips and fans, a skinned mesh; each imported and compared with the blob minted from the equivalent `.mesh.src`; import twice gives byte-identical blobs and manifest; re-import after reordering the file's meshes keeps the ids.
- [ ] **Runs (CLAUDE.md "Tests run by phase"):** `scripts/test-phase.sh --affected` plain; then the asan and tsan flavors (the importer parses hostile files); quote each run's final `ran X of Y tests (phases ...)` line in this file and never say "all tests pass" for a reduced run. `ctest -L docs` when a public header or a guide changed. Build clean (warnings are errors) with Clang and GCC, unity on and off. Importer code that is not behind the JSON or image-decoder wrappers uses the engine's types, never `std` (`std_usage_check`); file access only through `io::` (`file_access_check`).
- [ ] **Three machines (CLAUDE.md "Three machines"):** shared code is portable and checked on the Windows PC and the Mac no later than Day 339; until then the day is "open until the other machines run it" in `KNOWN-ISSUES.md`.
- [ ] **Documentation (CLAUDE.md "Public API is documented before a day is done"):** public headers carry `///` comments with the contract labels; `docgen lint` stays at zero; `cmake --build build --target docs` output committed; the guide page `docs/guide/assets.md` gets the "Importing glTF" section (this phase's three days add to it) and its tagged samples compile and run.
- [ ] **Module rules (CLAUDE.md "Module dependencies follow ARCHITECTURE.md"):** the importer lives in `tools/asset_mint/gltf/` and is never linked into the engine or a game (the Day 337 gate checks it); a new target or edge updates `ARCHITECTURE.md` and `tools/module_deps_check/modules.txt` in the same commit; every new test file has its line in `tests/phases.txt` (phase 22).
- [ ] **Day review (CLAUDE.md, required):** `/code-review high` over the day's diff after the scoped tests; verify, fix (with a regression test that fails without the fix) or decline each finding with a reason; record the count and outcome under "Post-implementation code review" below and in `STATUS.md`.
- [ ] `STATUS.md` and `KNOWN-ISSUES.md` updated in the same commit; commit and push.

**Done:** a `.glb` or `.gltf` with meshes imports to mesh blobs that equal what the `.mesh.src` path would mint, hostile files are refused naming the glTF object, ids survive a re-import, and the output is deterministic.
