## Outcome

Built as planned, with these deviations and decisions:

- **A level is a save.** The blob (`engine/asset/level.*`, type `LEVL`, sections 16 to 19) holds the entity records `storage::WorldStorage` writes (a count and framed component records), so saves and levels share one set of field codecs, and `LoadLevelBlob` loads through `WorldStorage::Load` (atomic: the world is untouched when a record is bad). The reference table (entity, component, field, declared type, id) and the dependency list are derived from the records; the parser recomputes them and refuses a blob that disagrees, and each entity's count in the table must be its container's.
- **`ResourceRef` field kind** (`storage/field.h`): a `storage::ResourceRef` member, or a `u64` declared with `FieldOptions::Reference(type_tag, nullable)`; the stored bytes are the same eight as a `u64`, so the animation fields (`clip`, `skeleton`) changed with no version bump. `storage::SkipField` and `ReadReferences` (`field_walk.*`) read references out of a record without building the component; an array of references is refused at registration; the SQL column layout treats the kind as the integer column the `u64` had.
- **Components:** `asset::MeshReference` (mesh, material, flags; id 50) and `asset::EntityName` (id 51). `scene::MeshRenderer` holds a `SharedPtr<MeshAsset>`, so it is not stored; Day 328's loader makes it from `MeshReference`.
- **Text form** (`tools/asset_mint/level_source.*`): registry-driven (`component TYPE`, `FIELD = VALUE`, defaults from a default-constructed component), `entity NAME` with a key derived from the level id and the name (`entity NAME key @HEX32`, `entity key @HEX32`), `parent`, `include`, and the shorthand `skeleton PATH` and `animation PATH [loop|once] [speed X]`. The printer writes the long form, entities by name, so text, blob and world print back identically. `asset_mint mint-level` and `unmint-level` (references resolved against the blobs under `--root`).
- **Checks at mint time:** typed references, null in a non-nullable field, unknown component or field (the message lists the registry's names), a parent that is nowhere, an include that is not a level or forms a cycle, a clip made for another skeleton than the entity's, and a final load of the blob into a scratch world.
- **Not done here:** column images (moved to Day 332, above). `include` names the level to spawn along with this one; the loader that spawns it is Day 328.

Runs (Linux machine): see the commit's `STATUS.md` entry for the final lines; Clang and GCC (non-unity) clean; `scripts/tidy.sh` on the changed files: no findings; `ctest -L docs` 7 of 7; the gates pass. The X11 window tests that need an active session failed as before.


## Post-implementation code review

`/code-review high` over the day's diff: 9 findings, 7 fixed (regression tests added; the SQL one checked to fail without the fix), 2 declined.

- Fixed: `mint-level` and `unmint-level` with a bare file name had an empty default root (now `.`); a `u64` declared a reference became `ResourceRef`, which dropped its SQL column (the kind is the integer column again; `tests/storage/sql_layout_test.cpp` fails without the change); an `Array<ResourceRef,N>` would have hidden its ids from the reference table (refused at registration); the per-entity record count in the table was not checked against the container (only the sum; hostile-blob test added); the `UnsupportedVersion` message named `asset_mint remint`, which does not exist yet (it names `mint-level`); two entities with one name in a hand-built blob printed as text that cannot be minted (the printer refuses them); `file:0:` in the tool's error line (omitted when there is no line).
- Declined: the minter's name lookup (`FindByName`, `FindResolved`) is linear, so minting a level is quadratic in its entities (an offline tool; 1,000 entities take no measurable time; filed in `KNOWN-ISSUES.md` with the size to revisit it at); `ProjectResolver::ResolveId` reads whole blobs to learn a header (Day 332's project tool replaces this resolver with the manifest; filed).
