# Phase 22 / Day 333 — The `asset_mint` Tool I: Project Files, Mint, Pack, Verify, Incremental Minting & Determinism

**Phase:** [Phase 22 — Asset Pipeline & Resource System](../phase-22-asset-pipeline.md)
**Depends on:** Days 314-327 and 316.

One command-line tool that turns a source tree into blobs and a pak, the same way every time. (Split in two on 2026-11-14, the user's decision: the reference-safe edits, `remint`/`unmint`, `pack --target`, version enforcement and the level column-image question are Day 334.)

## Tasks

- [x] **Skeleton and animation types in the tool (added 2026-11-13):** `adopt`, `mint`, `verify`, `list`, `remint` and `unmint` cover `.skel.src` and `.anim.src` (the minters and upgrade chains of Days 318 and 320 live here), a mesh source naming a skeleton and a clip source naming a skeleton are minted in dependency order and the incremental cache invalidates a clip when its skeleton source changes (the skeleton hash is part of the clip's input hash); `asset_mint list --skeletons` prints each skeleton's joint count, hash and the meshes and clips that use it; a test per new behavior.
- [x] **Project file `assets.project`** (a text file: source root, output root, pak name, per-extension rules with options such as the texture format and quality, excluded paths); a parser with line-numbered errors.
- [x] **Commands (part I):** `asset_mint adopt` (assign an id to a source that has none, writing it into the file; the only command that writes an id into a source), `mint` (all sources to blobs, in dependency order, every error reported), `pack` (blobs to a pak; refuses non-current or unverifiable blobs), `verify` (every blob and the pak: headers, hashes, **the dependency closure complete and typed, a base pak present by hash**; a hand-edited dependency section fails), `list` (ids, paths, types, sizes, read from the table; `--skeletons` as above; `mint` and `pack` also write `resources.table` and the pak's table section, and `verify` checks every table entry against the blobs' own ids) and `check` (the closure of the whole project: every reference resolves, every type and version matches, no cycle, no duplicate id). The commands of Day 334 (`copy`, `reid`, `refs`, `rename`, `move`, `delete`, `remint`, `unmint`) are not part of this day.
- [x] **Incremental minting:** an output manifest records for each blob the hashes of its inputs, its dependencies' hashes, the tool version and the options; an unchanged blob is not rewritten; a changed texture re-mints the materials that name it only if the material blob embeds anything from it (it does not: ids only), so only dependents whose *inputs* changed are rebuilt; `--force` rebuilds everything.
- [x] **Breaking a reference is caught (part I):** tests: a source deleted by hand makes the next `mint` fail naming every dependent (never a blob with a dangling id); two sources with one id (a plain `cp`) fail the mint naming both; a source with no id fails the mint naming `adopt`, and re-running `adopt` on an adopted file changes nothing; a hand-edited dependency section fails `verify`; `check` runs in the demo's ctest and in `ctest -L asset`. The tool-guarded changes (rename, move, delete, reid) and their tests are Day 334.
- [x] **Parallel minting** on the job system with a deterministic result: outputs and manifests are independent of the worker count and of the file system's listing order (everything sorted by id).
- [x] **Determinism tests** (`tests/asset/mint_determinism_test.cpp`): a sample project minted twice, with 1 and 8 workers, and after touching the source files' modification times, yields byte-identical blobs, manifest and pak; the tool version is part of the manifest so a version change re-mints; a path with a non-NFC name normalizes.
- [x] **Exit codes and messages:** errors name the file and line; a mint error in one file does not stop the others (all errors reported, exit code non-zero); `--quiet` and `--verbose`.
- [x] **Tool tests** through ctest scripts (`asset_mint_mint_sample`, `asset_mint_verify_sample`, `asset_mint_incremental`, `asset_mint_bad_source_exit_code`).
- [x] **Runs (CLAUDE.md "Tests run by phase"):** `scripts/test-phase.sh --affected` plain; then the asan and tsan flavors when the day touched concurrency, lifetime or memory code; quote each run's final `ran X of Y tests (phases ...)` line in this file and never say "all tests pass" for a reduced run. `ctest -L docs` when a public header or a guide changed. Build clean (warnings are errors) with Clang and GCC, unity on and off. New code uses the engine's wrappers and types, never `std` (`std_usage_check`); file access only through `io::` (`file_access_check`); settings only through `settings::Registry` (`config_access_check`).
- [x] **Three machines (CLAUDE.md "Three machines"):** shared code is portable and checked on the Windows PC and the Mac no later than Day 340; until then the day is "open until the other machines run it" in `KNOWN-ISSUES.md`.
- [x] **Documentation (CLAUDE.md "Public API is documented before a day is done"):** public headers carry `///` comments with the contract labels (`docs/DOC-CONVENTIONS.md`); `docgen lint` stays at zero; `cmake --build build --target docs` output committed; new modules are added to `docs/reference/modules.txt`; the guide page `docs/guide/assets.md` is updated and its tagged samples compile and run.
- [x] **Module rules (CLAUDE.md "Module dependencies follow ARCHITECTURE.md"):** a new module or edge updates `ARCHITECTURE.md`, `tools/module_deps_check/modules.txt` and the CMake targets (with `_asan`/`_tsan` flavors) in the same commit; no upward edge, no cycle; every new test file has its line in `tests/phases.txt` (phase 22).
- [x] **Day review (CLAUDE.md, required):** `/code-review high` over the day's diff after the scoped tests; verify, fix (with a regression test that fails without the fix) or decline each finding with a reason; record the count and outcome under "Post-implementation code review" below and in `STATUS.md`.
- [x] `STATUS.md` and `KNOWN-ISSUES.md` updated in the same commit; commit and push.

**Done:** a sample project mints, packs, verifies, lists and checks with one tool, a second run does nothing, and the output is byte-identical across worker counts.

## Outcome

`tools/asset_mint/project.{h,cpp}` (the project side: `ParseProjectConfig`, `Project` with `Load`, `Adopt`, `Mint`, `Pack`, `Verify`, `Check`, `List`, `PackDirectory`), the commands `adopt`, `mint`, `pack`, `verify`, `list [--skeletons]` and `check` in `tools/asset_mint/main.cpp` (`--force`, `--workers=N`, `--quiet`, `--verbose`; the one-file commands stay and `pack DIRECTORY OUTPUT.pak` now calls `PackDirectory`), `tools/asset_mint/check_mint.cmake` (the four script tests `asset_mint_mint`, `asset_mint_verify`, `asset_mint_incremental` and `asset_mint_bad_source`, label `asset`), the sample project `tests/asset/mint_sample` and `tests/asset/mint_determinism_test.cpp` (17 cases: a second mint does nothing; 1 and 8 workers, touched sources and a forced mint give byte-identical blobs, manifest, table and pak; a changed image, a changed skeleton, a manifest of another tool version; no id, two sources with one id, a source deleted by hand, an error in one file, a cycle; verify, a moved source, false references, unresolved references, capital-letter ids, a decomposed file name; the project file). Design: the sources are found under `source_root`, their ids read, their references found by reading each source for `@HEX16`, ids after `skeleton`, words that start with `/` and a material's `texture` path; a source's wave is one more than its deepest reference (a cycle is named); a wave's sources are minted in parallel (textures one at a time on the main thread because a block-compressed one fans out over the workers); the input hash covers the source text, a texture's images, the id and hash of every blob the source references (directly or through others), the target, the type version and the tool version; `assets.manifest` keeps the hashes and the references, `resources.table` is written by every mint. The split of the day (the user's decision, 2026-11-14) put the reference-safe edits, `remint`, `unmint`, `pack --target`, version enforcement and the level column-image question in Day 334.

Deviations, also in `KNOWN-ISSUES.md`: a rule of the project file has the one option `skip` (a texture's format and quality are lines of its own source; the plan's per-extension options need defaults in the minters); `verify` does not look for a base pak (the project file names none); a source whose referenced blob changed is minted again (its inputs changed) and its file is written only if the bytes differ, where the plan says it is not rebuilt (the minters read the referenced blobs' metadata, so the tool cannot tell which changes matter); the first cut of `adopt` writes only the `id` line (a mesh's `skeleton` id is written by hand).

Runs: see `STATUS.md`.

## Post-implementation code review

`/code-review high` over the day's tree: 10 findings, 9 fixed and 1 declined in part. Fixed (with regression tests where practical): `ProjectMint` had external linkage and held a type of the anonymous namespace (GCC's `-Wsubobject-linkage` in unity builds; moved in); a moved or renamed source left its old blob behind and `verify` did not notice (a successful mint deletes every blob no source maps to; `verify` now also reports a blob with no table entry and two blobs with one id; tested); every word of a source was matched against the project's paths, so a level entity named like another level made a cycle (only `@HEX16`, ids after `skeleton`, words starting with `/` and a material's `texture` path count; tested); an include or texture that named nothing was reported late or not at all (`skeleton`, `include`, `animation` and `texture` lines that name no source fail the load with their line; tested); `list`, `verify` and `pack` went on after the project file failed to load (they need `IsLoaded`; tested through the script test); `(void)` on `table.Add` and `ReadNamesBlob` (reported now); ids in capital letters were not recognized (accepted); a backslash in a project path and a trailing slash in `exclude` (the first is refused, the second stripped; tested); all blobs stayed in memory and the manifest was searched linearly (a blob is let go when the last source that needs it has been minted; the manifest has an index; the closure of each source is computed once). Declined in part: the whole bytes of an unchanged blob are still read to check them against the manifest (the plan wants the file intact, not just present), but they are no longer kept. The bookkeeping finding (STATUS.md, KNOWN-ISSUES.md, this section) is this commit.
