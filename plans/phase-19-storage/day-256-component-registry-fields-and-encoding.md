# Phase 19 / Day 256 — Component Registry I: Identities, Fields & the Canonical Encoding

**Phase:** [Phase 19 — Storage](../phase-19-storage.md)
**Depends on:** Phase 17 (components, `ComponentOf<T>`); Phase 10 (`String`, `Array`); Phase 16 (wrappers).

Describe how each component type is stored, and write the byte encoding. Outside `ecs`, without touching its hot paths.

## Tasks

- [ ] **New module `engine/storage`** (the registry and codec; CMake target `storage` with flavors, `ARCHITECTURE.md` row, `modules.txt`, `docs/reference/modules.txt`): depends on `foundation`, `ecs` and `jobs`; the registry part has no `database` dependency.
- [ ] **`ByteWriter` and `ByteReader` live in `foundation` (`foundation/bytes/`, a new module row with its layer above `cstr` and `types`, in `modules.txt`), not in `storage`** (Day 250 plan check: Phase 20's `NetWriter`/`NetReader` need the same bounds-checked reader and writer and extend these with quantized floats instead of duplicating them): canonical little-endian encoding, fixed-width integers, `f32`/`f64` as their bit patterns (a NaN payload, `-0` and denormals survive), `bool` as one byte validated on read, lengths as bounded varints; the reader is bounds-checked and returns a `Status` on truncation or an over-limit length, never reading past the span.
- [ ] **`storage::ComponentRegistry`:** `Register<T>(ComponentDesc)` with a stable numeric id written in code, a unique name, a version and a field list; registration errors (duplicate id, duplicate name, an id or name changed against a recorded manifest) are `Status` values; lookup by id, name and `ComponentOf<T>`.
- [ ] **Field descriptions** by pointer to member: `Field("x", &T::x)` for `u8`..`u64`, `i8`..`i64`, `f32`, `f64`, `bool`, `Vec2`/`Vec3`/`Vec4`, `Quat`, `Mat4`, enums (stored as their underlying integer, validated against a declared range), `Array<T, N>` of any stored type, `String` (bounded length, valid UTF-8 checked) and `EntityRef` (the type is declared here and resolved on Day 258); a struct with a field the registry cannot describe fails to compile (no silent skip).
- [ ] **Encode and decode of one component value** from and into the component's memory (`Encode(const void*, ByteWriter&)`, `Decode(ByteReader&, void*)`), with a `Derived` flag (never stored) and a `Skip` flag set explicitly.
- [ ] **Registered-or-flagged check:** `UnregisteredWithData(const ecs::World&)` lists component types present in a world that are neither registered nor marked `Derived`/`Skip`, so a new component cannot be forgotten silently; the engine's own components (`LocalTransform`, `Parent`, `SpatialMembership`, `SpatialBounds`, `SpatialLayer`, ...) are registered in `storage/builtin_components.cpp` and the derived ones flagged.
- [ ] **Tests** (`tests/storage/registry_test.cpp`, `encoding_test.cpp`): every field kind round trips bit-exact including NaN with payload, `-0`, denormals and extreme integers; golden byte strings for a fixed component set (a change to the encoding fails the test and must bump the format version); every registration error; truncated and over-long inputs return `Status` at every possible cut point; the unregistered-component list on a world with an extra component.
- [ ] **Guide** `docs/guide/storage.md` started: the registry and the encoding.
- [ ] **Runs (CLAUDE.md "Tests run by phase"):** `scripts/test-phase.sh --affected` plain; then the asan and tsan flavors when the day touched concurrency, lifetime or memory code (most days of this phase do); quote each run's final `ran X of Y tests (phases ...)` line in this file and never say "all tests pass" for a reduced run. `ctest -L docs` when a public header or a guide changed. Build clean (warnings are errors) with Clang and GCC, unity on and off. New code uses the engine's wrappers and types, never `std` (`std_usage_check`).
- [ ] **Two machines (CLAUDE.md "Windows is a supported platform"):** the code is portable; it is built and tested on the Windows PC no later than Day 265, and until then the day is listed as "open until the other machine runs it" in `KNOWN-ISSUES.md`.
- [ ] **Documentation (CLAUDE.md "Public API is documented before a day is done"):** public headers carry `///` comments with the contract labels (`docs/DOC-CONVENTIONS.md`); `docgen lint` stays at zero; `cmake --build build --target docs` output committed; new modules are added to `docs/reference/modules.txt`; the guide page named in the day is updated or created and its tagged samples compile and run.
- [ ] **Module rules (CLAUDE.md "Module dependencies follow ARCHITECTURE.md"):** a new module or edge updates `ARCHITECTURE.md`, `tools/module_deps_check/modules.txt` and the CMake targets (with `_asan`/`_tsan` flavors) in the same commit; no upward edge, no cycle; every new test file has its line in `tests/phases.txt` (phase 19).
