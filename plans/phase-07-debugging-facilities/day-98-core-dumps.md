# Phase 7 / Day 98 — Core Dumps

**Phase:** [Phase 7 — Debugging Facilities](../phase-07-debugging-facilities.md)
**Depends on:** Day 97 (the crash handling that the core dump complements).

Make core dumps happen reliably, and make it easy to open the latest one in `gdb` with the right symbols.

## Tasks

- [x] The interface is the platform-neutral idea of "post-mortem artifacts": `EnablePostMortemDumps(options) -> Result` with the result `Enabled`, `Limited(reason)` or `Unsupported` (iOS, consoles with their own system), documented per platform in the header: Linux cores, Windows WER `LocalDumps`, macOS cores and crash reports, Android tombstones. Only the Linux implementation exists now.
- [x] `EnableCoreDumps(options)` in `engine/foundation/os/linux/debug/core_dump.cpp` (the Linux implementation behind that interface): raise the soft `RLIMIT_CORE` to the hard limit (or a given size) with `setrlimit`, return what the limit was and is, and report when the hard limit is zero (nothing the process can do; the report says how to raise it). Call it from `InstallCrashHandler` (Day 95) when the option is set. On Linux also `prctl(PR_SET_DUMPABLE, 1)` (a setuid or capability-dropping process may have cleared it).
- [x] Report the destination so a developer knows where the core went: read `/proc/sys/kernel/core_pattern` at install time and put it in the crash context; if it starts with `|` (here: `systemd-coredump`) say "use `coredumpctl`"; otherwise print the expanded file name pattern. A test for each of the two forms using a function that takes the pattern text.
- [x] The scripts are Linux shell scripts, named and documented as such. (The PowerShell equivalent for WER dumps is a Phase 12 item: recorded on Day 101, which edits the Phase 12 file.)
- [x] Script `scripts/find-core.sh`: finds the newest core for a given executable (via `coredumpctl list`/`coredumpctl dump -o` when available, otherwise the file the pattern names in the current directory), checks that the core's recorded build id (the `NT_GNU_BUILD_ID` note in the executable inside the core, read with `readelf -n`/`eu-unstrip`) matches the binary you pass, and prints the `gdb` command. `scripts/open-core.sh` runs `gdb -ex bt -ex 'thread apply all bt' <exe> <core>` batch mode and prints the result. Both are shell scripts, tested by a script test in the style of `tests/test_phase_script` with a fixture core generated by a crashing child (skipped with a clear message when core dumps are impossible on the machine, recorded in `KNOWN-ISSUES.md` if so).
- [x] The developer guide section "Core dumps on Linux": `systemd-coredump` and `coredumpctl`, the `core_pattern` alternatives, `ulimit -c`, `/proc/sys/kernel/core_pattern` changes needing root (shown, never run by the engine), disk-space warnings, and the privacy note (a core contains process memory).
- [x] A test (death-test helper, child with core enabled and a core size cap) that crashes, then locates the core with the script and runs `gdb` in batch mode asking for the faulting function's name; skipped (not failed) when `gdb` is missing or cores are disabled, with the reason printed.
- [x] **Documentation:** `///` comments; the guide page extended; `docs/guide/building-and-testing.md` mentions the scripts; reference regenerated and committed; `docgen lint` at zero; `ctest -L docs` passes.
- [x] Run the day's scoped tests (`--affected`, asan and tsan flavors) and quote the `ran X of Y tests` lines.
- [x] **End-of-day review (CLAUDE.md):** `/code-review high` on the day's diff (code and scripts); record it here and in `STATUS.md`.
- [x] Update `STATUS.md`; commit.

**Done:** `EnableCoreDumps` raises the limit and tells the developer where the core goes; the two scripts find the newest core for a binary, verify its build id, and open it in `gdb`; the test proves it end to end on a machine with `gdb`, or says why it skipped; the guide documents the setup for `systemd-coredump` and plain cores.

## Post-implementation code review

`/code-review high` found 10 issues.

1. The "raises the limit" test could not reach that path (the default child has its hard limit set to 0). **Fixed**: the test uses a child with core dumps left on, and a second test covers the limited case.
2. The report described where a core goes even when none would be written. **Fixed**: when limited, the report says `none will be written: <why>`.
3. `PR_SET_DUMPABLE` ran unconditionally. **Partly fixed**: only after the limit was raised. The call itself stays (the caller asked for a core), and the header says so.
4. `find-core.sh` left a full core in a shared directory without `--output`, even on the mismatch path. **Fixed**: a private temporary directory removed on every path except success.
5. The test copied the core to a predictable `/tmp` name and leaked it when a check failed. **Fixed**: a private directory removed by a destructor.
6. The Linux test header was listed as public API. **Fixed**: excluded in `modules.txt` (also the two other `*_platform.h` headers), and documented anyway.
7. `SetCoreDumpDescription` wrote the context without the lock. **Fixed**.
8. Core settings were changed before the install could fail. **Fixed**: done last; a failed install leaves them alone. The non-Linux link problem (the neutral file calls Linux-only functions) is on the Day 101 checklist, with `RegisterThreadForCrashHandling`.
9. A file pattern picked the newest core of any program. **Fixed**: `%e` is replaced by the program name and `%p` by the pid.
10. The test skipped whenever no core was found. **Fixed**: it skips only when the machine cannot be expected to keep one (hard limit 0, a collector other than systemd-coredump, no gdb); otherwise a missing core fails.

Found while running the day's tests rather than by the review: the log ring let a torn line through when a writer was descheduled,
lapped by 256 newer lines, and then resumed (the TSan ring test caught it once in about a hundred loaded runs). Fixed by letting a
writer claim a slot only when it is idle and holds nothing newer (a busy slot's line stays out of the ring, and is still logged).
The ring test's reader now overlaps the writers by construction. 600 loaded repeats pass.
