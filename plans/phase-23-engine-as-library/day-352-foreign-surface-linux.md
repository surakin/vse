# Phase 23 / Day 352 — Rendering into a Host Window: the Foreign Surface on Linux

**Phase:** [Phase 23 — The Engine as a Loadable Library](../phase-23-engine-as-library.md)
**Depends on:** Days 349 and Phases 4, 8, 13.

The RHI renders into a native window the host owns (X11 and Wayland), recovers from loss, and can read the frame back.

## Tasks

- [x] RHI: a `SurfaceDescriptor` (a versioned, size-prefixed struct: `kind` (X11 window with its display, Wayland `wl_surface` with its `wl_display`, later `HWND`, `NSView`/`CAMetalLayer`), the handles, the size and the scale) replaces `os::Window` in swapchain creation and in `RecreateSurface`; the engine's own windows build a descriptor from `os::Window` (no change in behavior); Vulkan on X11 (`VK_KHR_xlib_surface` or xcb) and Wayland (`VK_KHR_wayland_surface`, **using the host's connection**, no second connection), the platform-neutral and RHI boundary gates extended to the foreign-handle types, `BACKEND.md` checklists updated, Metal and DX12 parity noted in `KNOWN-ISSUES.md` until Days 354-355.
- [x] The host owns size, visibility and DPI: `engine_surface_resized(engine*, surface, width, height, scale)`; the engine reports out-of-date and lost surfaces through a status and recovers through the Phase 8 reset path; the engine never creates, resizes or destroys the host's window.
- [x] CPU readback: `engine_surface_read_pixels(...)` (also the screenshot and test path), asynchronous with a ticket, an RGBA8 buffer owned by the caller.

## Outcome

**Done (2026-11-15, Linux).** 9 new table functions (`surface_create`, `surface_destroy`, `surface_resized`, `surface_rebind`, `surface_set_background`, `surface_state`, `surface_read_pixels`, `pixels_finish`, `pixels_destroy`), three structs (`engine_surface_info`, `engine_surface_state`, `engine_pixels`), the caps `ENGINE_CAP_SURFACE_X11`, `_SURFACE_WAYLAND` and `_READBACK`, handle kinds 6 (surface) and 7 (read-back ticket). `engine_c/surface.cpp` (`SurfaceHost`, owned by the runtime) gives every surface a Vulkan device on the host's window; every `frame` renders into each surface before it steps the worlds.

- **Deviation from the task text (RHI):** no `SurfaceDescriptor` replaces `os::Window` in the RHI. A new `os::ForeignWindow` (`engine/platform/foreign_window.h`) is an `os::Window` over the host's native handles (size and scale set by `SetSize`, handles replaced by `Rebind`), so `CreateDevice`, `CreateSwapchain` and `RecreateSurface` are unchanged and the Vulkan surface code (X11 `Display`/`Window`, Wayland on the host's `wl_display`/`wl_surface`, no second connection) is the engine's own. The descriptor can still come when HWND/NSView arrive (Days 354-355); nothing here blocks it.
- **Deviation (scene):** the surface renders a clear to a background color, not the demo's cube: the renderer is not behind the C API yet, so there is nothing to draw a cube with. The golden image is the clear color (red exactly; 0.5 reads 188 in sRGB). Filed in `KNOWN-ISSUES.md`.
- Resize/visibility: the host reports size and scale with `surface_resized`; size 0 pauses drawing. On X11 the swapchain takes the server's extent when it is rebuilt, so the reported size must be the real one (the test waits for the server to apply `XResizeWindow` as a toolkit does on `ConfigureNotify`). Loss: a destroyed X window reads as no drawable area (hidden), not `Lost`; `surface_rebind` rebuilds the swapchain on the same device (`RecreateSurface`, the Phase 8 path) for either case.
- Read-back: async ticket, filled by the next drawn frame before `Present` (Metal takes the image back at present), RGBA8 in a library-owned `engine_buffer`; at most 256 tickets and 64 surfaces.
- Tests: `host_surface.c` (`engine_c_surface`, plain and asan; the tsan flavor is a skipped stub: ThreadSanitizer cannot run the GPU driver's threads, as for the RHI tests) and `surface_wayland_test.cpp` (plain, in `engine_c_tests`): arguments, golden frame, sRGB color, ticket lifecycle, resize, hidden, unmapped, destroyed window and rebind, cancel on destroy, `destroy` refused with a surface out. The asan run has leak checking off (the driver's allocations have no module to suppress); memory errors stay on.
- Pages touched: `docs/guide/engine-library.md` (Day 352 section), `ARCHITECTURE.md` (engine_c depends on platform, rhi, rhi_backends); `docs/reference/` regenerated unchanged, `ctest -L docs` passes. ABI snapshot regenerated (unreleased). `tests/phases.txt` (3 lines), `std_usage_check` allow list (host_surface.c).
- Runs: plain `ran 3359 of 8903 tests (phases: all; flavors: plain; display: included; crash tests: excluded) in 100 s`, asan `ran 2683 of 8903 tests (phases: all; flavors: asan; display: included; crash tests: excluded) in 156 s`, tsan `ran 2349 of 8903 tests (phases: all; flavors: tsan; display: included; crash tests: excluded) in 198 s`, all passed (reduced runs, not the full suite). Clang and GCC, unity and non-unity trees and `build-shared` build clean; `ctest -L docs` passes.


## Post-implementation code review

`/code-review high` over the day's diff: 5 findings. **Fixed (2):** the guide claimed a destroyed window reads as `lost` and fails pending read-backs (on X11 it reads as hidden and they stay pending; the text now says which is which); `SurfaceObject::generation` duplicated the slot's generation (removed). **Declined (3):** the `Lost` branch has no test (a destroyed X window is `Minimized`; forcing a `Lost` swapchain needs a fault hook the RHI does not have: filed in `KNOWN-ISSUES.md`); `pixels_finish` copies the image once more through `MakeTextBuffer` (a second copy of at most one frame, taken on the screenshot path only); a failed `surface_rebind` leaves the `ForeignWindow` on the new handles while the surface stays lost (nothing draws until a successful rebind).
