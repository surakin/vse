## Outcome

Done (2026-11-15, Linux). The table gains 19 functions (ABI 1.0, still `status unreleased`, so no minor bump; `abi/engine_api.snapshot` regenerated): `frame`; `world_create/destroy`; `entity_create/destroy`; `component_set/get/remove/has` (kinds are `uint32_t`: transform, read-only world transform, mesh reference; name through `entity_name_set/get`); `query` by component mask; `counter_create/destroy/value/wait`, `jobs_submit`; `crash_handler_install/uninstall` (dump directory from the new setting `crash.dump_directory`; destroy uninstalls). New files `engine/engine_c/runtime.{h,cpp}` and `engine_internal.h`; `engine_c` now links `ecs`. Design: one lock for all world calls and the frame; handles are kind/generation/slot with a process-wide generation (a handle of an earlier engine is stale in a later one); worlds and counters register with `engine_objects.h`, so `destroy` refuses while any exists; the engine's job system is a scheduler on a thread of its own (participant 0 sleeps between jobs), started by the first submit; a frame always runs at least one world, and a budgeted frame resumes at the first world it skipped; at most 2048 jobs in flight (the scheduler aborts on full queues). Tests: `host_runtime` (`engine_c_runtime*`, plain, asan, tsan): a thousand entities, queries, frames and world matrices, budget, 500 jobs, jobs that use the world functions, wait timeout, destroy refusals, every bad call, 20000 submits (limit), two host threads beside a frame thread, crash handler restored, a crash in a job leaving a dump (plain and asan; under tsan Breakpad's dump helper hangs, as the Day 345 test notes). The guide has the section "The frame loop, worlds, jobs and the crash handler". Also: the four tsan SEGFAULTs of Days 320 and 322 are fixed (GPU tests left out of TSan on Linux like tests/rhi: NVIDIA driver threads), the BC GPU test compares mean squared error instead of each channel (the GeForce differs by up to 6 steps, the Radeon by 2), `host_reload` waits for the thread count to settle (it failed intermittently while the machine was loaded; the longest wait seen afterwards was 0 ms, so the cause is not proven), `fake_engine.c` uses designated initializers. Runs: plain `ran 3353 of 8889 tests (phases: all; flavors: plain; display: included; crash tests: excluded)`, asan `ran 2679 of 8889 tests (phases: all; flavors: asan; display: included; crash tests: excluded)`, tsan `ran 2345 of 8889 tests (phases: all; flavors: tsan; display: included; crash tests: excluded)`, no failing test in any; shared tree `engine_*`/`abi_*` 61 of 61 (plain, asan, tsan); docs 7 of 7; Clang unity and non-unity and GCC build clean.

## Post-implementation code review

Done (2026-11-15, Linux), `/code-review high`: 5 findings, all fixed. (1) `jobs_submit` could abort the process when the scheduler's queues were full: capped at 2048 in flight with `LIMIT_EXCEEDED` (the regression test aborts in the scheduler without the cap). (2) `crash_handler_install` viewed the text of a temporary (found by asan, stack-use-after-scope): the value is copied first. (3) An out-of-range `kind` was undefined behavior in an enum parameter (found by ubsan): the parameters are `uint32_t`. (4) A transform set could fail half done: the component it added is taken back. (5) The `frame` comment lacked the 3600-second bound. Found by running, not by the review: the budget could skip every world after a preemption (an intermittent failure of `engine_c_runtime_asan`, 1 in 40): the first world of a frame now always runs, 300 runs in parallel pass; the tsan crash child hangs in Breakpad's helper (skipped under tsan); `std_usage_check` wanted `u32`/`u64` spellings. Declined: none.
