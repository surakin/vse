## Outcome

- **Singleton list worked through.** Moved out of headers into one definition in the library: the log channel registry head (`log.cpp`), `jobs::Counter::PathStats()` (`scheduler.cpp`), `ecs::detail::SystemFn::Fallbacks()` (`schedule.cpp`). Allowed with a reason in `tools/shared_state_check/allowlist.txt`: `HeapAllocator::Default()` (no data), the `ENGINE_ENSURE` site record, `ecs::World`'s component tag (C++ component access stays inside the library), `ENGINE_DEATH_TEST_FN` (test programs only). The settings registry is an object, not a global, so there is nothing to share; the dup test covers the log, allocator, await counters and frame pool.
- **Gate `shared_state_check`** (6 ctest cases: real tree, planted violations by line, planted count, clean tree, stale entry twice). Rules: a non-const `static` object (function scope or `static inline` member), any `thread_local`, a non-const `inline` variable, in a header under `engine/`.
- **Thread-locals:** `FramePool::ThreadCache` and the Linux crash alternate stack have no destructor now (`static_assert`ed); `FramePool::ReleaseThreadCache()` and `debug::UnregisterThreadForCrashHandling()` (through the new `NotifyThreadEnd` hook) are called by job workers, the I/O thread and, for the creating thread, the scheduler's pool destructor. `tests/jobs/frame_pool_test.cpp` replaced its "free after the cache was destroyed" case with a release test. Windows and macOS got an empty `ReleaseThreadAlternateStack` (unbuilt here).
- **Boundary tests** (`tests/engine_library`, `-DENGINE_BUILD_SHARED=ON`, Linux; skipped stubs otherwise): `engine_dup_singletons` + planted pair, `engine_unload_after_jobs` (plain, asan, tsan), `engine_owner_release` / `engine_owner_wrong_free_planted` (plain, asan), `engine_crash_across_boundary`. They read the library through `engine_shared_state_probe` (ABI 1.1; `engine/engine_c/engine_state_probe.h`); Day 346 removes it (noted in its plan). The unload test fails with a destructor put back on the frame cache (checked). Ownership is checked by the engine's own live-block count: ASan did not report the host's `free` of an engine block, because the library binds its own `operator new`.
- **Vulkan slot holder converted in a follow-up commit** (the user asked why it was left): the per-thread command-pool slot is plain data released through `NotifyThreadEnd`, which is now a list of functions (`AddThreadEndHook`, 8 entries); the frame-pool cache registers itself the same way, so a thread that calls `NotifyThreadEnd` gives back everything. The tests that record on their own threads (`vulkan_commands_test`) call it; the existing "twice as many short-lived threads as slots" case fails without it.
- Docs: guide section "One of everything (Day 345)"; `docs/reference` regenerated; `ctest -L docs` 7 of 7.
- **Runs (Linux):** plain `--affected` `ran 3341 of 8864 tests (phases: all; flavors: plain; display: included; crash tests: excluded)` (two locked-session X11 failures; the two gate failures it showed were the new C hosts missing from the allow lists, fixed, gates re-run 48 of 48); asan `ran 2670 of 8864 tests (phases: all; flavors: asan; display: included; crash tests: excluded)` all passed; tsan `ran 2341 of 8864 tests (phases: all; flavors: tsan; display: included; crash tests: excluded)` with the four known Vulkan SEGFAULTs. Shared tree: all `engine_*` and `abi_check*` tests pass (plain, asan, tsan). Clang unity, Clang non-unity and GCC non-unity build clean (no warnings).
