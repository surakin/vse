# Phase 23 / Day 348 — Complete Shutdown, Unload & Reload

**Phase:** [Phase 23 — The Engine as a Loadable Library](../phase-23-engine-as-library.md)
**Depends on:** Days 345, 347.

The engine can be shut down completely and the library unloaded and loaded again in one process.

## Tasks

- [x] Audit shutdown: all threads joined, all registrations removed (`DeviceResources`, settings listeners, log sinks, signal handlers, atexit-style hooks), no static destructor that touches another static; a list in the guide of what `engine_destroy` guarantees.
- [x] `engine_destroy` with outstanding objects (a world with entities, a loaded resource, an in-flight async load or import): documented behavior (refuse with `ENGINE_STATUS_BUSY` listing what, or an explicit `force` that cancels and waits), each tested.
- [x] The reload cycle test: a C host loads, runs jobs, a headless frame, destroys, unloads, and repeats 50 times in one process, with the library built plain, asan (leaks reported at exit only for what is really leaked) and tsan; memory use returns to the baseline (a check on the process's resident size and on the allocator's statistics).
- [x] `dlclose` hazards: the library marked `-Wl,-z,nodelete` is **not** used; a test proves the library really unloads (its symbols are gone from `/proc/self/maps`); the documented limit: a host must not unload while the engine is alive.
- [x] Unload with other threads still inside (a host thread blocked in a callback): refused or documented, tested.
- [x] **Runs (CLAUDE.md "Tests run by phase"):** `scripts/test-phase.sh --affected` plain; then the asan and tsan flavors when the day touched concurrency, lifetime or memory code (this phase does, nearly every day); quote each run's final `ran X of Y tests (phases ...)` line in this file and never say "all tests pass" for a reduced run. `ctest -L docs` when a public header or a guide changed. Build clean (warnings are errors) with both compilers, unity on and off, **and with `-DENGINE_BUILD_SHARED=ON`** from Day 343 on.
- [x] **Three machines (CLAUDE.md):** this day is built and tested on the Linux machine; shared code (CMake, the gates, the C header, the loader) is checked on the other two no later than Day 357; until then the day is "open until the other machines run it" in `KNOWN-ISSUES.md`.
- [x] **Documentation (CLAUDE.md "Public API is documented before a day is done"):** headers carry `///` comments with the contract labels (`engine_c.h` has its own comment convention, set on Day 346, checked by `docgen` or its own gate); `docgen lint` at zero; `cmake --build build --target docs` output committed; the guide `docs/guide/engine-library.md` is updated.
- [x] **Module rules (CLAUDE.md):** a new module, target or edge updates `ARCHITECTURE.md`, `tools/module_deps_check/modules.txt` and `BUILD.md` (a new prerequisite) in the same commit; every new test file has its line in `tests/phases.txt` (phase 23).
- [x] **Day review (CLAUDE.md, required):** `/code-review high` over the day's diff after the scoped tests; verify, fix (with a regression test that fails without the fix) or decline each finding with a reason; record the count and outcome under "Post-implementation code review" below and in `STATUS.md`.
- [x] `STATUS.md` and `KNOWN-ISSUES.md` updated in the same commit; commit and push.

**Done:** 50 load-run-unload cycles in one process pass under asan and tsan, the library leaves the address space, and no resource of the engine remains.

## Outcome

Done (2026-11-15, Linux). `engine_destroy` now: refuses with `ENGINE_ERROR_IN_USE` while the engine counts an outstanding object (`engine_objects.h`: `EngineObjectAcquire/Release`, for the worlds, resources and imports of Days 349-351; no `force`, decided and written in the guide), restores the process's log channels (this closes Day 346's recorded limit), removes the log observer and waits for a running callback. The shared library has a destructor that frees the job system's immortal global frame pool (`FramePool::DestroyGlobalAtUnload`): the new reload test found it keeping about 2 MiB per load/unload cycle (15 MB to 107 MB over 50 cycles before the fix, 4.7 MB flat after). Tests: `engine_reload_cycles` (50 cycles in one process; after each the library is gone from `/proc/self/maps` and from the linker, the thread count is stable; resident size flat; plain, asan, tsan) and `engine_destroy_waits_for_callback` (a host thread blocked in the log callback holds destroy; the handle is stale and `create` refused meanwhile; plain, asan, tsan); `host_c` checks the outstanding-object refusal and, failing without the restore (checked by mutation), the log restore. The guide has the list of what destroy guarantees, the unload rules and the audit. Not done as written: `ENGINE_STATUS_BUSY` is `ENGINE_ERROR_IN_USE`. Runs: plain `ran 3352 of 8890 tests (phases: all; flavors: plain; display: included; crash tests: excluded)`, asan `ran 2678 of 8890`, tsan `ran 2348 of 8890`; shared tree `engine_*` 28 of 28; docs 7 of 7; Clang non-unity and GCC build clean. Failing only: the Windows PC's BC GPU test (known) and the four known tsan Vulkan SEGFAULTs.
