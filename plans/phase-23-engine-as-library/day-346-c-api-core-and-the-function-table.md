# Phase 23 / Day 346 — The C API Core: Version, Function Table, Create & Destroy

**Phase:** [Phase 23 — The Engine as a Loadable Library](../phase-23-engine-as-library.md)
**Depends on:** Days 344, 345.

`engine_c.h` v1 core: negotiation, the table, the engine object, settings, logging, errors.

## Tasks

- [x] Write `engine/engine_c/engine_c.h` (valid C11): `ENGINE_ABI_VERSION`, `engine_status` codes mapped from `asset::ErrorCode` and the other `Status` types (one table, tested for completeness), `engine_string` (pointer and length), `engine_buffer` with explicit ownership and a release function, opaque handles with generations (`engine_handle`), `size`-prefixed structs (`struct_size` first) for every struct that can grow, callbacks with a user pointer; the convention comment at its top.
- [x] **Remove the Day 343/345 probes** (`engine_shared_probe`, `engine_shared_state_probe`, `engine/engine_c/engine_state_probe.h`) and move the `tests/engine_library` hosts to the table: `abi_check` counts a removed symbol as a major-version change, so either bump to 2.0 in the same commit (nothing was released) or reset the list and the version header to 1.0 with the C header, and say which in the day file.
- [x] The one exported entry point `engine_get_api(u32 wanted_major, u32 wanted_minor, usize table_size_wanted, const engine_api** out)` returning a table of function pointers (the table's own size says which functions exist); the old versions' tables stay valid by construction.
- [x] `engine_create(const engine_create_info*, engine** out)` / `engine_destroy`: settings from a host-provided list of `key=value` entries and the command line the host passes (through the settings system, never `getenv` in the C API), a log callback (level, channel, message) with the thread rules documented, an allocator hook is **not** offered (decision on Day 342), `engine_last_error`.
- [x] `engine/engine_c/` implementation in C++ (module `engine_c`, layer above everything it wraps, exported with `ENGINE_API` only here), no exception or C++ type crossing; every function checks its handle and its `struct_size`; a handle used after destroy fails cleanly.
- [x] Tests: `tests/engine_library/host_c.c` compiled by the C compiler, linked statically against the C API first (the dynamic loading is Day 347): create with settings, run, destroy; error paths (null, wrong size, stale handle, a too-new version) each return the documented status.
- [x] Docs: `docs/guide/engine-library.md` (the first sections: the C API's conventions, versioning rules, ownership).
- [x] **Runs (CLAUDE.md "Tests run by phase"):** `scripts/test-phase.sh --affected` plain; then the asan and tsan flavors when the day touched concurrency, lifetime or memory code (this phase does, nearly every day); quote each run's final `ran X of Y tests (phases ...)` line in this file and never say "all tests pass" for a reduced run. `ctest -L docs` when a public header or a guide changed. Build clean (warnings are errors) with both compilers, unity on and off, **and with `-DENGINE_BUILD_SHARED=ON`** from Day 343 on.
- [x] **Three machines (CLAUDE.md):** this day is built and tested on the Linux machine; shared code (CMake, the gates, the C header, the loader) is checked on the other two no later than Day 357; until then the day is "open until the other machines run it" in `KNOWN-ISSUES.md`.

## Outcome

Done (2026-11-15, Linux). `engine_c.h` (valid C11, convention comment at the top): `engine_status` (21 codes), `engine_string`, `engine_buffer` with its own release, generation `engine_handle`, `struct_size` structs, `engine_log_fn`, the `engine_api` table (`status_name`, `create`, `destroy`, `get_info`, `setting_set`, `setting_get`, `last_error`, `get_extension`, `thread_detach`) and the one export `engine_get_api`. `engine_create` builds its settings layers by hand (host entries, a writable layer, the command line): no environment, user file or policy. The log callback uses the new `SetLogObserver` (`log/log.h`, test added). One engine per process. Status mapping (`status_map.h`): `asset::ErrorCode` and `settings::SetError` by `switch` without default, tested.

**ABI decision:** nothing was released, so the list and `engine_abi_version.h` were reset to 1.0 and the list carries `status unreleased` (a new `abi_check` directive that skips the version-bump rule, with a fixture case); Day 357 removes the line at the first release. The probe exports are gone; the Day 343/345 hosts reach the same state through the extension `engine.test_state` (built when `ENGINE_C_TEST_EXTENSION` is ON, the default for now). The C header is now checked force-included, as a host includes it. `engine_c` is a static library in all flavors (always built); the shared library compiles the C API sources itself.

Tests: `host_c` (plain, asan, tsan; every bad call returns its documented status) and `engine_c_tests` (status map). Guide: `docs/guide/engine-library.md` ("The C API"). Runs: plain `ran 3347 of 8878 tests (phases: all; flavors: plain; display: included; crash tests: excluded)`, asan `ran 2674 of 8878 tests (phases: all; flavors: asan; ...)`, tsan `ran 2345 of 8878 tests (phases: all; flavors: tsan; ...)` (four SEGFAULTs: the known tsan Vulkan ones); shared tree `engine_*`, `abi_check*`, `shared_state_check` 54 of 54; `ctest -L docs` 7 of 7; Clang unity and non-unity and GCC non-unity build clean.
