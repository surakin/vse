## Outcome

**Done (2026-11-15, Linux).** 7 new table functions (`import_gltf`, `import_gltf_async`, `import_poll`, `import_wait`, `import_finish`, `import_cancel`, `import_destroy`), four structs (`engine_import_options`, `engine_import_result`, `engine_import_info`, `engine_import_file`), `engine_info.caps` with `ENGINE_CAP_IMPORT_GLTF`, and the build option `ENGINE_LIBRARY_WITH_IMPORTER`.

- **Only `engine_c/import.cpp` includes the importer** (`ImportHost`, owned by the resource host, adds results to its memory backend with `ImportIntoBackend`: atomic). `asset_boundary_check` lists that file and `engine/engine_c/CMakeLists.txt` with their reasons; any other file of the library that includes the importer still fails the gate. The `assets.import.*` settings are registered at create and read into `ResourceConfig::import_limits`; each import may override every limit.
- **Deviation from the task text:** the option defaults to ON everywhere (not "OFF otherwise"): the static `engine_c` that the C-host tests link needs the importer. OFF leaves `asset_import` and the decoders out of the shared library (2.5 MB smaller) and every import call answers `UNSUPPORTED`; `engine_c_noimport` (the same sources compiled without it) is what `host_import_off` links in a default build.
- Async: tickets are a new handle kind (5), at most 256 at once (each is a job of the scheduler, whose queues are bounded), each an outstanding object of the engine; `import_finish` takes the outcome once and adds the resources. The host's `read_file` callback runs on a worker thread in the async case.
- Not done, by design: re-importing over resources that are still in the backend is `ALREADY_EXISTS` (the host removes the old ones and imports with the manifest: ids are kept); no in-place re-import.
- Tests: `tests/engine_library/host_import.c` (`engine_c_import`: plain, asan, tsan; `engine_c_import_shared`: the same against the shared library through `dlopen`, three flavors) and `host_import_off.c` (`engine_c_import_off`). 450 hostile files (64 truncations of the text and of a GLB each, 150 changed bytes each, a GLB whose header lies, odd shapes, nine limits): 414 refused with a message, 36 still valid glTF, no crash. ThreadSanitizer cannot follow libpng's `longjmp` (known issue), so its flavor leaves the fixture's PNG uncorrupted.
- Pages touched: `docs/guide/engine-library.md` (the host path), `ARCHITECTURE.md`; `docs/reference/` regenerated unchanged (the C header is not docgen's). ABI snapshot regenerated (unreleased).
- Runs (final, after the review's fixes): plain `ran 3357 of 8899 tests (phases: all; flavors: plain; display: included; crash tests: excluded) in 95 s`, asan `ran 2682 of 8899 tests (phases: all; flavors: asan; ...) in 148 s`, tsan `ran 2348 of 8899 tests (phases: all; flavors: tsan; ...) in 199 s`; `ctest -L docs` 7 of 7; `build-nounity`, `build-gcc`, `build-shared` (shared library, `abi_check*` and the three `engine_c_import_shared*` pass) build clean and run `host_import`.

## Post-implementation code review

`/code-review high`: 6 findings. Fixed: (1) the id seed was read from the host's options before the struct size was checked (an 8-byte struct read out of bounds: regression test with an 8-byte allocation, confirmed to fail under ASan without the fix); (4) `scripts/format.sh` over the directory reformatted four unrelated files and the whole of `engine_c.h`: reverted, only the day's lines remain; (5) a nested struct in `runtime.h` made docgen report a diagnostic (`Every engine header extracts with zero diagnostics`): now `ImportLimitValues`; (6) outstanding async imports were unbounded: 256, with a test. No change: (3) the option default differs from the task text (recorded above). Declined: (2) `import_finish` takes the outcome before adding it, so an `ALREADY_EXISTS` on the add loses the import and a second call is `NOT_FOUND`; the host removes the old resources and imports again (documented in the guide; keeping the result would hold up to the memory of a whole import in a ticket the host may never finish).
