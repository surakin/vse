# Phase 27 / Day 449 — The LuaJIT Backend II: The Sandbox and the Budgets

**Phase:** [Phase 27 — Scripting](../phase-27-scripting.md)
**Depends on:** Day 448.

Scripts are untrusted input: a bad script cannot hang, exhaust memory or reach the operating system.

## Tasks

- [x] The whitelist environment the spike settled: each state starts with only the allowed libraries, `loadstring`/`load` limited to text chunks (no bytecode from scripts), `require` replaced by the engine's asset-id loader (Day 463), `print` going to the engine log; `io`, `os`, `package`, `debug`, `ffi` and the `jit` control functions are absent; the globals table of the engine is read-only to scripts (a metatable that refuses writes), each script's own environment writable.
- [x] **Amended by Day 444 (user decisions, 2026-11-18):** the count hook cannot stop JIT-compiled loops, so a world has a **budget mode**: *budgeted* (states run with the JIT off through `luaJIT_setmode`, count hook and wall-clock budget active; the default for mods and untrusted scripts) or *trusted* (JIT on, no instruction budget; the game's own scripts); setting `script.budget` per world. In budgeted mode `pcall`, `xpcall` and `coroutine.resume`/`wrap` are replaced by C versions that re-raise once the budget has tripped (a `while true do pcall(...) end` stops), and `string.find`, `match`, `gmatch` and `gsub` are replaced by engine versions with a matcher step count (a backtracking pattern stops; spike: 52 s uninterruptible otherwise). Tests: the hostile corpus of the spec's section 5 with each case's time bound; the swallowing and pattern cases are the regression tests. `sizemcode` set for trusted states.
- [x] The instruction budget by `lua_sethook` with a count and the wall-clock budget checked in the same hook; exceeding either aborts the call with `BudgetExceeded` (the script's state is discarded or reset by policy: a setting `script.on_budget`: `reset` default, `disable`, `log`); the spike's finding on the JIT (a hooked state does not JIT-compile the hooked traces) is recorded and the budget is a per-call opt-in with a default for scripts' ticks.
- [x] The memory cap through the allocator: an allocation past the cap fails, Lua raises its own memory error, the call returns `OutOfMemory`, and the state stays usable (the cap's accounting survives the failure).
- [x] Deep recursion, string-doubling, `__gc` and coroutine-that-never-yields cases of the hostile corpus all end with a status in bounded time and memory, in plain, asan and tsan.
- [x] `math.random` and `os.time`-like facilities: `math.random` is seeded by the engine per state from a setting (deterministic runs); no wall-clock or environment access reaches a script except through the time binding (Day 453).
- [x] The conformance suite's budget cases now run and pass for LuaJIT.
- [x] **Runs (CLAUDE.md "Tests run by phase"):** `scripts/test-phase.sh --affected` plain; then the asan and tsan flavors (this phase runs script code on several threads on nearly every day, so tsan is not optional); quote each run's final `ran X of Y tests (phases ...)` line in this file and never say "all tests pass" for a reduced run. `ctest -L docs` when a public header or a guide changed. ## Outcome (2026-11-18, Linux)

`engine/script/luajit/`: `LuaJitOptions {budgeted, random_seed}`; budgeted states run with the JIT off (`luaJIT_setmode`) and honor `Budget::instructions` and `nanoseconds` through a count hook (blocks of 1000; after a trip it fires at every instruction); the Lua `pcall`, `xpcall`, `coroutine.resume` and `wrap` are replaced (a bootstrap chunk) to raise a tripped budget again (without them the `swallow` cases hang: checked); a chunk's top level runs under a default budget in a budgeted state. `Budget::memory_bytes` lowers the cap for one call (both modes). Trusted states refuse instruction and time budgets with `Unsupported`; their machine code is bounded by LuaJIT's `maxmcode` default. Sandbox: the whitelist of the spec, library tables and registered native tables as read-only proxies, a separate writable script environment over a read-only engine environment (`getmetatable`/`setmetatable` blocked), `print` to `LogScript`, `math.random` seeded per state. `lua_patterns.cpp`: a port of Lua 5.1's matcher with a step limit and locale-free character classes (`find`, `match`, `gmatch`, `gsub`). Settings `script.budget` and `script.random_seed` with `ScriptBudgeted` and `ScriptRandomSeed`. The conformance suite gained the `memory_budget` case; for LuaJIT every case runs (nothing skipped). Tests (`luajit_backend_test.cpp`): loops, swallowed budget errors (pcall, xpcall, nested, coroutines), recursion, string doubling, an instruction count, the trusted mode (and the suite on it), backtracking patterns, 16 pattern behaviors against Lua 5.1 results, the whitelist and read-only checks, `print`, the seed. Guide: "Budgets and the sandbox". `KNOWN-ISSUES.md`: the Day 444 findings entry replaced by the limits that remain.

Runs: see `STATUS.md` for the final `ran X of Y` lines of this day's plain, asan and tsan runs; phase 27 alone in asan and tsan: `ran 51 of 10522 tests (phases: 27; ...)`. GCC, unity off, forced debug checks: 52 test cases pass. Not run: `-DENGINE_BUILD_SHARED=ON`; Windows and macOS (Days 473-474).

## Post-implementation code review

By hand (not the `/code-review high` skill). Found and fixed during the day: (1) an unbounded top-level run (`Load` of `while true do end` hung the conformance corpus) now runs under a default budget in a budgeted state; (2) a first draft of the sandbox relied only on the hook firing at every instruction after a trip; the wrappers for `pcall`, `xpcall` and `coroutine.resume` are still needed (without them the swallowing cases hang, checked by removing them); (3) the new pattern file used `unsigned char`, which `std_usage_check` refused (now `u8`). Declined: reimplementing `table.sort` and the rest of the C library with step counts (bounded by the memory cap and data size, listed in `KNOWN-ISSUES.md`); an `on_budget` policy in the backend (the world's, Day 452).
