# Phase 27 / Day 448 — The LuaJIT Backend I: States, Loading, Calls and Errors

**Phase:** [Phase 27 — Scripting](../phase-27-scripting.md)
**Depends on:** Days 445-447.

The first real backend: one `lua_State` per `script::State`, with the engine's allocator under it.

## Tasks

- [x] `engine/script/luajit/` implements `script::Backend`: `lua_newstate` with a custom allocator that counts bytes against the memory cap and draws from the engine's heap (never `malloc`); the state's registry holds the engine's bookkeeping, nothing global in C.
- [x] Loading: source text through `luaL_loadbuffer` (never `loadfile`), chunk names that are asset ids or test names, syntax errors as `SyntaxError` with line and message; calling a function by a dotted path with `Value` arguments and results through a marshalling layer that bounds depth and size both ways.
- [x] Errors: `lua_pcall` with a message handler that builds a stack trace (function, source name, line) as values; a Lua error never unwinds through engine frames (exceptions are off: `lua_cpcall` and the LuaJIT C API's longjmp are contained inside the backend's own frames, and the build checks it).
- [x] Native registration: `RegisterFunction` puts a C callback into a named table; the callback gets a marshalled argument view and returns `Value`s or an error; a native that fails returns a Lua error to the script, not an abort.
- [x] The conformance suite passes for the LuaJIT backend (the budget cases are Day 449's: skipped by their `Unsupported` result today, recorded).
- [x] State independence and thread handover: states created on one thread run on another after the handover; tsan clean in the 8-thread state test.
- [x] **Runs (CLAUDE.md "Tests run by phase"):** `scripts/test-phase.sh --affected` plain; then the asan and tsan flavors (this phase runs script code on several threads on nearly every day, so tsan is not optional); quote each run's final `ran X of Y tests (phases ...)` line in this file and never say "all tests pass" for a reduced run. `ctest -L docs` when a public header or a guide changed. Build clean (warnings are errors) with both compilers and unity on and off; `-DENGINE_BUILD_SHARED=ON` and `-DENGINE_LIBRARY_WITH_IMPORTER=OFF` still build.
- [x] **Three machines (CLAUDE.md):** built and tested on the machine the day is done on (Linux); shared code (CMake, the gates, tests, headers) is checked on the Windows PC and the Mac no later than Days 473-474, and `KNOWN-ISSUES.md` lists what waits for those runs.
- [x] **Documentation (CLAUDE.md "Public API is documented before a day is done"), when a public header changed:** `///` comments with the contract labels and `docgen lint` at zero; `cmake --build build --target docs` output committed; `docs/guide/scripting.md` updated or created; tagged samples compile and run.

## Outcome (2026-11-18, Linux)

`engine/script/luajit/luajit_backend.{h,cpp}`: `CreateLuaJitBackend`, `RegisterLuaJitBackend` (`luajit`). One `lua_State` per state on a counting allocator over the engine heap (cap default 256 MiB; cleanup gets 1 MiB of slack so a state at its cap can still drop a coroutine and collect). Every call runs as a coroutine (`wait`, `wait_frames`, `wait_event` are Lua C functions that yield); every operation that can raise runs under `lua_cpcall`/`lua_pcall`/`lua_resume`, engine-side problems are returned by value; natives get arguments through a trampoline whose frame holds no owner and report failure as a Lua error. Values: tagged tables (metatables kept in the registry) for vec2/3/4, quaternion, entity, bytes, empty array/map; sorted keys for maps; integers outside +-2^53 refused. Errors: message cut to 4 KiB, trace to 16 KiB, traceback from `luaL_traceback`. Libraries: base, math, string, table, bit; file and loader functions removed (the whole sandbox is Day 449). Budgets return `Unsupported` (Day 449); capabilities: coroutines only. The conformance kit gained `exact_int64`. The smoke test moved to `engine/script/luajit/` and the `tests/script/` entry left `tools/luajit_boundary_check/allowlist.txt` (now empty); `tests/script` no longer links `luajit` itself. Tests: `tests/script/luajit_backend_test.cpp` (the shared suite, registry, tagged kinds, key order, refused values, traces, natives and dotted paths, the memory cap, no file functions, handover to a thread, huge messages). Guide: `docs/guide/scripting.md` ("The LuaJIT backend"); reference regenerated, lint at zero for `script`.

Runs: plain `scripts/test-phase.sh --affected`: `ran 3912 of 10495 tests (phases: all; flavors: plain; display: included; crash tests: excluded) in 363 s`; asan `ran 3208 of 10495 tests (phases: all; flavors: asan; ...) in 52 s`; tsan `ran 2863 of 10495 tests (phases: all; flavors: tsan; ...) in 44 s`; phase 27 alone in asan and tsan: `ran 41 of 10492 tests (phases: 27; ...)`. Failures: the known ones only (`engine_c_surface`, the Job-destroyed test in all three flavors, the audio voice-cost timing test in plain). GCC with unity off and forced debug checks: 42 test cases pass; GCC with unity on passes. Not run: `-DENGINE_BUILD_SHARED=ON`; Windows and macOS (LuaJIT builds on Linux x86-64 only so far; Days 473-474).

## Post-implementation code review

By hand (not the `/code-review high` skill). Found and fixed, each with a test shown to fail without the fix: (1) a coroutine that ran out of memory was never dropped, because `lua_cpcall` itself needs bytes and failed at the full cap, so the state stayed at its cap for good (test `the memory cap is an error value and the state survives`); the OOM path no longer builds a traceback and cleanup gets slack; (2) an empty tagged map returned as an array; (3) a script error with a 10 MB message copied it whole into the outcome (cut now; test `a huge error message is cut`). Declined: a Lua out-of-memory raised inside the native trampoline's argument conversion loses the C++ temporaries held in that frame (a leak, no crash; the state is at its cap anyway; recorded in the source); a script can still run forever (budgets are Day 449, so the LuaJIT kit leaves out the infinite-loop hostile source).
