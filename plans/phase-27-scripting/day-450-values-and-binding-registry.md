# Phase 27 / Day 450 — Value Marshalling and the Binding Registry

**Phase:** [Phase 27 — Scripting](../phase-27-scripting.md)
**Depends on:** Days 446, 448.

How native engine functions and types become visible to scripts without per-binding boilerplate and without letting a script hold a dangling pointer.

## Tasks

- [x] `script::BindingRegistry`: namespaces of functions with typed signatures (`f32`, `i32`, `bool`, `StringView`, `Vec3`, `Quaternion`, `Entity`, `Value`), documentation strings, a stable id per function, and a marshalling layer generated from the signature by templates (a wrong argument count or type is a Lua error with the function's name, never an abort or a read of garbage).
- [x] Handles: entities and engine objects cross into scripts as generation-checked handles (an index and a generation), never a pointer; a handle to a destroyed entity fails every call with a clear error; handles are values that can be stored in tables and sent in events.
- [x] Userdata types (`Vec3` and friends are by-value Lua cdata or small userdata chosen by the Day 444 spike; the spike's cost numbers decide, the choice and the reason are written here), metatables with operators, `tostring`, equality.
- [x] Binding installation per state: a state is built from the registry's list (so a state can be created with a subset, such as the task state of Day 461 that has no world access).
- [x] The binding documentation generator: the registry produces `docs/reference/script-api.md` (functions, signatures, descriptions, which bindings are `world`, `pure` or `thread-safe-anywhere`); `ctest -L docs` checks it is current.
- [x] Every binding is marked with the thread rule it follows: `pure` (any state, any thread), `world-read` (reads the tick-start view), `world-write` (goes through the command buffer), `main-thread-only` (refused from a partition job with a clear error); the registry refuses to install a function without a mark.

Build clean (warnings are errors) with both compilers and unity on and off; `-DENGINE_BUILD_SHARED=ON` and `-DENGINE_LIBRARY_WITH_IMPORTER=OFF` still build.

## Outcome (2026-11-18, Linux)

`engine/script/bindings.{h,cpp}`: `BindingRegistry::Add<&Fn>(ns, name, rule, params, doc)` derives the checks, conversions, errors, signature text and documentation from the function type (`f32`, `f64`, `i32`, `i64`, `bool`, `StringView`, `Vec2`, `Vec3`, `Vec4`, `Quaternion`, `ecs::Entity`, `Value`; any or `void` as the result); a wrong count or type is a `RuntimeError` that names the function, argument number and name, and the expected and actual type. The stable id is an FNV-1a hash of `ns.name` (a collision is refused). `Add` refuses an unmarked rule, a bad name, a namespace that is a Lua library's name (it would replace the library), a parameter-name list of the wrong length and a duplicate. Handles: an `Entity` parameter is checked against the installation's `EntityCheck` before the function runs, so a dead or invalid handle (also one kept in a script table or global) fails every call. `Install(state, InstallProfile, &error)`: `Main` (all), `Partition` (`MainThreadOnly` installed as a function that raises "is main-thread-only and cannot be called from a partition job"), `Task` (pure only); installing only reads the registry (8 threads tested). `standard_bindings.cpp`: `num`, `vec3`, `quat` (all pure). `RenderMarkdown` (sorted, independent of registration order) and `tools/script_api_doc` (`--write`, `--check`, `--print`) produce `docs/reference/script-api.md`; ctest `docs_script_api` (label `docs`, phase 3 through `test:docs_*`) fails when the page is stale and the `docs` target rewrites it.

**Value types in scripts (task 3): tagged tables, not userdata or cdata.** The Day 444 spike's numbers favored cdata for speed, but `ffi` is removed from the sandbox (Day 449) and userdata cannot be built from Lua, so the vector types stay the Day 448 tagged tables (they round trip as `Value`s without a handle registry, and the sandbox has no other way to make them). The LuaJIT backend gives the five metatables (`vec2`, `vec3`, `vec4`, `quat`, `entity`) `+ - unary- * /` (scalar and componentwise forms; `quat * quat`; `quat * vec3` rotates), `==`, `tostring` and `__metatable = false`. The cost is a table per value; heavy per-frame vector math should use batch bindings (later days).

Tests (`tests/script/bindings_test.cpp`, 10 cases): conversions, id and signature, argument errors (count, type, range, untagged table, `pcall`), handle generations (kept in a table, invalid, unknown), refusals, main-thread-only in a partition state, subset install, operators, documentation order, 8 threads. Guide: "Bindings". `ARCHITECTURE.md`, `modules.txt` and `module_map.txt` list the tool.

Runs: see `STATUS.md`.

## Post-implementation code review

By hand (not the `/code-review high` skill). Found and fixed: (1) GCC rejected unused `args` and `env` parameters in the zero-argument case of the signature templates (`[[maybe_unused]]`; GCC unity-off now builds and passes); (2) a namespace named like a Lua library (`math`) would replace that library in the state: `Add` now refuses it, with a test; (3) docgen lint: missing ownership and thread-safety labels. Recorded, not changed: a failed `Install` leaves earlier bindings in the state pointing at freed records, so the doc says to discard the state (a failure needs an out-of-memory in `RegisterFunction`); `Entity` handles nested in a `Value` are not checked; the security-review note on `table.insert/remove` reaching a read-only proxy is the existing limit in `KNOWN-ISSUES.md`.

Runs: plain `ran 3932 of 10553 tests (phases: all; flavors: plain; ...)`, asan `ran 3227 of 10553`, tsan `ran 2882 of 10553`; only the known failures (`engine_c_surface`, the Job-destroyed test, the audio voice-cost timing test) plus `docs_check` until the reference was regenerated after formatting (then `ctest -L docs`: 9 of 9 pass). GCC and Clang, unity off: script tests pass. Not run: `-DENGINE_BUILD_SHARED=ON`; Windows and macOS (Days 473-474).
