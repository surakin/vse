## Post-implementation code review

`/code-review high --max-findings all` over the phase (`73729aa7..HEAD`), done as three read-only reviews by area (concurrency core; LuaJIT backend and sandbox; bindings and C API): 12 + 12 + 12 findings. **Fixed (7, plus `time.frame`):** the task owners of dropped instances were missed after two `Compact` calls in one tick (sorted now); a resumed wait drew from an unseeded stream (seeded from the entity, tick and coroutine id; regression test); a resume ran script code for an instance that had failed; the C API's default call and task budget was unlimited (now `DefaultBudget`; regression in `host_script`); `script_task_run` read fields before the `struct_size` check; the chunk count wrapped at counts near 2^64; a value pool could copy unbounded bytes through overlapping slices (16 MiB cap); `time.frame` was always 0 (now the tick). **Recorded, not fixed (`KNOWN-ISSUES.md`):** the rest, with the largest being the per-run order of `pairs` over hashed keys (a script rule is in the guide), the replaceable behavior host, budgets that a long C-library call can pass, the writable engine metatables, the conflict key that ignores the component, magnitude limits of physics inputs, and the global ECS slot per defined component type. Each declined finding is a hardening or a rare case that needs a design change (the sandbox, the merge key) not made on the closing day.
