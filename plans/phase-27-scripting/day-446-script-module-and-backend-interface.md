# Phase 27 / Day 446 — The Script Module and the Language-Backend Interface

**Phase:** [Phase 27 — Scripting](../phase-27-scripting.md)
**Depends on:** Day 445; Phase 17.

The seam: what the engine asks of a language, with no mention of Lua. The LuaJIT backend and a test backend are two implementations of it.

## Post-implementation code review

By hand over the day's diff (one finding, plus two found by the gates earlier: GCC's `-Wsign-compare` in `value.cpp`, and `ENGINE_VERIFY` in a header). Fixed: `State::Call` and `Resume` left a reused `CallOutput` as it was, so results of an earlier call stayed in the list and a stale suspension looked live; they now call `CallOutput::Reset()` first and refuse a null output with `Invalid` (test `Call and Resume empty a reused output first`; I did not run it against the unfixed code, but the earlier call's result would make `results.Size()` 2). Declined: a lock-based owner check (the point of the design is no lock; the token check catches the wrong-thread use that matters in tests and debug builds); a total-node limit at construction (a hostile tree is bounded by what its builder allocates, and `Check` bounds it at the boundary).
