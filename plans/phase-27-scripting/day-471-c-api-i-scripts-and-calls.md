## Notes

- New: `engine/engine_c/script_api.h/.cpp` (a world's `ScriptHost`: backend, bindings, runtime, host functions, budget; the value pool codec; the table functions), `BindingRegistry::AddDynamic` (a binding a host decides at run time, `bindings.h`), `tests/engine_library/host_script.c` (ctest `engine_c_script`, three flavors), two cases in `tests/script/bindings_test.cpp`. The header gained `engine_value`, `engine_value_pool`, `engine_script_load`, `engine_script_component`, `engine_script_budget`, `engine_script_stats`, `ENGINE_COMPONENT_SCRIPT` (17), `ENGINE_CAP_SCRIPT`, and the table functions `script_load`, `script_call`, `script_register_function`, `script_set_budget`, `script_stats` (appended at the end; snapshot regenerated, still ABI 1.0 unreleased); `engine.h` wraps them.
- The module is built in only where `TARGET script AND TARGET luajit` (`ENGINE_C_WITH_SCRIPT`, like the importer): Linux x86-64 now; elsewhere the functions answer UNSUPPORTED and the library has no `ENGINE_CAP_SCRIPT`.
- Differences from the plan text (decisions of the day): the world's runtime is made lazily (settings read at engine creation); host functions are all callable from the partitions' threads (the registry's states are `Partition` profiles: a `main-thread-only` rule would raise in every script state), declared `world-read`, or `pure` with a flag; `script_call` takes a global function path only (no entity form), refuses with NOT_READY instead of waiting when the world is busy; `script_unload` and a script given by resource id are not built (`KNOWN-ISSUES.md`); the frame ticks the scripts serially on the host's thread (`ScriptRuntime::Tick` goes parallel only from a scheduler participant, which the host's thread is not).
- Found on the way: `QueryFn` kept its component ids in `ecs::ComponentId wanted[14]` for 16 kinds (a stack overrun for a mask with more than 14 bits; fixed, regression in `host_script.c`, shown failing under asan without the fix); `host_runtime.c` and `host_physics.c` used `0x10000` as an unknown mask bit, now the script bit (they use `0x20000`); `host_import.c`'s `EXPECTED_FORMAT_VERSION` had not followed the script resource type of Phase 27 (updated to the current `890cfad7a888d86f`, the documented procedure).
- Pages touched: `docs/guide/engine-library.md` ("Scripts: loading, calling and host functions"), `docs/reference/script.md`, `symbols.txt`, `ARCHITECTURE.md`.
