# Phase 27 / Day 464 — Hot Reload

**Phase:** [Phase 27 — Scripting](../phase-27-scripting.md)
**Depends on:** Days 457-458, 460, 463.

Edit a script and the running game picks it up, keeping what it can; development only.

## Tasks

- [x] **File layer: a directory watcher, `io::DirectoryWatcher`** (`engine/foundation/io/directory_watcher.h`, one implementation per platform; `Backend:` labels, a section in `io/BACKEND.md` kept in step by `io_backend_lists`, `///` docs with `docgen lint` at zero). Watches one directory (non-recursive; a recursive flag only where the platform gives it for free) and reports events as values: `Created`, `Modified`, `Removed`, `Renamed` (old and new name), plus `Overflow` ("the backend lost events: rescan"). API: `Open(path, options, out)`, `Poll(Span<Event>)` (non-blocking, from any one thread), `Wait(timeout)` (blocks until an event or the timeout), `Close`; errors are `io::Status` values, never an abort on a bad path. Events carry names relative to the directory, are coalesced per name within one `Poll`, and never name a path outside it (a hostile rename cannot point elsewhere).
- [x] **Linux backend: inotify** (`io/linux/directory_watcher.cpp`): `inotify_init1(IN_CLOEXEC | IN_NONBLOCK)`, one watch per directory (`IN_CREATE | IN_CLOSE_WRITE | IN_MOVED_FROM | IN_MOVED_TO | IN_DELETE | IN_ATTRIB`, `IN_Q_OVERFLOW` becomes `Overflow`), `IN_MOVED_FROM`/`IN_MOVED_TO` paired by cookie into `Renamed`, `Wait` through `poll(2)` on the descriptor, descriptor use only through the `os/` primitives (`file_access_check` allow-list entry with its reason). `IN_CLOSE_WRITE` rather than `IN_MODIFY` so an editor's half-written file is not reported mid-write; a save by rename-over (most editors) arrives as `IN_MOVED_TO`.
- [x] **The Windows and macOS backends are not this day's:** they are written and run on the PC and the Mac on Days 473 and 474 (their tasks are in those files), against the same conformance suite. Until then `io::DirectoryWatcher::Open` on those platforms uses the polling fallback, so hot reload works everywhere from this day, and `KNOWN-ISSUES.md` lists the two native backends as waiting.
- [x] **A portable polling fallback** (`io/directory_watcher_poll.cpp`, platform-neutral, built everywhere and used when the native backend cannot open, e.g. a network share or a watch limit): `Directory` listing plus `Stat` (size and modification time, then a content hash is the consumer's job), same events and same API; its interval is `io.watch_poll_ms` (a setting). It is also the oracle in the conformance test.
- [x] **A conformance test** (built as `tests/io/directory_watcher_test.cpp`, one `RunCases` run against the polling and the native backend; labelled phase 9 with the rest of `tests/io`; the PC and Mac runs are Days 473-474): create, write-and-close, truncate-and-rewrite, rename-over (the editor save), rename away, delete, a burst of 1000 files (events or one `Overflow`, never silence), a name with UTF-8, a directory that is removed while watched (`Removed` of the directory, then `Open` again fails by value), `Wait` times out with no event, `Close` while another thread is in `Wait` returns it, and no event for a path outside the directory. Linux (inotify) and the fallback run plain, asan and tsan here; the Windows and macOS backends run the suite on Days 473-474.
- [x] **Gates:** `file_access_check` allow list (the inotify descriptor in `io/linux/`, with a reason), `platform_neutral_check` (Win32 and Cocoa headers only in their directories), `module_deps_check`/`ARCHITECTURE.md` (the watcher is in `engine/foundation/io`, no new module), `std_usage_check` (wrapped types only), `BUILD.md` (CoreServices on macOS).
- [x] `ScriptDevWatcher` (through `io::DirectoryWatcher`, not a re-read of every file each poll: it reads and hashes only the files an event names, and a full rescan on `Overflow`; with the polling fallback when the native watcher cannot open) notices a changed source, recompiles it in a scratch state first (a failed compile reports file, line and message and **keeps the old version running**), then stages the new version.
- [x] The swap happens per partition at the sync point, never during a tick: for each instance of the script, the state is carried over by the script's own hooks (`on_reload_save(self) -> table` and `on_reload_restore(self, saved)`; without hooks the instance's persistent subset of `self` (Day 469) is kept and the callbacks are rebound), cancelled coroutines get `on_cancel`; all partitions swap in the same sync point so a tick never mixes versions.
- [x] Pending events and tasks started by the old version still deliver (their handlers rebind by name); a handler that no longer exists is dropped with a log line.
- [x] Reload of a dependency reloads its dependents in dependency order; a reload loop guard (rate limit) so an editor saving twice does not reload twice in a tick.
- [x] Thread rules: the reload runs on the main thread between ticks; partitions are idle at that point (the ownership token check proves it); tsan clean while ticks run on 16 threads and reloads arrive.
- [x] Tests: reload with state kept, reload with a syntax error (old version continues), reload during waits, reload of a dependency, 100 reloads in a row under load; the reload is a no-op and absent when `script.hot_reload` is off (default off in a shipped build).
- [x] **Runs (CLAUDE.md "Tests run by phase"):** `scripts/test-phase.sh --affected` plain; then the asan and tsan flavors (this phase runs script code on several threads on nearly every day, so tsan is not optional); quote each run's final `ran X of Y tests (phases ...)` line in this file and never say "all tests pass" for a reduced run. `ctest -L docs` when a public header or a guide changed. Build clean (warnings are errors) with both compilers and unity on and off; `-DENGINE_BUILD_SHARED=ON` and `-DENGINE_LIBRARY_WITH_IMPORTER=OFF` still build.
- [x] **Three machines (CLAUDE.md):** built and tested on the machine the day is done on (Linux); shared code (CMake, the gates, tests, headers) is checked on the Windows PC and the Mac no later than Days 473-474, and `KNOWN-ISSUES.md` lists what waits for those runs.
- [x] **Documentation (CLAUDE.md "Public API is documented before a day is done"), when a public header changed:** `///` comments with the contract labels and `docgen lint` at zero; `cmake --build build --target docs` output committed; `docs/guide/scripting.md` updated or created; tagged samples compile and run.
- [x] **Module rules (CLAUDE.md):** a new module, target or edge updates `ARCHITECTURE.md`, `tools/module_deps_check/modules.txt`, `tests/module_map.txt` and `BUILD.md` in the same commit; every new test file has its line in `tests/phases.txt` (phase 27); only wrapped types, no `std`, no raw platform macros; Lua headers only in the LuaJIT backend files (the boundary gate).
- [x] **Day review (CLAUDE.md, required):** `/code-review high` over the day's diff after the scoped tests; verify, fix (with a regression test shown to fail without the fix) or decline each finding with a reason; record the count and outcome under "Post-implementation code review" below and in `STATUS.md`.
- [x] `STATUS.md` and `KNOWN-ISSUES.md` updated in the same commit; commit and push.

**Done:** The file layer has a directory watcher with an inotify backend run on Linux (plain, asan, tsan), and a polling fallback (the Windows and macOS native backends are Days 473-474); a saved script change takes effect in the running world at a sync point on every thread, keeps state through hooks, and a broken edit leaves the old script running.
