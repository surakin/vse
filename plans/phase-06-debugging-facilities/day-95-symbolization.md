# Phase 6 / Day 95 — Modules & Symbolization

**Phase:** [Phase 6 — Debugging Facilities](../phase-06-debugging-facilities.md)
**Depends on:** Day 94.

Turn frame addresses into `module+offset` and, where the binary has symbols, a function name; produce the text and the
structured forms; give developers a tool that adds `file:line` offline.

## Tasks

- [ ] Add `engine/foundation/debug/module_map.h`: `ModuleInfo` (path, load base, end, `BuildId` (up to 20 bytes plus a kind: ELF note, Mach-O UUID, PE GUID+age; only the ELF kind is produced now), a flag for "has a symbol table"), `LoadedModules` (fixed capacity of 128 modules, filled from `/proc/self/maps` by `os::` raw `open`/`read`/`close` calls into a stack buffer; no `fopen`, no heap), and `FindModule(address)`. The list is refreshed on demand (a library may be `dlopen`ed later) and once eagerly when the crash handler is installed (Day 97), so the handler itself only reads the cache plus a bounded re-read.
- [ ] Build id: read `NT_GNU_BUILD_ID` from each module's program headers (mmap the file read-only, parse `PT_NOTE`; for the main executable also expose `GetBuildId()` as a lowercase hex string for the log and the dump). Test that a binary built with `-Wl,--build-id` yields the id `readelf -n` prints, and that a binary without one reports empty.
- [ ] Add `engine/foundation/debug/symbolizer.h`: `SymbolizeFrame(address) -> FrameInfo { module, offset, function_name, function_offset }` with a reader for `.symtab` then `.dynsym` of the module's file (mmap, binary search over a sorted copy is not possible without the heap, so use a single linear scan with the nearest-preceding-symbol rule and cap the scan time; if Spike B showed a table cache is needed, build it at install time, not in the handler). Functions only (`STT_FUNC`), sizes honored so an address past a function's end is not named after it. Names stay mangled in the async-signal-safe path.
- [ ] Demangling for the non-signal paths (assert, ensure, the logger): `__cxa_demangle` allocates, so use it only from `FormatStackTrace(..., demangle=true)` called outside signals, with a fixed-size output buffer and a fallback to the mangled name. Tools get mangled names plus `c++filt`.
- [ ] Formatting: `FormatStackTrace(const StackTrace&, char* out, usize capacity, options)` writes `#N  0xADDR  module+0xOFF  function+0xOFF` lines, one per frame, with a fixed layout documented in the guide (the offline tool parses exactly this), truncating without overrun; also `WriteStackTrace(fd, ...)` that writes frame by frame with `write(2)` so a partial report survives a second fault. The structured form for the minidump comes on Day 99.
- [ ] The symbol reader sits behind a `ModuleSymbols` interface with an ELF implementation now; Mach-O and PE/PDB readers are Phase 9 and 8 additions that do not change `SymbolizeFrame`. The report line format is identical on every platform (module name is the file's base name plus the build id, so a trace pasted from Windows or macOS goes through the same tool).
- [ ] Add the dev tool `tools/symbolize/` (own small program, uses the foundation, runs `llvm-symbolizer` (installed; reads ELF, Mach-O and PDB, so the one tool serves every platform) with `addr2line -f -i -e <module> <offsets>` as the fallback, as a child process through the Day 92 process code or `posix_spawn`, reads a pasted report or a crash file from stdin, prints `function  file:line` per frame including inlined frames, and prints the raw frame unchanged when the module file is missing or has no debug info). It is a dev-time tool like `docgen`: never linked into the engine or a game, not part of the runtime. Tests with a fixture binary compiled with `-g` in the test (a planted function at a known line) and a stripped one.
- [ ] Tests (in `tests/debug`): a trace of a known chain resolves to the right module and the right function names for exported and static functions in a `-g` binary; a symbol in a `dlopen`ed shared library is found after the refresh and not before; a stripped copy of the test binary falls back to `module+offset` (child process runs the stripped copy); an address in no module prints `??`; formatting never overruns (ASan, capacities 0, 1, 80 and 4096); the whole path runs inside a signal handler (child process) with no allocation (a counting allocator hook in the child proves zero allocations between the signal and the exit).
- [ ] **Documentation:** `///` comments; `docs/guide/foundation-debugging.md` gets "Reading a trace" with the line format and "Resolving file and line offline" with the tool's command line; `docs/reference/` regenerated; `docgen lint` at zero; `ctest -L docs` passes; the tool has a `DESIGN` note in the spec and a mention in `docs/README.md`.
- [ ] Run the day's scoped tests (`--affected`, `--flavor asan`, `--flavor tsan`) and quote the `ran X of Y tests` lines.
- [ ] **End-of-day review (CLAUDE.md):** `/code-review high` on the day's diff; extra attention to the ELF parsing of untrusted/corrupt files (bounds on every offset and size); record it here and in `STATUS.md`.
- [ ] Update `STATUS.md`; commit.

**Done:** a captured trace prints as `module+offset` plus function names with no allocation, the same trace resolves to `file:line` through `tools/symbolize`, corrupt or stripped inputs degrade to the raw form, and the tests pass in all three flavors.
