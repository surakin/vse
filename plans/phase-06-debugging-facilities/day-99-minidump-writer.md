# Phase 6 / Day 99 — The Minidump Writer

**Phase:** [Phase 6 — Debugging Facilities](../phase-06-debugging-facilities.md)
**Depends on:** Days 95 and 97, and the Day 91 decision (own writer on Linux, crashing thread only).

Write the Microsoft minidump format from the crash handler, so one file format is read by the same tools on every
platform (WinDbg, Visual Studio, lldb, `minidump-stackwalk`); Windows uses the OS call in Phase 8.

## Tasks

- [ ] Split the writer in two: a **portable serializer** (`WriteMinidump(sink, const CrashSnapshot&)`, no OS calls, no `ucontext_t`) and a **platform snapshot** (`TakeCrashSnapshot(NativeContext, CrashSnapshot&)` per platform: threads, CPU contexts, modules, readable memory ranges). Windows will not use the serializer at all (it calls `MiniDumpWriteDump`, which writes the same format); macOS, Android and iOS reuse it with their own snapshot functions. The format is little-endian on every platform.
- [ ] Define the format pieces in `engine/foundation/debug/minidump.h` (own struct definitions from the public format description; no Microsoft header): `MINIDUMP_HEADER` (signature `MDMP`, version, stream count, directory offset), `MINIDUMP_DIRECTORY`, `SystemInfo` (CPU architecture `AMD64`/`ARM64`, OS id for Linux, the kernel release string), `ThreadList` (the crashing thread: id, stack range, context location), `ModuleList` (one entry per `LoadedModules` entry: base, size, name, CodeView record with the build id as a PDB70-style GUID or the Breakpad ELF build-id convention, as Spike D showed the readers accept), `Exception` (signal as exception code, fault address, thread id), and the `Memory64List`/`MemoryList` stream holding the crashing thread's stack bytes from the stack pointer up to a cap (default 256 KB, set in options). Little-endian, `static_assert`s on every struct size and offset.
- [ ] The serializer is tested with synthetic snapshots shaped like each platform's: x86-64 and AArch64 contexts, 4 KB and 16 KB page sizes, module names with Windows-style paths and with Android app-private paths, a module without a build id, no stack memory, 1 and 200 modules; every one is read back by the Day 100 reader and by `lldb`. Real snapshots exist for Linux x86-64 only.
- [ ] The CPU context records: `CONTEXT` for AMD64 (all general registers, `rip`, `rsp`, `eflags`, segment registers, the floating-point state from `ucontext`) and for ARM64 behind the same interface (Linux AArch64 context layout, filled from `ucontext` on that architecture; compiled only there; the x86-64 version is what is tested now).
- [ ] The writer `WriteMinidump(fd, const CrashInfo&)` is async-signal-safe: it writes sequentially with `pwrite`/`write` calls from fixed stack buffers, computes every offset up front from the fixed stream sizes (no seeking back, no heap), and writes streams in a fixed order so a truncated file (disk full, a second fault) is still a valid prefix whose directory says what is present. Module names come from `LoadedModules`; the stack memory is copied from the live stack through `process_vm_readv` on self (a safe read that fails instead of faulting), falling back to a smaller range.
- [ ] Hook into the handler (Day 97): when `write_minidump` is set, write `<dump dir>/crash-<pid>-<time>.dmp` after the text report; the file name is printed in the report. Honor the privacy rules of Day 91 (directory, size cap, never uploaded).
- [ ] Linux-specific facts a reader needs, written into the format notes: module base addresses versus ELF load addresses (the entry records the mapping start of the first segment), the thread's `ucontext` versus the registers of the interrupted code, and that other threads are listed by id with no context (file the gap in `KNOWN-ISSUES.md`: other threads' stacks need a helper process using ptrace).
- [ ] Tests (children via the death-test helper): the produced file has the right signature and version, every directory entry lies inside the file, every string and location is in range, struct sizes match the `static_assert`s; the module list matches `/proc/self/maps` of the child; the exception record holds the fault address of a deliberate null write at a known address; the crashing thread's instruction pointer equals the address of the faulting function; the stack bytes at `rsp` equal a pattern the child wrote just before faulting; a file truncated at every stream boundary is still parsed as a valid prefix by the reader of Day 100; the writer allocates nothing (counting allocator) and completes inside a handler on the alternate stack.
- [ ] **Documentation:** `///` comments; the guide gets "Minidumps" (what is in the file, what is not, where it goes, how to read it); the format notes go into the design spec; reference regenerated and committed; `docgen lint` at zero; `ctest -L docs` passes.
- [ ] Run the day's scoped tests (`--affected`, asan and tsan flavors) and quote the `ran X of Y tests` lines.
- [ ] **End-of-day review (CLAUDE.md):** `/code-review high`; extra attention to every offset and size computation and to what the writer reads from the process; record it here and in `STATUS.md`.
- [ ] Update `STATUS.md`; commit.

**Done:** a crashing child leaves a `.dmp` whose structure, module list, exception record, instruction pointer and stack bytes are verified by the Day 100 reader; the writer is async-signal-safe and allocation-free; a truncated dump remains a valid prefix; the guide and spec describe the format.
