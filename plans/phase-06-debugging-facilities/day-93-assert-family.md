# Phase 6 / Day 93 — Assert, Ensure, Verify & the Handler Chain

**Phase:** [Phase 6 — Debugging Facilities](../phase-06-debugging-facilities.md)
**Depends on:** Day 92 (the helper tests the abort paths).

Replace the single `ENGINE_ASSERT` with a family of macros and one handler chain that tests, the crash handler and a
debugger can all hook, without breaking the 334 existing call sites.

## Tasks

- [ ] Define the failure record (platform-neutral: no `errno`, no signal numbers): `AssertInfo { kind, file, line, function, condition_text, message }` (all `const char*`, no allocation) and the kinds `Assert`, `Ensure`, `Verify`, `Unreachable`, `NotImplemented`.
- [ ] Add `SetAssertHandler(handler) -> previous` and the handler type `AssertAction (*)(const AssertInfo&)` returning `Abort`, `Continue` or `Break`; the default handler prints one line (`ASSERT FAILED: file:line function: condition: message`, truncated at 512 bytes, to the shared write sink as before), then returns `Break` if a debugger is attached and `Abort` otherwise. Thread-safe: the handler pointer is an atomic; calling it takes no lock.
- [ ] Compiler and architecture differences live in one header, `engine/foundation/debug/compiler.h`: `ENGINE_DEBUG_BREAK()` (`int3` on x86-64, `brk #0xf000` on AArch64, `__debugbreak()` on MSVC, `__builtin_debugtrap()` where clang has it), `ENGINE_UNREACHABLE_HINT()` (`__builtin_unreachable()` / `__assume(0)`), `ENGINE_NOINLINE`, and the printf-format attribute; nothing else in the phase names a compiler builtin. Platform differences for debugger detection sit behind `IsDebuggerAttached()` (Linux and Android: `TracerPid` in `/proc/self/status` read with raw syscalls, cached for at most a second; the sketches for Windows `IsDebuggerPresent` and macOS/iOS `sysctl` `P_TRACED` go in the spec). The break macro stops the debugger at the failing line in the caller, not inside the handler. Test the pieces separately; the break itself is exercised only in the child of a death test with a stub that records it.
- [ ] Macros in `engine/foundation/log/assert.h` (one include for all of them): `ENGINE_ASSERT(cond, msg)` unchanged in meaning (always on, fatal; messages stay string literals, there are no format strings), `ENGINE_ENSURE(cond, msg)` (evaluates `cond` once, returns it as a `bool`, reports once per call site with the trace of Day 94 when it exists and a counter, then continues), `ENGINE_VERIFY(expr, msg)` (always evaluates `expr`; checked only when `ENGINE_DEBUG_CHECKS` is set), `ENGINE_CHECK_SLOW(cond, msg)` (compiled out unless `ENGINE_SLOW_CHECKS`), `ENGINE_UNREACHABLE(msg)` (fatal in debug, `__builtin_unreachable()` in release), `ENGINE_NOT_IMPLEMENTED()`. Define how `ENGINE_DEBUG_CHECKS`/`ENGINE_SLOW_CHECKS` follow the CMake build type, and an option to force them on in a release build.
- [ ] Per-site ensure state: a function-local `static` atomic flag and counter per call site (no registry allocation); a global registry of sites would need the heap, so keep an intrusive linked list of the static records, linked on first failure with a compare-and-swap, so `EnsureReport()` can list every site that failed with its count. Test concurrent first failures from 8 threads: exactly one report per site.
- [ ] Keep the old test hooks working: `SetExitSinkForTesting` and `SetWriteSinkForTesting` stay, marked deprecated for new tests; migrate `container_vector_test.cpp` to `SetAssertHandler` (handler throws or `longjmp`s as that test needs) and delete the exit sink when no test uses it. `AssertFail` now ends in `abort()` after the handler returns `Abort` (so the crash handler and a debugger see `SIGABRT`); document the change from exit code 1.
- [ ] Sweep the call sites: no mechanical rewrite of the 334 existing asserts, but classify the ones that guard recoverable runtime conditions (for example allocator failure after `TryReserve`) and list them in the design notes as `ENSURE` candidates; convert only those in `engine/foundation` where the caller can really continue, with a test for each converted site.
- [ ] Tests (in `tests/debug`, using the death-test helper): a failing `ENGINE_ASSERT` in a child dies with `SIGABRT` and prints the one-line report; the handler that returns `Continue` lets an assert pass in-process (the capture test); `ENGINE_ENSURE` returns the condition, reports once for 1000 failures at one site and once each for two sites, and counts correctly; `ENGINE_VERIFY` evaluates its expression in release configuration (compile the same test with the check macro off, as a separate small target or a `#define` before the include); `ENGINE_CHECK_SLOW` does not evaluate its operand when off (a counter proves it); `ENGINE_UNREACHABLE` and `ENGINE_NOT_IMPLEMENTED` abort in a child; a handler installed on one thread is seen by another; messages longer than the buffer are truncated without overrun (ASan).
- [ ] **Documentation:** `///` comments on every new symbol with `Aborts:` and `Thread-safety:` labels; update `docs/guide/foundation-logging-and-assert.md` with the family, when to use which, and an example of a capture handler in a test (tagged sample that compiles); rewrite the `Fails:`/`Aborts:` convention paragraph in `docs/DOC-CONVENTIONS.md` to name `ENGINE_ASSERT` versus `ENGINE_ENSURE`; docgen reference regenerated and committed; `docgen lint` at zero; `ctest -L docs` passes.
- [ ] Run the day's scoped tests (`--affected`, then `--flavor asan`, `--flavor tsan`) and quote the `ran X of Y tests` lines.
- [ ] **End-of-day review (CLAUDE.md):** `/code-review high` on the day's diff; fix or decline each finding with a reason; record it here under "Post-implementation code review" and in `STATUS.md`.
- [ ] Update `STATUS.md`; commit.

**Done:** the six macros and `SetAssertHandler` exist with the semantics above, all existing tests pass unchanged except the migrated one, the new tests pass in plain, ASan and TSan, `AssertFail` aborts with `SIGABRT`, and the guide, conventions page and reference are updated.
