# Phase 6 / Day 92 — Death-Test Helper & the `tests/debug` Suite

**Phase:** [Phase 6 — Debugging Facilities](../phase-06-debugging-facilities.md)
**Depends on:** Day 91.

Every later day tests code that aborts or crashes. Build the helper that runs a function in a child process and reports
what happened, and the test target that holds this phase's tests, first. The helper **re-executes the test binary**
instead of calling `fork`: `fork` does not exist on Windows, and in a multithreaded parent it leaves the child with
locks it can never release, so a re-exec model is both portable and safer. Platforms that cannot start a process (iOS,
consoles) report `Unsupported` and the death tests skip there.

## Tasks

- [ ] Add `engine/foundation/debug/death_test.h` with `RunInChild(name, argument, options) -> ChildResult`: starts a new process of the running executable with the environment variable `ENGINE_DEATH_TEST_CHILD=<name>` and `<argument>` (a short string the child function parses), runs the function registered under `name` there, and returns `exited`/`exit_code`, `signaled`/`signal`, `timed_out`, and the captured stderr and stdout text (fixed-capacity buffer, truncation flagged). `options`: timeout in milliseconds (default 10 s, the child is killed with `SIGKILL` and `timed_out` set), whether to capture stdout, extra environment entries, and whether to disable core dumps in the child (default yes, so tests do not fill the disk).
- [ ] Registration: `ENGINE_DEATH_TEST_FN(name, argument_text)` defines a function and registers it by name in a static table; a hidden Catch2 test case (`[.death-child]`, defined once in the library `debug_test_support` that `tests/debug` and other test targets link) reads `ENGINE_DEATH_TEST_CHILD`, looks the function up, runs it, and leaves through `_exit(0)` so no reporter, atexit handler or static destructor runs in the child. The parent starts the child with the test binary's own path and the filter `[.death-child]`, so the child needs no change to `main` and works with `Catch2WithMain`.
- [ ] Implement the spawn for Linux in `engine/foundation/os/linux/debug/death_test.cpp`: `pipe2` with `O_CLOEXEC`, `posix_spawn` with file actions that redirect the child's stdout/stderr to the pipes (the executable path from `/proc/self/exe`), `poll` with a deadline in the parent while draining the pipes (never a blocking read after the child dies without closing, never a deadlock when the child fills the pipe), `waitpid` retried on `EINTR`, and reaping on every path. The platform-neutral part (`ChildResult`, registration, the hidden test case, the options) is in `debug/`; only the spawn/wait/pipe code is per platform, so Windows adds `CreateProcess` + job objects and macOS reuses the POSIX code.
- [ ] What the child inherits: a fresh process image, so nothing from the parent except the environment and the two pipes; the parent's threads, locks and allocator state do not matter (this is why re-exec replaces `fork`). Document that the child function gets only its argument string; larger inputs are written to a temp file the argument names.
- [ ] `Unsupported` convention: `RunInChild` returns a result with `supported == false` on a platform with no process spawning, and a helper macro `ENGINE_REQUIRE_DEATH_TEST_SUPPORT()` makes the test skip with a printed reason; test that the skip path works by forcing the unsupported result in a unit test.
- [ ] Add the `tests/debug/` directory with its CMake target `debug_tests` in the three flavors (plain, ASan, TSan, linked against `foundation`, `foundation_asan`, `foundation_tsan`) using `engine_discover_tests`, a `lsan_options.cpp` if the leak checker needs it, and Catch2 as in `tests/jobs`.
- [ ] Wire the scoping: add `tests/debug/` lines to `tests/phases.txt` (phase 6) and a `flavors 6 plain,asan,tsan` line; add `tests/debug 6` and `engine/foundation/debug`/`engine/foundation/os/linux/debug` to the module map `tests/module_map.txt` (with the phases of the tests that cover them); run `test_phase_labels` and the `test_phase_script_*` tests to prove the map still validates.
- [ ] Neutral results: `ChildResult` carries `reason` (a `CrashReason`: none, access violation, bus error, illegal instruction, arithmetic fault, stack overflow, abort, assert, ensure) decoded by the platform backend from the child's exit status (Linux: the terminating signal; the Windows backend will decode NTSTATUS exit codes such as `0xC0000005`), with the raw status kept beside it. Add `debug/fault_injection.h`: `InjectFault(FaultKind)` (null write, abort, illegal instruction, divide by zero, stack overflow, misaligned access where the platform has one), implemented per platform, so every crash test says `InjectFault(...)` and checks `reason`, never a signal number.
- [ ] Platform selection: `engine/foundation/CMakeLists.txt` selects `FOUNDATION_DEBUG_PLATFORM_SOURCES` from `CMAKE_SYSTEM_NAME` next to the existing os selection (Linux only now; the Windows and macOS branches stop with a message naming Phase 8 or 9).
- [ ] The neutral-header gate: a CMake-script ctest in the style of `tools/raw_new_check` (`tools/platform_neutral_check`, fixtures that plant each violation) that fails if a header under `engine/foundation/debug/` or a test source under `tests/debug/` (other than files named `*_linux_*`) names a platform type or constant (`ucontext_t`, `siginfo_t`, `SIG[A-Z]+`, `pid_t`, `HANDLE`, `/proc`, `fork(`, `<unistd.h>`, `<windows.h>`); it runs from this day on, so no later day can slip a platform detail into a neutral file. Phase label 6.
- [ ] Tests: a child that returns normally (exit code 0), calls `_exit(7)`, raises `SIGSEGV` by writing to null, calls `abort()`, writes 1 MB to stderr (the pipe fills; no deadlock), hangs (timed out and killed within the deadline plus a margin), closes stderr and then crashes, starts a grandchild that keeps the pipe open (the helper still returns at the child's exit), and receives its argument string and environment entries; the test binary being started from another working directory works (the path comes from `/proc/self/exe`, not `argv[0]`). The platform-neutral parts are also tested without spawning (registration, result decoding). Every test also asserts there is no zombie left (`waitpid(-1, WNOHANG)` finds nothing) and no leaked descriptor (`/proc/self/fd` count before and after).
- [ ] Run the helper's tests in all three flavors, at `-j16` and 20 times in a loop (`ctest --repeat until-fail:20`) to catch flakiness; record the numbers. Anything flaky goes to `KNOWN-ISSUES.md` with its phase.
- [ ] **Documentation:** `///` comments with the contract labels of the new module (add `module foundation/debug "Foundation: Debugging"` to `docs/reference/modules.txt` with `strict thread-safety`, `strict ownership` and `strict failure`); `docs/guide/foundation-debugging.md` created with a section "Testing code that crashes" (including the per-platform support table: re-exec on Linux/macOS/Windows, `Unsupported` on iOS and consoles) and a tagged, compiled sample; `docgen lint` at zero known findings; `cmake --build build --target docs` output committed; `ctest -L docs` passes.
- [ ] Run the day's scoped tests: `scripts/test-phase.sh --affected` (the day touches an `engine/foundation` header, so it runs everything), then `--flavor asan` and `--flavor tsan` of the same selection; quote the `ran X of Y tests` lines.
- [ ] **End-of-day review (CLAUDE.md):** run `/code-review high` on the day's diff, fix or decline each finding with a reason, record it under "Post-implementation code review" here, and mention it in `STATUS.md`. Extra scrutiny on the spawn/pipe lifetime and descriptor handling.
- [ ] Update `STATUS.md`; commit.

**Done:** the neutral-header gate passes with its planted-violation tests; `RunInChild` (re-exec model, `Unsupported` where a platform cannot spawn) reports exit code, signal, timeout and captured output for the cases above without leaking a process or descriptor, in all three flavors, repeated 20 times without a failure; `tests/debug` is wired into the phase map and the scoped runner; the guide page and reference exist and `ctest -L docs` passes.
