# Phase 6 / Day 95 — Vendoring sentry-native & the Crash Facade

**Phase:** [Phase 6 — Debugging Facilities](../phase-06-debugging-facilities.md)
**Depends on:** Days 91-94.

Crash capture and minidumps come from sentry-native 0.17.6 with its Breakpad backend and no transport (`PLAN.md`
assumption #20; chosen on Day 91, see `docs/superpowers/specs/2026-11-06-debugging-design.md`). This day vendors and
builds it, puts the neutral facade in front of it, and adds the small tool that pulls the minidump out of sentry's
envelope.

## Tasks

- [ ] Vendor sentry-native as source under `third_party/sentry_native/` from the `sentry-native.zip` asset of release 0.17.6 (downloaded into its own empty directory; submodules are in the asset): keep `src/`, `include/`, `CMakeLists.txt`, `cmake/`, `external/breakpad` (what the build compiles), `vendor/libunwind`, their CMake files and every `LICENSE`; prune tests, examples, benchmarks, fuzzing, `ndk/`, `external/crashpad`, `external/libunwindstack-ndk`. Write `VENDORED.md` from the spec's draft (upstream, pin, the licenses of each nested project, the prune list, size on disk, the exact configure options, the upgrade steps). No submodule, no `FetchContent`.
- [ ] CMake integration: `add_subdirectory(third_party/sentry_native)` with `SENTRY_BACKEND=breakpad`, `SENTRY_TRANSPORT=none`, `SENTRY_BUILD_SHARED_LIBS=OFF`, no tests, no examples, no install; the vendored targets get their own warning flags and are kept out of `CMAKE_UNITY_BUILD` batches; one uninstrumented build is linked into the plain, ASan and TSan programs (ASan worked in Day 91 Spike D; **TSan is tested here**: build a crashing program under TSan, record the result, and if it fails document that the handler is off in the TSan flavor).
- [ ] Add `engine/foundation/debug/crash_handler.h`: the neutral `CrashReason` enum (access violation, bus error, illegal instruction, arithmetic fault, stack overflow, abort, assert, ensure), `CrashHandlerOptions` (dump directory defaulting to `os::GetCrashDumpDirectory()`, never the working directory; the report-file path to attach; an optional handler path for backends that need one (empty for Breakpad); enable/disable; **no URL or DSN field**), `InstallCrashHandler(options) -> Result`, `UninstallCrashHandler()`, and a `Result` with `Unsupported`. No library type, no signal number in the header.
- [ ] Add the one implementation file `engine/foundation/debug/crash_handler_sentry.cpp`, the only file that includes `sentry.h` (a C header: no STL, no exceptions, so it compiles under the production flags): map the options to sentry's (database path, release = build id, session tracking off, no DSN, an attachment for the report file), route sentry's logger to `LogCore` (it prints `[sentry] DEBUG` lines to stderr by default), install the `on_crash` hook that Day 96 fills in, `sentry_init`/`sentry_close`. Extend the Day 94 gate so `sentry.h` is allowed only in this file, with a planted-violation fixture.
- [ ] Add `tools/crash_extract/` (a dev tool like `docgen`, never linked into the engine): reads a sentry `.envelope` (a JSON header line, then item-header line + payload of the stated length, repeated) and writes the `event.minidump` item as `<id>.dmp`; exits non-zero on a malformed or truncated envelope without reading out of range. Tests: an envelope from a crashing child; a byte-flip and truncation sweep under ASan (no crash, no out-of-range read); an envelope with no minidump item; two minidump items.
- [ ] No-upload guarantee: a ctest that fails if a built test or demo binary links `libcurl`, a TLS library or `winhttp` (`ldd`/`readelf -d` on Linux; Day 91 measured only libstdc++, libm, libgcc and libc), and a unit test that `CrashHandlerOptions` has no URL or DSN field (a `static_assert` on `offsetof`/field names via a trait is not possible, so the test checks the documented field list and the header text); document the guarantee in the guide.
- [ ] Add `os::GetCrashDumpDirectory()` (Linux: `$XDG_STATE_HOME/<app>/crashes`, falling back to `~/.local/state/<app>/crashes`, created with mode 0700; the app name comes from the executable name or `ENGINE_APP_NAME`), with a failure result for a platform without a writable location.
- [ ] Smoke test (death-test helper): a child installs the handler and crashes with `InjectFault(NullWrite)`; the parent finds exactly one envelope in the database directory within a deadline, `crash_extract` turns it into a file that starts with `MDMP`, the child's exit status is the original fault, and the temp directory is removed after. Run in plain, ASan and TSan flavors (or recorded as plain-only with the reason found above).
- [ ] Failure paths: an unwritable dump directory (install returns an error and the program still runs, with a logged warning); installing twice; uninstall then crash (default behavior, no dump); a crash before `InstallCrashHandler` (no dump, original signal). Tests for each.
- [ ] **Documentation:** `///` comments; the guide gets "Installing the crash handler" and "Where dumps go, and what is never sent"; `third_party/sentry_native/VENDORED.md` linked from the guide; reference regenerated and committed; `docgen lint` at zero; `ctest -L docs` passes.
- [ ] Run the day's scoped tests (`--affected`, which runs everything because CMake changed), then asan and tsan flavors, and quote the `ran X of Y tests` lines.
- [ ] **End-of-day review (CLAUDE.md):** `/code-review high` on the day's diff (our CMake, facade, tool, tests; the vendored sources reviewed only for what was pruned or patched); extra attention to the envelope parser and the dump directory permissions; record it here and in `STATUS.md`.
- [ ] Update `STATUS.md`; commit.

**Done:** sentry-native builds from vendored source under our CMake; a child that crashes leaves an envelope from which `crash_extract` produces a valid minidump, and still dies with the original fault; nothing in the binary can upload (checked by a test); `sentry.h` appears in exactly one engine file, enforced by the gate; the tests pass in the flavors recorded above.
