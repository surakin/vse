# Phase 6 / Day 97 — The Crash Handler

**Phase:** [Phase 6 — Debugging Facilities](../phase-06-debugging-facilities.md)
**Depends on:** Days 94-96.

Install handlers for fatal signals that print the report and then let the original fault proceed, on every thread,
including a stack overflow, without ever making things worse.

## Tasks

- [ ] Add `engine/foundation/debug/crash_handler.h`: the neutral `CrashReason` enum (access violation, bus error, illegal instruction, arithmetic fault, stack overflow, abort, assert, ensure) with the raw platform code, `InstallCrashHandler(CrashHandlerOptions)` / `UninstallCrashHandler()` and the options (report sink, dump directory from `os::`'s crash-dump directory function by default (never the working directory: mobile sandboxes forbid it), whether to write a minidump (Day 99), whether to chain, whether to raise `RLIMIT_CORE` (Day 98)). Idempotent; installing twice replaces the options, not the previous-handler record.
- [ ] Linux backend `engine/foundation/os/linux/debug/crash_handler.cpp` (the neutral header says what each other platform does: Windows a vectored/unhandled exception filter with `SetThreadStackGuarantee` for stack overflow, macOS/iOS signals plus a Mach exception port, Android signals chained with `debuggerd`'s handler, which also decides the chaining design below): `sigaction` with `SA_SIGINFO | SA_ONSTACK` and no `SA_NODEFER` (decide `SA_RESETHAND` together with the re-raise design below) for `SIGSEGV`, `SIGBUS`, `SIGABRT`, `SIGFPE`, `SIGILL` (and `SIGTRAP` only if Spike C says a debugger break must not be intercepted: it is not installed). An alternate stack per thread: `sigaltstack` with a 64 KB region for every thread the engine creates (a `thread_local` guard object in the job system's thread entry and the main thread, and a documented `RegisterThreadForCrashHandling()` for other threads); the stack memory is static or mmap'd, never freed while the handler could run.
- [ ] The handler body, in order: block re-entry (an atomic flag; a second fault while handling prints one line `double fault` and goes straight to the re-raise), capture the trace from the context, write the report to the report fd (stderr by default) and to `<dump dir>/crash-<pid>-<time>.txt` opened with raw `open`, call the minidump and core hooks if enabled, restore the previous disposition for the signal (the saved `sigaction`, or `SIG_DFL`) and return/re-raise so the kernel delivers the original fault: for synchronous faults (`SIGSEGV`, `SIGBUS`, `SIGILL`, `SIGFPE`) return after resetting the handler so the faulting instruction re-executes and faults again into the default action (core dump, exit status by signal); for `SIGABRT` do `raise` after resetting. The process exit status must show the original signal; a debugger still sees the fault.
- [ ] No unsafe calls: the handler calls only the functions of Days 94-96 (checked by a grep gate described in the tests) and raw syscalls (`write`, `open`, `close`, `getpid`, `gettid`, `clock_gettime`); no `malloc`, `printf`, `std::` anything, `pthread_mutex_*`. Add a CMake-script gate in the style of `tools/raw_new_check`, `tools/signal_safety_check`, that scans `engine/foundation/os/linux/debug/crash_handler.cpp` and the report path for a list of forbidden identifiers, with fixtures that plant each one and prove the gate fails.
- [ ] The signal-to-`CrashReason` mapping is a table in the Linux backend only; the report, the dump and the tests speak `CrashReason`. A test feeds each `CrashReason` to the report writer through the neutral entry point (no signal), so the report path is verified without a platform handler.
- [ ] Chaining and sanitizers (from Spike C): record the previous `sigaction` for each signal and call it after our report when it was a real handler (an application, or a sanitizer that installed itself first); under ASan/TSan, `InstallCrashHandler` does not replace the sanitizer's handlers unless told to, and `SIGABRT` raised by `AssertFail` under a sanitizer still reaches our report because `AssertFail` already printed it (so the handler is optional there). Write the policy table into the guide.
- [ ] Interaction with threads: a fault on a worker thread (`engine/jobs/worker_pool.cpp`), on the I/O thread (`async_io.cpp`), inside a driver thread (no frame pointers: the trace is short but the report is complete), and on the main thread; each names the thread. Two threads faulting at once: one reports, the other waits in `pause()` until the process dies.
- [ ] Tests (death-test helper, all in child processes, plain/ASan/TSan where meaningful), written against the neutral API so Phases 8 and 9 run the same sources: `InjectFault(FaultKind::NullWrite)` gives `ChildResult::reason == AccessViolation`, the report on stderr contains the faulting function name and the reason text, and the dump file exists; each other `FaultKind` (abort, illegal instruction, divide by zero, a bus error where the platform has one) does likewise with its `CrashReason`; Linux-only details (a truncated-file `mmap` `SIGBUS`, the raw signal in the status) are in files named `*_linux_*` and are exempt from the neutral-header gate; a stack overflow by infinite recursion still produces a report (alternate stack) and a `SIGSEGV` status; a fault on a `std::thread` and on a job worker; a second fault inside the handler (provider that crashes) ends with `double fault` and the original status; the previous handler (a test handler that writes a marker) is called after the report; uninstall restores the default behavior; running the whole set 20 times shows no flaky result.
- [ ] Debugger check (manual, recorded): run a crashing test under `gdb` and confirm the debugger stops at the original faulting instruction, not inside the handler; record the commands; if no human has done it by the end of the day, it goes to `KNOWN-ISSUES.md` as a check not yet done.
- [ ] **Documentation:** `///` comments with `Thread-safety:` and `Fails:`; guide "Installing the crash handler" (options, policy table, what a report looks like, how to read an exit status); reference regenerated and committed; `docgen lint` at zero; `ctest -L docs` passes.
- [ ] Run the day's scoped tests (`--affected`, asan and tsan flavors) and quote the `ran X of Y tests` lines.
- [ ] **End-of-day review (CLAUDE.md):** `/code-review high`; this is the day with the most signal-safety, lifetime and concurrency risk, so treat every finding seriously; record it here and in `STATUS.md`.
- [ ] Update `STATUS.md`; commit.

**Done:** fatal signals on any thread, and a stack overflow, print a complete report and a dump file and then terminate with the original signal in the exit status; a fault in the handler cannot loop; the previous handler is chained; the gate proves the handler path calls nothing unsafe; the tests pass in plain, ASan and TSan and repeat 20 times without failure.
