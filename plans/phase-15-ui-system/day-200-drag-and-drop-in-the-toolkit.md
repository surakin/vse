# Phase 15 / Day 200 — Drag and Drop in the Toolkit

**Phase:** [Phase 15 — UI System](../phase-15-ui-system.md)
**Depends on:** Days 188, 192, 194 (input routing), 196 (list box), 197 (text field), 199 (containers).

Widgets that start drags, widgets that accept drops, drag visuals, and the bridge to the OS drag and drop of Day 188. The same machinery serves a drag inside one surface and a drag from or to another program.

## Tasks

- [x] **Model (`ui/drag_drop.h`):** `DragPayload` = a list of typed entries (`Text`, `FileList`, `Custom(name, bytes)`, and an application pointer entry valid only inside the process), allowed actions (copy, move, link), an optional drag visual (an `ImageId` or a widget tree snapshot built by the source); `DragSource` (a widget calls `Surface::BeginDrag(payload, visual)` from a press-and-move after a slop distance from the theme); `DropTarget` interface on widgets: `CanAccept(payload, position) -> action`, `OnDragEnter/Over/Leave`, `OnDrop(payload, position, action)`.
- [x] **Routing:** a drag takes pointer capture on the surface; hover during a drag goes to drop targets only (the topmost widget under the pointer that accepts, else its accepting ancestor); popups and the top layer receive drags like any widget; auto-scroll when the pointer rests near the edge of a `ScrollView` or `ListBox` (speed from the distance, from the surface clock); a hover-delay hook (tabs and submenus open while a drag waits over them); Escape cancels; release over no target cancels with the cancel callback.
- [x] **Visuals:** the drag visual draws in the top layer following the pointer with an offset; the drop target highlights from the theme (variant `drop-target`, state `drag-over`); the cursor shows the action (copy/move/not-allowed) through `CursorShape`; an insertion line for list reordering from the theme.
- [x] **OS bridge (`ui_window`):** a drag that leaves the surface becomes an OS drag (`Window::BeginDrag` with the payload's text, file and custom entries) when the payload has any OS-representable entry; an OS `DragEnter/Over/Drop` becomes a `DragPayload` over the surface's drop targets, with the data requested asynchronously and the drop delivered when it arrives (the target sees `OnDrop` only with complete data; a failed read reports a failure message, not a half drop); a pointer-only payload is never offered to the OS.
- [x] **Built-in uses:** `ListBox` item reordering and drag-out of selected items (opt-in, a model hook `MoveItems`); `TextField` accepts a text drop (inserts at the drop position, moves the selection when dragging from itself with the move action) and offers its selection as a drag source; `TabView` tab reordering and drag-to-hover-select; `Window` file drop to the surface as a drop target for `FileList` with an `OnFilesDropped` callback on the root; `Splitter` and dialogs are unaffected.
- [x] **Clipboard in the toolkit:** `ui::Clipboard` (Day 197's in-process interface) now has the OS implementation behind it - `OsClipboard` over `Window::SetClipboardText/RequestClipboardText` from Day 187, asynchronous: paste in a text field requests, shows nothing until the data event arrives, then inserts (and undo treats it as one edit); Paste is enabled from `ClipboardChanged` and `ClipboardHasFormat`; the in-process clipboard stays as the implementation for offscreen surfaces and tests; primary selection: select-to-copy and middle-click paste in text fields where `Primary` is supported (Linux), off elsewhere.
- [x] **Menus and accelerators:** Edit > Cut/Copy/Paste/Select All items enable from the focus owner (`CanCut/CanCopy/CanPaste`), Ctrl+C/X/V and Shift+Insert/Delete accelerators route to the focus owner before surface shortcuts.
- [x] **Tests (`tests/ui/drag_drop_test.cpp`, `clipboard_test.cpp`, with the harness and a fake `os::Window`):** begin/slop/cancel rules; drop target selection (accepting ancestor, overlapping widgets, popups); auto-scroll rates with a fake clock; list reorder results (including drop at the ends and on itself); text drop positions and move-vs-copy within one field; tab reorder; OS drag in (text, files, custom, a failed read) and out (payload entries mapped to formats, pointer entries withheld); action to cursor mapping; async paste: nothing inserted before the data event, one undo step after, a timeout shows the failure; Paste enable/disable follows `ClipboardChanged`; primary selection copy and middle-click paste; hostile payloads (huge text, invalid UTF-8) capped without crashing.
- [x] **`ui_demo` hooks (finished on Day 204):** the list box in the left panel reorders by dragging, the text field accepts dropped files (shows the paths) and text, and Edit > Copy/Paste works against other programs.
- [x] **Tests are written with the code:** every public behavior above has a test; GPU tests carry the `gpu` tag, use `FOR_EACH_GPU_BACKEND` and skip a backend that has no shaders (Vulkan only until Day 202 mints DXIL); every new test file has its line in `tests/phases.txt` (phase 15).

## Notes

- Drop-target highlight and insertion line are the `droptarget` and `dropmarker` widget kinds plus the `kStateDragOver` bit (drawn by `Widget::DrawTree`), instead of a variant and a state of each kind.
- Cursor: the platform layer has no copy cursor, so copy shows the arrow, move the four-way arrow, link the hand, refusal the forbidden sign.
- Not built: dragging between two list boxes, and a submenu opening on a drag hover (the hook exists; no menu uses it).
- **Runs (Linux):** plain `ran 1837 of 5004 tests (phases: all; flavors: plain; display: included; crash tests: excluded)`; asan `ran 1491 of 5004 tests (phases: all; flavors: asan; display: included; crash tests: excluded)`; tsan `ran 1182 of 5004 tests (phases: all; flavors: tsan; display: included; crash tests: excluded)`. `ctest -L docs` passes, docgen lint at zero, the seven gates pass, Clang and GCC build clean in unity and non-unity.

## Post-implementation code review

`/code-review high`: 4 findings, 3 fixed, 1 declined.

- **Fixed:** a drag held here stayed active after window focus loss or a modal opening (`ReleasePointer` now ends it); a move out of a text field could delete text that had changed (the text is checked first); a drop onto the dragged range was judged against the current selection (the range taken is used). Regression tests for all three fail without the fixes (confirmed).
- **Declined:** a second OS drop while the first is still reading leaves the old request ids unread; the window evicts them and the next drop is unaffected.
