# Phase 15 / Day 187 — Platform: the OS Clipboard (Wayland, X11)

**Phase:** [Phase 15 — UI System](../phase-15-ui-system.md)
**Depends on:** Days 185, 186.

Copy and paste with other programs: text first, then file lists and a private format for the engine's own data. The Win32 backend follows on Day 205 behind the same interface.

## Tasks

- [x] **API on `os::Window`** (defaults report unsupported so Win32 and macOS compile): `Clipboard` operations `SetClipboardText(StringView)`, `RequestClipboardText()` (asynchronous: the answer arrives as a `ClipboardData` event on a later `PumpEvents`, because Wayland and X11 transfer through the other client), `ClipboardHasFormat(Format)`, formats `Text` (UTF-8), `FileList` (a list of `io::Path`), `Custom(mime/atom name)` with bytes; `SupportsClipboard()`; selection kinds `Clipboard` and `Primary` (the X11/Wayland middle-click selection; Win32 has none and reports unsupported).
- [x] **Events:** `ClipboardData{request_id, format, bytes or failure}` and `ClipboardChanged` (the owner changed; used to enable/disable Paste) added to `InputEvent` (Day 185); a request that gets no answer in 2 s (the owner is gone or stuck) completes with a `Timeout` failure, so a paste never hangs the UI.
- [x] **Wayland:** bind `wl_data_device_manager`; offering data = `wl_data_source` with the MIME types `text/plain;charset=utf-8`, `text/plain`, `UTF8_STRING`-equivalents, `text/uri-list` for files; serving `send` requests by writing to the passed file descriptor without blocking the pump (non-blocking writes continued across `PumpEvents`, a size limit and a timeout); receiving = `wl_data_offer` selection, `receive(mime, fd)` and non-blocking reads accumulated across pumps; selection serial from the last key or pointer event; the source is cancelled and freed on `cancelled`; primary selection through `zwp_primary_selection_device_manager_v1` when the compositor has it (generated bindings committed, `VENDORED.md` updated).
- [x] **X11:** `CLIPBOARD` and `PRIMARY` selections: own with `XSetSelectionOwner`, answer `SelectionRequest` for `TARGETS`, `UTF8_STRING`, `STRING` (Latin-1 conversion where lossless), `text/uri-list`, `TIMESTAMP`; request with `XConvertSelection` and read the property on `SelectionNotify`; **INCR** transfers in both directions for data larger than the server's maximum request (receive: accumulate chunks; send: chunk on `PropertyNotify`), a 64 MiB cap; selection ownership lost (`SelectionClear`) reported as `ClipboardChanged`. No clipboard manager persistence is implemented (documented: contents vanish with the process, as for any client that does not hand them to a manager).
- [x] **Safety:** data from other programs is untrusted: text is validated as UTF-8 (invalid sequences become U+FFFD, counted), the length is capped (default 16 MiB, a setting-free constant documented), file-list entries are parsed as `file://` URIs with percent-decoding and rejected if they are not absolute local paths; no network URIs are followed.
- [x] **Fake-protocol tests:** the offer/receive state machines for both protocols with a scripted peer: round trip of ASCII, accents, a combining mark, a 4-byte emoji, an empty string, a 5 MiB text through INCR and through a pipe that stalls (continued across pumps), a peer that never answers (timeout), a peer that closes the pipe early, ownership lost during a transfer, two requests in flight, a request for a missing format, invalid UTF-8 from the peer, a hostile file list (`..`, relative, `http:`), oversize data.
- [x] **Real-server tests** (skip with a printed reason without a display): X11 between two connections of the same test process (set on one, request on the other), Wayland through the test compositor seam the existing Wayland tests use; the primary selection where available.
- [x] **Probe program:** `game/input_probe` (Day 186) gets keys to copy a string, paste and print what arrived, and show the formats on offer; tried by eye against another program (a terminal, a text editor) on both backends in both directions, recorded in this file.
- [x] **BACKEND checklist:** `engine/platform/BACKEND.md` lists the clipboard operations, events and format rules; Win32 (`OpenClipboard`, `CF_UNICODETEXT`, `CF_HDROP`, `WM_CLIPBOARDUPDATE`) and macOS (`NSPasteboard`) sections say "not implemented yet" and name Day 205 / Phase 26.
- [x] **Tests are written with the code:** every public behavior above has a test; GPU tests carry the `gpu` tag, use `FOR_EACH_GPU_BACKEND` and skip a backend that has no shaders (Vulkan only until Day 202 mints DXIL); every new test file has its line in `tests/phases.txt` (phase 15).

## Post-implementation code review

`/code-review high` over the day's diff: 9 findings. **Fixed (7), each with a test or a reason none is possible:**

1. `SIGPIPE` killed the process when a Wayland peer closed its pipe early. `PipeWriter` now blocks the signal around the write and takes a raised one off the pending set. Regression: "a pipe whose peer closes early" (the process died with exit 141 without the fix).
2. A `SelectionRequest` from a program that had already exited made `XChangeProperty` raise `BadWindow`, and Xlib's default handler ends the process. Answers now run in an `XErrorScope`. Regression: `X11Window survives a clipboard requestor that vanished before the answer` (confirmed to abort without the fix).
3. The selection released on destroy was not waited for, so it could clear the next owner on another connection (seen as a flaky `ClipboardHasFormat`). `XSync` after the release.
4. INCR sending called `XSelectInput` on the requestor, which replaces the whole mask when the requestor is our own window. Own requests are answered locally and the call is skipped for our own window.
5. `wl_data_device.release` is a version 2 request; the device is destroyed instead on version 1.
6. The property read offset counted the bytes of the `long` copy instead of 32-bit units of the property (wrong for lists above one chunk).
7. A selection owned before the window opened was never queried, so `ClipboardHasFormat` stayed false. Regression: "a window opened after another program took the clipboard knows its formats".

**Declined (2):** the Wayland transfer paths cannot be tested end to end (no test compositor; recorded in `KNOWN-ISSUES.md`); the X error handler is process-global, so a second thread using Xlib at the same moment would have its errors swallowed (the window is owner-thread-only, the scope is a few requests long, and the alternative, a per-display handler list, is not available in Xlib).
