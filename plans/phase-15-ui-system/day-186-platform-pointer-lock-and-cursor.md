# Phase 15 / Day 186 — Platform: Relative Pointer, Pointer Lock and Cursor Shape (Wayland and X11)

**Phase:** [Phase 15 — UI System](../phase-15-ui-system.md)
**Depends on:** Day 185.

What the viewport widget needs for camera control (hide the cursor and read relative motion) and what every widget needs to look right (resize arrows, a text I-beam).

## Tasks

- [x] **API on `os::Window`** (defaults do nothing and report false, so Win32 and macOS compile): `SetCursor(CursorShape)` with `CursorShape` = Arrow, IBeam, Hand, ResizeHorizontal, ResizeVertical, ResizeDiagonalNWSE, ResizeDiagonalNESW, ResizeAll, NotAllowed, Hidden; `SupportsCursorShape()`; `SetCursorImage(const CursorImage&)` / `ClearCursorImage()` / `SupportsCursorImage()` (a custom cursor from RGBA8 premultiplied pixels, a size up to 128x128 and a hotspot, copied by the window; it replaces the shape until cleared; a scale factor field picks the right size on HiDPI); `SetPointerLock(bool)` / `PointerLocked()` / `SupportsPointerLock()`; relative motion arrives as a new event `RelativeMotion{dx, dy}` (device units, unaccelerated where the server gives them) and only while locked.
- [x] **Wayland cursor shape:** bind `wp_cursor_shape_manager_v1` when the compositor offers it (generated bindings committed under `linux/wayland/generated/` with `VENDORED.md` updated, same pattern as xdg-shell); when it does not, load the cursor theme through `libwayland-cursor` only if that is already allowed by the plan's library line (it ships with the reference Wayland client library) - otherwise report `SupportsCursorShape() == false` and keep the default cursor; decide at implementation which, and file the other as the fallback in `KNOWN-ISSUES.md`.
- [x] **Custom cursor images:** Wayland through `wl_pointer.set_cursor` with a `wl_shm` buffer on a cursor surface (buffer scale from the window's scale; the image is re-set on every `wl_pointer.enter`, since the serial changes), X11 through `XcursorImageCreate`/`XcursorImageLoadCursor` (libXcursor, check against the plan's library line and `BUILD.md`; the fallback is `XRenderCreateCursor` or a 1-bit `XCreatePixmapCursor`, recorded if used); both cache by image hash and free on replace and on window destroy. The image is data, so a game can load it from its own assets; no image decoder is added here.
- [x] **Wayland pointer lock:** `zwp_pointer_constraints_v1` (lock the pointer, persistent lifetime off) and `zwp_relative_pointer_manager_v1` (relative motion events); generated bindings committed; the lock is released on focus loss and re-requested on focus gain if the caller still wants it; a compositor without the protocols reports `SupportsPointerLock() == false`.
- [x] **X11 cursor shape and lock:** `XDefineCursor` with the standard font cursors (`XCreateFontCursor`) cached per shape; pointer lock by `XGrabPointer` with a blank cursor, confine to the window, and **XInput2 raw motion** (`XI_RawMotion`, XInput2 is part of libX11's family `libXi`: check it against the plan's library line and file it in `BUILD.md`; if it is not acceptable, use grab + warp-to-center and record the limit); lock released on focus loss and on `Hidden`/`Arrow` restore.
- [x] **Safety:** a lock never outlives its window or process: destroying the window or a crash handler path releases the grab (X11 does it when the connection closes; the test checks `Destroy` releases it explicitly); a lock request while unfocused is remembered and applied on focus; a second request is a no-op.
- [x] **Tests:** a custom cursor of 1x1, 32x32 and 128x128 sets, replaces, clears and survives a focus change and a pointer re-enter (real servers; the validation and hash are pure tests), is refused above the size limit or with a hotspot outside the image, and does not leak (shm buffer and X cursor freed, counted); tests of the request/release state machine (`PointerLockState`, shared by both backends, so no fake protocol is needed) (focus loss, regain, double request, destroy while locked, compositor without the protocol); real-server tests on X11 (grab taken, raw motion arrives from an XTest motion, released on destroy) and, where the session's compositor supports it, Wayland; `SetCursor` on every shape does not fail and is idempotent.

## Notes

- **Decisions:** Wayland cursor shapes use `wp_cursor_shape_v1` (generated bindings, with `tablet-v2` for its interface table); `libwayland-cursor` is not used, so a compositor without the protocol reports `SupportsCursorShape() == false` (`Hidden` still works through `wl_pointer.set_cursor`). X11 uses `libXcursor` (theme cursors, ARGB images) and `libXi` (XInput 2 raw motion): X.org libraries of `libX11`'s family, noted in `PLAN.md` assumption #3, `BUILD.md` and `CLAUDE.md`. X11 has no cursor scaling, so `scale` only matters on Wayland.
- **Shared rules:** `platform/cursor.h` (`CursorShape`, `CursorImage`, `ValidateCursorImage`, `HashCursorImage`, `PointerLockState`) is pure data and logic in `platform_input`, so the lock rules and the image checks are tested without a display. `InputEventType::RelativeMotion` carries the deltas in `x`, `y`.
- **Unity build:** the X11 cursor code is `x11_cursor_impl.inc`, included by `x11_window.cpp`, not a translation unit: a second .cpp including the X11 headers in the same unity batch finds their guards set and their macros removed. `X.h`'s `CursorShape` macro is `#undef`ed after the X11 includes (and saved and restored by `x11_enable.h`/`x11_disable.h`).
- **Tests:** `tests/foundation/window_cursor_test.cpp` (pure + Wayland on the real compositor) and the X11 cases in `x11_window_test.cpp` (phase 1 label, for the X11 macro reason). There is no fake Wayland protocol (no seam exists): the Wayland tests check that the compositor accepts every request and that buffers do not leak. X11 raw motion cannot be injected (no XTest, warps make no raw events): only "never sent unlocked" is tested.
- **Runs** were made with `DBUS_SYSTEM_BUS_ADDRESS` pointing nowhere, because the desktop session was locked (the display tests skip on a locked session): plain `ran 1514 of 3830 tests (phases: all; flavors: plain; display: included; crash tests: excluded)`, asan `ran 1061 of 3830 tests (phases: all; flavors: asan; ...)`, tsan `ran 761 of 3830 tests (phases: all; flavors: tsan; ...)`; `ctest -L docs` 6 of 6; Clang unity, GCC and non-unity build clean.
- **Not done:** the by-eye check with `input_probe` on both backends (nobody at the machine: the session was locked); filed in `KNOWN-ISSUES.md`.
