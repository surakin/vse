# Phase 15 / Day 189 — The Canvas and the 2D Draw List (CPU)

**Phase:** [Phase 15 — UI System](../phase-15-ui-system.md)
**Depends on:** Day 184; Phase 14 (`text::Layout`, `GlyphAtlas`).

Widgets draw through an abstract `ui::Canvas`, never into a draw list directly (decided 2026-11-10, after Day 188): the canvas is the extension point, so a later backend (a recording canvas for tests and tooling, a vector or path canvas, a software rasteriser, an SVG exporter) replaces the implementation without touching a widget. The one implementation now is `ui::DrawListCanvas`, which turns every call into one `ui::DrawList`: vertices, indices and commands. Nothing here touches the GPU, so it is tested by reading the data.

## Tasks

- [ ] **`ui/canvas.h` (abstract):** `class Canvas` with pure virtual drawing operations in **logical units** and the state a widget needs: `DrawRect`, `DrawRoundedRect` (per-corner radii), `DrawBorder`, `DrawLine`, `DrawTriangle`, `DrawImage(rect, ImageId, uv rect, tint)`, `DrawText(layout, style, origin, color)`, `DrawShadow`, `PushClip`/`PopClip`, `BeginLayer(order)`/`EndLayer`, and queries `Scale()` (the surface's scale factor) and `PixelSnap` helpers so a widget can reason about whole pixels without knowing the backend. No `DrawList`, `Vertex`, GPU or RHI type in this header. The snapping and scaling rules (Day 184 spec section 1: rectangles snapped to whole pixels, borders and strokes rounded after scaling) are part of the canvas contract, written once in the header and kept by every implementation. Non-copyable, owner-thread only; the cost of a virtual call per primitive is accepted (hundreds to a few thousand per frame) and measured in the Day 206 bench.
- [ ] **`ui/draw_list_canvas.h`:** `DrawListCanvas : Canvas` holds a `DrawList*` (borrowed) and the clip and layer stacks; it converts logical to physical units with the scale, snaps as the contract says, and appends vertices, indices and commands. Everything below about the draw list is its implementation and is tested through it.
- [ ] **A recording canvas for tests (`ui/testing/recording_canvas.h`):** a second, trivial `Canvas` that records the calls (kind, rect, color, clip depth) so widget tests on Days 195-200 can assert "this button drew a rounded rect with the hover color" without reading vertices, and so the abstraction is exercised by two implementations from the start.
- [ ] **`ui/draw_list.h`:** `Vertex` (position in physical pixels, uv, packed RGBA color, and the parameters the rounded-rect shader needs - rect half size, corner radius, border width; the layout from Spike B: 40 bytes, a `flags` word whose low bits select the draw **mode** - rectangle SDF, glyph coverage, image color - per vertex, so rectangles and glyphs of a frame share one bound texture and merge into few commands, Day 184 spec section 6), `DrawCommand` (index offset and count, clip rectangle, `ImageId` or the glyph atlas page, a blend mode), `DrawList` owning `Vector<Vertex>`, `Vector<u32>` and `Vector<DrawCommand>`; `Clear()` keeps capacity so steady state allocates nothing.
- [ ] **Primitives (the `DrawListCanvas` side, named as the draw list has them; each `Canvas::Draw...` maps to one):** `AddRect(rect, color)`, `AddRoundedRect(rect, radius, color)` (per-corner radii), `AddBorder(rect, radius, width, color)`, `AddLine(a, b, width, color)`, `AddTriangle` (arrows in combo boxes and menus), `AddImage(rect, ImageId, uv rect, tint)`, `AddText(layout, style, origin, color)` (glyph quads from `text::PositionedGlyph` and the `GlyphAtlas`, whole-pixel placement as `TextRenderer` does), `AddShadow(rect, radius, blur, color)` for popups (a larger SDF quad).
- [ ] **Clip stack:** `PushClip(rect)` / `PopClip()` intersect with the parent; a command carries its clip rectangle; commands merge when their state is equal and a draw is added to the same texture, so a typical window is a handful of commands; an empty intersection drops the draw before any vertex is made.
- [ ] **Layers:** `BeginLayer(order)` so popups, tooltips and drag visuals draw above everything regardless of the order widgets were visited; layers sort by order, stable within an order, and the sorted result is what the renderer sees.
- [ ] **Text through the atlas:** a glyph the atlas cannot hold counts as dropped (same counters as `TextRenderer`); text above `kMaxAtlasPixelSize` scales as on Day 181; atlas pages are named in the command so the renderer binds the right texture.
- [ ] **Determinism and cost:** same input, same bytes (a golden of the vertex/index/command data for a fixed scene, in `tests/ui/golden/`); steady-state allocation test (the render-graph allocation counter, 100 frames of the same scene allocate nothing); budget numbers from Spike B reproduced here with a bench section in `game/renderer_bench` added on Day 206.
- [ ] **Tests (`tests/ui/draw_list_test.cpp`, `tests/ui/canvas_test.cpp`):** the same calls through `DrawListCanvas` and `RecordingCanvas` give matching records (a golden scene drawn through the abstract `Canvas&` into both); logical-to-physical conversion at scales 1, 1.25 and 2 (a 1-unit border is 1 and 2 pixels, never 1.5); each primitive's vertex count and bounds; clip intersection and the dropped empty clip; command merging; layer ordering; text quad positions equal `TextRenderer`'s for the same layout (the same function of layout and entry, tested against the text module directly); image and tint; huge counts (100k rects) stay within 32-bit indices and report overflow as a counter, never a wrap.
- [ ] **Tests are written with the code:** every public behavior above has a test; GPU tests carry the `gpu` tag, use `FOR_EACH_GPU_BACKEND` and skip a backend that has no shaders (Vulkan only until Day 205 mints DXIL); every new test file has its line in `tests/phases.txt` (phase 15).
- [ ] **Runs (CLAUDE.md "Tests run by phase"):** `scripts/test-phase.sh --affected` plain on Linux; then the asan and tsan flavors when the day touched lifetime, memory or concurrency code; quote each run's final `ran X of Y tests (phases ...)` line in this file. `ctest -L docs` when a public header or a guide changed. Build clean (warnings are errors) with Clang and GCC, unity on and off.
- [ ] **Two machines (CLAUDE.md "Windows is a supported platform"):** shared code is built and tested on the Windows PC before the phase closes (Day 205); a day done on one machine files "open until the other machine runs it" in `KNOWN-ISSUES.md`.
- [ ] **Documentation:** public headers carry `///` comments with the contract labels (`docs/DOC-CONVENTIONS.md`); `docgen lint` stays at zero; `cmake --build build --target docs` output committed; the guide page `docs/guide/ui.md` gains the day's section (tagged samples compile and run); new modules are in `docs/reference/modules.txt`.
- [ ] **Module rules:** `ARCHITECTURE.md`, `tools/module_deps_check/modules.txt` and `BUILD.md` updated in the same commit when a module, an edge or a prerequisite changed; `module_deps_check`, `platform_neutral_check`, `std_container_check`, `file_access_check` and `config_access_check` pass.

**Done:** widgets can draw a scene of rectangles, borders, images and text through the abstract `ui::Canvas`; the `DrawListCanvas` builds it into a deterministic, allocation-free-in-steady-state draw list that the tests read back, with clips and layers correct, and a second (recording) canvas implements the same interface.
