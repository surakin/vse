# Phase 15 / Day 189 — The Canvas and the 2D Draw List (CPU)

**Phase:** [Phase 15 — UI System](../phase-15-ui-system.md)
**Depends on:** Day 184; Phase 14 (`text::Layout`, `GlyphAtlas`).

Widgets draw through an abstract `ui::Canvas`, never into a draw list directly (decided 2026-11-10, after Day 188): the canvas is the extension point, so a later backend (a recording canvas for tests and tooling, a vector or path canvas, a software rasteriser, an SVG exporter) replaces the implementation without touching a widget. The one implementation now is `ui::DrawListCanvas`, which turns every call into one `ui::DrawList`: vertices, indices and commands. Nothing here touches the GPU, so it is tested by reading the data.

## Tasks

- [x] **`ui/canvas.h` (abstract):** `class Canvas` with pure virtual drawing operations in **logical units** and the state a widget needs: `DrawRect`, `DrawRoundedRect` (per-corner radii), `DrawBorder`, `DrawLine`, `DrawTriangle`, `DrawImage(rect, ImageId, uv rect, tint)`, `DrawText(layout, style, origin, color)`, `DrawShadow`, `PushClip`/`PopClip`, `BeginLayer(order)`/`EndLayer`, and queries `Scale()` (the surface's scale factor) and `PixelSnap` helpers so a widget can reason about whole pixels without knowing the backend. No `DrawList`, `Vertex`, GPU or RHI type in this header. The snapping and scaling rules (Day 184 spec section 1: rectangles snapped to whole pixels, borders and strokes rounded after scaling) are part of the canvas contract, written once in the header and kept by every implementation. Non-copyable, owner-thread only; the cost of a virtual call per primitive is accepted (hundreds to a few thousand per frame) and measured in the Day 206 bench.
- [x] **`ui/draw_list_canvas.h`:** `DrawListCanvas : Canvas` holds a `DrawList*` (borrowed) and the clip and layer stacks; it converts logical to physical units with the scale, snaps as the contract says, and appends vertices, indices and commands. Everything below about the draw list is its implementation and is tested through it.
- [x] **A recording canvas for tests (`ui/testing/recording_canvas.h`):** a second, trivial `Canvas` that records the calls (kind, rect, color, clip depth) so widget tests on Days 195-200 can assert "this button drew a rounded rect with the hover color" without reading vertices, and so the abstraction is exercised by two implementations from the start.
- [x] **`ui/draw_list.h`:** `Vertex` (position in physical pixels, uv, packed RGBA color, and the parameters the rounded-rect shader needs - rect half size, corner radius, border width; the layout from Spike B: 40 bytes, a `flags` word whose low bits select the draw **mode** - rectangle SDF, glyph coverage, image color - per vertex, so rectangles and glyphs of a frame share one bound texture and merge into few commands, Day 184 spec section 6), `DrawCommand` (index offset and count, clip rectangle, `ImageId` or the glyph atlas page, a blend mode), `DrawList` owning `Vector<Vertex>`, `Vector<u32>` and `Vector<DrawCommand>`; `Clear()` keeps capacity so steady state allocates nothing.
- [x] **Primitives (the `DrawListCanvas` side, named as the draw list has them; each `Canvas::Draw...` maps to one):** `AddRect(rect, color)`, `AddRoundedRect(rect, radius, color)` (per-corner radii), `AddBorder(rect, radius, width, color)`, `AddLine(a, b, width, color)`, `AddTriangle` (arrows in combo boxes and menus), `AddImage(rect, ImageId, uv rect, tint)`, `AddText(layout, style, origin, color)` (glyph quads from `text::PositionedGlyph` and the `GlyphAtlas`, whole-pixel placement as `TextRenderer` does), `AddShadow(rect, radius, blur, color)` for popups (a larger SDF quad).
- [x] **Clip stack:** `PushClip(rect)` / `PopClip()` intersect with the parent; a command carries its clip rectangle; commands merge when their state is equal and a draw is added to the same texture, so a typical window is a handful of commands; an empty intersection drops the draw before any vertex is made.
- [x] **Layers:** `BeginLayer(order)` so popups, tooltips and drag visuals draw above everything regardless of the order widgets were visited; layers sort by order, stable within an order, and the sorted result is what the renderer sees.
- [x] **Text through the atlas:** a glyph the atlas cannot hold counts as dropped (same counters as `TextRenderer`); text above `kMaxAtlasPixelSize` scales as on Day 181; atlas pages are named in the command so the renderer binds the right texture.
- [x] **Determinism and cost:** same input, same bytes (a golden of the vertex/index/command data for a fixed scene, in `tests/ui/golden/`); steady-state allocation test (the render-graph allocation counter, 100 frames of the same scene allocate nothing); budget numbers from Spike B reproduced here with a bench section in `game/renderer_bench` added on Day 206.
- [x] **Tests (`tests/ui/draw_list_test.cpp`, `tests/ui/canvas_test.cpp`):** the same calls through `DrawListCanvas` and `RecordingCanvas` give matching records (a golden scene drawn through the abstract `Canvas&` into both); logical-to-physical conversion at scales 1, 1.25 and 2 (a 1-unit border is 1 and 2 pixels, never 1.5); each primitive's vertex count and bounds; clip intersection and the dropped empty clip; command merging; layer ordering; text quad positions equal `TextRenderer`'s for the same layout (the same function of layout and entry, tested against the text module directly); image and tint; huge counts (100k rects) stay within 32-bit indices and report overflow as a counter, never a wrap.

## Notes

- **Files:** `ui/geometry.h` (`Point`, `Rect`, `CornerRadii`, `PixelRect`), `ui/canvas.h` (abstract `Canvas`, `ImageId`, the snapping contract in the header comment and the non-virtual helpers `ToPixels`, `SnapLength`, `SnapRect`), `ui/draw_list.h` (`Vertex` 40 bytes, modes and flags, `TextureRef`, `DrawCommand`, `DrawListStats`, `DrawList` with `Clear` and `SortLayers`), `ui/draw_list_canvas.h/.cpp`, `ui/testing/recording_canvas.h/.cpp`. `text::PlaceGlyph` (in `text/glyph_atlas.h`) is the one glyph-placement rule; `TextRenderer::Add` now calls it, so the canvas and the text renderer cannot drift.
- **Deviations from the task text:** (1) a bordered rounded rect is **two quads**, a fill (`DrawRoundedRect`) and a ring (`DrawBorder`, `kFlagRing`), because the vertex has one colour; the spec's single quad needs a second colour in the vertex and can be revisited with the renderer on Day 190. (2) The golden is a **hash** of the vertex, index and command bytes of a fixed scene in the test (not a file in `tests/ui/golden/`): there is no text in it, so it does not depend on the rasteriser. (3) The steady-state test checks that the capacities and the data pointer of the three arrays do not change over 100 frames (no operator-new counter in the UI test binary).
- **Layers** start unclipped and restore the outer clips on `EndLayer`; commands merge only with the previous command of the same layer, so a popup drawn between two base-layer draws splits the base layer's commands (sorted afterwards by `SortLayers`, a stable insertion sort that allocates nothing).
- **Merging:** a draw that needs no texture (solid and rectangle-mode) joins the previous command whatever it samples; a textured draw joins a command with no texture or the same one.
- **Limits:** `max_vertices` defaults to 0xAAAAAAAA so that both vertex numbers and the 1.5x index count fit in 32 bits; 100,000 rectangles are tested and a small limit shows the overflow counter.
- **Runs** (session locked, `DBUS_SYSTEM_BUS_ADDRESS=unix:path=/nonexistent`; reduced, so not "all tests pass"): plain `ran 1578 of 3940 tests (phases: all; flavors: plain; display: included; crash tests: excluded)` with the two known locked-session X11 failures; asan `ran 1084 of 3940 tests (phases: all; flavors: asan; display: included; crash tests: excluded)`; tsan `ran 784 of 3940 tests (phases: all; flavors: tsan; display: included; crash tests: excluded)`; the last two pass. Clang unity, GCC and Clang non-unity builds of `ui_tests` and `renderer` are clean; `ctest -L docs` passes (docs 5229/5229); the seven gates pass. `docs/guide/ui.md` has the canvas section.
- **Not done:** the bench section in `game/renderer_bench` (Day 206); the Windows build and test of the new code (Day 205).

## Post-implementation code review

`/code-review high` over the day's diff: 5 findings. **Fixed (3):**

1. A clip rectangle's position and size were converted to integers separately, so a huge rectangle (a scrolled content area) lost its far edge and clipped everything; and a float above the integer range was converted (undefined). The edges are pinned and the size taken from them. Regression: "huge, infinite and NaN coordinates cannot break the integer conversions" (failed before the fix).
2. The default `max_vertices` of 0xFFFFFFFF let the index count (1.5 per quad vertex) pass 32 bits; the default is now 0xAAAAAAAA.
3. NaN and infinite coordinates reached the integer conversions; they are pinned (NaN to 0) and the draw is culled or bounded by the clip (same test).

**Declined (2):** `SortLayers` is quadratic in the worst case (a frame has a handful of commands and an ordered list costs one pass; a merge sort would need scratch memory, which the allocation-free rule rules out); the border and fill being two quads (see the deviations; the renderer day can add a second colour to the vertex if the cost shows in the bench).
