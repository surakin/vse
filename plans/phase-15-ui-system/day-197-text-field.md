# Phase 15 / Day 197 — The Single-Line Text Field

**Phase:** [Phase 15 — UI System](../phase-15-ui-system.md)
**Depends on:** Days 185 (text events), 192, 194; Phase 14 Day 179 (`text/cursor.h`).

Editing text with grapheme-correct cursor and selection, the widget that proves Phase 14's cursor API.

## Tasks

- [x] **`TextField` model:** UTF-8 `String` text, cursor offset and selection anchor (byte offsets on grapheme boundaries only, via `text::NextBoundary`/`PreviousBoundary`), insertion of `Text` events, Backspace/Delete by cluster, Home/End, Left/Right by cluster, Ctrl+Left/Right by word (the `ui` word-boundary function decided on Day 184), Shift extends the selection, Ctrl+A selects all, Enter fires `OnSubmit`, Escape fires `OnCancel`, Tab moves focus (not inserted).
- [x] **Mouse:** click sets the cursor with `OffsetAtPoint`, drag with capture selects, double-click selects a word, triple-click all, I-beam cursor shape on hover, the click-time threshold and slop from the theme/surface.
- [x] **Scrolling inside the field:** when the text is wider than the field, the visible window follows the cursor with a margin and clips; selection rectangles from `SelectionRects`; caret drawn from `PositionOfOffset`, blinking from the surface clock (no blinking while the cursor moves, resets on input), blink off when unfocused.
- [x] **Editing rules:** maximum length (in clusters), a validator callback (accept/reject a proposed text before applying it - used by number fields and the settings screen), read-only mode (cursor and selection work, edits do not), password variant (bullets drawn instead of text, no copy), placeholder text when empty and unfocused.
- [x] **Undo/redo:** a bounded undo stack of edit operations (insert, delete, replace) with coalescing of consecutive typing; Ctrl+Z / Ctrl+Shift+Z (or Ctrl+Y).
- [x] **Clipboard:** Ctrl+C/X/V/Insert variants through a `ui::Clipboard` interface; today's implementation is the in-process one (used by offscreen surfaces and tests); the OS-backed implementation (`OsClipboard`, asynchronous paste, primary selection) is wired on Day 200 behind the same interface, so the text field does not change; the interface already has an asynchronous `RequestPaste(callback)` shape so the field is written for it from the start.
- [x] **Text events and IME:** only `Text` events insert; an unknown key does nothing; documented: no IME or complex-script input (the phase file's scope).
- [x] **`SpinBox` finished:** embeds a `TextField` with a numeric validator; arrows and wheel adjust; Enter commits; invalid text reverts on focus loss.
- [x] **Tests (`tests/ui/text_field_test.cpp`):** the Day 184 spike's cases made permanent - a combining mark, a flag, a ZWJ sequence and a Hangul syllable each move and delete as one unit; selection by shift and by mouse; word movement; undo coalescing; max length counts clusters; validator rejection leaves text unchanged; read-only; password draws bullets and refuses copy; caret position pixels equal `PositionOfOffset`; scrolling follows the cursor; blink timing from a fake clock; spin box commit and revert; a randomized edit sequence checked against a simple reference model (seeded).
- [x] **Tests are written with the code:** every public behavior above has a test; GPU tests carry the `gpu` tag, use `FOR_EACH_GPU_BACKEND` and skip a backend that has no shaders (Vulkan only until Day 205 mints DXIL); every new test file has its line in `tests/phases.txt` (phase 15).

## Notes

- **Where:** `engine/ui/widgets/text_field.h/.cpp` (`TextField`), `engine/ui/clipboard.h/.cpp` (`Clipboard`, `LocalClipboard`), `engine/ui/text_words.h/.cpp` (`ClassOf`, `WordStart`, `WordEnd`, `WordRangeAt`), `Surface::SetClipboard`/`GetClipboard`, `SpinBox` (embedded field, `Field()`, `Commit()`), `WithAlpha` and `IsAsciiDigit` in `widgets/look.h`; tests `tests/ui/text_field_test.cpp` (13 cases, with the seeded random sequence against a model); the "The text field" section of `docs/guide/ui.md`.
- **Calls made:** the foundation has no character-class table, so word classes are code point ranges (documented in `text_words.h`). Cluster stepping uses `text::NextBoundary`/`PreviousBoundary` over the field's layout (a byte-wise fallback when no font is available). A password field lays out a second run of bullets and maps offsets by cluster count. Multi-click is counted inside the field from event times (the events carry no click count). The spin box's own Home and End are gone: the embedded field uses them for the caret. A pasted text is cut at its first line break. Undo and redo from the keyboard are refused when the field is read-only. The undo history is bounded at 100 steps, so the random test undoes only as far as the history goes.
- **Runs:** plain `ran 1690 of 4259 tests (phases: all; flavors: plain; display: included; crash tests: excluded)`, asan `ran 1192 of 4259 tests (...asan...)`, tsan `ran 883 of 4259 tests (...tsan...)`; `ctest -L docs` passes; Clang, GCC, unity and non-unity clean.

## Post-implementation code review

`/code-review high`: 6 findings. Fixed: (1) undo and redo keys edited a read-only field (test fails without the fix); (2) typing after replacing a selection did not join the same undo step (test fails without the fix); (3) typing over a selection with the same text left the selection in place (caught by the random test against the model). Declined: a stationary pointer outside the field does not keep scrolling during a drag (needs an update tick during capture; filed); word classes are ranges, not a Unicode table (filed); no selection highlight while unfocused and the history keeps copies of every edit's text (bounded at 100 steps).
