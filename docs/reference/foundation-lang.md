# Foundation: Language support

**Headers:** `engine/foundation/lang/initializer_list.h`, `engine/foundation/lang/limits.h`, `engine/foundation/lang/new.h`, `engine/foundation/lang/ordering.h`, `engine/foundation/lang/scalar.h`, `engine/foundation/lang/traits.h`, `engine/foundation/lang/utility.h`

Brace-initializer lists (Phase 16): the engine's spelling of `<initializer_list>`. The compiler requires the standard type for `{a, b, c}` to convert to a parameter, so `InitializerList<T>` is an alias of it, not a distinct type.

Numeric limits (Phase 16): the engine's spelling of `<limits>`.

Allocation-function support (Phase 16): the engine's spelling of the parts of `<new>` that code outside the allocators needs.

Three-way comparison results (Phase 16): the engine's spelling of `<compare>`. A class that defines `operator<=>` returns `Ordering`.

Scalar math (Phase 16): the engine's spelling of `<cmath>`. Every function forwards inline to the standard one of the same meaning and has `f32` and `f64` forms (an integer argument converts to `f64`, as for the standard functions). Vector, matrix and quaternion types are in `math/`; these are the functions on one number. The `f64` overloads are new: `Sqrt`, `Sin`, `Cos` and `Acos` used to take only `f32`, so a `double` argument now keeps its precision instead of narrowing.

Type traits (Phase 16): the engine's spelling of `<type_traits>`. Variable templates are `IsX<T>`, type transformations are aliases `Remove...<T>`; each is exactly the standard facility of the same meaning.

Language-support utilities (Phase 16): the engine's spelling of `<utility>`. This header and the other `lang/` headers are the only files that include the standard library's language-support headers.
