## `Archetype` {#ecs-archetype}

`class ecs::Archetype` — defined in `engine/ecs/archetype.h`

```cpp
class Archetype { ... }
```

All entities with one set of components, in 32 KiB chunks of columns.

Rows are added at the end of the last chunk and removed by moving the archetype's last row into the gap, so rows stay dense and only the last chunk is partly filled. A new chunk is taken from the pool when the last is full; an emptied last chunk goes back at once. The archetype never allocates per entity. Row positions change on a removal: the caller keeps its entity table in step (it is told which entity moved).

| Field | Value |
|---|---|
| Thread-safety | thread-compatible. Reading columns from several threads is safe while no thread adds or removes rows. |
| Ownership | owns its chunks (returned to the pool by the destructor, which destroys the live components). The pool and the registry must outlive it. |

## `CommandBuffer` {#ecs-commandbuffer}

`class ecs::CommandBuffer` — defined in `engine/ecs/command_buffer.h`

```cpp
class CommandBuffer { ... }
```

A recording of structural changes to apply later, so a system can create, destroy and re-shape entities while a query is running.

Record with `Create`, `Destroy`, `Add`, `Remove` and `Set`; apply with [`ecs::World::Apply`](#ecs-world-apply-commandbuffer-amp) at a sync point. `Create` returns a **placeholder** entity (`Entity::IsPlaceholder()`): later commands in the same buffer may name it, and [`ecs::CommandBuffer::Resolve`](#ecs-commandbuffer-resolve-entity-const) gives the real entity after the buffer was applied. Component values are moved into the buffer when recorded and moved out when applied; a command that is never applied destroys its values when the buffer is cleared or destroyed.

The buffer keeps its memory between uses (`Clear` releases no storage), so a system that records every frame allocates only on the first frames. A buffer is not tied to a world: it holds no world pointer.

| Field | Value |

## `Query` {#ecs-query}

`class ecs::Query` — defined in `engine/ecs/query.h`

```cpp

```

A cached, typed selection of the entities that have the components the terms ask for, and none that a `Without` excludes.


The systems of a program, ordered, and the frame loop that runs them on one thread.

`Add` systems, `Build` once (a stable topological order: stages in the order made, within a stage the constraints, ties by registration order; a cycle is rejected with its path), then `Run` once per frame: each stage runs its systems in order, then applies their command buffers in registration order; the frame ends with `World::Advance`. A system that records `Destroy` of an entity another system `Add`s to in the same stage: the buffers apply in registration order, so the earlier system's commands take effect first and a later command on the dead entity is skipped and counted.

| Field | Value |
|---|---|
| Thread-safety | thread-compatible. |
| Ownership | owns the systems and their buffers; borrows the settings registry given to `UseSettings`. |

## `MakeTransformSystem(const char*)` {#ecs-maketransformsystem-const-char-star}

`function ecs::MakeTransformSystem` — defined in `engine/ecs/transform.h`

```cpp
SystemDesc MakeTransformSystem(const char* name);
```

The propagation as a system: reads `LocalTransform`, `Parent` and `HierarchyDepth`, writes `WorldTransform`, and writes the [`ecs::TransformReport`](#ecs-transformreport) resource.

Roots whose local transform changed get `local.ToMatrix()`. When anything changed, children are processed depth by depth (each depth in parallel when the system has the frame thread to itself), world = parent world * local, and a matrix is written, and its chunk stamped as written, only if it differs from the stored one; a frame where nothing changed costs a few `Changed` checks. Policies: a child whose parent was destroyed loses `Parent` and becomes a root; a child in a cycle, or deeper than 64, keeps its previous matrix (counted); a stored depth that disagrees with the parent's (a raw `Set<Parent>`) is recomputed from the chain, the child is processed at the right depth at once, and its own descendants catch up the next frame.

| Field | Value |
|---|---|
| Parameter `name` | a string literal naming the system. |
| Returns | the system; give it to [`ecs::Schedule::Add`](#ecs-schedule-add-systemdesc) (add `InStage` or `After` as needed). |
