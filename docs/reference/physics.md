Compound shapes: several shapes on one body, each with a local transform, a material and its own group and mask. The mass, the centre of mass and the inertia of the whole are computed once when the compound is made.

The height field of a collider: a grid of 16-bit height samples read in place, a pyramid of block minima and maxima over it, the surface the grid defines (two triangles a cell) and the queries on that surface; and the library a world keeps its fields in.

The field lives in its own space: x and z in metres from the CENTRE of the map (so the shape's bound is centred on the shape's origin like every other shape's), y in metres as the height. Sample `(i, j)` is at `(i * cell_size - half_x, height(i, j), j * cell_size - half_z)`. The terrain asset's own space starts at the first sample; its point `(x, z)` is this field's `(x - half_x, z - half_z)` (`HeightAtMap` takes the asset's coordinates).

The surface: the cell between samples `(cx, cz)` and `(cx + 1, cz + 1)` is cut along the diagonal from its minimum-x, minimum-z corner to its maximum-x, maximum-z corner into triangle `2 * cell` (corners `(0,0)`, `(1,1)`, `(1,0)`: the half where the fraction along x is at least the one along z) and triangle `2 * cell + 1` (corners `(0,0)`, `(0,1)`, `(1,1)`), both counter-clockwise seen from above, so their normals point up. A cell is `cz * (width - 1) + cx`. The height at a point is the plane of its triangle: the same function as `asset::HeightMapView::HeightAt`.

The contact solver of the physics module: sequential impulses with warm starting. Contacts become rows (a normal and two friction rows per point); the rows are solved in a fixed order, so the result does not depend on the order the narrow phase produced the manifolds in. Only `+ - * /` and `Sqrt` are used.

The static triangle mesh of a collider: an immutable, shared mesh with a bounding-volume hierarchy over its triangles (`spatial::StaticBvh`), face normals and the triangle across each edge, and the library a world keeps its meshes in.

## `Collide(const Shape&,const Pose&,const Shape&,const Pose&,f32,ContactManifold*,const HullLibrary*,const MeshLibrary*,const CompoundLibrary*,const HeightFieldLibrary*)` {#physics-collide-const-shape-amp-const-pose-amp-const-shape-amp-const-pose-amp-f32-contactmanifold-star-const-hulllibrary-star-const-meshlibrary-star-const-compoundlibrary-star-const-heightfieldlibrary-star}

`function physics::Collide` — defined in `engine/physics/collide.h`

```cpp
CollideResult Collide(const Shape& a, const Pose& pose_a, const Shape& b, const Pose& pose_b, f32 margin, ContactManifold* manifold, const HullLibrary* hulls = nullptr, const MeshLibrary* meshes = nullptr, const CompoundLibrary* compounds = nullptr, const HeightFieldLibrary* fields = nullptr);
```

Finds the contact between two shapes, the one entry point of the narrow phase.

The table, by the kinds of A and B (either order; the result is the same as for the other order, flipped): every pair of sphere, capsule and box is built by a closed form or the separating axis and every pair with a convex hull by GJK and EPA. A pair without a test returns `Unsupported` and leaves the manifold alone. Only `+ - * /` and `Sqrt` are used, so the result is bit-identical on every machine.

| Field | Value |
|---|---|
| Parameter `a` | shape A. |
| Parameter `pose_a` | where A is. |
| Parameter `b` | shape B. |
| Parameter `pose_b` | where B is. |
| Parameter `margin` | the contact margin, at least 0: shapes apart by less than this still make a contact, with a negative depth. |
| Parameter `manifold` | receives the contact when the result is `Contact`; not null. Its friction and restitution are not touched. |
| Parameter `hulls` | the library the hull shapes' ids refer to; may be null when neither shape is a hull (a hull that is not in it makes the result `None`). |
| Parameter `meshes` | the library the mesh shapes' ids refer to; may be null when neither shape is a mesh (a mesh that is not in it gives `None`). A mesh against a mesh is `Unsupported`. |
| Parameter `compounds` | the library the compound shapes' ids refer to; may be null when neither shape is a compound (a compound that is not in it gives `None`). A compound is collided child by child and the contacts merge (their feature ids carry the child indices). |
| Parameter `fields` | the library the height field shapes' ids refer to; may be null when neither shape is a height field (a field that is not in it gives `None`). A field against a field or a mesh is `Unsupported`. |
| Returns | `Contact`, `None` or `Unsupported`. |
| Fails | an invalid shape returns `None`. |
| Ownership | `manifold` is the caller's and the libraries are borrowed; nothing is kept. |

## `StateHasher` {#physics-statehasher}


## `SyncBodies(ecs::World&,PhysicsWorld&)` {#physics-syncbodies-ecs-world-amp-physicsworld-amp}

`function physics::SyncBodies` — defined in `engine/physics/sync.h`

```cpp
SyncReport SyncBodies(ecs::World& ecs, PhysicsWorld& physics);
```

Makes the physics world follow the ECS world.

It destroys the bodies of entities that are gone or lost their `RigidBody` or `Collider`, updates a body whose components changed, and creates a body for every new entity.

Entities are visited in entity order (index, then generation), not in chunk order, so two worlds built the same way get the same body ids. A new body starts at the entity's `LocalTransform` and `Velocity` (optional). An entity with a `Parent` is not simulated, except a **static** body: it is placed at the translation and rotation of its `ecs::WorldTransform` (the scale divided out of each column: the caller sizes the shape) and follows it, every call moving the body where the world matrix changed (`PhysicsWorld::SetTransform`, which wakes the bodies touching it, and the movable bodies touching it at the new place are woken too; counted in `replaced`). A world matrix with a column of zero length gives no body (counted as refused). The world matrix is the one the transform propagation last wrote: run it before this call. The call changes the ECS world's structure (it adds and removes `BodyLink`), so it runs between iterations, at a sync point.

| Field | Value |
|---|---|
| Parameter `ecs` | the ECS world. |
| Parameter `physics` | the physics world. |
| Returns | what was done. |
| Fails | an entity with invalid components is counted in `refused` and skipped. |
| Aborts | called while the ECS world is being iterated. |

## `DriveKinematicBodies(ecs::World&,PhysicsWorld&,f32)` {#physics-drivekinematicbodies-ecs-world-amp-physicsworld-amp-f32}

`function physics::DriveKinematicBodies` — defined in `engine/physics/system.h`

```cpp
u32 DriveKinematicBodies(ecs::World& ecs, PhysicsWorld& physics, f32 dt);
```

Sets the velocity of every kinematic body that has an entity so the next step carries it to the entity's `LocalTransform`.

This is how a program moves a platform or a door by moving its entity: the speed is the distance (and the small rotation, as an angular velocity) over `dt`, so the body pushes what is in its way and carries what stands on it instead of jumping. A kinematic body whose transform equals its pose gets no change (it stays asleep). Call it before `PhysicsWorld::Update`, once per update, with the update's `dt`; do not call it for a body whose velocity the program sets itself (a character controller's).

| Field | Value |
|---|---|
| Parameter `ecs` | the ECS world. |
| Parameter `physics` | the physics world. |
| Parameter `dt` | the time the move should take, in seconds, above zero (usually the fixed step). |
| Returns | the number of bodies whose velocity was set. |
| Fails | a non-positive or non-finite `dt` does nothing; an entity that has no body is skipped. |
| Aborts | called while the ECS world is being iterated. |
