## `BlockHasher` {#audio-blockhasher}

`class audio::BlockHasher` — defined in `engine/audio/block_hash.h`

```cpp
class BlockHasher { ... }
```

A running FNV-1a 64-bit hash of f32 samples.

A sample is hashed by its bit pattern in **little-endian byte order** whatever the machine's own order, with **-0.0 hashed as +0.0** (the sign of a zero that depends on the order of independent operations is not a difference a listener can hear). A NaN or an infinity is hashed as it is and makes `Valid()` false, because a mix that produced one has failed. Nothing but the samples is hashed: no block lengths, no padding. The hash equals the physics `StateHasher`'s over the same words (the same FNV-1a constants), but the audio module does not depend on physics, so it has its own.

| Field | Value |
|---|---|
| Thread-safety | thread-compatible; one hasher belongs to one thread. |
| Ownership | plain value; owns nothing. |

## `Limiter` {#audio-limiter}

`class audio::Limiter` — defined in `engine/audio/limiter.h`

```cpp
class Limiter { ... }
```

A look-ahead peak limiter on interleaved frames.

For each frame the limiter looks at the loudest sample of the next `lookahead_frames` frames, asks for the gain that holds it to the threshold, averages that gain over the look-ahead (so the gain moves in a ramp, not a step) and releases exponentially. Since every gain in the average was asked for by a window that contains the frame being output, **the output never exceeds the threshold**. Below the threshold the gain is exactly 1, so the signal passes bit for bit, delayed by the look-ahead. Arithmetic is `+ - * /` only.

| Field | Value |
|---|---|
| Thread-safety | thread-compatible; one thread processes. |
| Ownership | owns its delay line and histories; allocates in `Init` only. |

## `Mixer` {#audio-mixer}

`class audio::Mixer` — defined in `engine/audio/mixer.h`

```cpp
class Mixer { ... }
```

The mixer: a voice pool, the command queue and the block renderer.

Positions are 32.32 fixed point in `u64`, so a long clip does not drift; the interpolation (`+ - * /` only) is linear, 4-point Hermite or 16-tap windowed sinc. Voices are summed in slot order, never thread order. The output is not clipped: the master limiter and the device boundary do that (Day 422). A clip's channels are routed to the output layout: a mono clip pans over front left and right (equal power, centre gain 0.7071), a stereo clip on a layout with front left and right balances (centre gain 1), any other pair goes through the conversion table of `audio/convert.h`.

Two threads use a mixer. The **control thread** (the game) calls `Play`, `Stop`, the setters, `IsPlaying`, `PollEvents` and `SetWatermark`; the **audio thread** (the device callback) calls `RenderBlock`, `TryRenderBlock` and `Render`. The two sides share only the command ring, the event ring and two atomic counters, so no call locks, and the audio side allocates nothing. Every control call returns at once: a `Play` reserves its slot and generation on the control side (so the id can be used before the audio thread has seen the command) and posts the command, which takes effect at its block stamp. Every setter ramps over `MixerConfig::ramp_frames`, ending exactly on the target; a stop fades out before the voice is freed; the order of effect is the order posted.

A clip is released on the audio thread when its voice ends; keep another reference (the resource handle) while voices play, so that the audio thread never frees a clip.

| Field | Value |
|---|---|
| Thread-safety | thread-compatible; one control thread and one audio thread use it as described above, and `Position`, `VoiceCount` and `Stats` read audio-thread state, so they are for offline use or after the renderer has stopped. |
| Ownership | owns the voice pool, the rings and each voice's clip reference. |

## `SpeakerGains(ChannelLayout,f32,f32,f32,f32,f32*)` {#audio-speakergains-channellayout-f32-f32-f32-f32-f32-star}

`function audio::SpeakerGains` — defined in `engine/audio/panning.h`

```cpp
void SpeakerGains(ChannelLayout layout, f32 x, f32 y, f32 z, f32 spread, f32* gains);
```

The speaker gains of a mono source in `direction` from the listener.

The direction is in listener space (x right, y up, z forward) and need not be a unit vector. Stereo uses an equal-power law of the lateral position; quad, 5.1 and 7.1 use vector-based amplitude panning over the two speakers on either side of the direction (a 2x2 solve), normalised so the squares of the gains add to 1. Elevation and `spread` both blend toward every speaker at equal level; a direction without a horizontal part (overhead, or at the listener) spreads fully. The LFE channel gets 0. The gains vary continuously with the direction.

| Field | Value |
|---|---|
| Parameter `layout` | the output layout. |
| Parameter `x` | the direction's right component. |
| Parameter `y` | the direction's up component. |
| Parameter `z` | the direction's forward component. |
| Parameter `spread` | 0 for a point source to 1 for one that fills every speaker. |
| Parameter `gains` | receives `ChannelCount(layout)` gains, the rest 0. |
| Fails | a non-finite input gives a centred source. |

## `StreamBuffer` {#audio-streambuffer}

`class audio::StreamBuffer` — defined in `engine/audio/stream.h`

```cpp
class StreamBuffer { ... }
```

A ring of decoded frames between a refill job and one mixer voice.

The consumer (the audio thread) calls `Pop`, `Ended`, `Flush` and `SetLoop`; any one thread at a time calls `Refill` (a second caller returns at once). A flush bumps an epoch: frames written for an older epoch are never read. The samples a stream produces depend only on the source and the flushes, never on when `Refill` ran; only whether a block found them in time does (an underrun).

| Field | Value |
|---|---|
| Thread-safety | thread-compatible; one consumer thread and one producer at a time, as above. |
| Ownership | owns the source and the ring. |
