## `BlockHasher` {#audio-blockhasher}

`class audio::BlockHasher` — defined in `engine/audio/block_hash.h`

```cpp
class BlockHasher { ... }
```

A running FNV-1a 64-bit hash of f32 samples.

A sample is hashed by its bit pattern in **little-endian byte order** whatever the machine's own order, with **-0.0 hashed as +0.0** (the sign of a zero that depends on the order of independent operations is not a difference a listener can hear). A NaN or an infinity is hashed as it is and makes `Valid()` false, because a mix that produced one has failed. Nothing but the samples is hashed: no block lengths, no padding. The hash equals the physics `StateHasher`'s over the same words (the same FNV-1a constants), but the audio module does not depend on physics, so it has its own.

| Thread-safety | thread-compatible; one hasher belongs to one thread. |

## `AudioClip` {#audio-audioclip}

`class audio::AudioClip` — defined in `engine/audio/clip.h`

```cpp
class AudioClip { ... }
```

A clip: the samples and what they are, held as `f32` so the mixer converts nothing at play time.

A 3-minute stereo clip at 48 kHz is 69 MB as `f32` (35 MB as 16-bit); the spec chose `f32` and long clips stream instead (Day 435), so a clip above `kMaxClipFrames` is refused. The samples live in a [`SharedBytes`](foundation-containers.md#sharedbytes) and are named by an offset, never by a pointer, so a clip over a blob shares the blob's storage. Clips are immutable once made.

| Field | Value |
|---|---|
| Thread-safety | thread-safe to read once made. |
| Ownership | shares its bytes (`SharedBytesPtr`); shared by `AudioClipPtr`. |

## `BuildChannelMatrix(ChannelLayout,ChannelLayout)` {#audio-buildchannelmatrix-channellayout-channellayout}

`function audio::BuildChannelMatrix` — defined in `engine/audio/convert.h`

```cpp
ChannelMatrix BuildChannelMatrix(ChannelLayout from, ChannelLayout to);
```

Builds the table that converts `from` to `to`.

The rules: the same layout is the identity; a speaker the destination has goes to it with gain 1; mono goes to front left and front right with gain 1 each (a copy); a layout goes to mono through stereo with the gain 0.5 on each side (an average); a speaker the destination lacks is folded ITU-style with `kDownmixGain` (front center into both fronts, a back or side speaker into the front on its side or, for a side speaker, into the back on its side when the destination has one) and the LFE channel is dropped. Folding adds, so a loud 5.1 frame can exceed 1.0; the master limiter deals with it.

| Parameter `from` | the source layout. |
| Parameter `to` | the destination layout. |
| Returns | the table. |
| Thread-safety | thread-safe; pure. |
