# Foundation: Fundamental Types

_Generated by docgen. Do not edit._

**Headers:** `engine/foundation/int128.h`, `engine/foundation/types.h`

128-bit integers: [`u128`](#engine-int128-namespace-u128) and [`i128`](#engine-int128-namespace-i128).

Plain classes of two 64-bit halves with a defined layout and one defined behavior on every compiler and target (MSVC has no `__int128`). Where the compiler has `unsigned __int128` the operators use it internally; elsewhere, or when `ENGINE_FORCE_PORTABLE_INT128` is defined, they use portable algorithms (carry arithmetic, 32-bit partial products, Knuth algorithm D) that are tested against the native type. `ENGINE_HAS_NATIVE_INT128` says which one this translation unit uses.

Where the builtin type's behavior is undefined this one is defined: `+ - *` and unary minus wrap modulo 2^128 (also for [`i128`](#engine-int128-namespace-i128)), a shift by 128 or more gives 0 (or the sign fill for `i128 >>`), and division truncates toward zero.

The engine's type vocabulary, used instead of the raw standard names so every layer agrees on exact widths.

| Need | Type | |---|---| | a raw byte, or a buffer of them | `byte` (an alias of `u8`; a buffer is `Vector<byte>`, a view is `ByteSpan`) | | 8, 16, 32, 64-bit integers | `i8`..`i64`, `u8`..`u64` (aliases of the `<cstdint>` types) | | 128-bit integers | `i128`, `u128` (classes in `int128.h`: the same behavior on every compiler, with `__int128` inside where it exists) | | an object size or an index | `usize`; the signed difference of two pointers is `isize` | | floating point | `f32`, `f64` | | truth | native `bool` |

Code the project owns does not spell `unsigned char`, `uint8_t` and the like; the `std_container_check` gate (Phase 10 Day 129) will reject them.
