# Foundation: Paths and Files

_Generated by docgen. Do not edit._

**Headers:** `engine/foundation/io/error.h`, `engine/foundation/io/file_system.h`, `engine/foundation/io/path.h`

Errors of the file layer, reported as values: [`io::Error`](#io-error) and [`io::Status`](#io-status).

Operations on paths: looking at the disk, creating, removing and renaming, resolving, and the special folders.

Every function returns a [`io::Status`](#io-status) (or a bool for pure questions) and never throws or aborts on a bad path; the lexical part of a path stays in [`io::Path`](#io-path). Functions follow symbolic links unless their name or comment says otherwise.

Lexical path manipulation: [`io::Path`](#io-path), [`io::PathBuilder`](#io-pathbuilder) and [`io::PathStyle`](#io-pathstyle).

Nothing here touches the disk or the operating system: a path is a value, and every operation is a function of its text. Operations that need the file system (absolute, canonical, exists, symbolic links) live in the file-system helpers. The rules were fixed by a table of 60 inputs per style (`docs/superpowers/specs/2026-11-06-file-layer-design.md`, Appendix A) and are tested against it.

## `Path` {#io-path}

`class io::Path` — defined in `engine/foundation/io/path.h`

```cpp
class Path { ... }
```

A value type holding a UTF-8 path in canonical form: `/` as the only separator, repeated and trailing separators removed (so a path never ends in a separator except a root, and no operation adds one), a `PathStyle` that decides how the text is read.

Canonical form does not resolve `.` or `..` (see [`Path::Normalize`](#io-path-normalize-const)) and never changes the case of a name. The empty path is a valid value meaning "no path"; it is not the same as `.`. Equality, ordering and hashing follow the style: POSIX compares bytes, Windows compares ASCII letters case-insensitively and every other byte exactly.

Memory comes from the default heap allocator; copying, `Parent`, `Normalize` and the builders allocate and abort when the allocator is out of memory. For code that cannot allocate use [`PathBuilder`](#io-pathbuilder).

| Field | Value |
|---|---|
| Thread-safety | thread-compatible. Const operations are safe from many threads. |
| Ownership | owns its text. |

## `PathBuilder` {#io-pathbuilder}

`class io::PathBuilder` — defined in `engine/foundation/io/path.h`

```cpp
template <usize Capacity>
class PathBuilder { ... }
```

A path in a fixed buffer of `Capacity` bytes, for code that cannot allocate (early startup, signal-adjacent code). It has the same canonical form and rules as [`Path`](#io-path); it exposes the operations such code needs.

`Set` and `Append` use temporary arrays of `Capacity` bytes on the stack (two for `Append`) besides the member buffer, so a large capacity costs stack; pick the smallest that fits.

| Field | Value |
|---|---|
| Thread-safety | thread-compatible. |
| Ownership | owns its buffer (inline). |
