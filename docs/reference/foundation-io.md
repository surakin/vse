Errors of the file layer, reported as values: [`io::Error`](#io-error) and [`io::Status`](#io-status).

[`io::File`](#io-file): an open file as an abstract interface, so the same code reads a local file, a pak entry or a file on a server. Only the local file exists now. Also the helpers that work through any `File`, the scheme registry that picks a backend, and [`io::WriteFileAtomic(const Path&,const void*,usize,u32)`](#io-writefileatomic-const-path-amp-const-void-star-usize-u32).

Operations on paths: looking at the disk, creating, removing and renaming, resolving, and the special folders.

Every function returns a [`io::Status`](#io-status) (or a bool for pure questions) and never throws or aborts on a bad path; the lexical part of a path stays in [`io::Path`](#io-path). Functions follow symbolic links unless their name or comment says otherwise.

Lexical path manipulation: [`io::Path`](#io-path), [`io::PathBuilder`](#io-pathbuilder) and [`io::PathStyle`](#io-pathstyle).

Nothing here touches the disk or the operating system: a path is a value, and every operation is a function of its text. Operations that need the file system (absolute, canonical, exists, symbolic links) live in the file-system helpers. The rules were fixed by a table of 60 inputs per style (`docs/superpowers/specs/2026-11-06-file-layer-design.md`, Appendix A) and are tested against it.

## `Directory` {#io-directory}

`class io::Directory` — defined in `engine/foundation/io/directory.h`

```cpp
class Directory { ... }
```

An open directory that yields its entries one at a time, so a directory of a million files costs one entry of memory.

The order of entries is unspecified (it is the file system's). Use [`io::ListDirectory`](#io-listdirectory-const-path-amp-bool-vector-lt-directoryitem-gt-star) with `sorted` when you need a stable order, for example in tools whose output must be reproducible. Entries created or removed while iterating may or may not be seen, and an entry is never returned twice; nothing crashes.

| Field | Value |
|---|---|
| Thread-safety | thread-compatible; one thread iterates one directory. Ownership: owns the open directory; closes it on destruction. Move-only. |

## `File` {#io-file}

`class io::File` — defined in `engine/foundation/io/file.h`

```cpp
class File { ... }
```

An open file. Implemented per backend; use [`io::File::Open`](#io-file-open-const-path-amp-openmode-u32-fileptr-star) to get one.

Offsets are 64-bit. `Read` and `Write` at an offset carry no shared state, so many threads may read different (or the same) offsets of one file at once. The stream operations (`Seek`, `Tell`, the offset-less `Read` and `Write`) share one position: use them from one thread. No operation exposes a descriptor or handle.

After `Close`, every operation except `Close` fails with `Invalid`; `Close` is idempotent. The destructor closes the file and logs a failed close (it cannot report it): call `Close` yourself where the result matters.

| Field | Value |
|---|---|
| Thread-safety | thread-compatible; offset reads and writes may run concurrently, everything else needs external synchronization. |
| Ownership | owned through `FilePtr`; not copyable. |

## `WriteFileAtomic(const Path&,const void*,usize,u32)` {#io-writefileatomic-const-path-amp-const-void-star-usize-u32}

`function io::WriteFileAtomic` — defined in `engine/foundation/io/file.h`

```cpp

```

Replaces the contents of `path` so that a reader sees the old file or the new one, never a mix, and a crash leaves one of them.

Writes a temporary file in the same directory, flushes and syncs it, then renames it over `path`. The temporary is removed on every failure path, and the directory is synced after the rename so the new entry survives a crash. A symbolic link at `path` is followed (the file it points to is replaced, the link stays). The replacement is a new file: a replaced file keeps its permission bits, but its owner, hard links, ACLs and extended attributes are not carried over (the writing user owns the result). ## `Path` {#io-path}

`class io::Path` — defined in `engine/foundation/io/path.h`

```cpp
class Path { ... }
```

A value type holding a UTF-8 path in canonical form: `/` as the only separator, repeated and trailing separators removed (so a path never ends in a separator except a root, and no operation adds one), a `PathStyle` that decides how the text is read.

Canonical form does not resolve `.` or `..` (see [`Path::Normalize`](#io-path-normalize-const)) and never changes the case of a name. The empty path is a valid value meaning "no path"; it is not the same as `.`. Equality, ordering and hashing follow the style: POSIX compares bytes, Windows compares ASCII letters case-insensitively and every other byte exactly.

Memory comes from the default heap allocator; copying, `Parent`, `Normalize` and the builders allocate and abort when the allocator is out of memory. For code that cannot allocate use [`PathBuilder`](#io-pathbuilder).

| Field | Value |
|---|---|
| Thread-safety | thread-compatible. Const operations are safe from many threads. |
| Ownership | owns its text. |

## `PathBuilder` {#io-pathbuilder}

`class io::PathBuilder` — defined in `engine/foundation/io/path.h`

```cpp
template <usize Capacity>
class PathBuilder { ... }
```

A path in a fixed buffer of `Capacity` bytes, for code that cannot allocate (early startup, signal-adjacent code). It has the same canonical form and rules as [`Path`](#io-path); it exposes the operations such code needs.

`Set` and `Append` use temporary arrays of `Capacity` bytes on the stack (two for `Append`) besides the member buffer, so a large capacity costs stack; pick the smallest that fits.

| Field | Value |
|---|---|
| Thread-safety | thread-compatible. |
| Ownership | owns its buffer (inline). |
