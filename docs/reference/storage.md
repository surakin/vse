# Storage

**Headers:** `engine/storage/builtin_components.h`, `engine/storage/component_record.h`, `engine/storage/component_registry.h`, `engine/storage/entity_ref.h`, `engine/storage/field.h`, `engine/storage/identity.h`, `engine/storage/status.h`, `engine/storage/storage_settings.h`

The engine's own components, registered for storage (Phase 19 Day 256): the transform and hierarchy of `ecs` and the membership and bounds of `spatial`. Ids below 1000 belong to this file; a game registers its own components from 1000 up.

One stored component of one entity, framed: [`storage::ComponentRecord`](#storage-componentrecord) (id, version, bytes) and its read and write (Phase 19 Day 257). The entity container of Day 260 is a count followed by these. A record the process does not know is carried as [`storage::OpaqueComponent`](#storage-opaquecomponent) and written back unchanged.

[`storage::ComponentRegistry`](#storage-componentregistry) (Phase 19 Day 256): how each component type is stored. A component is registered once with a stable numeric id written in code, a unique name, a version and a list of fields ([`storage::Field`](#storage-field-const-char-star-fieldoptions)); the registry encodes and decodes one component value to and from the canonical bytes, finds a registration by id, name or ECS type, and lists the component types a world holds that nobody registered.

The stored identity of an entity, as a field type: [`storage::EntityKey`](#storage-entitykey) (128 bits) and [`storage::EntityRef`](#storage-entityref) (a reference to another entity by key). Day 256 declares the types and their encoding (16 bytes); Day 258 adds key generation, the key index and the resolution of references on load.

Field descriptions (Phase 19 Day 256): [`storage::Field`](#storage-field-const-char-star-fieldoptions) describes one member of a component by pointer to member, and carries the functions that write it to and read it from the canonical encoding (`foundation/bytes/`). A member whose type has no encoding fails to compile: nothing is skipped silently.

Stable identities for entities (Phase 19 Day 258): [`storage::KeyGenerator`](#storage-keygenerator) draws keys, [`storage::EntityKeyComponent`](#storage-entitykeycomponent) gives an entity one, [`storage::KeyIndex`](#storage-keyindex) maps keys to entities and back, and [`storage::ResolveReference`](#storage-resolvereference-const-keyindex-amp-entitykey-missingpolicy-referencereport-star-ecs-entity-star), [`storage::CaptureParents`](#storage-captureparents-ecs-world-amp-const-keyindex-amp-parentreport-star) and [`storage::ApplyParents`](#storage-applyparents-ecs-world-amp-const-keyindex-amp-missingpolicy-parentreport-star) turn stored references back into entities.

Errors of the storage layer, reported as values: [`storage::ErrorCode`](#storage-errorcode) and [`storage::Status`](#storage-status). No storage failure aborts, and no input, however damaged, is a reason to abort.

The storage settings (Phase 19 Day 257): [`storage::RegisterStorageSettings`](#storage-registerstoragesettings-settings-registry-star) declares the four limits that bound every decode, and [`storage::LimitsFromSettings`](#storage-limitsfromsettings-const-settings-registry-amp) turns them into [`storage::CodecLimits`](#storage-codeclimits). Day 264 adds the rest (path, layout, autosave).
