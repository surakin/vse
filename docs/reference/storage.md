## `AsyncSave` {#storage-asyncsave}

`class storage::AsyncSave` — defined in `engine/storage/async_storage.h`

```cpp
class AsyncSave { ... }
```

A save in progress: the writer job is running (or has finished) and the session still has to learn the outcome.

A save is two steps. `WorldStorage::SaveAsync` reads the world (encoding on the workers) and returns; the writer job then owns the store until it is done. `Finish` (or `Wait`) reports how it went and, for a save with a session, brings the session up to date; call it on the thread that owns the world and the session, before the next save with that session. A handle destroyed without `Finish` waits for the writer, then, if the save succeeded, brings the session up to date on the destroying thread (so that thread must own the world and the session, as for `Finish`).

| Field | Value |
|---|---|
| Thread-safety | thread-compatible; `IsDone` is thread-safe, `Wait` belongs to the main thread of the scheduler, and `Finish` is called by one thread at a time. |
| Ownership | borrows the `WorldStorage` (and through it the store), the scheduler and the session of the options, all of which must outlive it; owns the encoded records. |

## `SqlStore` {#storage-sqlstore}

`class storage::SqlStore` — defined in `engine/storage/sql_store.h`

```cpp
class SqlStore final : public Store { ... }
```

The record store on a [`database::Connection`](database.md#database-connection): one table holds the records, one the metadata, and, in column layout, one table per queryable component.

- `entity(key BLOB PRIMARY KEY, seq INTEGER NOT NULL, hash BLOB NOT NULL, data BLOB NOT NULL)`: the key as 16 bytes big-endian (so the database's order is key order), the number of the write that stored it, the content hash as 8 bytes big-endian, and the record's bytes;
- `meta(key TEXT PRIMARY KEY, value BLOB)`.

(A database migrated in place by `ALTER TABLE ... ADD COLUMN` has `seq` without `NOT NULL`, the rebuild path has it with; the store does not depend on the difference.)

**Column layout.** With `SqlStoreOptions::columns`, a component flagged `kComponentQueryable` also gets `c_<name>(key BLOB PRIMARY KEY REFERENCES entity(key) ON DELETE CASCADE, one column per scalar or vector field)`: integers, booleans and enums are `INTEGER` (a `u64` as its bit pattern), `f32`/`f64` are `REAL` (a NaN is stored as NULL), a `Vec2`/`Vec3`/`Vec4`/`Quaternion` is one `REAL` column per part (`<field>_x`, `_y`, `_z`, `_w`); strings, arrays, matrices, boxes and references stay in the blob only. The blob remains the source of truth: a load reads it alone, so both layouts load the same world. The tables follow the registry: a new field is added with `ALTER TABLE ADD COLUMN` where the connection supports it, otherwise the table is rebuilt, and in both cases refilled from the blobs inside the transaction `Open` makes. Opening a database that was last written without columns refills every table from the blobs. Table and column names come from the registry and must be plain identifiers (`Open` returns `Invalid` otherwise); they are the only SQL text not written as a literal, and all values are bound.

Only the portable statement subset of the storage design (section 4c) is used, every statement is prepared once when the store opens and data is only bound. The schema version is the connection's (`Connection::SchemaVersion`) and is also written to the metadata (`schema_version`); `Open` applies the missing migration steps in one transaction, and a database with a newer schema than this program knows is refused with `TooNew` and left as it was.

A store borrows its connection and uses it alone: while a batch is open, every call from another thread returns `Busy` (one connection cannot show committed state to readers while it holds a transaction); without a batch any thread may call, one at a time.

| Field | Value |
|---|---|
| Thread-safety | thread-safe; one internal lock around the connection. |
| Ownership | borrows the connection, which must outlive the store; owns its prepared statements. |

## `Store` {#storage-store}

`class storage::Store` — defined in `engine/storage/store.h`

```cpp
class Store { ... }
```

A record store: entity records in key order, batches, and metadata.

**Batches.** `Begin` opens an all-or-nothing batch: `Put`, `Remove` and `SetMetadata` made after it become visible together at `Commit` and not at all after `Rollback`. Outside a batch each mutation is its own batch. A mutation that fails inside a batch leaves the batch open; the caller rolls it back.

**Threads.** One writer at a time: mutations, `Begin`, `Commit` and `Rollback` come from one thread (the one that called `Begin` while a batch is open; a mutation from another thread while a batch is open is `Busy`). Readers (`Get`, `Scan`, `Count`, `GetMetadata`) may run on any thread at any time and see the last committed state, except that the thread that owns the open batch sees its own uncommitted changes.

| Field | Value |
|---|---|
| Thread-safety | thread-safe as described above; the implementation locks internally. |
| Ownership | a store owns its records; results are copied out. |
