[`net::Address`](#net-address): an IPv4 or IPv6 address as a value, with strict parsing, canonical formatting and classification. No syscalls, no allocation.

Asynchronous socket operations for coroutines: [`net::Accept`](#net-accept-reactor-amp-socket-amp-socket-star-endpoint-star-waitoptions), [`net::Connect`](#net-connect-reactor-amp-socket-amp-const-endpoint-amp-waitoptions), [`net::Receive`](#net-receive-reactor-amp-socket-amp-mutablebytespan-waitoptions), [`net::Send`](#net-send-reactor-amp-socket-amp-bytespan-waitoptions), [`net::ReceiveFrom`](#net-receivefrom-reactor-amp-socket-amp-mutablebytespan-endpoint-star-waitoptions) and [`net::SendTo`](#net-sendto-reactor-amp-socket-amp-bytespan-const-endpoint-amp-waitoptions).

Each is a [`jobs::Task`](jobs.md#jobs-task): `co_await` it from a job (or another task) and it returns an [`net::IoResult`](#net-ioresult). It tries the non-blocking operation of the [`net::Socket`](#net-socket) first; when that would block it waits on the [`net::Reactor`](#net-reactor) (so the coroutine is resumed on a participant, never on the reactor thread) and tries again, until the operation finishes, fails, times out or is cancelled. The arguments are borrowed for the whole operation: the socket, buffers and endpoints must stay alive and unmoved until the `co_await` returns, which is the case when the task is awaited in the expression that creates it.

The timeout of a [`net::WaitOptions`](#net-waitoptions) covers the whole operation, not each wait: a [`net::Send`](#net-send-reactor-amp-socket-amp-bytespan-waitoptions) that trickles data still ends when the time is up. Only one coroutine may wait for each direction of a socket at a time.

[`net::CancelToken`](#net-canceltoken): cancels the waits and operations that were started with it.

The time source of the networking layer: [`net::Clock`](#net-clock), the real [`net::MonotonicClock`](#net-monotonicclock) and the test double [`net::ManualClock`](#net-manualclock).

The wire vocabulary of messages: [`net::NetWriter`](#net-netwriter) and [`net::NetReader`](#net-netreader), a bit-packed encoding with ranged integers, canonical varints, length-limited strings and byte arrays, and quantized floats, vectors, rotations and angles, plus deltas against a baseline.

**Layout.** Bits are packed from the least significant bit of byte 0 upward; a value's low bit comes first. A fixed-width integer written at a byte boundary is therefore exactly the little-endian encoding of [`bytes::ByteWriter`](foundation-bytes.md#bytes-bytewriter). Nothing is padded unless [`net::NetWriter::AlignToByte`](#net-netwriter-aligntobyte) is called, which writes zero bits that the reader requires to be zero (one valid encoding of every message).

**Errors are values** ([`net::CodecError`](#net-codecerror)). A failed write or read changes nothing: the position stays where it was and the reader remains usable. Every length and count has a mandatory maximum; nothing is allocated for a length before it is checked against both the maximum and the bytes that remain.

**Quantization is deterministic**: the arithmetic is done in `f64` with every intermediate product stored before it is used again, so no compiler can fuse a multiply and an add differently on another platform.

[`net::DatagramPort`](#net-datagramport): the datagram I/O the UDP transport runs over, so the same transport code runs on a real UDP socket ([`net::SocketDatagramPort`](#net-socketdatagramport)) and on the simulated network ([`net::SimDatagramPort`](#net-simdatagramport)).

[`net::Endpoint`](#net-endpoint) (an address and a port) and [`net::EndpointSet`](#net-endpointset) (a bounded list of them, for resolver results). Values; no syscalls, no allocation.

Length-prefixed framing for byte streams: [`net::FrameWriter`](#net-framewriter) and [`net::FrameReader`](#net-framereader).

A frame is a 4-byte big-endian length followed by that many payload bytes. A frame carries at least one byte and at most `max_frame_bytes`; the limit is checked on the length, before any buffer is sized for the payload, so a hostile peer cannot make the reader allocate by announcing a large frame (the payload buffer grows only with bytes that really arrived). The reader accepts the stream cut at any place, down to one byte at a time.

[`net::Listener`](#net-listener): a listening socket with the accept loop's policy: back off when the process is out of descriptors, and a cap on connections that were accepted but are not yet handled.

The networking settings (Phase 20 Day 281): [`net::RegisterNetSettings`](#net-registernetsettings-settings-registry-star) declares every `net.*` option once, and the `...FromSettings` functions turn the current values into the configuration structs of the transports, the TCP stream and the simulated network. Nothing in `engine/net` reads the environment or the command line itself (`config_access_check`): a user sets `net.max_connections` in a settings file, in `ENGINE_NET_MAX_CONNECTIONS` or with `--net-max-connections`.

[`net::Poller`](#net-poller): the platform's readiness primitive, one per [`net::Reactor`](#net-reactor). The only file of the readiness code that differs between operating systems (epoll on Linux, `select` on Windows, kqueue on macOS).

[`net::RateLimiter`](#net-ratelimiter): token buckets per address and in total, and a ban list with expiry, in memory that never grows.

The transports ask it before they spend work or memory on a stranger: a handshake packet (UDP), an accepted stream (TCP). A request is allowed when the address's bucket and the global bucket both hold a token. An address that misbehaves (a cookie that does not check, a stream that breaks the protocol before its handshake is done) is given a strike; enough strikes ban it for a while and everything it sends is refused without further work.

**Time.** Buckets refill from the caller's [`net::Clock`](#net-clock) time (nanoseconds, never going back), so a test with a manual clock decides exactly what is allowed. A bucket holds at most `burst` tokens and refills at `rate` per second.

**Memory.** The per-address state lives in a table of `max_addresses` entries allocated once. An address hashes to a bucket of 8 entries; a new address takes a free or idle entry of its bucket, else the entry seen longest ago that is not banned. An attacker that rotates through many addresses can therefore push other addresses' state out (they start again with a full bucket) but never grows the table; the global bucket still bounds the total rate, and a ban lasts until it expires unless the bucket holds nothing but bans.

[`net::Reactor`](#net-reactor): readiness and timers for sockets, on the job system.

One dedicated thread waits in the platform's poller ([`net::Poller`](#net-poller)) for armed sockets and for the nearest timer. A coroutine `co_await`s a wait ([`net::Reactor::WaitReadable`](#net-reactor-waitreadable-const-socket-amp-waitoptions), [`net::Reactor::WaitWritable`](#net-reactor-waitwritable-const-socket-amp-waitoptions), [`net::Reactor::Sleep`](#net-reactor-sleep-u64-waitoptions)); when the wait ends, the reactor hands the coroutine to [`jobs::Scheduler::Schedule`](jobs.md#jobs-scheduler-schedule-coroutinehandle-lt-gt), so it resumes on a participant. The reactor thread runs no continuation of yours, and there is no thread per connection.

Every wait ends exactly once with one [`net::Status`](#net-status): `Ok` (the socket is ready to try again; the operation itself then reports a real error), [`net::ErrorCode::TimedOut`](#net-errorcode-timedout), [`net::ErrorCode::Cancelled`](#net-errorcode-cancelled) (a [`net::CancelToken`](#net-canceltoken), or the reactor was shut down), [`net::ErrorCode::Closed`](#net-errorcode-closed) ([`net::Reactor::Forget`](#net-reactor-forget-const-socket-amp) or [`net::Reactor::Close`](#net-reactor-close-socket-amp) ran for the socket), or [`net::ErrorCode::Invalid`](#net-errorcode-invalid) (the socket is not open, or another coroutine already waits for the same direction of the same socket). The rules that make this safe:

- a socket that is already ready when the wait starts completes at once (the check is by level, not by edge);
- a cancel racing with a completion has one outcome, decided under the reactor's lock;
- a socket must be closed through [`net::Reactor::Close`](#net-reactor-close-socket-amp) while coroutines may wait for it (closing the descriptor behind the reactor's back would leave them waiting for ever);
- [`net::Reactor::Shutdown`](#net-reactor-shutdown) completes every wait with Cancelled.

The reactor must be shut down (or destroyed) before the scheduler it was given, because it schedules the continuations. On Linux the poller is epoll; on Windows it is a `select` poller.

[`net::Signal`](#net-signal): a one-shot event that another thread fires and a coroutine waits for.

[`net::SimDatagramPort`](#net-simdatagramport): a [`net::DatagramPort`](#net-datagramport) attached to a [`net::SimNetwork`](#net-simnetwork).

[`net::SimNetwork`](#net-simnetwork): a deterministic in-process packet network for tests, with impairments per direction, driven by a clock that moves only when the test says so.

Packets go from one [`net::Endpoint`](#net-endpoint) to another through a link that can add latency and jitter, drop packets (uniformly or in bursts), reorder, duplicate and corrupt them, cap the bandwidth with a bounded queue, and refuse packets above an MTU. Every random choice comes from one seeded generator, and packets in flight are ordered by (delivery time, order of sending), so the same seed and the same calls give the same packet trace byte for byte.

Time moves in whole ticks of one millisecond: [`net::SimNetwork::Advance`](#net-simnetwork-advance-u64) delivers the packets that are due and calls [`net::PacketSink::OnTick`](#net-packetsink-ontick-u64) on every attached sink, tick by tick.

[`net::SimStreamNetwork`](#net-simstreamnetwork): a deterministic in-process model of TCP streams for tests: reliable, in-order bytes with a one-way latency, a bounded send buffer (so writes are partial and block), reads of at most a few bytes at a time on request, an orderly end of stream and refused connections. It has no loss: TCP hides loss from its user, so what a stream user can observe is the delay, the chunking and the end.

[`net::SimulatedTransport`](#net-simulatedtransport): a complete [`net::Transport`](#net-transport) that runs over a [`net::SimNetwork`](#net-simnetwork), with its own small reliability protocol (acknowledgements, retransmission with backoff, a send window, keep-alive, time-out), so that every guarantee of the interface can be tested under loss, reordering, duplication and corruption, and replayed exactly from a seed.

It is also the specification by example of the interface: the conformance suite (`tests/net/transport_conformance.h`) passes on it first, and the UDP and TCP transports must pass the same tests.

**Protocol.** One packet carries one message or one control item (connect request, accept, refuse, acknowledgement, ping, pong, close) behind a 4-byte checksum, so a corrupted packet is dropped and counts as loss. Reliable messages are numbered per channel and kind, acknowledged one by one, and sent again when the retransmission time (twice the smoothed round trip plus four times its variance, doubled after each unanswered try, between 20 ms and 2 s) has passed. At most 256 reliable messages are in flight per connection; the rest wait in a queue of [`net::SimTransportConfig::max_queued_messages`](#net-simtransportconfig-max-queued-messages). Messages are at most [`net::SimTransportConfig::max_message_bytes`](#net-simtransportconfig-max-message-bytes) bytes: one packet each, with no fragmentation.

[`net::Socket`](#net-socket): a non-blocking TCP or UDP socket behind one interface, the only door to the operating system's socket API.

[`net::SocketStreamProvider`](#net-socketstreamprovider): a [`net::StreamProvider`](#net-streamprovider) on real, non-blocking TCP sockets.

Errors of the network layer, reported as values: [`net::ErrorCode`](#net-errorcode) and [`net::Status`](#net-status). No network failure aborts, and none throws.

[`net::StreamIo`](#net-streamio) and [`net::StreamProvider`](#net-streamprovider): the byte-stream I/O the TCP transport runs over, so the same transport code runs on real TCP sockets ([`net::SocketStreamProvider`](#net-socketstreamprovider)) and on a simulated reliable stream ([`net::SimStreamNetwork`](#net-simstreamnetwork)).

[`net::TcpStream`](#net-tcpstream): a connected TCP socket that sends and receives length-prefixed frames with bounded memory, and reports why it ended.

Sending is a bounded queue: [`net::TcpStream::Send`](#net-tcpstream-send-bytespan) puts a frame in it and answers `LimitExceeded` when it is full instead of growing (the backpressure is a value), and [`net::TcpStream::Flush`](#net-tcpstream-flush-usize-waitoptions) drains it to the socket, waiting whenever the socket is full; awaiting it is the "writable again" signal. Receiving is [`net::TcpStream::ReceiveFrame`](#net-tcpstream-receiveframe-waitoptions): it reads into a buffer of fixed size and decodes frames with a [`net::FrameReader`](#net-framereader), so a frame can arrive in pieces of any size. A frame whose length is zero or above the limit closes the stream with [`net::CloseReason::ProtocolError`](#net-closereason-protocolerror) before any memory is spent on it.

Every end of a stream has a [`net::CloseReason`](#net-closereason): the peer closed (cleanly, at a frame boundary), the peer reset the connection, a timeout fired (a connection that sends nothing for the idle time is half-open or dead), the owner closed it, or the peer broke the framing. The first reason is kept.

One coroutine may receive and one may flush at a time; they may run in parallel with each other. [`net::TcpStream::Send`](#net-tcpstream-send-bytespan) may be called from any thread. [`net::TcpStream::Close`](#net-tcpstream-close) and [`net::TcpStream::Abort`](#net-tcpstream-abort) are for when no receive or flush is outstanding (cancel them with their [`net::CancelToken`](#net-canceltoken) and wait for them first).

[`net::TcpTransport`](#net-tcptransport): the [`net::Transport`](#net-transport) interface over byte streams (Phase 20 Day 277), for what needs reliable ordered delivery: a store over the network, tools, remote debugging.

**Wire.** Everything is a frame of [`net::FrameWriter`](#net-framewriter) (a 4-byte big-endian length, then the payload). The first byte of a payload is its type: `Hello` (protocol version, channel count, largest message), `Data` (channel, reliability kind, message), `Close` (code), `Ping` and `Pong` (a time stamp for the round trip). Each side sends its `Hello` first (the server answers only after it has read a valid client `Hello`, so a stranger that speaks something else gets nothing back), and a frame of any other type before the peer's `Hello` is a protocol violation. The channel count and message size in force are the smaller of the two sides'.

**Reliability kinds.** A stream is reliable and ordered, so [`net::Reliability::ReliableOrdered`](#net-reliability-reliableordered) and [`net::Reliability::ReliableUnordered`](#net-reliability-reliableunordered) are carried as asked (the unordered kind arrives in order, which it permits). The two unreliable kinds degrade: [`net::TcpTransport::Supports`](#net-tcptransport-supports-reliability-const) says false and [`net::TcpTransport::DegradesUnreliable`](#net-tcptransport-degradesunreliable-const) true, and such a message is sent as reliable ordered (and arrives with that kind). Channels are labels on one stream, so a large message on one channel delays the others (head-of-line blocking is what TCP is).

**Limits.** A frame longer than the message limit plus its header is refused before any buffer is sized for it; the send queue is bounded ([`net::ErrorCode::LimitExceeded`](#net-errorcode-limitexceeded) is backpressure); a stream that does not finish the handshake in time, stays silent for the time-out, or breaks the protocol is closed; connections over the cap are closed on arrival.

**Time and I/O.** The transport reads a [`net::Clock`](#net-clock) and moves bytes through a [`net::StreamProvider`](#net-streamprovider), so it runs unchanged over real sockets ([`net::SocketStreamProvider`](#net-socketstreamprovider)) and over the simulated streams ([`net::SimStreamNetwork`](#net-simstreamnetwork)). It is polled: [`net::TcpTransport::Poll`](#net-tcptransport-poll-event-star) accepts, reads, writes, runs the timers and returns events.

[`net::TimeBudget`](#net-timebudget): the time left of one operation that waits several times.

[`net::Transport`](#net-transport): the interface everything above networking uses to exchange messages with peers, whatever carries them (the in-process [`net::SimulatedTransport`](#net-simulatedtransport), the UDP transport of Days 274-276, the TCP transport of Day 277).

A transport is **polled**: the application calls [`net::Transport::Poll`](#net-transport-poll-event-star) once or more per frame and receives [`net::Event`](#net-event)s (a connection opened, a message arrived, a connection closed with its reason); nothing calls back into the application and no thread of the application's is blocked. A message is delivered whole, or not at all, and never corrupted or duplicated into delivery twice. What survives loss depends on the [`net::Reliability`](#net-reliability) the sender chose, per message, on one of a fixed number of channels per connection. The channels are independent: a lost reliable message on one channel does not hold back the messages of another.

**Buffers.** The bytes of a received message are a view valid until the next call to [`net::Transport::Poll`](#net-transport-poll-event-star) on the same transport; copy what you keep. [`net::Transport::Send`](#net-transport-send-connectionid-u8-bytespan-reliability) copies the bytes it is given.

**Closing.** After [`net::Transport::Close`](#net-transport-close-connectionid-u32), or after a [`net::EventKind::Closed`](#net-eventkind-closed) event, a connection delivers no more events and refuses sends; its id is never reused by that transport.

[`net::SocketDatagramPort`](#net-socketdatagramport): a [`net::DatagramPort`](#net-datagramport) on a real, non-blocking UDP socket.

The wire format and the small algorithms of the UDP transport (Phase 20 Day 274): packet kinds and headers, wraparound-safe sequence numbers, the acknowledgement window, and the keyed hash behind the handshake cookie. Everything here is a pure function or a small value type, tested without a network.

**Format.** One datagram is one packet. All integers are little-endian. The first byte is the kind in its low three bits, a flag (0x08, payloads only: the acknowledgement fields are valid), a reserved bit that must be zero (0x10), and the protocol version in its high three (anything else is dropped).

```
ConnectRequest     [kind][u64 client_salt][zero padding to 1200 bytes]
Challenge          [kind][u64 client_salt][u64 cookie]
ChallengeResponse  [kind][u64 client_salt][u64 cookie][zero padding to 1200 bytes]
Accepted           [kind][u64 client_salt][u16 connection_id]
Denied             [kind][u64 client_salt][u8 reason]
Payload            [kind][u16 connection_id][u16 sequence][u16 ack][u32 ack_bits][frames...]
Disconnect         [kind][u16 connection_id][u32 code]
                   (a client that gives up during the handshake sends connection_id 0 and appends [u64 client_salt])
Reset              [kind][u16 connection_id]
```

The two requests that a stranger can send are padded to the full size, and every answer to a stranger is far smaller than the request, so the server cannot be used to amplify traffic towards a forged source address.

[`net::UdpTransport`](#net-udptransport): the game-traffic transport over UDP datagrams (Phase 20 Days 274-276). Day 274 builds the first third: the packet format, a handshake that costs a server no state before the client proves it owns its address, the connection state machine and the sequence/acknowledgement machinery of every packet. Day 275 adds the four reliability kinds on independent channels, several small messages per packet and fragmentation of large ones; congestion control and the refined round-trip estimate follow on Day 276, behind the same [`net::Transport`](#net-transport) interface.

**Data.** A message becomes one frame, or fragments of 1024 bytes for a message that does not fit a packet. Frames of all channels are packed into packets (resent frames first, then channels in ascending order, so a lower channel number is a higher priority). A packet's acknowledgement acknowledges its reliable frames; a frame is sent again when its packet is three or more packets behind an acknowledged one and was not acknowledged, or when its time-out (from the round-trip estimate, doubling per try) passes. Reliable-ordered delivery keeps a bounded reorder buffer per channel; a peer whose gap exceeds it, or that exceeds the reassembly and reorder byte budget, is disconnected with [`net::DisconnectReason::ProtocolError`](#net-disconnectreason-protocolerror). Fragments are declared up front (index, count, total size) and checked exactly: sizes, overlap and total are validated before any memory is committed.

**Handshake** (the wire format is in `net/udp_protocol.h`). The client sends a ConnectRequest padded to a full datagram. The server answers with a small Challenge holding a cookie, a keyed hash of the client's endpoint, the client's random salt and the current time period, and **keeps nothing**. The client repeats the cookie in a ChallengeResponse (padded again); only then does the server create the connection and answer Accepted with the connection id. Requests that are not full-size are dropped, so no answer is larger than the request that caused it. A forged source address cannot complete the exchange and so cannot make the server hold a connection or flood a third party. A cookie is valid for the period it was made in and the next one. Handshake packets are repeated with a doubling delay until answered or the connect time-out.

**Trust.** The cookie stops spoofed-source floods and amplification. It does not authenticate a peer and nothing is encrypted: until the encryption outcome of Day 280 is built this transport is for trusted networks only.

**Time and I/O.** The transport reads a [`net::Clock`](#net-clock) and moves datagrams through a [`net::DatagramPort`](#net-datagramport), so it runs unchanged over a real socket ([`net::SocketDatagramPort`](#net-socketdatagramport)) and over the simulated network ([`net::SimDatagramPort`](#net-simdatagramport)). It is polled: [`net::UdpTransport::Poll`](#net-udptransport-poll-event-star) receives, runs the timers and returns events.

## `Address` {#net-address}

`class net::Address` — defined in `engine/net/address.h`

```cpp
class Address { ... }
```

An IPv4 or IPv6 address.

IPv4 keeps its four bytes; IPv6 keeps sixteen bytes and an optional scope (the zone of a link-local address): a numeric interface index or an interface name of up to 15 characters, which a backend turns into an index. The type has no syscalls, so everything here is testable on any machine, with the rules of any operating system.

Parsing is strict: dotted decimal IPv4 has four parts of one to three digits each, no leading zero (so none reads as octal), each at most 255; IPv6 follows RFC 4291 text forms (`::`, an embedded dotted IPv4 tail, groups of one to four hex digits), upper or lower case; a single `[` `]` pair around the whole address is accepted; nothing may follow. Formatting is the canonical form of RFC 5952 (lower case, no leading zeros, the longest run of two or more zero groups compressed, the first on a tie, an IPv4-mapped address as `::ffff:a.b.c.d`).

## `CancelToken` {#net-canceltoken}

### `Accept(Reactor&,Socket*,Endpoint*,WaitOptions)` {#net-listener-accept-reactor-amp-socket-star-endpoint-star-waitoptions}

`method net::Listener::Accept` — defined in `engine/net/listener.h`

```cpp
jobs::Task<IoResult> Accept(Reactor& reactor, Socket* connection, Endpoint* peer, WaitOptions options = {});
```

Accepts one connection, applying the policy of the listener.

While [`net::ListenerOptions::max_unhandled`](#net-listeneroptions-max-unhandled) connections are unhandled, nothing is accepted: the kernel's queue fills and further clients wait or are refused, which is the back-pressure. When the process is out of descriptors (`LimitExceeded`) the loop sleeps (5 ms, doubling to 200 ms) and tries again instead of spinning, until the options say stop. A connection that died before it was accepted is skipped.

| Field | Value |

| Parameter `connection` | receives the new socket; must not be open. |
| Parameter `peer` | receives the peer's endpoint. |

| Returns | success, or the failure ([`net::ErrorCode::TimedOut`](#net-errorcode-timedout), [`net::ErrorCode::Cancelled`](#net-errorcode-cancelled), [`net::ErrorCode::Closed`](#net-errorcode-closed), ...); the count is zero. |

## `Resolve(Reactor&,Resolver&,StringView,u16,AddressFamily,WaitOptions)` {#net-resolve-reactor-amp-resolver-amp-stringview-u16-addressfamily-waitoptions}

`function net::Resolve` — defined in `engine/net/resolve.h`

```cpp
jobs::Task<ResolveResult> Resolve(Reactor& reactor, Resolver& resolver, StringView host, u16 port, AddressFamily family = AddressFamily::None, WaitOptions options = {});
```

Turns `host` and `port` into endpoints without blocking a participant or the reactor.

A numeric host (`127.0.0.1`, `::1`, `[::1]`) is parsed here and never reaches the resolver thread. A name is queued for the [`net::Resolver`](#net-resolver); the coroutine waits for its signal, with the timeout and cancel token of `options`. The operating system's resolver cannot be cancelled, so a resolution that times out or is cancelled is abandoned: the coroutine goes on at once and the result is dropped when the thread finishes.

| Field | Value |
|---|---|
| Parameter `reactor` | the reactor the coroutine waits on. |
| Parameter `resolver` | the resolver thread to use (not used for a numeric host). |
| Parameter `host` | a host name or a numeric address, not containing a zero byte; read when the task starts, so it must stay valid from the call until the `co_await` returns (await the task in the expression that creates it). |
| Parameter `port` | the port of every endpoint. |
| Parameter `family` | [`net::AddressFamily::V4`](#net-addressfamily-v4) or [`net::AddressFamily::V6`](#net-addressfamily-v6) to ask for one family, [`net::AddressFamily::None`](#net-addressfamily-none) for any. |
| Parameter `options` | token and timeout. |
| Returns | the endpoints, or the failure in the status. |
| Fails | [`net::ErrorCode::Invalid`](#net-errorcode-invalid) (empty or too long), [`net::ErrorCode::NotFound`](#net-errorcode-notfound), [`net::ErrorCode::TimedOut`](#net-errorcode-timedout), [`net::ErrorCode::Cancelled`](#net-errorcode-cancelled), [`net::ErrorCode::LimitExceeded`](#net-errorcode-limitexceeded) (the resolver's queue is full). |
| Ownership | `reactor`, `resolver` and `host` are borrowed until the `co_await` returns. |

## `Signal` {#net-signal}

`class net::Signal` — defined in `engine/net/signal.h`

```cpp

```

A one-shot event. A coroutine waits for it with [`net::Reactor::WaitSignal`](#net-reactor-waitsignal-signal-amp-waitoptions); any thread calls [`net::Signal::Fire`](#net-signal-fire). It is how work done on another thread (a name resolution on the resolver thread, say) wakes the coroutine that asked for it, with the timeout and cancellation of every other wait.

A signal fired before the wait starts makes the wait end at once with Ok. At most one coroutine waits for a signal.

| Field | Value |

## `Socket` {#net-socket}

`class net::Socket` — defined in `engine/net/socket.h`

```cpp
class Socket { ... }
```

A move-only handle to a TCP stream, a TCP listener or a UDP socket.

Every socket is non-blocking and not inherited by child processes from the moment it exists. A call that cannot finish returns [`net::ErrorCode::WouldBlock`](#net-errorcode-wouldblock) and did nothing; wait for readiness (the reactor of Day 269, or a poll in a test) and call again. Partial reads and writes are normal results: a count below the request is not an error. An interrupted system call is retried inside the backend. A write to a peer that has gone never raises a signal; it reports [`net::ErrorCode::Closed`](#net-errorcode-closed) or [`net::ErrorCode::Reset`](#net-errorcode-reset).

A socket has an address family from the moment it is opened. An IPv6 socket accepts IPv4 endpoints as IPv4-mapped addresses and an IPv4 socket refuses IPv6 endpoints (except an IPv4-mapped one, which is unmapped), and an IPv4-mapped peer address is reported as IPv4. A closed or default-constructed socket answers every operation with [`net::ErrorCode::Invalid`](#net-errorcode-invalid); none crashes.

| Field | Value |
|---|---|
| Thread-safety | thread-compatible. One thread at a time per socket; a socket may be moved to another thread. |
| Ownership | owns the operating-system handle and closes it in the destructor. |
