# The Render Hardware Interface

_Generated by docgen. Do not edit._

**Headers:** `engine/rhi/caps.h`, `engine/rhi/desc.h`, `engine/rhi/enums.h`, `engine/rhi/format.h`, `engine/rhi/handle.h`, `engine/rhi/limits.h`, `engine/rhi/rhi_log.h`

The device limits the layers above the RHI depend on.

Descriptors passed to the device's creation functions, each with a `Validate()` that checks it without a device.

`Validate()` reports the first problem as a static string starting with the descriptor name (for example `"BufferDesc: size is zero"`) and returns null when the descriptor is acceptable. It checks only what can be known without a device, against the RHI-wide ceilings in `rhi/limits.h`; the device's own limits and handle liveness are checked at creation.

Enumerations and type-safe flag sets shared by every RHI descriptor and command.

Flag enums are `u32` scoped enums whose `|`, `&` and `Has` operators are enabled by specializing [`rhi::EnableFlagOperators`](#rhi-enableflagoperators); there are no raw integer masks in the interface.

Texel and vertex-independent pixel formats, and a table describing their layout.

The set is the intersection of what Vulkan, Direct3D 12 and Metal can all express. Not every format is supported by every device or for every usage; ask the device.

Opaque, generation-checked handles to device-owned GPU resources.

A handle is a plain 8-byte value. The device validates it on every use, so a handle to a destroyed resource is detected rather than dereferenced.

RHI-wide size ceilings shared by the descriptors and the default device limits.

These are the values every backend is required to support. A device may support more, never less; the descriptors validate against these, and the device validates against its own `DeviceCaps`.

Logging for the RHI: the `LogRhi` channel and a printf-style helper.

## `Handle` {#rhi-handle}

`struct rhi::Handle` — defined in `engine/rhi/handle.h`

```cpp
template <typename Tag>
struct Handle { ... }
```

A generation-checked reference to one device-owned resource of the kind named by `Tag`.

The all-zero value is the canonical invalid handle; test validity with `IsValid()` (a zero generation), not by comparing with a default-constructed handle. Live handles always have a non-zero generation, which the device bumps when the slot is destroyed, so a stale copy compares unequal to the current handle for that slot and is rejected by the device. Handles from different devices must not be mixed.

| Field | Value |
|---|---|
| Thread-safety | thread-safe. An immutable-style plain value; copying and comparing need no synchronization. |
| Ownership | a handle does not own the resource; the resource lives until the device's `Destroy*` call and the GPU has finished with it. |
