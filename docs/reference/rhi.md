## `CommandList` {#rhi-commandlist}

`class rhi::CommandList` — defined in `engine/rhi/command_list.h`

```cpp
class CommandList { ... }
```

Records GPU commands for later submission with [`rhi::Device::Submit`](#rhi-device-submit-commandlist-star-const-star-usize).

A list is obtained from [`rhi::Device::CreateCommandList`](#rhi-device-createcommandlist), recorded between `Begin` and `End` on one thread, then submitted. Each command lists the preconditions whose violation is a programming error (`Aborts:`). Real backends assert them in debug builds and under validation layers; the null backend logs and counts each violation instead, so tests can assert on them, and skips the offending command.

Resource states are explicit: before a resource is used in a way that needs a state, a `Barrier` moves it there from the state it is in. Buffers in `MemoryLocation::CpuToGpu` and `GpuToCpu` memory are exempt: they have a fixed state and never need barriers.

| Field | Value |
|---|---|
| Thread-safety | thread-compatible. Record one list from one thread; different lists can be recorded on different threads at the same time. |
| Ownership | a list is owned by the device and stays valid until the next `Device::BeginFrame`. |

## `Device` {#rhi-device}

`class rhi::Device` — defined in `engine/rhi/device.h`

```cpp
class Device { ... }
```

The GPU device: owner of every resource, factory of command lists, and the submission point.

Creation functions never abort on an environment problem: they log the reason on [`rhi::LogRhi`](#rhi-logrhi) and return the invalid handle. Passing a stale or foreign handle, or violating a documented precondition, is a programming error (`Aborts:`); the null backend counts such errors instead of aborting.

`Destroy*` makes the handle invalid at once but defers the actual release until the GPU has finished the frames that could use the resource.

| Field | Value |
|---|---|
| Thread-safety | thread-safe for resource creation, destruction, mapping and `CreateCommandList` (serialized internally). `Submit`, `BeginFrame`, `EndFrame` and `WaitIdle` must be called from one thread at a time (the submission thread). |
| Ownership | the caller owns the device and releases it with [`rhi::DestroyDevice`](#rhi-destroydevice-device-star), after `WaitIdle` and after dropping every command list. |

```cpp
virtual UploadTicket UploadTexture(TextureHandle dst, u32 mip, u32 layer, const void* data, u32 row_pitch) = 0;
```

Copies one mip level of one layer from the CPU into a texture, outside the frame's command lists.

The data is staged and copied on the GPU; it has been read from `data` when the call returns, and the copy is ordered after earlier submitted work. The whole texture moves to `ShaderRead`: it must be in state `Undefined` (the first upload) or `ShaderRead` (uploading another level or layer), and the other levels keep their contents. The device remembers only what its own upload and readback calls did: if you moved the texture elsewhere with `Barrier` in a command list, move it back to `ShaderRead` before uploading again, because the device cannot see the list's barriers. Large levels are split to fit the staging ring. Uploads to one texture must not overlap in time (use one thread per texture). Depth-stencil formats with a stencil aspect cannot be uploaded.

| Field | Value |
|---|---|
| Parameter `dst` | a texture created with `Sampled` and `CopyDst` usage. |
| Parameter `mip` | the mip level. |
| Parameter `layer` | the array layer. |
| Parameter `data` | the texel rows of the level; must not be null. |
| Parameter `row_pitch` | bytes between rows (block rows for compressed formats); 0 means tightly packed. Otherwise at least the row size and a multiple of the texel (block) size. |
| Returns | a ticket; see [`rhi::Device::UploadBuffer`](#rhi-device-uploadbuffer-bufferhandle-u64-const-void-star-u64). |
| Fails | a lost device or staging memory running out logs and returns a ticket with `ok` false; the texture is then left in `ShaderRead` with the level only partly written. |
| Aborts | `dst` is invalid or stale, lacks usage, `mip` or `layer` is out of range, `data` is null, `row_pitch` is invalid, or the texture is in another state. |
| Ownership | `data` is borrowed for the call only; it must hold the level's rows at `row_pitch`. |

### `UploadBuffer(BufferHandle,u64,const void*,u64)` {#rhi-device-uploadbuffer-bufferhandle-u64-const-void-star-u64}

`method rhi::Device::UploadBuffer` — defined in `engine/rhi/device.h`

```cpp
virtual UploadTicket UploadBuffer(BufferHandle dst, u64 offset, const void* data, u64 size) = 0;
```

Copies bytes from the CPU into a buffer, outside the frame's command lists.

The data is staged and copied on the GPU; it has been read from `data` when the call returns. The copy is ordered after all work submitted earlier and before all work submitted later, so a later `Submit` can use the new contents after a barrier from `CopyDst`. The buffer is in state `CopyDst` afterwards. Large uploads are split to fit the staging ring. Uploads from several threads are serialized.

A buffer in `CpuToGpu` memory is the exception: it is written at once through its mapping, with no GPU copy and no ordering against work already submitted, and it keeps its fixed state. Do not overwrite data the GPU may still be reading (use a buffer per frame in flight).

| Fails | a lost device, or staging memory running out, logs and copies nothing. |
| Aborts | `dst` is invalid or stale, lacks `CopyDst` usage, `data` is null, or the range is outside the buffer. |
| Ownership | `data` is borrowed for the call only. |

## `Handle` {#rhi-handle}

`struct rhi::Handle` — defined in `engine/rhi/handle.h`

```cpp
template <typename Tag>
struct Handle { ... }
```

A generation-checked reference to one device-owned resource of the kind named by `Tag`.

The all-zero value is the canonical invalid handle; test validity with `IsValid()` (a zero generation), not by comparing with a default-constructed handle. Live handles always have a non-zero generation, which the device bumps when the slot is destroyed, so a stale copy compares unequal to the current handle for that slot and is rejected by the device. Handles from different devices must not be mixed.

| Field | Value |
|---|---|
| Thread-safety | thread-safe. An immutable-style plain value; copying and comparing need no synchronization. |
| Ownership | a handle does not own the resource; the resource lives until the device's `Destroy*` call and the GPU has finished with it. |

## `HandlePool` {#rhi-handlepool}

`class rhi::HandlePool` — defined in `engine/rhi/handle_pool.h`

```cpp
template <typename T, typename Tag>
class HandlePool { ... }
```

A pool of `T` values addressed by [`rhi::Handle`](#rhi-handle), with generation checking and a deferred-destruction queue.

Slots live in fixed-size chunks that are never moved, so a pointer from `Get` stays valid until that slot is freed or retired and collected. Freeing a slot bumps its generation at once, so every older handle to it fails `Get`. `Retire` does the same but keeps the value alive until the frame it was retired in has completed on the GPU; `CollectRetired` then hands the value back to the caller for backend cleanup and recycles the slot.

The pool holds at most [`rhi::HandlePool::kMaxCapacity`](#rhi-handlepool-kmaxcapacity) slots; `Allocate` fails past that.

| Field | Value |
|---|---|
| Thread-safety | not-thread-safe. The owning device serializes access behind its mutex. |
| Ownership | owns the stored values and the chunk memory (libc `malloc`); both are released by the destructor, which also destroys live and retired values without calling any cleanup hook. |

## `ValidateSpirv(const u32*,usize,ShaderStage,const char*)` {#rhi-validatespirv-const-u32-star-usize-shaderstage-const-char-star}

`function rhi::ValidateSpirv` — defined in `engine/rhi/spirv.h`

```cpp
const char* ValidateSpirv(const u32* words, usize word_count, ShaderStage stage, const char* entry);
```

Checks that a SPIR-V module is well formed enough to hand to a driver and that it implements `stage`.

The check reads the header and walks every instruction once. It accepts a module only if: the magic number is right (a byte-swapped module gets its own message), the version is 1.0 to 1.6, the id bound is non-zero, every instruction has a non-zero length that stays inside the module and the stream ends exactly at the last word, the module declares capability `Shader` and no `Kernel`, uses the `Logical` addressing model with the `GLSL450` or `Vulkan` memory model, and has an `OpEntryPoint` named `entry` whose execution model matches `stage`. This is a subset check of what the engine's shaders use, not a validator: `spirv-val` is the dev-time validator.

| Field | Value |
|---|---|
| Parameter `words` | the module's 32-bit words in host byte order. |
| Parameter `word_count` | number of words in `words`. |
| Parameter `stage` | the single stage the module must implement (vertex, fragment or compute). |
| Parameter `entry` | the entry point name to look for; at most [`rhi::kMaxShaderEntryNameLength`](#rhi-kmaxshaderentrynamelength) bytes. |
| Returns | null if the module is acceptable, else a static string naming the first problem. |
| Fails | reported through the return value, never by aborting. |
| Thread-safety | thread-safe. A pure function of its arguments. |
| Ownership | the returned string is static and is never freed by the caller; `words` and `entry` are borrowed. |

## `UniformRing` {#rhi-uniformring}

`class rhi::UniformRing` — defined in `engine/rhi/uniform_ring.h`

```cpp
class UniformRing { ... }
```

Hands out aligned slices of a persistently mapped `CpuToGpu` buffer, a fresh region each frame.

The ring owns one buffer of `kSlots` equal regions. [`rhi::UniformRing::BeginFrame`](#rhi-uniformring-beginframe) picks the region for the current frame (`FrameNumber() % kSlots`) and empties it; `Allocate` then bumps a pointer through it. Because a region is reused only every `kSlots` frames and a device runs at most three frames in flight, the GPU is done with a region before the CPU writes it again. Put an allocation in a bind group entry with `offset` and `size`, or bind the whole buffer once and use the offsets in your own shader indexing.

| Field | Value |
|---|---|
| Thread-safety | thread-compatible. `Allocate` is thread-safe and lock-free; `BeginFrame` and the destructor must not run concurrently with anything else. |
| Ownership | the ring owns its buffer and destroys it in the destructor; the device must outlive the ring. |
