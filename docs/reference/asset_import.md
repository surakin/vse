Importing glTF animations as clips.

Phase 22 Day 337. Each glTF animation yields one clip per skeleton it animates, named `<animation>_<skin>`: translation, rotation and scale channels on joint nodes become tracks. `LINEAR` keys map to keys, `STEP` becomes a pair of keys at the step (the later one a tick after), `CUBICSPLINE` is resampled to linear keys at the clip rate and the error that made is measured and reported. Channels on nodes that are no joint, and `weights` channels, are dropped with a counted warning. [`asset::BuildClipBlob`](asset.md#asset-buildclipblob-const-typeregistry-amp-resourceid-const-clipbuildinput-amp-vector-lt-byte-gt-star-u32-f32-star-f32-star) then reduces and quantizes the keys.

The glTF importer: glTF 2.0 files become the engine's resources, in memory.

Phase 22 Days 335 to 338. Bytes go in, minted blobs come out; [`asset::ImportIntoBackend`](#asset-importintobackend-hostmemorybackend-amp-const-importresult-amp) adds them to a [`asset::HostMemoryBackend`](asset.md#asset-hostmemorybackend) that the rest of the engine reads like any other backend. This is a library a program opts into: no runtime engine module depends on it (the gate `asset_boundary_check`), and `asset_mint import-gltf` is a thin command over it.

The input may be hostile (a file fetched from a room): every failure is a [`asset::Status`](asset.md#asset-status) and a [`asset::GltfError`](#asset-gltferror) that names the glTF object, nothing aborts, and every count and size is checked against [`asset::ImportLimits`](#asset-importlimits) before anything is allocated. External files (`.bin` and image URIs) are read through a [`asset::GltfSource`](#asset-gltfsource), so the host decides where bytes come from.

Built so far (Day 335): the container (`.gltf`, `.glb`, base64 `data:` URIs), the accessors, the limits, the id sources and the import manifest, and `ImportIntoBackend`. [`asset::ImportGltf`](#asset-importgltf-bytespan-gltfsource-amp-const-importoptions-amp-importresult-star-gltferror-star) reads and checks the container and reports what it holds; it imports resources from Day 336 on (meshes), Day 337 (skeletons and animation) and Day 338 (images, textures, materials).

The glTF scene as a level: one entity per node of the default scene.

Phase 24 Day 364 (the scene output moved out of Phase 22 Day 338). Every node reachable from the default scene's root nodes becomes an entity of a level blob: its name, its local transform (translation, rotation, scale), its parent and, for a node with a mesh, the imported mesh and the material of the mesh's first primitive, and for a node with a skin the skeleton instance. Several nodes that use one glTF mesh give several entities that share one mesh resource. The level is a resource like the others (path `<prefix>/levels/<scene>`), added with the rest by `ImportIntoBackend`.

Importing glTF images, textures and materials.

Phase 22 Day 338. Images (a URI, a `data:` URI or a buffer view) decode to RGBA8; each glTF texture becomes one texture resource per way it is used (sRGB color for the base color, linear data for the normal map; BC7 block compression, mip chain) minted by [`asset::MintTextureFromPixels`](asset.md#asset-minttexturefrompixels-const-typeregistry-amp-resourceid-const-texturemintspec-amp-u32-u32-span-lt-const-bytespan-gt-vector-lt-byte-gt-star-u32-jobs-scheduler-star); each glTF material becomes one material resource of the standard G-buffer template, minted from a generated `.mat.src` by [`asset::MintMaterial`](#asset-mintmaterial-stringview-const-materialreferenceresolver-amp-const-typeregistry-amp-vector-lt-byte-gt-star-materialsourceerror-star-u32). What the template cannot hold (a metallic-roughness, occlusion or emissive texture, an emissive color, a texture transform) is dropped with a counted warning naming the material, or refused when it changes what the surface is (`KHR_materials_unlit`, a `KHR_texture_transform`).

Importing glTF meshes into mesh blobs.

Phase 22 Day 336. Each glTF mesh becomes one engine mesh resource whose material slots are the glTF primitives, built through [`asset::BuildMeshBlob`](asset.md#asset-buildmeshblob-const-typeregistry-amp-resourceid-const-meshbuildinput-amp-vector-lt-byte-gt-star-u32): what is imported is exactly what a `.mesh.src` of the same data would mint. Missing attributes are made deterministically (normals, tangents, zero texture coordinates); what the mesh format cannot hold (morph targets, vertex colors, a second texture-coordinate set) is refused or dropped with a counted warning.

`asset_import` is linked by the offline tool and by a host that imports glTF at run time, never by the runtime engine.

Line-oriented text; `#` starts a comment; fields are separated by spaces or tabs:

id 00000000000000aa template gbuffer option NORMAL_MAP param base_color color 0.8 0.2 0.1 1 param roughness float 0.4 texture albedo_tex textures/brick_albedo sampler linear_sampler filter linear address repeat anisotropy 8 state cull none

`id` comes first and `template` second. `template` names a built-in template (`gbuffer`, `gbuffer_color`, `gbuffer_skinned`, `gbuffer_skinned_color`); each `option` is one of the template's fragment permutation options. `param NAME TYPE VALUES` sets a member of the template's parameter block (TYPE is `float`, `int`, `uint`, `vec2`, `vec3`, `vec4`, `mat4` or `color`, the last with three or four values; the member's own type decides which are accepted); a member the source does not set keeps the template's default (zero when it has none). `texture SLOT PATH` binds a texture slot to the resource at PATH; `sampler SLOT [filter nearest|linear] [address repeat|clamp|mirror] [anisotropy N]` describes a sampler slot (`filter` sets minification, magnification and mip filtering together); `state FIELD VALUE` overrides one render-state field (`cull none|front|back`, `depth_test on|off`, `depth_write on|off`, `depth_compare never|less|equal|lessequal|greater|notequal|greaterequal|always`, `alpha_blend on|off`).

## `BuildImportSummary(const GltfDocument&,const GltfNodeGraph&,const ImportOptions&,const Vector<u32>&,const Vector<String<HeapAllocator>>&,ImportResult*)` {#asset-buildimportsummary-const-gltfdocument-amp-const-gltfnodegraph-amp-const-importoptions-amp-const-vector-lt-u32-gt-amp-const-vector-lt-string-lt-heapallocator-gt-gt-amp-importresult-star}

```cpp
void BuildImportSummary(const GltfDocument& document, const GltfNodeGraph& graph, const ImportOptions& options, const Vector<u32>& nodes, const Vector<String<HeapAllocator>>& names, ImportResult* result);
```

Writes the summary of the nodes of a level into `result->summary`.

The text is one JSON object: `{"version":1,"nodes":[{"name":"Spawn","position":[x,y,z],"mesh":-1|index},...],"bounds":{"min":[x,y,z],"max":[x,y,z]}` `(or null when no mesh node has a POSITION range),"materials":["name",...],"animations":[{"name":"Walk","duration":s},...]}`. `nodes` lists the entities of the level in the order of the level (names as `level_spawn` gives them, unique; `position` is the node's world position times `options.scale`); `bounds` is the box of the meshes' POSITION ranges (the accessors' `min` and `max`) under the nodes' world matrices, times `options.scale`; `materials` and `animations` are in the file's order (an unnamed one has the name `""`), the `duration` being the longest sampler input range in seconds (0 when the accessors give no range). | Parameter `options` | `scale`. |
| Parameter `nodes` | the indexes into `graph.nodes` of the level's entities, in level order. |
| Parameter `names` | the entity name of each of `nodes` (as long as `nodes`). |
| Parameter `result` | receives `summary` (replaced). |
| Fails | never (a range the file does not give is left out of the facts). |
| Thread-safety | thread-safe for separate calls with separate arguments. |
