Filled before anything can crash, so the crash path only reads fixed buffers: no allocation, no file access.

Catching a fatal fault and leaving a minidump of the process behind.

Built on sentry-native's Breakpad backend behind this interface (PLAN.md assumption #20); nothing here names the library. The library installs handlers for the fatal signals; when one arrives it writes a minidump (every thread, the registers, the stack memory, the module list) into a database directory on the local disk and the process then dies from the original fault. **Nothing is ever sent anywhere:** the library is built without a network transport and these options have no address to send to.

Platform-neutral description of why a process or thread was stopped abnormally.

Debugging code, the crash handler and the tests speak [`debug::CrashReason`](#debug-crashreason); the platform backends translate their own codes (signals, exception codes) into it.

The text report that goes with a crash or a failed assertion: why, on which thread, in which build on which machine, the call stack, what the engine's subsystems say about their state, and the last lines the program logged.

Everything it prints is prepared ahead of time (see crash_context.h, the log ring in log.h, and the state providers below), so writing it allocates nothing and takes no lock and can run inside a crashing process. It writes in small pieces, one section line at a time, so if something faults in the middle the part already written is intact.

Running code that is supposed to crash, in a child process, and seeing what happened.

The helper starts a fresh copy of the running program; it does not `fork`, because `fork` does not exist on every platform and in a multithreaded process it leaves the child holding locks it can never release. The child runs one function registered with [`ENGINE_DEATH_TEST_FN`](#engine-death-test-fn); the parent gets a [`debug::ChildResult`](#debug-childresult). Asking whether a debugger is attached to the running process.

Deliberate faults for testing crash handling.

Tests call [`debug::InjectFault`](#debug-injectfault-faultkind) inside a child process (see death_test.h) and check the reported [`debug::CrashReason`](#debug-crashreason); they never name a signal or exception code. Each platform implements the faults it has.

The executable and shared libraries loaded into the running process, for naming the module an address belongs to.

Making sure a crash leaves a post-mortem artifact a developer can open later, and saying where it will be.

This is the platform-neutral idea; each platform implements it its own way: - Linux: a core file, or a handoff to `systemd-coredump` (`coredumpctl`); the process raises its core size limit. - Windows (Phase 8): Windows Error Reporting `LocalDumps`. - macOS (Phase 9): the system's core files and crash reports. - Android: tombstones, which the system always writes ([`debug::PostMortemResult::Enabled`](#debug-postmortemresult-enabled) with nothing to do). - iOS and consoles with their own crash system: [`debug::PostMortemResult::Unsupported`](#debug-postmortemresult-unsupported). The minidump the crash handler writes ([`debug::InstallCrashHandler`](#debug-installcrashhandler-const-crashhandleroptions-amp)) is separate and always on; a core dump is bigger and holds the whole process memory, so it is a developer's tool, off by default.

Capturing the call stack and turning it into function names, files and lines.

Built on libbacktrace behind this interface (PLAN.md assumption #20); nothing here names the library. Capturing and resolving need no frame pointers. After [`debug::InitDebugFacilities`](#debug-initdebugfacilities) has run once they never call `malloc` (the library maps memory with `mmap` when it first reads the debug information of a part of the program), so a crash handler can use them; they do take the library's internal lock, so a fault inside them on the same thread is not survivable. File and line need debug information in the binary (`-g`); without it frames carry the function name from the symbol table, or only the module and offset.

## `CrashReason` {#debug-crashreason}

```cpp

```

Why a process died or a fault was reported, independent of the operating system.

A backend maps its native code to the closest value and keeps the raw code beside it. A stack overflow is a hardware access violation on every platform, so a process that only left an exit status reports [`debug::CrashReason::AccessViolation`](#debug-crashreason-accessviolation); [`debug::CrashReason::StackOverflow`](#debug-crashreason-stackoverflow) is reported only by code that saw the fault happen.

|---|---|---|
| <a id="debug-crashreason-none"></a>`None` | `0` | The process did not die from a fault (it exited normally, or was killed from outside). |
| <a id="debug-crashreason-accessviolation"></a>`AccessViolation` |  | An invalid memory access: a null or wild pointer, or a write to read-only memory. |
| <a id="debug-crashreason-buserror"></a>`BusError` |  | An access the hardware could not complete, such as a page beyond the end of a mapped file. |
| <a id="debug-crashreason-illegalinstruction"></a>`IllegalInstruction` |  | The CPU met an instruction it cannot execute. |
| <a id="debug-crashreason-arithmeticfault"></a>`ArithmeticFault` |  | A trapping arithmetic error such as an integer divide by zero. |
| <a id="debug-crashreason-stackoverflow"></a>`StackOverflow` |  | The stack ran out; only reported by code that saw the fault happen. |
| <a id="debug-crashreason-abort"></a>`Abort` |  | The program called `abort` (or an equivalent) on purpose. |
| <a id="debug-crashreason-assertfailed"></a>`AssertFailed` |  | An `ENGINE_ASSERT` failed. |
| <a id="debug-crashreason-ensurefailed"></a>`EnsureFailed` |  | An `ENGINE_ENSURE` failed and execution continued. |

## `CrashStateFn` {#debug-crashstatefn}

`alias debug::CrashStateFn` — defined in `engine/foundation/debug/crash_report.h`

```cpp
using CrashStateFn = void (*)(void* context, char* out, usize capacity);
```

Writes the text of one state provider into `out`.

**The rules, because this runs in a crashing process:** read only plain memory that is always valid (a few atomics or copies the subsystem keeps up to date), call nothing that allocates or locks or reads a file, write at most `capacity` bytes including the terminating null byte, and finish quickly. A provider that breaks these rules can lose the rest of the report.

`context` is the pointer given at registration; `out` is where to write the null-terminated text, `capacity` bytes ([`debug::kCrashStateTextBytes`](#debug-kcrashstatetextbytes)).

## `FormatStackTrace(const StackTrace&,char*,usize,const FormatOptions&)` {#debug-formatstacktrace-const-stacktrace-amp-char-star-usize-const-formatoptions-amp}

`function debug::FormatStackTrace` — defined in `engine/foundation/debug/stack_trace.h`

```cpp
usize FormatStackTrace(const StackTrace& trace, char* out, usize capacity, const FormatOptions& options = FormatOptions());
```

Writes a trace as text, one line per frame, to a buffer.

The line layout is fixed so tools can read it: `#N  0xADDRESS  function  file:line`. `N` is the frame number (an inlined function repeats the number of the frame it was inlined into and ends with ` [inlined]`); the address has 16 hex digits; `file:line` is left out when unknown; when the function is unknown the module and offset take its place (`/path/lib.so+0xOFFSET`), or `??` when even the module is unknown. A trace that was cut ends with `  ... more frames`.

| Field | Value |
|---|---|
| Parameter `trace` | the trace to write. |
| Parameter `out` | the buffer; borrowed for the call. |
| Parameter `capacity` | size of `out`; the text is cut to fit and always ends with a null byte if `capacity` is not 0. |
| Parameter `options` | how to write names. |
| Returns | the number of bytes written, not counting the null byte. |
| Thread-safety | thread-safe. Async-signal-safe once [`debug::InitDebugFacilities`](#debug-initdebugfacilities) has run (it never calls `malloc`), unless `options.demangle`. |
| Ownership | `out` stays the caller's; nothing is retained after the call. |
