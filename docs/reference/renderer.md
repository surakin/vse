Bounding volumes used for culling: a sphere and an axis-aligned box, and how they follow a transform.

Cameras and the matrices they produce, in the conventions every renderer pass shares.

* World and view space are right-handed with Y up; a camera looks down -Z in view space. * [`renderer::PerspectiveVulkan`](#renderer-perspectivevulkan-f32-f32-f32-f32) maps view space to Vulkan clip space: X right, Y *down* (the matrix flips Y) and depth 0..1 (near -> 0, far -> 1, no reverse-Z). Viewports take a positive height; the flip lives in the projection. * Meshes are counter-clockwise seen from outside. With the projection above that is a front face for `FrontFace::CounterClockwise`, and `CullMode::Back` removes faces that point away. * Matrices are column-major ([`Mat4`](foundation-math.md#mat4)), which is std140's layout for a `mat4`, so one can be copied into a uniform buffer as it is.

The data every frame feeds to the shaders: one `FrameData` uniform and one storage buffer of per-object data, both rewritten each frame. A draw picks its object by instance index, so no bind group is created per draw.

The view frustum and the tests that decide whether an object can be seen.

A material is a shader permutation plus a parameter block and textures, with the bind groups and pipelines it needs.

A [`renderer::MaterialSystem`](#renderer-materialsystem) holds templates (the shaders and render state) and materials (the parameter values and textures of one surface). Everything is validated against the shaders' reflection when it is created, and the system owns every bind group and pipeline, so a draw creates no object. Descriptor sets follow one convention: set 0 is the frame uniform ([`renderer::FrameData`](#renderer-framedata)), set 1 the material, set 2 the per-object storage buffer.

CPU-side geometry ([`renderer::MeshData`](#renderer-meshdata)), its GPU copy ([`renderer::GpuMesh`](#renderer-gpumesh)) and procedural shapes.

The scene a frame is built from: a fixed-capacity list of objects and lights with stable ids; the ECS replaces it in Phase 9.

Identification of the renderer library; the first real symbol of Phase 4 (the camera and scene arrive on Day 73).

The renderer: a deferred, render-graph-driven renderer built on the RHI.

Shader permutations: one Slang source built offline into several SPIR-V modules, one per option combination.

A shader declares its options in a `// permutation-options: A B C` comment and uses them as compile-time defines (`#if A`); a manifest next to it (`<name>.perm`) lists which combinations to build. The `shader_mint` tool compiles each listed key, drops duplicate modules, and commits the result as `<name>.perm.inc`: a [`renderer::ShaderPermutations`](#renderer-shaderpermutations) table that [`renderer::FindPermutation`](#renderer-findpermutation-const-shaderpermutations-amp-permutationkey-reflectionerror-star) searches at run time. A key that was not built is an error naming the shader and the key, never a silent fallback.

What a compiled shader says about itself: its stage, bindings, uniform and push-constant block layouts, vertex inputs and compute local size. The offline `shader_mint` tool extracts it from `slangc` output into a compact blob committed as `shaders/<name>.refl.inc`; the renderer parses the blob and builds bind group layouts and vertex layouts from it instead of writing them a second time by hand.

## `MaterialSystem` {#renderer-materialsystem}

`class renderer::MaterialSystem` — defined in `engine/renderer/material.h`

```cpp
class MaterialSystem { ... }
```

Templates, materials, default textures, bind groups and the pipeline cache.

Creation validates against reflection and returns an invalid id (after logging) on any mismatch; a stale or invalid id passed to another function is a programming error. Parameter writes go to a CPU shadow and reach the GPU in one batch per frame in [`renderer::MaterialSystem::FlushMaterials`](#renderer-materialsystem-flushmaterials). Use is: `BeginFrame`, change materials, `FlushMaterials`, then record draws with the bind groups and pipelines the system hands out.

Parameter names are the member names of the fragment (or vertex) shader's set-1 uniform block; texture and sampler names are the shader's variable names. A texture slot left unset uses a default texture: the one the template lists for it in `texture_defaults`, otherwise one chosen by name (a name starting with `normal` gets the flat normal, one starting with `emissive` or `black` gets black, anything else white). Name your normal and emissive slots to match, or list them. Samplers left unset use a linear, repeating sampler.

| Field | Value |
|---|---|
| Thread-safety | thread-compatible. |
| Ownership | borrows the device, which must outlive it; owns the shaders, layouts, buffers, bind groups, pipelines and default textures it creates. Textures and samplers given to a material belong to the caller and must outlive it. |
