# Platform: Windowing and Input

**Headers:** `engine/foundation/os/input.h`, `engine/foundation/os/linux/debug/debugger_linux.h`, `engine/foundation/os/linux/platform_window_host.h`, `engine/foundation/os/linux/wayland/wayland_connection.h`, `engine/foundation/os/linux/wayland/wayland_input.h`, `engine/foundation/os/linux/wayland/wayland_platform_window.h`, `engine/foundation/os/linux/wayland/wayland_window.h`, `engine/foundation/os/linux/x11/x11_window.h`, `engine/foundation/os/linux/xkb_keyboard.h`, `engine/foundation/os/window.h`

Keyboard and mouse input types shared by every platform backend.

Keys are layout-aware: they name the symbol the user's layout produces, not the physical position.

Linux window host: picks, opens and owns the Wayland or X11 window backend.

Wayland connection: the compositor connection and the globals the engine binds.

Wayland seat input: keyboard and pointer events from a `wl_seat` into an `InputState`.

Wayland platform window: the Wayland backend packaged as an `os::Window`.

Wayland window: a `wl_surface` wrapped as a mapped xdg-shell toplevel.

X11 window backend: the fallback `os::Window` built on libX11.

XKB keyboard: libxkbcommon keymap and state used to translate evdev keycodes into engine keys.

Platform-neutral window interface implemented by each display backend (Wayland, X11).

The interface is polled: pump events, then read size, close request and the bound `InputState`.

## `WaylandWindow` {#os-wayland-waylandwindow}

`class os::wayland::WaylandWindow` — defined in `engine/foundation/os/linux/wayland/wayland_window.h`


| Field | Value |
