Portable command-line parsing: positional arguments plus `--name` and `--name=value` flags, and, for a program that declares its options, `--name value` as well, with unknown options and missing values reported. Engine, game and tool code never touches raw `argc`/`argv` directly (`cmdline_access_check`).

Process control: the engine's spelling of `fflush`, `abort`, `_Exit` and `getenv` (`os::Exit`, which runs the exit handlers, is in `os/os.h`). A program's output is not here: it goes through the log system (`out::Print`, `log/output.h`), which sends it to the console and every other log device; what is left here is flushing the C streams that libraries write to. Writing to a descriptor without buffering is [`os::Write`](#os-write-int-const-void-star-usize); files are the `io` module's.

Loader smoke test that locates the Vulkan driver and resolves `vkCreateInstance`; not the RHI.

Built only where the engine has a Vulkan backend (Linux, Windows): macOS has no Vulkan (MoltenVK is a third-party layer), so this file and its source are not part of the macOS build, and nothing there may include it.

The C library's error number: the engine's spelling of `errno`, which is a macro and cannot be named from other files. The `E*` constants (`EINTR`, `ENOENT`, ...) arrive through this header.

The C library's locale (`setlocale`): the engine's own code never changes it, and formats and parses stored numbers with [`FormatGeneral`](foundation-cstr.md#formatgeneral-char-star-usize-f64-int-noexcept), [`FormatShortest`](foundation-cstr.md#formatshortest-char-star-char-star-f64-noexcept) and [`ParseDoubleExact`](foundation-cstr.md#parsedoubleexact-const-char-star-const-char-star-noexcept), which ignore it. A host program may change it (Qt and GTK call `setlocale(LC_ALL, "")` at startup), so tests use this wrapper to run the engine under a locale whose decimal point is `,`.

Thin wrappers around OS calls: file descriptors, memory reservation, clocks, dynamic libraries.

Exit/Write/Read/Open/Close keep POSIX-shaped signatures; the implementation lives per platform. Files and directories belong to the file layer ([`io::File`](foundation-io.md#io-file), [`io::Directory`](foundation-io.md#io-directory), [`io::Path`](foundation-io.md#io-path)); the descriptor functions here are for the console, pipes, sockets and the signal-safe code of the debugging facilities.

**Windows**. Descriptors are the engine's own: 0, 1 and 2 are the standard handles, and [`os::Open`](#os-open-stringview-int-int) hands out 3 and up from a fixed table of 256 handles, claimed without a lock so the crash path can use it (the C runtime's descriptors are not used: a thread stopped inside one holds a lock a crash report would wait on). `long` is 32 bits there, so one [`os::Write`](#os-write-int-const-void-star-usize) or [`os::Read`](#os-read-int-void-star-usize) moves at most 2^31 - 1 bytes and reports a short count, which every caller handles. Writes to a console are converted from UTF-8 and shown with the console's Unicode API; the console's code page is never changed (that would outlive the program in the user's shell). Paths are UTF-8 and become UTF-16 at the call, with `/` turned into `\` and the `\\?\` prefix added to long absolute paths.

**macOS**. The descriptor, memory, sleep and library calls are the POSIX ones Linux uses (`os/posix/`); the clock, random bytes, process figures and library search are macOS's own (`os/macos/os.cpp`). Pages are the system's size: 4 KiB on x86-64 and 16 KiB on Apple silicon, so no code may assume 4 KiB.

Signal handlers: the engine's spelling of `std::signal`. The `SIG*` constants and the POSIX `sigaction` family arrive through this header.

Terminal detection: is a descriptor a terminal and how many colours it shows (Maintenance: log devices).

The rules follow the usual conventions: `NO_COLOR` (set and not empty) turns colour off, `CLICOLOR_FORCE` (set and not `0`) turns it on even for a pipe, `TERM=dumb` has none, `COLORTERM=truecolor` or `24bit` is 24-bit colour, a `TERM` naming `256color` is 256 colours, any other `TERM` is the basic 16. On Windows the console's virtual terminal processing is switched on for the descriptor, and a console is taken as 24-bit colour when `TERM` is unset. The user's choice in the settings (`log.color`) overrides all of it.

## `CommandLine` {#os-commandline}

`class os::CommandLine` — defined in `engine/foundation/os/command_line.h`

```cpp
template <typename Allocator>
class CommandLine { ... }
```

Parsed command line: program name, positional arguments and `--name[=value]` flags.

Without declared options (the constructor with no option list), tokens starting with `--` and longer than two characters are flags; a flag with `=` carries a value, and all other tokens are positional arguments. With declared options, a flag that takes a value also takes the next token (`--root DIR`), a flag that is not declared, a missing value or a value given to a flag that takes none is an error ([`os::CommandLine::Ok`](#os-commandline-ok-const), [`os::CommandLine::Error`](#os-commandline-error-const)), a bare `--` ends the flags (everything after it is positional), and a token with one dash is positional unless a one-dash option of that name is declared (`-1`, `-`). Repeating a flag keeps the last occurrence. All strings are copied, so the original `argv` need not outlive the object.

| Field | Value |
|---|---|
| Thread-safety | thread-compatible. Concurrent const access is safe; construction is not synchronized. |
| Ownership | owns copies of all strings, allocated from the allocator passed at construction, which must outlive this object. |
