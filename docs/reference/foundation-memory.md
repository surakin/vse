## `ArenaAllocator` {#arenaallocator}

```

Linear bump allocator over one fixed-capacity block of virtual memory.

Allocations are never freed individually; [`ArenaAllocator::Reset`](#arenaallocator-reset) makes the whole capacity reusable and [`ArenaAllocator::FreeAll`](#arenaallocator-freeall) returns the block to the OS. Memory is not zeroed and no destructors are run.

| Field | Value |
|---|---|
| Thread-safety | not-thread-safe. Synchronize externally if shared. |
| Ownership | owns the backing block; it is released by `FreeAll` or the destructor. Pointers returned by `Alloc` are invalidated by `Reset` and `FreeAll`. |

## `HeapAllocator` {#heapallocator}

`class HeapAllocator` — defined in `engine/foundation/mem/heap_allocator.h`

```

Stateless heap allocator that frees individual blocks.

Satisfies the allocator contract of [`Vector`](foundation-containers.md#vector) (`Alloc`) and, because it has `Free`, makes [`Vector`](foundation-containers.md#vector) release its storage. Use [`HeapAllocator::Default`](#heapallocator-default) for the shared instance. Blocks are always aligned to at least 16 bytes.

| Field | Value |
|---|---|
| Thread-safety | thread-safe; the type holds no state and the heap is thread-safe. |
| Ownership | the caller owns each block until it passes it to `Free`. |

## `PoolAllocator` {#poolallocator}

`class PoolAllocator` — defined in `engine/foundation/mem/pool_allocator.h`

```cpp
class PoolAllocator { ... }
```

Allocator handing out equally sized slots from one fixed block, with O(1) allocation and free.

Free slots form an intrusive singly-linked list stored in the slots' own first bytes, so a slot is at least pointer-sized. Slot memory is not zeroed and no constructors or destructors run.

| Field | Value |
|---|---|
| Thread-safety | not-thread-safe. Synchronize externally if shared. |
| Ownership | owns the backing block, released by the destructor. A slot belongs to the caller from `Alloc` until it is passed to `Free`. |

Bump allocator whose allocations can be discarded in LIFO order by rewinding to a saved marker.

Same storage strategy as [`ArenaAllocator`](#arenaallocator); the difference is the marker API. Memory is not zeroed and no destructors are run.
