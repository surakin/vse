Fixed-size array with inline storage, the engine's `std::array`: the size is a compile-time constant and the elements live inside the object. [`Vector`](#vector) is every case where the size is only known at runtime or changes.

Open-addressing hash map (linear probing, tombstone deletion) whose slot storage is a [`Vector`](#vector), plus the `Hash` function-object templates it uses.

Growable array that owns its storage: on the heap by default, or from a caller-supplied allocator such as an arena. The fixed-size, inline counterpart is [`Array`](#array).

## `Array` {#array}

`struct Array` — defined in `engine/foundation/containers/array.h`

```cpp
template <typename T, usize N>
struct Array { ... }
```

Array of exactly `N` elements stored inside the object itself.

An object holding an `Array` is as large as its other members plus `N` elements: there is no pointer and no allocation. It is an aggregate, so it is initialized like a C array (`Array<int, 3> a = {{1, 2, 3}};`) and unmentioned elements are value-initialized. Indexing is not bounds-checked, like [`Vector`](#vector).

| Field | Value |
|---|---|
| Thread-safety | not-thread-safe. Synchronize externally if shared. |
| Ownership | owns its elements, which are destroyed with it. |

## `HashMap` {#hashmap}

`class HashMap` — defined in `engine/foundation/containers/hash_map.h`

```cpp
template <typename K, typename V, typename Allocator>
class HashMap { ... }
```

Hash map from `K` to `V` using open addressing with linear probing.

`K` needs `operator==`, a `Hash<K>` specialization, and a default constructor; `V` needs a default constructor. Keys and values are copied in and stored by value. The table starts with at least 8 slots and doubles when the load factor, counting tombstones, reaches 0.7. Growth rehashes into a new block and abandons the old one inside the allocator, as with [`Vector`](#vector). Growth invalidates pointers returned by `Find`. There is no iteration support.

| Field | Value |
|---|---|
| Thread-safety | not-thread-safe. Synchronize externally if shared, including concurrent `Find` calls with a writer. |
| Ownership | the allocator owns all storage and must outlive the map; the map never frees memory. |

## `Vector` {#vector}

`class Vector` — defined in `engine/foundation/containers/vector.h`

```cpp
template <typename T, typename Allocator = HeapAllocator>
class Vector { ... }
```

Growable contiguous array of `T`; the default allocator is the heap.

`Allocator` must provide `void* Alloc(usize size, usize align)` returning nullptr on exhaustion; [`HeapAllocator`](foundation-memory.md#heapallocator) and [`ArenaAllocator`](foundation-memory.md#arenaallocator) satisfy this. If it also provides `void Free(void* ptr, usize size, usize align)` (the heap does) the vector frees its old block on growth and its storage on destruction; otherwise (an arena) old blocks are abandoned inside the allocator until it is reset. Capacity starts at 4 elements on first push and doubles. Growing invalidates references and pointers to elements. This replaces a hand-paired `new T[n]` / `delete[]`: use `Resize` for a runtime-sized table.

| Field | Value |
|---|---|
| Thread-safety | not-thread-safe. Synchronize externally if shared. |
| Ownership | the vector destroys its elements. It frees storage only when the allocator has `Free`; the allocator must outlive the vector. |

### `Resize(usize)` {#vector-resize-usize}

`method Vector::Resize` — defined in `engine/foundation/containers/vector.h`

```cpp
void Resize(usize new_size);
```

Changes the size to `new_size`: new elements are value-initialized (zero for scalars) and a smaller size destroys the tail. An empty vector gets exactly `new_size` capacity (a table sized once); one that already holds elements grows at least geometrically, so repeated `Resize(Size() + k)` is not quadratic.
