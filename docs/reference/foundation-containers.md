Small algorithms over spans and values, so no code needs `<algorithm>`.

`Min`, `Max` and `Clamp` take values; `IndexOf` searches a span; `Sort` orders a span in place with a comparison (not stable, no allocation); `StableSort` keeps equal elements in their order (it allocates a scratch buffer from the heap); `LowerBound`, `UpperBound` and `BinarySearch` search a sorted span; `NthElement` and `PartialSort` select the best `k` without sorting the rest. The sorts also take a [`Vector`](#vector) or anything else with `Data()` and `Size()`.

Fixed-size array with inline storage, the engine's `std::array`: the size is a compile-time constant and the elements live inside the object. [`Vector`](#vector) is every case where the size is only known at runtime or changes.

[`BinaryHeap`](#binaryheap): a priority queue in a [`Vector`](#vector), for the "pick the best next" loops that were linear scans.

[`DenseMap`](#densemap): a map whose entries sit densely in slots, with a hash index from key to slot: for the caches and tables that iterate in a stable order or hand out slot numbers, which were written as a `Vector` plus a `HashMap` of positions with the swap-remove fix-up repeated at every site.

[`Deque`](#deque): a growable ring of elements, pushed and popped at both ends in O(1), for the queues that were written as `Vector::Remove(0)`.

The engine's hash functions: `Hash<K>`, the function object [`HashMap`](#hashmap) and [`HashSet`](#hashset) use for their keys, and `Fnv1a64`, the one byte hash. Every module that hashes bytes calls `Fnv1a64` instead of writing FNV-1a out again; its values are the published FNV-1a 64-bit values, so a hash stored in a minted file or compared across machines does not change.

Open-addressing hash map (linear probing, tombstone deletion) whose slot storage is a [`Vector`](#vector). The hash functions are in `containers/hash.h`; the set of keys alone is [`HashSet`](#hashset).

A set of keys over the open-addressing table [`HashMap`](#hashmap) uses, for the membership tests that were written as `HashMap<K, u8>`. The set stores its keys alone.

The open-addressing table under [`HashMap`](#hashmap) and [`HashSet`](#hashset): linear probing, tombstones, a power-of-two capacity and the walk, written once. A set stores its keys, a map stores `{key, value}` entries; `KeyOf` says where an element's key is.

[`SharedBytes`](#sharedbytes): a region of immutable bytes whose owner is shared. Two classes that need the same bytes (a loaded file and the GPU object uploaded from it, and uploaded again after a device reset) do not point into each other: both hold a [`SharedPtr`](#sharedptr) to one of these.

Reference-counted owning pointer for objects with several owners. [`UniquePtr`](#uniqueptr) is the default; use this only where ownership is genuinely shared.

Non-owning views of contiguous elements: [`Span`](#span), [`ByteSpan`](#bytespan) and [`MutableByteSpan`](#mutablebytespan).

A span is a pointer and a length. It owns nothing, allocates nothing and is cheap to pass by value; the viewed memory must outlive it. Functions that read or write a run of elements take a span, so a caller can hand them a [`Vector`](#vector), an [`Array`](#array), a C array or a pointer and a length without converting.

Owning pointer to one object, the engine's replacement for a raw `new` / `delete` pair. [`Array`](#array) and [`Vector`](#vector) own runs of elements; [`SharedPtr`](#sharedptr) shares one object.

Growable array that owns its storage: on the heap by default, or from a caller-supplied allocator such as an arena. The fixed-size, inline counterpart is [`Array`](#array).

## `BinaryHeap` {#binaryheap}

`class BinaryHeap` — defined in `engine/foundation/containers/binary_heap.h`

```cpp
template <typename T, typename Less, typename Allocator = HeapAllocator>
class BinaryHeap { ... }
```

A binary max-heap of `T` ordered by `Less`: `Top` is an element no other is greater than, `Push` and `Pop` are O(log n).

Elements that compare equal come out in no promised order, so a deterministic caller makes the order total: put a sequence number in the element and compare it last (`a.priority < b.priority || (a.priority == b.priority && a.sequence > b.sequence)` pops the oldest of equal priorities first). The heap has no `begin()`/`end()`: its storage order means nothing. `Remove(index)` takes an element out from the middle, at a storage position read with `At`.

| Field | Value |
|---|---|
| Thread-safety | not-thread-safe. Synchronize externally if shared. |
| Ownership | owns its elements, in a [`Vector`](#vector) on `Allocator`. |

## `DenseMap` {#densemap}

`class DenseMap` — defined in `engine/foundation/containers/dense_map.h`

```cpp
template <typename K, typename V, typename Allocator = HeapAllocator>
class DenseMap { ... }
```

A map from `K` to `V` whose entries are dense in slots `0..Size()-1`, found by key through a hash index.

- **Slots** are stable until a removal: `Emplace` appends, and a removal moves the last entry into the hole (O(1)) and reports where it came from, so a caller that keeps slot numbers can follow the move.
- **Order:** a range-for (`for (auto& [key, value] : map)`) visits the slots in order. For a given sequence of calls the order is always the same (unlike [`HashMap`](#hashmap)'s), so it may reach a deterministic output.
- **Keys** need `operator==` and `Hash<K>`, may be move-only (a [`String`](foundation-strings.md#string)) and are stored once; a lookup may use a [`HeterogeneousKey`](#heterogeneouskey) (a [`StringView`](foundation-strings.md#stringview) for a [`String`](foundation-strings.md#string) key). The index holds 4-byte slot numbers and each entry keeps its hash, so growth never hashes a key again.

Use it where entries are walked in a stable order or named by slot; use [`HashMap`](#hashmap) otherwise.

| Field | Value |
|---|---|
| Thread-safety | not-thread-safe. Synchronize externally if shared, including concurrent `Find` calls with a writer. |
| Ownership | owns its keys and values; the allocator must outlive the map. |

## `Deque` {#deque}

`class Deque` — defined in `engine/foundation/containers/deque.h`

```cpp
template <typename T, typename Allocator = HeapAllocator>
class Deque { ... }
```

A double-ended queue of `T` in one growable ring: `PushBack`, `PushFront`, `PopFront` and `PopBack` are O(1) (amortized for the pushes), and `operator[]` counts from the front.

The capacity is a power of two (at least 8), allocated on the first push and doubled when full; growth moves the elements into a new block, front first, and invalidates references to them. `T` may be move-only.

| Field | Value |
|---|---|
| Thread-safety | not-thread-safe. Synchronize externally if shared. |
| Ownership | the deque destroys its elements; its storage comes from the allocator, freed when the allocator has `Free` (as [`Vector`](#vector)), else abandoned inside it; the allocator must outlive the deque. |

## `HashMap` {#hashmap}

`class HashMap` — defined in `engine/foundation/containers/hash_map.h`

```cpp
template <typename K, typename V, typename Allocator>
class HashMap { ... }
```

Hash map from `K` to `V` using open addressing with linear probing.

`K` needs `operator==` and a `Hash<K>` specialization. Keys and values are stored by value, constructed when they are inserted (copied or moved in) and destroyed when they are removed, when the table is rehashed into a new one (they are moved across) and with the map; neither needs a default constructor, and either may be move-only (a [`String`](foundation-strings.md#string) key). A key can also be looked up by a type `Q` it compares equal to (`K == Q`) whose `Hash<Q>` agrees with `Hash<K>` for equal keys: a [`StringView`](foundation-strings.md#stringview) for a [`String`](foundation-strings.md#string) key.

The table (shared with [`HashSet`](#hashset)) is a power of two in size (a probe step is a mask, not a division) and is made by the first insert, not by the constructor; it rehashes when the load factor, counting tombstones, reaches 0.7: into twice the slots if the live entries alone fill at least half of that, otherwise into the same number (which clears the tombstones left by removals). Growth invalidates pointers returned by `Find`.

Iteration (`ForEach`, or a range-for: `for (auto& [key, value] : map)`) visits the entries in no particular order: no deterministic output may depend on it. The map must not be changed while it is walked.

| Field | Value |
|---|---|
| Thread-safety | not-thread-safe. Synchronize externally if shared, including concurrent `Find` calls with a writer. |
| Ownership | the map owns its keys and values; its storage comes from the allocator, which must outlive the map, and is released as a [`Vector`](#vector) releases it (freed when the allocator has `Free`, else abandoned inside it). |

## `SharedPtr` {#sharedptr}

`class SharedPtr` — defined in `engine/foundation/containers/shared_ptr.h`

```cpp
template <typename T, typename Count = AtomicRefCount>
class SharedPtr { ... }
```

Shares ownership of one `T`, destroying it when the last owner goes away.

The object and its count live in one heap allocation made by [`MakeShared`](#makeshared-args-amp-amp). `Count` selects the policy: [`AtomicRefCount`](#atomicrefcount) (the default) lets owners on different threads copy and release their own pointers concurrently; [`PlainRefCount`](#plainrefcount) is cheaper for pointers confined to one thread. The pointed-to object itself is not synchronized by either. There are no weak pointers.

| Field | Value |
|---|---|
| Thread-safety | thread-safe for copying and destroying distinct pointers that share one object when `Count` is `AtomicRefCount`; not-thread-safe with `PlainRefCount`. One `SharedPtr` object is never safe to modify from two threads. |
| Ownership | shares ownership of the object; it is destroyed when the last owner is released. |

## `Vector` {#vector}

`class Vector` — defined in `engine/foundation/containers/vector.h`

```cpp
template <typename T, typename Allocator = HeapAllocator>
class Vector { ... }
```

Growable contiguous array of `T`; the default allocator is the heap.

`Allocator` must provide `void* Alloc(usize size, usize align)` returning nullptr on exhaustion; [`HeapAllocator`](foundation-memory.md#heapallocator) and [`ArenaAllocator`](foundation-memory.md#arenaallocator) satisfy this. If it also provides `void Free(void* ptr, usize size, usize align)` (the heap does) the vector frees its old block on growth and its storage on destruction; otherwise (an arena) old blocks are abandoned inside the allocator until it is reset. Capacity starts at 4 elements on first push and doubles. Growing invalidates references and pointers to elements. This replaces a hand-paired `new T[n]` / `delete[]`: use `Resize` for a runtime-sized table.

| Field | Value |
|---|---|
| Thread-safety | not-thread-safe. Synchronize externally if shared. |
| Ownership | the vector destroys its elements. It frees storage only when the allocator has `Free`; the allocator must outlive the vector. |
