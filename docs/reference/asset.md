The asset settings (Phase 22 Day 315): [`asset::RegisterAssetSettings`](#asset-registerassetsettings-settings-registry-star) declares the byte budgets of the load buffer pool and of the memory backend and (Day 320) the animation error bounds; the readers return them.

[`asset::ResourceBackend`](#asset-resourcebackend): the seam every source of resources implements (loose files, the memory backend of a host application, later paks and the network), with [`asset::ResourceReader`](#asset-resourcereader) (ranged reads of one resource) and [`asset::TableTicket`](#asset-tableticket) (the asynchronous read of a backend's id <-> path table).

The versioned blob container every minted resource is stored in: [`asset::BlobWriter`](#asset-blobwriter) writes it, [`asset::BlobReader`](#asset-blobreader) validates and reads it.

Layout (all integers little-endian, no padding other than the alignment gaps, which are zero):

| offset | size | field | |---|---|---| | 0 | 4 | magic `ABLB` | | 4 | 4 | container version ([`asset::kContainerVersion`](#asset-kcontainerversion)) | | 8 | 4 | resource type tag | | 12 | 4 | type version (the registry's current version, nothing else is read) | | 16 | 8 | the blob's own [`asset::ResourceId`](#asset-resourceid) (null only for a `NAMES` blob) | | 24 | 4 | target tag (the platform family the layout was made for; 0 is the development target) | | 28 | 4 | flags (0) | | 32 | 4 | section count | | 36 | 4 | reserved (0) | | 40 | 8 | total size of the blob in bytes | | 48 | 16 | content hash of the whole blob with these 16 bytes zero | | 64 | 24 each | section table: id (u32), reserved (u32, 0), offset (u64), size (u64), ids strictly increasing |

Every section starts at a multiple of 64 bytes (of 4096 when it is 1 MiB or larger) so a loader can hand a span of the file buffer straight to the GPU upload. Section 1 is the standard dependency section (a `u32` count, then `(id u64, type u32, type version u32, role u32)` records strictly sorted by id); ids below 16 are reserved.

Block compression for the texture minter: decoders for BC1, BC2, BC3, BC4, BC5 and BC7, and encoders for BC1, BC4, BC5 and BC7, in exact integer arithmetic so the output is byte-identical on every compiler, machine and worker count. Phase 22 Day 324.

A block is 4x4 texels, row-major, stored in 8 bytes (BC1, BC4) or 16 bytes (BC2, BC3, BC5, BC7). The decoders give 8-bit RGBA texels (BC4 puts its channel in red and BC5 its two in red and green; the others read 0 and alpha 255). The interpolated colors of BC1 are `(2a + b) / 3` and `(a + b) / 2` of the 8-bit expanded endpoints, truncated: the decoder is the reference of this engine, GPUs differ by at most one step. The encoders choose among endpoint sets by the sum of squared channel errors and break every tie in favor of the lower index or the first candidate tried, so the result depends on the input texels only. A partial block at the right or bottom edge repeats its last column and row.

The animation clip blob (type `ANIM`, version 1): per-joint keyframe tracks and events for one skeleton, built by [`asset::BuildClipBlob`](#asset-buildclipblob-const-typeregistry-amp-resourceid-const-clipbuildinput-amp-vector-lt-byte-gt-star-u32-f32-star-f32-star) and read in place through [`asset::ClipView`](#asset-clipview). Phase 22 Day 320.

Sections (little-endian, ids from 16): 16 header (96 bytes: duration, sample rate hint, flags, joint count, track count, event count, the skeleton hash, the measured error bounds, the bound box), 17 the track table (72 bytes per animated joint), 18 the key data, 19 the events (16 bytes each). The skeleton is the blob's one dependency (role [`asset::kClipRoleSkeleton`](#asset-kcliproleskeleton)).

A channel (translation, rotation or scale) of a track is either constant (its value sits in the track table, no keys) or keyed. Keyed times are `u16` ticks: 1 / sample rate when every key lies on that grid, otherwise duration / 65535. Rotations are smallest-three: the largest component is dropped (made positive), the other three stored as `SNorm16`, the first of them as 14 bits with the dropped index in the low two bits of its word (6 bytes per key). Translations and scales are `UNorm16x3` between a per-channel minimum and extent stored with the channel. Sampling interpolates linearly (rotations: normalized shortest-arc lerp).

[`asset::ContentHash`](#asset-contenthash): the 128-bit content hash of a blob (SHA-256 truncated to its first 16 bytes, the choice of Phase 22 Day 313, Spike 2). It names blobs in the network cache, lets `verify` and the packer detect corruption and identifies a base pak. It is not on the load path of a local file, and it is not a security feature (the engine's networking is for trusted networks).

[`asset::FaultyBackend`](#asset-faultybackend): a wrapper around any [`asset::ResourceBackend`](#asset-resourcebackend) that injects failures, chunked reads and latency, for the tests of every later day (the file layer has a network-like double for the same job).

[`asset::FilesystemBackend`](#asset-filesystembackend): a directory of loose blobs served through [`asset::ResourceBackend`](#asset-resourcebackend), the backend of development builds.

The level blob (type `LEVL`, version 1): entities as the storage module's records, the table of every resource they name, and the list of levels it includes. Built by [`asset::BuildLevelBlob`](#asset-buildlevelblob-const-typeregistry-amp-const-storage-componentregistry-amp-resourceid-const-leveldata-amp-vector-lt-byte-gt-star-u32-const-storage-codeclimits-amp), read by [`asset::ParseLevelBlob`](#asset-parselevelblob-bytespan-const-typeregistry-amp-const-storage-componentregistry-amp-leveldata-star-resourceid-star-const-storage-codeclimits-amp) and put into a world by [`asset::LoadLevelBlob`](#asset-loadlevelblob-bytespan-const-typeregistry-amp-const-storage-componentregistry-amp-ecs-world-amp-storage-keyindex-amp-leveldata-star-const-storage-codeclimits-amp). Phase 22 Day 327.

A level is the same data a save is: one [`storage::EntityRecord`](storage.md#storage-entityrecord) per entity (the entity container of `storage::WorldStorage`: a count, then framed component records encoded by the [`storage::ComponentRegistry`](storage.md#storage-componentregistry)), so there is one set of field codecs for saves and levels. What a level adds is what a save has no use for: the references. Every field declared with [`storage::FieldOptions::Reference`](storage.md#storage-fieldoptions-reference-u32-bool) (or typed [`storage::ResourceRef`](storage.md#storage-resourceref)) names a resource by id; the blob lists each such use in a table and each distinct resource as a dependency, so the manager can load the closure before a single entity exists.

Sections (ids from [`asset::kFirstUserSection`](#asset-kfirstusersection)): 16 the header (64 bytes: the entity, record, reference and include counts), 17 the entity table (32 bytes per entity: key high, key low, offset into section 18, size, record count; keys strictly increasing, the offsets tiling section 18), 18 the entity containers one after another, 19 the reference table (24 bytes each: entity index, component id, field index, type tag, id; in entity, record and field order; null references are not listed). The standard dependency section lists every distinct referenced resource and every included level (role bits [`asset::kLevelRoleReference`](#asset-klevelrolereference) and [`asset::kLevelRoleInclude`](#asset-klevelroleinclude)).

A stored component is read only at its registered version; a level written with an older one is refused with `UnsupportedVersion` and fixed by re-minting from its source, never converted.

[`asset::LoadBufferPool`](#asset-loadbufferpool): reusable, pre-faulted buffers that resources are read into. Phase 22 Day 313 (Spike 5) measured a read into a fresh buffer at four times the cost of a read into one whose pages were already touched, so the pool touches the pages once, when it creates a buffer, and keeps the buffer for the next load of that size.

The material blob (type `MATL`, version 1): a template name, shader permutation options, the parameter block in the template's uniform layout, texture bindings by resource id, sampler descriptions and render-state overrides. Built by [`asset::BuildMaterialBlob`](#asset-buildmaterialblob-const-typeregistry-amp-resourceid-const-materialassetdata-amp-vector-lt-byte-gt-star-u32) and read by [`asset::LoadMaterialBlob`](#asset-loadmaterialblob-bytespan-const-typeregistry-amp-materialassetdata-star-resourceid-star). Phase 22 Day 326.

Sections (ids from [`asset::kFirstUserSection`](#asset-kfirstusersection)): 16 the header (96 bytes: flags, counts, the state overrides and the 48-byte template name), 17 the parameter block (the bytes copied into the material's uniform buffer, laid out as the template's block, so loading copies one block), 18 the parameter table (name, type, offset and size of each value the source set; 64 bytes each), 19 the texture bindings (slot name and resource id; 64 bytes each), 20 the samplers (64 bytes each), 21 the permutation options (48-byte names). Every texture id is also a dependency of the blob (type `TEXR`, role = the binding's index), so the loader follows the references without reading the sections.

[`asset::HostMemoryBackend`](#asset-hostmemorybackend): a real backend for resources whose bytes the host application provides at run time (the content a host that embeds the engine registers through Phase 23's C API), with no file, pak or server behind it.

The mesh blob (type `MESH`, version 1): geometry laid out for the GPU, built by [`asset::BuildMeshBlob`](#asset-buildmeshblob-const-typeregistry-amp-resourceid-const-meshbuildinput-amp-vector-lt-byte-gt-star-u32) and read zero-copy through [`asset::MeshView`](#asset-meshview). Phase 22 Day 319.

Sections (ids from 16, little-endian, each 64-byte aligned by the container): 16 header (96 bytes), 17 attributes (16 bytes each: location, format, offset, binding), 18 vertex stream 0 (the exact bytes of the vertex buffer), 19 indices (16 or 32 bit, a triangle list), 20 LODs (16 bytes each), 21 material slots (40 bytes each), and for a skinned mesh 22 the skin stream (binding 1: `UInt8x4` joint indices at location 5, `UNorm8x4` weights at location 6, summing to exactly 255 per vertex) and 23 the bind-pose box of each joint's influence set. A skinned mesh declares its skeleton as a dependency (role [`asset::kMeshRoleSkinSkeleton`](#asset-kmeshroleskinskeleton)) and records the skeleton hash and joint count. Section 40 (`MORP`, morph targets) is reserved and refused by this version.

[`asset::MountTable`](#asset-mounttable): the ordered set of backends the resource manager reads from. A lookup by id goes to the highest-priority backend that has the resource (so a loose-file mount overrides a pak), and the mounts' id <-> path tables are read asynchronously and merged.

The pak: many resources in one file, found by id ([`asset::PakWriter`](#asset-pakwriter), [`asset::PakReader`](#asset-pakreader)). Phase 22 Day 316.

All integers are little-endian. The layout, in file order:

| Part | Size | Content | |---|---|---| | header | 128 | magic `APAK`, format version, flags, target tag, alignment, type count, entry count, type table offset, names offset and size, base pak identity (16 bytes, zero for none), reserved zero | | type table | 8 each | `(tag u32, version u32)` for each resource type the pak holds, sorted by tag | | names | any | the id <-> path table as a `NAMES` blob (optional, flag bit 0), 64-byte aligned | | entries | any | the blobs in id order, each 64-byte aligned (4096 from 1 MiB), zero padding between | | index | 48 each | `(id u64, offset u64, size u64, content hash 16, type u32, reserved u32)` sorted by id | | footer | 48 | index offset, entry count, index hash (16), file size, magic `KPAK`, format version |

The pak's identity (what a patch pak names as its base) is its index hash. Version 1 stores blobs uncompressed.

[`asset::PakBackend`](#asset-pakbackend): a pak file served through [`asset::ResourceBackend`](#asset-resourcebackend) (read-only).

[`asset::ResourceId`](#asset-resourceid): a resource's stable identity, and the rules for the virtual paths that name it. An id is a permanent 64-bit number assigned once by `asset_mint adopt`; it is not derived from the path, so a rename or a move never changes it. The runtime refers to resources by id only; a path is an alias for tools and sources.

[`asset::ResourceTable`](#asset-resourcetable): the id <-> path map of the engine (the user's decision of 2026-11-13: one table where the map lives). It is a value type: each backend supplies its own (a stored `NAMES` blob, a pak section, a server's reply, or one built on demand by scanning a folder), and the mount table merges them by priority (Day 315). The load path never uses it: the runtime refers to resources by id, and paths are resolved at the edges.

[`asset::ResourceType`](#asset-resourcetype) (a four-character tag) and [`asset::TypeRegistry`](#asset-typeregistry) (the known types and the one current version of each, the single source of truth the minters, the packer, `verify` and the manager share).

The skeleton resource (Phase 22 Day 318): the joint hierarchy, the bind pose and the inverse bind matrices that skinned meshes and animation clips refer to. [`asset::BuildSkeletonBlob`](#asset-buildskeletonblob-const-typeregistry-amp-resourceid-span-lt-const-skeletonjoint-gt-bool-vector-lt-byte-gt-star-u32) writes a `SKEL` blob, [`asset::SkeletonView`](#asset-skeletonview) reads one in place.

Layout of the blob's sections (all little-endian, one section each, 64-byte aligned by the container):

| Section | Content | |---|---| | 16 header | 48 bytes: joint count `u32`, flags `u32` (bit 0: names present), skeleton hash (16 bytes), bind-pose bound center `f32 x3`, radius `f32`, two zero `u32` | | 17 parents | `u16` per joint; 0xFFFF for a root; a parent index is always below the joint's own | | 18 translations | `f32 x3` per joint: the bind pose, local space | | 19 rotations | `f32 x4` (x, y, z, w) per joint: unit quaternions with w >= 0 | | 20 scales | `f32 x3` per joint | | 21 inverse bind | 3x4 row-major `f32` (48 bytes) per joint: the bytes the GPU joint palette takes | | 22 name hashes | `u32` per joint (FNV-1a of the name; only with names) | | 23 names | `u32` offsets (joint count + 1) then the characters, no terminators (only with names) |

Errors of the asset pipeline, reported as values: [`asset::ErrorCode`](#asset-errorcode) and [`asset::Status`](#asset-status). No asset failure aborts, and no input, however damaged, is a reason to abort.

The texture blob (type `TEXR`, version 1): every mip level of every layer, laid out the way the upload wants, built by [`asset::BuildTextureBlob`](#asset-buildtextureblob-const-typeregistry-amp-resourceid-const-texturebuildinput-amp-vector-lt-byte-gt-star-u32) and read zero-copy through [`asset::TextureView`](#asset-textureview). Phase 22 Day 323.

Sections (ids from 16, little-endian, each 64-byte aligned by the container): 16 header (64 bytes), 17 the level table (16 bytes per subresource: `u64` offset into the data section, `u32` size, `u32` row pitch; subresource `layer * mip_count + mip`), 18 the data. There is no "generate at load" flag: every level is stored, and the mip filter, the sRGB handling and the premultiplication happened in the minter. Each subresource starts at a multiple of the recorded subresource alignment (an offset in the data section, which the container aligns to 64 bytes) and its rows are `row_pitch` bytes apart (the row size rounded up to the row alignment and the texel size), so the loader hands the spans to the upload unchanged. The alignments depend on the target API (`TextureLayoutForTarget`); `RetargetTextureBlob` re-lays a blob out for another target.

Mip generation for the texture minter: a deterministic filter in exact integer arithmetic, so the same input gives byte-identical output on every compiler, machine and thread count. Phase 22 Day 323.

The formats are `R8_UNorm`, `RG8_UNorm`, `RGBA8_UNorm`, `RGBA8_SRGB`, `R16_Float`, `RGBA16_Float`. An sRGB texture is filtered in linear light (a 16-bit linear value per channel, through a fixed table). Half-float texels are exact multiples of 2^-24 and are filtered as such integers. Nothing here uses floating-point arithmetic.

A level of `w x h` texels gives a next level of `max(1, w / 2) x max(1, h / 2)`. Destination texel `i` of an axis (source length `s`, destination length `d`) covers the source range `[i * s / d, (i + 1) * s / d)` (integer division), so an odd length gives its last texel a range of three. The box filter averages that range; the Kaiser filter is the fixed 6-tap kernel `-5 24 109 109 24 -5` (sum 256, a Kaiser-windowed sinc with beta 4) over the source texels `lo - 2 .. lo + 3` (`lo` the start of the range), edges clamped; an axis of length 1 is copied.

## `BuildClipBlob(const TypeRegistry&,ResourceId,const ClipBuildInput&,Vector<byte>*,u32,f32*,f32*)` {#asset-buildclipblob-const-typeregistry-amp-resourceid-const-clipbuildinput-amp-vector-lt-byte-gt-star-u32-f32-star-f32-star}

`function asset::BuildClipBlob` — defined in `engine/asset/clip.h`

```cpp
Status BuildClipBlob(const TypeRegistry& types, ResourceId id, const ClipBuildInput& input, Vector<byte>* out, u32 target = 0, f32* rotation_degrees = nullptr, f32* translation = nullptr);
```

Builds a clip blob: reduces the keys of every channel (a deterministic greedy split that keeps the error inside the bounds), folds constant channels into the track table, quantizes, measures the error against the source keys at every source key and at 8 points inside each segment, and records the measured bounds in the header.

| Field | Value |
|---|---|
| Fails | `Invalid` (no tracks and no events, a duration that is not finite and above 0, a joint at or past the joint count or used twice, keys not strictly increasing or outside [0, duration], a value that is not finite, a rotation that is not unit length, events out of order or past the duration, a null skeleton); `LimitExceeded` (a count above the limits, or a measured error above `limits`). |
| Ownership | borrows `input` for the call; `*out` is replaced; `*rotation_degrees` and `*translation`, when not null, receive the measured errors (also on a `LimitExceeded` failure). |

## `FilesystemBackend` {#asset-filesystembackend}

`class asset::FilesystemBackend` — defined in `engine/asset/filesystem_backend.h`

```cpp
class FilesystemBackend : public ResourceBackend { ... }
```

Serves the blobs under a root directory.

The index (id, type, virtual path, file) is built once, on first use, either from the stored table `resources.table` at the root (a minted `NAMES` blob) or, when there is none, by one walk of the directory that reads each file's 64-byte header (the path is the file's location under the root, the id the blob's own, never an id from a file name). A stored table is a cache that is never trusted over the files: `Stat` and `Open` check the header of the file they find against the id they were asked for. Files that do not start with the blob magic are ignored by the walk; two files that claim one id fail the build of the index. `Watch` rescans and reports what changed (modification stamps and sizes decide, so an unchanged file is not read again).

The walk goes 64 directories deep; a blob below that is not indexed.

A path never leaves the root: the index only holds files found under it, and a symbolic link is followed only when its target is inside the root too (loops fail to resolve and are skipped).

| Field | Value |
|---|---|
| Thread-safety | thread-safe (one lock around the index). |
| Ownership | owns its index; `types` must outlive the backend. |

## `HostMemoryBackend` {#asset-hostmemorybackend}

`class asset::HostMemoryBackend` — defined in `engine/asset/memory_backend.h`

```cpp
class HostMemoryBackend : public ResourceBackend { ... }
```

Resources provided by the host.

The bytes of every resource are a complete blob (Day 314): `Add` checks the container, that the blob's own id is the id the host passed, that the content hash verifies and, when the host passes one, that it equals the host's hash. Bytes are *copied* into memory the backend owns, or *borrowed* (the host keeps them alive and gives a release function, called exactly once, after the resource was replaced or removed and its last open reader closed). A replace never tears a read: an open reader keeps the bytes it opened. Every add, replace and remove leaves a `Watch` record. The bytes of all resources count against the budget (`assets.memory_backend_bytes`); an add past it returns `LimitExceeded` (back-pressure, never eviction: the host owns the content).

| Field | Value |
|---|---|
| Thread-safety | thread-safe; adds, replaces and removes may run concurrently with reads. |
| Ownership | owns copied bytes; borrowed bytes belong to the host until their release function ran. Readers must not outlive the backend object, but the bytes they read outlive a replacement. |

## `MountTable` {#asset-mounttable}

`class asset::MountTable` — defined in `engine/asset/mount_table.h`

```cpp
class MountTable { ... }
```

Ordered mounts and the merged table.

A mount has a path prefix (`/` for none; the entries of its table appear under it), a priority (higher wins; the later of two equal priorities wins) and a backend the caller owns. Loads by id never use a table. Path questions (`Resolve`, `PathsOf`) are answered from the mounts' tables in priority order: a mount whose table has not arrived answers `NotReady` (never `NotFound`, which would be a lie), a mount whose table read failed answers with that failure, and a path two mounts map to different ids is won by the higher priority and listed as shadowed in the merged table.

| Field | Value |
|---|---|
| Thread-safety | thread-safe. The tables-ready callback runs on the thread that finished the last table read. A backend must not be unmounted (or destroyed) while a call into it from `Stat` or `Open` is running. |
| Ownership | borrows the backends (they must outlive their mount); owns its tickets and tables. |
