# Assets and resources

_Generated by docgen. Do not edit._

**Headers:** `engine/asset/asset_module.h`, `engine/asset/blob.h`, `engine/asset/content_hash.h`, `engine/asset/resource_id.h`, `engine/asset/resource_table.h`, `engine/asset/resource_type.h`, `engine/asset/status.h`

The versioned blob container every minted resource is stored in: [`asset::BlobWriter`](#asset-blobwriter) writes it, [`asset::BlobReader`](#asset-blobreader) validates and reads it.

Layout (all integers little-endian, no padding other than the alignment gaps, which are zero):

| offset | size | field | |---|---|---| | 0 | 4 | magic `ABLB` | | 4 | 4 | container version ([`asset::kContainerVersion`](#asset-kcontainerversion)) | | 8 | 4 | resource type tag | | 12 | 4 | type version (the registry's current version, nothing else is read) | | 16 | 8 | the blob's own [`asset::ResourceId`](#asset-resourceid) (null only for a `NAMES` blob) | | 24 | 4 | target tag (the platform family the layout was made for; 0 is the development target) | | 28 | 4 | flags (0) | | 32 | 4 | section count | | 36 | 4 | reserved (0) | | 40 | 8 | total size of the blob in bytes | | 48 | 16 | content hash of the whole blob with these 16 bytes zero | | 64 | 24 each | section table: id (u32), reserved (u32, 0), offset (u64), size (u64), ids strictly increasing |

Every section starts at a multiple of 64 bytes (of 4096 when it is 1 MiB or larger) so a loader can hand a span of the file buffer straight to the GPU upload. Section 1 is the standard dependency section (a `u32` count, then `(id u64, type u32, type version u32, role u32)` records strictly sorted by id); ids below 16 are reserved.

[`asset::ContentHash`](#asset-contenthash): the 128-bit content hash of a blob (SHA-256 truncated to its first 16 bytes, the choice of Phase 22 Day 313, Spike 2). It names blobs in the network cache, lets `verify` and the packer detect corruption and identifies a base pak. It is not on the load path of a local file, and it is not a security feature (the engine's networking is for trusted networks).

[`asset::ResourceId`](#asset-resourceid): a resource's stable identity, and the rules for the virtual paths that name it. An id is a permanent 64-bit number assigned once by `asset_mint adopt`; it is not derived from the path, so a rename or a move never changes it. The runtime refers to resources by id only; a path is an alias for tools and sources.

[`asset::ResourceTable`](#asset-resourcetable): the id <-> path map of the engine (the user's decision of 2026-11-13: one table where the map lives). It is a value type: each backend supplies its own (a stored `NAMES` blob, a pak section, a server's reply, or one built on demand by scanning a folder), and the mount table merges them by priority (Day 315). The load path never uses it: the runtime refers to resources by id, and paths are resolved at the edges.

[`asset::ResourceType`](#asset-resourcetype) (a four-character tag) and [`asset::TypeRegistry`](#asset-typeregistry) (the known types and the one current version of each, the single source of truth the minters, the packer, `verify` and the manager share).

Errors of the asset pipeline, reported as values: [`asset::ErrorCode`](#asset-errorcode) and [`asset::Status`](#asset-status). No asset failure aborts, and no input, however damaged, is a reason to abort.
