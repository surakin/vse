# Foundation: Strings

Grapheme cluster segmentation (UAX #29): iterate or count user-perceived characters in UTF-8 text.

Canonical Unicode normalization (NFC and NFD) per UAX #15, plus the Unicode property lookups it is built on.

Text types: non-owning StringView, allocator-backed String, and StringBuilder for formatting numbers and text.

Strings are byte sequences, treated as UTF-8 by the helpers in utf8.h.

UTF-8 helpers on StringView: codepoint counting, validation and iteration.

Raw UTF-8 decode and encode on `const char*` buffers, with no dependency on the string module.

[`StringView`](#stringview), the non-owning text view. It lives in the base layer (it needs nothing but `types.h`) so the OS primitives, the log and the integer types can take text without depending on the string module; `string/string.h` includes it, so existing code is unaffected.

## `String` {#string}

`class String` — defined in `engine/foundation/string/string.h`

```cpp
template <typename Allocator>
class String { ... }
```

Owning, growable, always NUL-terminated string whose bytes come from an allocator.

Backed by a [`Vector`](foundation-containers.md#vector) of `char`, so it inherits that class's allocation behavior: growth abandons old blocks inside the allocator rather than freeing them. Contents are expected to be well-formed UTF-8. A moved-from string is left with no storage and must not be used except for assignment or destruction.

| Field | Value |
|---|---|
| Thread-safety | not-thread-safe. Synchronize externally if shared. |
| Ownership | the allocator owns the memory and must outlive the string; the string never frees it. Views and C-string pointers are invalidated by any append. |
