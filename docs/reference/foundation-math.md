# Foundation: Math

_Generated by docgen. Do not edit._

**Headers:** `engine/foundation/math/geometry.h`, `engine/foundation/math/math_util.h`, `engine/foundation/math/matrix.h`, `engine/foundation/math/quaternion.h`, `engine/foundation/math/transform.h`, `engine/foundation/math/vector.h`

Shapes and the tests between them (Phase 18 Day 238): boxes, spheres, planes, rays and the view frustum, shared by the renderer's culling and the spatial module. Moved here from `engine/renderer/bounds.h` and `frustum.h`, which keep `using` aliases. Boxes and spheres are closed sets: shapes that only touch overlap, and a ray that grazes a face or an edge hits it.

Scalar math helpers: the constants; the functions (`Sqrt`, `Sin`, `Cos`, `Acos`, ...) are in `lang/scalar.h`, which this header includes.

Mat3 and Mat4: column-major storage with the column-vector convention.

Each matrix stores its columns directly. A vector transforms as `v' = M * v`, and composition is left-multiplication: `M2 * M1` applies `M1` first. This matches the GLM/OpenGL convention.

Quaternion rotations: Hamilton convention, right-handed, `w` is the scalar part.

Consistent with matrix.h: `ToMat3` rotates a vector the same way `RotateVector` does, and `a * b` rotates by `b` first, then by `a`.

Position, rotation and scale (TRS) and composition of two of them.

Uses the same column-vector convention as matrix.h and quaternion.h.

Vec2, Vec3 and Vec4: plain float component structs with basic arithmetic.

No SIMD or special alignment. Index access uses an explicit switch rather than relying on struct layout.

## `Slerp(const Quaternion&,const Quaternion&,f32)` {#slerp-const-quaternion-amp-const-quaternion-amp-f32}

`function Slerp` — defined in `engine/foundation/math/quaternion.h`

```cpp
inline Quaternion Slerp(const Quaternion& a, const Quaternion& b, f32 t);
```

Interpolates along the shortest arc between two unit quaternions at constant angular speed.

If `a` and `b` are on opposite hemispheres, `b` is negated first so the short way round is taken. Nearly parallel inputs fall back to a normalized linear interpolation to avoid dividing by a near-zero sine.

| Field | Value |
|---|---|
| Parameter `a` | start rotation (result at `t` = 0); must be unit length. |
| Parameter `b` | end rotation (result at `t` = 1); must be unit length. |
| Parameter `t` | interpolation factor, normally in [0, 1]; values outside extrapolate. |
| Returns | the interpolated rotation. |
