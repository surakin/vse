The OS clipboard behind the toolkit's [`ui::Clipboard`](ui.md#ui-clipboard) (Phase 15, Day 200): asynchronous, with the primary selection where the platform has one.

The window adapter (Phase 15, Day 194): the one place where an [`os::Window`](platform-window-input.md#os-window) meets a [`ui::Surface`](ui.md#ui-surface). `ui` itself names no window.

## `OsClipboard` {#ui-osclipboard}

`class ui::OsClipboard` — defined in `engine/ui_window/os_clipboard.h`

```cpp
class OsClipboard final : public Clipboard { ... }
```

A [`ui::Clipboard`](ui.md#ui-clipboard) over an [`os::Window`](platform-window-input.md#os-window)'s clipboard.

`SetText` offers the text to other programs. `RequestPaste` asks the owner of the selection and returns a ticket; nothing is called until the window's `ClipboardData` event arrives and the [`ui::WindowAdapter`](#ui-windowadapter) hands it to `HandleData`, which calls the function with the text. A request that ended without text (a timeout, an empty selection, an oversized transfer) calls no paste function and runs the `OnFailed` listeners with the status. `HasText` reads the window's record of the selection ([`os::Window::ClipboardHasFormat`](platform-window-input.md#os-window-clipboardhasformat-clipboardkind-clipboardformat-stringview-const), kept by `ClipboardChanged`), so a Paste command can be enabled without asking. The primary selection is on when the window supports it. Offscreen surfaces keep using [`ui::LocalClipboard`](ui.md#ui-localclipboard).

| Field | Value |
|---|---|
| Thread-safety | owner-thread-only. |
| Ownership | borrows the window, which must outlive the clipboard; owns its pending requests. |

## `WindowAdapter` {#ui-windowadapter}

`class ui::WindowAdapter` — defined in `engine/ui_window/window_adapter.h`

```cpp
class WindowAdapter { ... }
```

Feeds a window's input events to a surface and gives the surface's cursor to the window.

A frame of a windowed program reads: `window.PumpEvents()`, `adapter.PumpInto(window, surface)`, `surface.Frame(...)`, `adapter.UpdateCursor(window, surface)`. The window's coordinates are physical pixels; the adapter divides pointer positions by the surface scale to get logical units. A `Resize` of the window becomes `Surface::Resize` at the same scale (several in one pump cost one layout). A wheel event is placed at the last pointer position. The window's pointer enter becomes a move, its leave a surface-level pointer leave, its focus gain and loss the surface's window focus. Clipboard and drag events are dropped for now (they arrive with the widgets that use them).

| Field | Value |
|---|---|
| Thread-safety | owner-thread-only. |
| Ownership | owns nothing; the window and the surface are borrowed for each call. |
