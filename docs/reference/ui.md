The canvas widgets draw on (Phase 15, Day 189): an abstract 2D drawing surface in logical units.

A widget never builds vertices: it calls the operations of [`ui::Canvas`](#ui-canvas), and the implementation decides what that means. The implementation of the toolkit is [`ui::DrawListCanvas`](#ui-drawlistcanvas) (it appends to a [`ui::DrawList`](#ui-drawlist) that the renderer draws); [`ui::RecordingCanvas`](#ui-recordingcanvas) records the calls for tests. A vector canvas, a software rasteriser or an exporter can be added without touching a widget. No draw-list, GPU or RHI type appears in this header.

**Units and snapping (the contract of every implementation).** Widgets work in logical units; `Scale()` physical pixels make one unit (1, 1.25, 2, ...).

- A rectangle is snapped to whole pixels by rounding its **edges**: `left = round(x * scale)`, `right = round((x + w) * scale)`, so two rectangles that share an edge in logical units share it in pixels, with no gap and no overlap. A non-empty rectangle is never thinner than one pixel.
- A border, a stroke width or any other thickness is scaled and then rounded to whole pixels, never below one pixel while it is above zero: 1 unit is 1 pixel at scale 1, 2 pixels at scale 2, and 1 pixel at scale 1.25 (never 1.25).
- Corner radii and blur distances are scaled but not rounded; a radius larger than half of the shorter side is reduced to it.
- Lines and triangles have arbitrary angles: their points are scaled, not snapped.
- Text is laid out by the caller **in physical pixels** (`text::TextStyle::pixel_size` is the logical size times `Scale()`); its origin is logical and is scaled, and the glyphs then land on whole pixels as `renderer::TextRenderer` places them.
- A colour is packed RGBA with red in the lowest byte; a fully transparent colour draws nothing.

The 2D draw list (Phase 15, Day 189): the data [`ui::DrawListCanvas`](#ui-drawlistcanvas) builds and the renderer draws. Vertices, 32-bit indices and commands; no GPU type.

Positions are physical pixels with the origin at the top-left of the surface. Every primitive is a quad (4 vertices, 6 indices) except a triangle (3, 3); the fragment shader picks its work from the **mode** in the low bits of `Vertex::flags`, so rectangles, glyphs and images of one frame share one pipeline and a command is split only by clip, atlas page or image.

The canvas that builds a [`ui::DrawList`](#ui-drawlist) (Phase 15, Day 189).

The events a surface delivers to its widgets (Phase 15, Day 192): pointer, wheel, key, text, focus and tick, as plain data.

The plain geometry types of the UI toolkit: points, rectangles and corner radii in logical units, and the whole-pixel rectangle the draw list clips with.

The container widgets (Phase 15, Day 193): [`ui::BoxLayout`](#ui-boxlayout), [`ui::StackLayout`](#ui-stacklayout), [`ui::AnchorLayout`](#ui-anchorlayout), [`ui::GridLayout`](#ui-gridlayout) and [`ui::Spacer`](#ui-spacer).

Layout is two steps per widget. `Measure(constraints)` says what size the widget wants from its content; `Arrange(rect)` places it and its children. Everything is in logical units and fractional; the canvas snaps rectangles to whole pixels when drawing, so neighbours share an edge at any scale. A child that is collapsed takes no space; one that is only hidden keeps it. Children read their `LayoutProps` (weight, alignment, minimum and maximum size, grid cell, anchors).

The vocabulary of layout (Phase 15, Day 193): constraints, alignment and the per-widget layout properties the containers read.

The surface (Phase 15, Day 192): the root of a widget tree with its size, scale, clock, theme, font provider, focus, pointer capture and popup layer. It knows no window.

The offscreen test harness (Phase 15, Day 192): a surface with no window, a font, an atlas and helpers to send input, run frames and read rectangles and pixels.

A canvas that records the calls instead of drawing them, so a widget test can say "this button drew a rounded rect with the hover colour" (Phase 15, Day 189).

A small CPU rasteriser for a [`ui::DrawList`](#ui-drawlist) (Phase 15, Day 192), so widget tests compare pixels without a GPU. For tests only; the renderer is the real thing.

It follows the UI shader (`shaders/ui.frag.slang`): solid, rounded-rectangle (anti-aliased, with ring and shadow) and glyph modes, premultiplied blending, the scissor of each command, a target that is not sRGB (colours are written as given). Image-mode commands are skipped (a software test has no image textures).

A block of text that sizes itself from its content (Phase 15, Day 193): the base of the label widget.

The look of the toolkit as data: colors, metrics, fonts and per-widget styles that every widget draws from (Phase 15, Day 191).

A [`ui::Theme`](#ui-theme) is plain data. A widget asks a [`ui::ThemeSet`](#ui-themeset) for its look by kind, variant and state; the set walks a chain (the built-in default, the surface's theme, the overrides of the widget and its ancestors), a value left unset falls to the next level, and the result is scaled to physical pixels. Colors are `0xAABBGGRR` (the draw list's format); all metrics and font sizes are logical units.

The retained widget tree (Phase 15, Day 192): a [`ui::Widget`](#ui-widget) owns its children, belongs to one [`ui::Surface`](#ui-surface) and draws through the abstract [`ui::Canvas`](#ui-canvas).

## `DrawListCanvas` {#ui-drawlistcanvas}

## `Surface` {#ui-surface}

`class ui::Surface` — defined in `engine/ui/surface.h`

```cpp
class Surface { ... }
```

A tree of widgets and everything the widgets share.

A window, a test or an in-world screen feeds it events with `Post` and runs `Frame`; the surface never names a window. The frame cycle is: apply the queued events, call `Update` of the widgets that want it, run layout if dirty, and (when a draw list is given) rebuild it if anything looks different or the list is empty.

Pointer events go to the capture owner, else to the deepest widget under the pointer (popups first); a button press captures the pointer to the widget it hit until the last button is released. Key and text events go to the focus owner. An event the target does not handle bubbles to its parents. Enter and leave follow the hit widget.

| Field | Value |
|---|---|
| Thread-safety | owner-thread-only. |
| Ownership | owns the root and the popup layer; borrows the theme, the font provider and the widgets' references (focus, capture, hover), which are cleared when a widget dies. |

## `ThemeSet` {#ui-themeset}

`class ui::ThemeSet` — defined in `engine/ui/theme.h`

```cpp
class ThemeSet { ... }
```

What a surface keeps: the theme in use and the cache of resolved styles.

The application owns the themes. `Resolve` walks the chain least specific first: the built-in light theme, the surface's theme, then the `overrides` (the nearest ancestor's override before the widget's own). For each theme the kind's default style is laid over the result, then the variant's. A style with overrides is not cached; the one without is, keyed by kind, variant, state and scale, and the cache is dropped by `SetTheme`.

| Field | Value |
|---|---|
| Thread-safety | owner-thread-only. |
| Ownership | borrows the surface theme, which must outlive its use here. |

## `Widget` {#ui-widget}

`class ui::Widget` — defined in `engine/ui/widget.h`

```cpp
class Widget { ... }
```

A node of the widget tree.

Children are owned (`UniquePtr`) and drawn in order, so the last child is on top and is hit-tested first. A widget's id is a hash of its parent's id and its name (its index among the siblings when the name is empty), so it is the same every time a tree is built the same way. Bounds are in surface coordinates, logical units. The state bits (hover, pressed, focused) are kept by the surface; `Disabled` follows [`ui::Widget::EffectivelyEnabled`](#ui-widget-effectivelyenabled-const).

Removal is safe from inside an event handler: while the surface dispatches, [`ui::Widget::RemoveChild`](#ui-widget-removechild-widget-star) and [`ui::Widget::RemoveFromParent`](#ui-widget-removefromparent) queue the removal and the widget dies when the dispatch ends. Destroying a widget clears the surface's references to it (focus, capture, hover).

| Field | Value |
|---|---|
| Thread-safety | owner-thread-only. |
| Ownership | owns its children; borrows the parent and the surface. |
