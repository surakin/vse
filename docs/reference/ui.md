The implementation of the toolkit is [`ui::DrawListCanvas`](#ui-drawlistcanvas) (it appends to a [`ui::DrawList`](#ui-drawlist) that the renderer draws); [`ui::RecordingCanvas`](#ui-recordingcanvas) records the calls for tests. **Units and snapping (the contract of every implementation).** Widgets work in logical units; `Scale()` physical pixels make one unit (1, 1.25, 2, ...).

- A rectangle is snapped to whole pixels by rounding its **edges**: `left = round(x * scale)`, `right = round((x + w) * scale)`, so two rectangles that share an edge in logical units share it in pixels, with no gap and no overlap. A non-empty rectangle is never thinner than one pixel.
- A border, a stroke width or any other thickness is scaled and then rounded to whole pixels, never below one pixel while it is above zero: 1 unit is 1 pixel at scale 1, 2 pixels at scale 2, and 1 pixel at scale 1.25 (never 1.25).
- Corner radii and blur distances are scaled but not rounded; a radius larger than half of the shorter side is reduced to it.
- Lines and triangles have arbitrary angles: their points are scaled, not snapped.
- Text is laid out by the caller **in physical pixels** (`text::TextStyle::pixel_size` is the logical size times `Scale()`); its origin is logical and is scaled, and the glyphs then land on whole pixels as `renderer::TextRenderer` places them.
- A colour is packed RGBA with red in the lowest byte; a fully transparent colour draws nothing.

## `DrawListCanvas` {#ui-drawlistcanvas}

`class ui::DrawListCanvas` — defined in `engine/ui/draw_list_canvas.h`

```cpp
class DrawListCanvas final : public Canvas { ... }
```

A [`ui::Canvas`](#ui-canvas) that converts logical units to physical pixels, snaps as the canvas contract says, and appends vertices, indices and commands to a draw list.

A frame is `list.Clear()`, `Begin(scale, width, height)`, any number of draws, then `list.SortLayers()`. Clips and layers are physical-pixel rectangles on stacks that keep their capacity. Consecutive draws with the same clip, layer and texture share a command; a draw that needs no texture joins any command.

## `Surface` {#ui-surface}

`class ui::Surface` — defined in `engine/ui/surface.h`

```cpp
class Surface { ... }
```

A tree of widgets and everything the widgets share.

A window, a test or an in-world screen feeds it events with `Post` and runs `Frame`; the surface never names a window. The frame cycle is: apply the queued events, call `Update` of the widgets that want it, run layout if dirty, and (when a draw list is given) rebuild it if anything looks different or the list is empty.

Pointer events go to the capture owner, else to the deepest widget under the pointer (popups first); a button press captures the pointer to the widget it hit until the last button is released. Key and text events go to the focus owner. An event the target does not handle bubbles to its parents. Enter and leave follow the hit widget.

| Field | Value |
|---|---|
| Thread-safety | owner-thread-only. |
| Ownership | owns the root and the popup layer; borrows the theme, the font provider and the widgets' references (focus, capture, hover), which are cleared when a widget dies. |

## `TextBlock` {#ui-textblock}

`class ui::TextBlock` — defined in `engine/ui/text_block.h`

```cpp

```

Draws one string in one font and reports its size to the layout.

The text is laid out in physical pixels (font size times the surface scale) and the result converted back to logical units. With wrapping on, the width given to `Measure` is the wrap width, so the height depends on the width: a container measures the block at the width it will give it. The layout is cached on (text, font, pixel size, wrap width, font object); an unchanged block does not lay out again. The default color is the theme's `Text`, the default font the theme's `Body`; a block with a style kind (a [`ui::Label`](#ui-label)) takes both from its style in the theme instead, in the widget's state (so a disabled label uses the disabled color).

## `Widget` {#ui-widget}

`class ui::Widget` — defined in `engine/ui/widget.h`

```cpp
class Widget { ... }
```

A node of the widget tree.

Children are owned (`UniquePtr`) and drawn in order, so the last child is on top and is hit-tested first. A widget's id is a hash of its parent's id and its name (its index among the siblings when the name is empty), so it is the same every time a tree is built the same way. Bounds are in surface coordinates, logical units. The state bits (hover, pressed, focused) are kept by the surface; `Disabled` follows [`ui::Widget::EffectivelyEnabled`](#ui-widget-effectivelyenabled-const).

Removal is safe from inside an event handler: while the surface dispatches, [`ui::Widget::RemoveChild`](#ui-widget-removechild-widget-star) and [`ui::Widget::RemoveFromParent`](#ui-widget-removefromparent) queue the removal and the widget dies when the dispatch ends. Destroying a widget clears the surface's references to it (focus, capture, hover).

| Field | Value |
|---|---|
| Thread-safety | owner-thread-only. |
| Ownership | owns its children; borrows the parent and the surface. |

## `ComboBox` {#ui-combobox}

`class ui::ComboBox` — defined in `engine/ui/widgets/combobox.h`

```cpp
class ComboBox : public Widget { ... }
```

A box that shows the selected item of a [`ui::ListModel`](#ui-listmodel) and opens a drop-down [`ui::ListBox`](#ui-listbox) (virtualized, so a model of 100,000 items is as cheap as one of ten).

While closed, Up and Down select the previous or next item (they run `OnSelectionChanged`), Home and End the first and last, letters select by type-ahead, and the wheel selects when `SetWheelSelects(true)`. Alt+Down, F4, Space and Enter open the list, and so does a press on the box. While open, the list has the keyboard (arrows, Home, End, PageUp, PageDown, type-ahead); Enter or a click on an item chooses it and closes the list, Escape or a click elsewhere closes it and keeps the old selection; the focus goes back to the box.

With `SetEditable(true)` the box holds a [`ui::TextField`](#ui-textfield): choosing an item puts its text in the field, and typing text equal to an item selects that item (any other text selects none), so the text and the selection never disagree. Down in the field opens the list.

| Ownership | borrows the model; owns its text field and, while it is open, hands the drop-down list to the surface. |

## `ListBox` {#ui-listbox}

`class ui::ListBox` — defined in `engine/ui/widgets/list_box.h`

```cpp
class ListBox : public Widget { ... }
```

A scrolling list of text items from a model.

The list is virtual: rows are all one height, so the item under a point and the range in view come from arithmetic, and only the rows in view are laid out and drawn (a ring of cached text layouts re-used as the list scrolls); 100,000 items cost the same per frame as 100. The list scrolls with its own vertical bar and with the wheel. Click selects (with Ctrl or Shift in multiple mode), the arrow keys, PageUp, PageDown, Home and End move the current item and select it, Space selects it, Enter runs `OnActivate`; typing letters selects the next item whose text starts with what was typed (typed quickly, the letters make a prefix; the same letter repeated cycles through the items starting with it). After the model changes call `ModelChanged`.

| Field | Value |
|---|---|
| Thread-safety | owner-thread-only. |
| Ownership | borrows the model; owns the selection and the row cache. |

## `ValueRange` {#ui-valuerange}

`struct ui::ValueRange` — defined in `engine/ui/widgets/range.h`

```cpp

```

A range of `f64` values with an optional step.

A value snaps to the grid `min + k * step` for a whole number `k`, computed as one multiplication from the minimum, so a thousand steps drift by nothing; the grid stops at the last point not above `max`. In integer mode the step is at least 1. Without a step (0) the value is only clamped. A NaN becomes the minimum.

| Ownership | owns nothing. |

## `TextField` {#ui-textfield}

`class ui::TextField` — defined in `engine/ui/widgets/text_field.h`

```cpp
class TextField : public Widget { ... }
```

An editable line of text.

Offsets are byte offsets into the UTF-8 text and are always on grapheme boundaries (`text::NextBoundary` and `text::PreviousBoundary` over the field's layout): a combining mark, a flag, a ZWJ sequence or a Hangul syllable moves and deletes as one unit. Only `Text` events insert, so a key the field does not know does nothing; there is no input method and no complex-script shaping (Phase 14 scope). Ctrl+Left and Ctrl+Right move by word ([`ui::WordStart`](#ui-wordstart-stringview-u32), [`ui::WordEnd`](#ui-wordend-stringview-u32)). The field scrolls sideways to keep the caret in view.

The keys are Left, Right, Home, End (Shift extends the selection, Ctrl moves by word), Backspace, Delete (Ctrl: by word), Ctrl+A, Ctrl+C / Ctrl+Insert, Ctrl+X / Shift+Delete, Ctrl+V / Shift+Insert, Ctrl+Z, Ctrl+Shift+Z and Ctrl+Y, Enter (`OnSubmit`), Escape (`OnCancel`). Tab, Up and Down are left to the surface and the parents. The mouse: a click places the caret, Shift+click extends, a drag selects (the pointer is captured), a double click selects a word, a triple click all.

Edits go through one path that applies, in order, the read-only flag, the maximum length (in clusters; a longer insertion is cut), and the validator; an edit that changes nothing is not recorded. Consecutive typing, and consecutive Backspace or Delete presses, are one undo step. A password field draws bullets, refuses copy and cut, moves and edits by cluster, and treats its whole text as one word (word movement, word deletion and a double click go to the ends), so the spaces do not show.

| Field | Value |
|---|---|
| Thread-safety | owner-thread-only. |
| Ownership | owns its text, its undo history and its layouts; borrows the validator's user pointer and the surface's clipboard. |

## `SpinBox` {#ui-spinbox}

`class ui::SpinBox` — defined in `engine/ui/widgets/value_widgets.h`

```cpp
class SpinBox : public Widget { ... }
```

A number with up and down buttons.

The box is drawn in the `textfield` style; the left part holds an embedded [`ui::TextField`](#ui-textfield) and the right part the buttons (up above, down below). A press on a button, an arrow key or a wheel notch changes the value by the step, PageUp and PageDown by ten steps; every change goes through the range, so the value is always in range and on the grid. The field takes digits, a sign (when the range has negative values) and a decimal point (when `SetDecimals` is above 0) and nothing else; Enter, and losing the focus, commit the text (a text that is not a number, or that the range rejects, goes back to the value), and Escape reverts it. Home and End move the caret in the field.
